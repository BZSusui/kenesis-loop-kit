# 実績カタログ取り込み — 新規画像をAI自動タグ付けして人間確認のうえ登録する

## 目的と成果物

里見さん所有の実績画像・手動収集の見本サムネイルを、実績カタログ(SCR-004・`catalog/catalog.json`)へ登録する
(REQ-106)。各画像を Claude が**視覚認識**して業種・テイスト・主配色(7カテゴリ)・カラム構成を推定し、
**登録前に人間が確認・修正**したうえでカタログへ追記する。「画像を入れるとAIが自動タグ付けしてくれる」を実現する。

- **成果物**: 承認された画像を `catalog/img/{id}.{ext}` へ移動し、`catalog/catalog.json` の `entries` へ
  `CATALOG_RULES.md` のスキーマ準拠エントリを追記(＋`generatedAt` 更新)。`catalog.json` が無ければ空スキーマから作る。
- **最重要の不変**: 画像・JSON・案件名は **`catalog/` 配下(Git除外)にのみ**置く。`catalog/` の外へ書き出さない。
- **人間確認は必須ゲート**: 推定タグは**登録前に提示**し、人間の承認を得てから確定する。**推測で自動確定しない**
  (`/draft-generate` の「受付チェックを飛ばさない」規律と同型)。

## 参照ファイル

| ファイル | 読むタイミング |
|---|---|
| `templates/CATALOG_RULES.md` | **取り込みの前に必ず全体を読む**。カタログJSONスキーマ・主配色7カテゴリ・タグ付け規約・機密規律の正 |
| `draft-gen/bridge.py`(`validate_catalog`/`is_safe_catalog_name`/`CANONICAL_COLORS`) | JSON整形・安全名・許可色カテゴリの決定論的な正(スキーマは CATALOG_RULES と同一) |
| `docs/wireframes/SCR-004-catalog.html` | 見た目の正(`.autotag`「登録前に確認・修正できます」・own/refバッジ・主配色7チップ) |
| 対象画像 `catalog/.pending/*.jpg` / `*.png` | 取り込み対象。**Read で開いて視覚認識**し業種・テイスト・主配色・カラムを推定する |

## 起動と入力(2経路・後方互換)

- **起動語**: `/catalog-import`。
- **① ジョブ仕様 `.json` パス(ローカルブリッジ経由)**: `catalog/.pending/{jobId}.import.json`
  (`{schema:"catalog-import-job", version:1, files:[...]}`)。引数がこのファイルパスのときは**そのファイルを読み込み**、
  `schema` が `"catalog-import-job"` / `version` が `1` であることを確認し、`files`(取り込み対象のファイル名の列挙)を取り出す。
  ブリッジが検証済みの安全名のみを書くため、プロンプトに可変ユーザー文字列は載らない(注入対策)。
- **② 手動 `$ARGUMENTS`**: `catalog/.pending/` 内の対象ファイル名の列挙(例 `salon_top.jpg cafe.png`)。
  **未指定のときは `catalog/.pending/` 内の JPG/PNG 全件**を対象にする。
  収集見本(第三者著作物)を取り込むときは、その旨(`ref`)を指示に明示する(既定は自社実績 `own`)。
- いずれの経路でも**同じ受付チェック**へ合流する。スキーマ・機密規律・人間確認ゲートは経路によらず同一。

## 手順

### 1. 受付(機密規律・安全名の確認)

- `templates/CATALOG_RULES.md` を**全体読み込む**。
- 対象は `catalog/.pending/` 内の JPG/PNG のみ。各ファイル名が**安全名**(`^[A-Za-z0-9][A-Za-z0-9._-]*$`・`..`/`/`/`\` を含まない)
  であることを確認する。安全でない名前・`catalog/.pending/` の外を指す入力は**取り込まず**理由を伝えて停止する。
- ジョブ仕様経路のときは `schema=="catalog-import-job"` / `version==1` を確認する。異なれば停止する。

### 2. 視覚認識(AI自動タグ付け・§3.3)

各対象画像を **Read で開いて視覚認識**し、次を推定する:

- **業種**(`industry`): カタログの**推奨業種語彙17区分**(飲食店・カフェ・食関連/美容室・エステ・化粧品/ファッション/
  スクール・教室/不動産・建築/ホテル・旅館・レジャー/士業事務所（法律/会計/コンサルティング他）/コーポレート／BtoB/
  EC・物販/フィットネス・ジム・スポーツ/イベント・キャンペーンLP/ジュエリー・時計・貴金属/クリニック・病院・介護リハビリ/
  農業・ファーム/求人・採用/アート・ポートフォリオ/その他・団体/NPO ＝受け皿)を叩き台に、自由文字列で最も近い1つ
  (ハード enum 強制はしない＝後方互換)。断定できないときは近い候補を挙げ、手順3で人間に確認する。表記はカタログ
  SCR-004 のチップと同一(完全一致でフィルタするため全角/半角スラッシュに注意)。CATALOG_RULES §3 業種が正。
- **テイスト**(`taste`): シンプル/ナチュラル/高級感/ポップ/和風/かっこいい/レトロ 等から単一。
- **主配色**(`colors`): **`CANONICAL_COLORS` の7カテゴリ(グリーン/ブルー/レッド/ゴールド/ピンク/モノトーン/マルチカラー)から選ぶ**。
  **第1主配色を必須・第2/第3を任意(最大3件)**。単一色を決められない多色サイトは `マルチカラー` を**単独**で付ける
  (他色と併用しない)。**画素の厳密HEXは求めない**・**7カテゴリ外の値を付けない**(§3.3)。ベージュ/ホワイト等の微細色は
  `tags`/`note` の自由記述に置き、フィルタ用 `colors` は7カテゴリに寄せる。
- **カラム構成**(`columns`・任意): 見た目から DRAFT_RULES §8 の6値(`1col`/`2col-*`/`3col`)に近いものを推定。
- **セクション別レイアウト型**(`sectionLayouts`・任意): 画像の各セクションを **DRAFT_RULES §12.1.1/§12.1.2 の型プール**へ寄せて
  1型ずつ提案する(対象は HERO/ABOUT/MENU/GALLERY/VOICE/FLOW/STAFF の7セクションのみ・1セクション1型)。**該当セクションが
  無い/未判定はキー省略**、**プール外は `"other"`**。**型マーカーは DRAFT_RULES §12.1.x の語彙のみ**(独自語で付けない・語彙の正は
  DRAFT_RULES)。参考準拠生成(KLK-031)の土台。
- **用途メモ**(`note`・任意): レイアウトの特徴を短く。
- **own/ref**: 既定 `own`(自社実績)。収集見本は取り込み指示で `ref` を明示された分のみ `ref`。

### 3. 人間確認(必須ゲート・登録前に確認・修正)

推定タグを**登録前に一覧提示**し、人間が「**この内容で登録** / **タグを修正** / **除外**」を選べるようにする
(ワイヤー `.autotag`「登録前に確認・修正できます」・`.edit`「タグを修正」)。

- ファイル名・推定した業種/テイスト/主配色(7カテゴリ・第1必須/最大3件・マルチカラーは単独)/カラム/**セクション別レイアウト型(`sectionLayouts`)**/own|ref を、非エンジニアにも分かる形で提示する。
- **確認・承認を得るまで `catalog.json` へ確定しない**。修正指示があれば反映して再提示する(`sectionLayouts` も他タグと同様に修正可)。除外指定の画像は登録しない。

### 4. 確定(承認された分のみ・catalog/ 配下に限定)

承認された画像についてのみ:

- 画像を `catalog/img/{id}.{ext}` へ**移動**する(`id` は既存 `entries` と衝突しない一意な連番。例 `cat-0001`・`cat-0002`…。
  `catalog/img/` と `catalog.json` の双方を見て最大連番の次を採る)。`file` は移動後の実ファイル名。
- `catalog/catalog.json` の `entries` へ `CATALOG_RULES.md` スキーマ準拠のエントリを追記し、`generatedAt` を現在時刻(ISO8601)に更新する。
  `catalog.json` が無ければ `{"schema":"klk-catalog","version":1,"entries":[]}` から作る。**承認された `sectionLayouts` のみ**を
  entry に書く(省略・`{}` も可・該当なしのキーは作らない)。
- 追記後の `catalog.json` が `validate_catalog` 相当(schema/version/各entryの id・file・source∈{own,ref}・
  colors⊆7カテゴリ・件数1..3・マルチカラー単独排他・**`sectionLayouts` は present のとき object かつ各値が非空文字列**)を満たすことを自己確認する。

### 5.(任意)オフラインスナップショット再生成

人間から要求されたときのみ、`catalog/catalog.html`(データをインライン・画像を相対 `img/{file}` 参照)を再生成する。
**生成先は `catalog/` 配下(Git除外)に限定**する(機密インライン・§3.1)。要求が無ければ作らない。

### 6. 報告(非エンジニア向け)

- 登録した件数・各画像に付与したタグ(業種/テイスト/主配色/カラム/own|ref)。
- 保存先(`catalog/img/` と `catalog/catalog.json`・**いずれもGit公開対象外**)。
- 除外した画像(あれば理由)。
- 閲覧の仕方: `python3 draft-gen/bridge.py` を起動して `http://127.0.0.1:8765/catalog` を開くと反映される旨。

## してはならないこと

- **人間確認を飛ばして自動確定すること**(推定タグをそのまま `catalog.json` へ書き込む)。
- **セクション別レイアウト型(`sectionLayouts`)を人間確認なしで自動確定すること**(他タグと同じ人間確認ゲートを必ず通す)。
- **型マーカーを DRAFT_RULES §12.1.1/§12.1.2 以外の独自語で付けること**(語彙の正は DRAFT_RULES・プール外は `"other"`)。
- **主配色を7カテゴリ(`CANONICAL_COLORS`)以外の値で付けること**(厳密HEX抽出をしようとすること)。
- **マルチカラーを具体色と併用すること**(`["マルチカラー","ピンク"]` 等・マルチカラーは単独指定のみ)。
- **主配色を4件以上、または空(0件)で付けること**(第1主配色が必須・最大3件)。
- 画像・JSON・案件名を **`catalog/` の外へ書き出すこと**(REQ-011/NFR-004・社外秘漏洩)。
- 収集見本(`ref`)を第三者著作物として扱わず、公開・再配布・そっくり再現の材料にすること
  (`source:"ref"` を明示し、報告・スナップショットに「社内参考のみ」を残す)。
- 安全名でないファイル名・`catalog/.pending/` の外を指す入力を取り込むこと(注入・パストラバーサル対策)。
- 実在の顧客名・個人情報・シークレット(api key / secret / password / token / private key)を
  `catalog/` の外へ出すこと(器である `draft-gen/catalog.html` には機密を焼き込まない)。
