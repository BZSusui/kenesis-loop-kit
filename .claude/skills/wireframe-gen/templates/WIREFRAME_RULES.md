> このファイルはワイヤーフレーム生成Skillが従うマスター規約です。
> 生成されるすべてのHTMLファイルはこの規約に準拠すること。

## 1. ファイル規約

- **形式**: 単一ファイルの静的HTML。1画面 = 1ファイル。
- **配置**: `docs/wireframes/` 直下。サブディレクトリは作らない。
- **命名**: `SCR-ID-画面名英語.html`(例: `SCR-001-login.html`)。英語名は小文字ケバブケース。
- **ハブページ**: `docs/wireframes/index.html`(命名固定)。
- **文字コード**: UTF-8。`<meta charset="utf-8">` を必ず含める。
- **外部依存ゼロ**: CDN・外部CSS/JS・画像ファイル・Webフォントの参照を禁止する。CSSは`<style>`タグ内、アイコンや図はインラインSVGまたはUnicode文字で表現する。理由: エージェントがファイル単体で全情報を読めること、オフラインでも表示が崩れないことを保証するため。
- **JavaScript**: 原則使用しない。画面内の表示確認に不可欠な場合(タブ切替・モーダル開閉など)のみ、`<script>`タグ内に最小限記述してよい。フォーム送信・API呼び出し・状態管理のコードは書かない。

## 2. 冒頭コメント(必須)

すべてのワイヤーフレームHTMLの1行目(DOCTYPE直後)に、以下のコメントを挿入すること:

```html
<!--
  ⚠ このファイルはワイヤーフレーム(画面イメージの確認用)です。実装コードではありません。
  実装は docs/SPEC.md セクション9(技術的制約)に定められた技術スタックで別途行うこと。
  このHTML/CSSを本番コードへコピーしてはならない。
  対応画面: {SCR-ID} {画面名} / 準拠SPEC: v{X.X} / 生成日: {YYYY-MM-DD}
  配色・余白・アクセシビリティは デジタル庁デザインシステム(DADS) の基準に準拠
  出典：デジタル庁デザインシステムウェブサイト https://design.digital.go.jp/dads/
  （同サイトのコンテンツを加工して作成）
-->
```

## 3. 画面情報バー(必須)

各画面の最上部に、レビュー時の識別用として次の情報バーを固定表示すること(スクリーンショット共有時にも画面を特定できるようにするため):

- 表示内容: `{SCR-ID} {画面名} | ワイヤーフレーム | 準拠SPEC v{X.X}`
- スタイル: 画面幅いっぱいの細い帯(高さ32px程度・濃いグレー背景・白文字・小さめフォント)。本体デザインと混同されない見た目にする。
- バーの右端に `index.html` へ戻るリンクを置く。

## 4. 忠実度(中忠実度)の基準

本プロジェクトのワイヤーフレームは**中忠実度**とする。完成イメージの共有が目的である。

- **配色**: DADS(デジタル庁デザインシステム)の基準に従ったカラーパレット(後述5)を使用する。プロジェクト指定のブランドカラーがある場合も、DADSのコントラスト下限を満たす形に調整して使う。
- **寸法感**: 実際の利用を想定したコンテナ幅・フォーム幅・ボタンサイズにする(例: PCフォームは最大幅480px程度、タップ対象は最小44px)。
- **ダミーデータ**: 現実的な内容にする(「山田太郎」「suzuki@example.com」「2026-07-04」等)。「テキストテキスト」「aaa」のような無意味な埋め草は使わない。
- **作り込まないもの**: アニメーション、ホバー時の凝った演出、faviconなど。目的は完成イメージの共有であり、ピクセル単位の再現ではない。

## 5. カラーパレットと余白(DADS準拠)

配色と余白の**正はデジタル庁デザインシステム(DADS)**である: `docs/design-system/`。
生成前に `docs/design-system/foundations/color/index.md` と
`docs/design-system/foundations/spacing/index.md` を読むこと(この2ファイルのみでよい)。

### 5.1 DADSが定める下限(必ず満たす)

| 対象 | 基準 |
|---|---|
| テキストと背景のコントラスト | **4.5:1 以上**(常時) |
| 枠線・ディバイダー等の非テキスト要素と隣接背景 | **3:1 以上** |
| プライマリーカラーと主要背景色 | **4.5:1 以上** |
| セカンダリー／ターシャリーカラーと主要背景色(隣接表示要素として使う場合) | **3:1 以上**(テキストに使うなら 4.5:1 以上) |
| フォーカスインジケーター | Yellow-300 と Black の**2重構造。いかなる場合も変更しない** |
| 余白 | 基準単位 **8 CSS px** の倍率スケール。使うスケールは**3〜5段階に絞る** |

> **重要**: DADSのMarkdownアーカイブには**HEX値・デザイントークン定義が含まれていない**(実値はFigmaとコードスニペット側)。
> したがって特定の色を「DADSが定める色」と称してコメントやHTMLに書いてはならない。
> 具体値は「DADSの原則と下限を満たす値をプロジェクト側で決めたもの」として扱い、コントラスト比の実測値を根拠として記録する。

### 5.2 パレットの決定方法

初回生成時に一度だけユーザーへ「ブランドカラーや参考にしたい既存サイト・資料はありますか?」と確認する。

- **指定がある場合**: そのブランドカラーを**キーカラー**として、DADSのカラースキーム構造
  (プライマリー / セカンダリー / ターシャリー / バックグラウンド)に当てはめて組む。
  各色は 5.1 の下限を満たすまで明度を調整する。**下限を満たせない色はテキスト用途に使わない**。
- **指定がない場合**: 下の既定パレット(青系キーカラー)を使う。

### 5.3 既定パレット(DADS下限を満たすことを実測済み)

括弧内は白背景 `#FFFFFF` に対するコントラスト比。

| 変数名 | 色 | 役割 | 使用比率の目安 |
|---|---|---|---|
| --color-base | #FFFFFF | 主要背景・カード面 | 65〜70% |
| --color-primary | #0B5A9C (7.10:1) | 塗りボタン(**白文字可**)・選択状態・見出し帯・アクティブ表示 | 15〜20% |
| --color-secondary | #E8F1F8 (1.14:1) | セクション背景・カード面の変化付け(**非テキスト面のみ**。この上の本文は --color-text を使う) | 10%以下 |
| --color-tertiary | #6A96BF (3.12:1) | 装飾線・アイコン背景・非活性の塗り(**非テキスト専用**。文字色にも白文字の下地にも使わない) | 5%以下 |
| --color-text | #1F2933 (14.76:1) | 本文文字(**純黒 #000000 は使わない**) | — |
| --color-text-sub | #59636E (6.11:1) | 補助文字・プレースホルダ・キャプション | — |
| --color-link | #0B5A9C (7.10:1) | 未訪問リンク(青。DADSのリンクカラー慣習に従う) | — |
| --color-link-visited | #8B2A7A (7.75:1) | 訪問済リンク(青と明度差のあるマゼンタ寄り。DADSの識別性向上の指針に従う) | — |
| --color-border | #767C82 (4.22:1) | 入力欄枠・カード枠・ディバイダー(非テキスト3:1を満たす) | — |
| --color-bg-subtle | #F2F5F7 (1.09:1) | テーブルの縞・非活性領域の背景 | — |
| --color-error | #B3212E (6.62:1) | エラー文字・必須マーク・破壊的操作の塗りボタン(**白文字可**) | 5%以下 |
| --color-success | #1B6B3A (6.54:1) | 完了・成功の表示(**白文字可**) | 5%以下 |

**フォーカスインジケーター**:

| 変数名 | 色 | 役割 |
|---|---|---|
| --color-focus-inner | #000000 | 内側の黒レイヤー |
| --color-focus-outer | #F2CE00 | 外側の黄色レイヤー(**暫定値**) |

- すべてのフォーカス可能要素に、この2重構造のアウトライン(例: `outline: 2px solid var(--color-focus-inner); box-shadow: 0 0 0 4px var(--color-focus-outer);`)を当てる。
- `--color-focus-outer` は DADS の **Yellow-300 の実値がMarkdownアーカイブに含まれないための暫定値**である。
  暫定であることを `index.html` のコメントに明記し、確定値はコードスニペットまたはFigmaから取得して差し替える。
  この2重構造そのものを崩す変更(片方だけにする・色相を変える等)はしない。

### 5.4 余白スケール

DADSの基準単位 8 CSS px の倍率から、次の5段階のみを使う。中間の端数値(13px・22pxなど)を散在させない。

| 変数名 | 値 | 用途の目安 |
|---|---|---|
| --space-1 | 8px | 隣接する密接な要素間(ラベルと入力欄など) |
| --space-2 | 16px | フォーム項目間・リスト項目間 |
| --space-3 | 24px | 見出しと本文・カード内パディング |
| --space-4 | 40px | セクション内のブロック間 |
| --space-5 | 64px | セクション間 |

### 5.5 記録と実装

- 決定したパレット・余白スケールは `index.html` 内のコメントに記録し、全画面で統一する。
  **SPEC.mdには書かない**(見た目の正はワイヤーフレーム側、という責務分担を守るため)。
  ブランド指定パレットを組んだ場合は、各色のコントラスト比の実測値もコメントに残す。
- CSSでは上記をCSSカスタムプロパティとして `:root` に定義し、直値の散在を避ける。
- 上記以外の色を追加しない。追加が必要な場合はユーザーに確認し、5.1 の下限を満たす値にする。
- **出典表記**: 各ワイヤーフレームHTMLの冒頭コメントと `index.html` のフッタに次を記載する。

  ```
  出典：デジタル庁デザインシステムウェブサイト https://design.digital.go.jp/dads/
  （同サイトのコンテンツを加工して作成）
  ```

## 6. レスポンシブ(モバイルレイアウト必須)

すべての画面ワイヤーフレームは、PCレイアウトとモバイルレイアウトの**両方を1ファイル内に定義**する。可変レイアウト任せにせず、メディアクエリで明示的にモバイル時の変形を書くこと(生成のたびにモバイル対応の有無が変わる、という再現性のなさを防ぐため)。

- `<meta name="viewport" content="width=device-width, initial-scale=1">` を必ず含める。
- **ブレークポイント**: 640px以下をモバイルとする(`@media (max-width: 640px)`)。モバイルの設計基準幅は375px。
- **標準変形ルール**(モバイル時):
  - 複数カラムは縦積みにする(サイドバーは本文の下または折りたたみ)
  - グローバルナビゲーションはハンバーガーアイコン表示にする(ワイヤーフレームでは展開後のメニューを静的に併記するか、注記で示せばよい。JSでの開閉実装は不要)
  - 主要ボタンは全幅にする。タップ対象は最小44pxを維持する
  - テーブルは横スクロール(`overflow-x: auto`)またはカード型への変形とし、どちらを採るか画面ごとに選ぶ
  - 余白・フォントサイズはモバイル向けに詰めるが、可読性(本文14px以上)を維持する
- モバイル時に**表示を省略する要素**がある場合は、勝手に消さず、画面内の注記または生成後の報告で明示する(モバイルでの要素の取捨選択は画面仕様の一部であり、暗黙に決めてはならない)。

## 7. 画面間リンク(遷移の再現)

- SPECセクション6の遷移図に定義された遷移は、対応するボタン・リンクに実ファイルへの相対リンク(`<a href="SCR-002-dashboard.html">`)を張り、ブラウザ上で遷移を辿れるようにする。
- 条件分岐する遷移(ログイン成功/失敗など)は、成功側をリンクにし、失敗側は画面内にエラー表示例を静的に併記するか、注記で示す。
- 未作成の画面への遷移は、リンクにせずグレー表示+「(未作成: SCR-xxx)」の注記を付ける。

## 8. ダミーデータ・記載禁止事項

- 実在の個人名・メールアドレス・電話番号・住所を使わない(example.com / 架空の氏名を使う)。
- APIキー・パスワード等のシークレットの実値を、例としても記載しない。
- 実在企業のロゴ・ブランド名を使わない(自プロジェクト名は可)。

## 9. index.html(ハブページ)と compare.html(比較ビュー)の構成

### index.html

1. **タイトルとメタ情報**: プロジェクト名、準拠SPEC版数、最終更新日。
2. **画面一覧**: SPECセクション6と同じ順で、カード形式(SCR-ID・画面名・目的・対応要件ID・ステータス[作成済/未作成]・画面を開くリンク・**「PC/スマホ比較」リンク**)。
3. **画面遷移図**: SPECのMermaid遷移図を、外部依存ゼロを守るため**手描きのインラインSVGまたはCSSレイアウト**で再現する(Mermaid.jsは読み込まない)。各ノードは対応するHTMLへのリンクにする。
   - **表現方法の選択（座標破綻を避ける）**: 画面数が少なく分岐も単純（目安: ノード7個以下・一直線〜軽い分岐）ならインラインSVGで座標を置いてよい。それを超える、または双方向・合流の多い複雑な遷移では、**座標計算の要らないCSSレイアウト**（ノード=カードを縦/横に並べ、遷移を「→ ラベル」付きのリンク行や矢印記号で表す）にフォールバックしてよい。無理に大きなSVGを手座標で描いてノードの重なり・矢印のずれを出すより、崩れない表現を優先する。
   - どちらの表現でも、遷移のラベル（「ログイン成功」等）と方向がSPECのMermaid定義と一致していること。未作成画面のノードはグレー表示にする。
4. **レビュー手順の説明**: 非エンジニア向けに「カードをクリックして画面を開く」「『PC/スマホ比較』でモバイル表示を並べて確認できる」「修正してほしい点はSCR-IDと場所を添えて伝える」を短く記載する。
5. 画面の追加・削除・改名があった場合、index.htmlは必ず再生成する(手動編集で差分対応しない)。

### compare.html(PC/スマホ並列プレビュー)

画面ごとの比較ページを量産する代わりに、`docs/wireframes/compare.html` を1ファイルだけ生成する:

- URLクエリ(例: `compare.html?screen=SCR-001-login.html`)で対象画面を受け取り、同じHTMLを**幅の異なる2つのiframe**(PC: 幅100%・スマホ: 幅375px×高さ667pxの端末風フレーム)で並べて表示する。iframeの幅がビューポート幅として働くため、メディアクエリによるモバイルレイアウトがそのまま確認できる。
- クエリなしで開かれた場合は、画面一覧へのリンクを表示する。
- **JS使用の例外**: index.html と compare.html に限り、レビュー補助(クエリの読み取り・iframe切替など)のための最小限のJSを許可する。画面ワイヤーフレーム本体のJS原則(セクション1)は変わらない。外部依存ゼロの原則はこの2ファイルにも適用する。

## 10. アクセシビリティ(DADS基準)

DADSはアクセシビリティを最優先事項として掲げており(`docs/design-system/guidance/accessibility/index.md`)、
ワイヤーフレーム段階から次を満たす。ここで崩すと実装段階での手戻りが大きくなる。

- フォーム部品には`<label>`を対応付ける(プレースホルダをラベルの代替にしない)。
- 見出しは`<h1>`から順に階層を守る。見た目の大きさで見出しレベルを選ばない。
- **コントラスト**: セクション5.1の下限(テキスト4.5:1 / 非テキスト3:1)を、補助文字・プレースホルダ・
  枠線・ディバイダーを含めてすべて満たす。
- **フォーカス**: すべてのフォーカス可能要素に、セクション5.3の2重構造のフォーカスインジケーターを当てる。
  `outline: none` で消すことは禁止する。
- **タップ対象**: 最小44px(セクション4・6と整合)。
- **色以外の手がかり**: エラー・必須・状態の表示を色だけで伝えない(アイコン・テキストラベルを併記する)。
- 画像プレースホルダには内容を説明する`alt`を書く(装飾目的なら`alt=""`)。

対応するDADSコンポーネントがある部品(ボタン・インプットテキスト・チェックボックス等)は、
`docs/design-system/components/{slug}/index.md` のアクセシビリティ要件を確認してから形を決める。
参照するのは**その画面に登場するコンポーネントのファイルだけ**でよい(全件読み込みは禁止)。
