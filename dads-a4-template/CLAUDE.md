# CLAUDE.md — dads-a4-template

このフォルダで作業するときの運用ルール。**作業開始前に [HANDOVER.md](HANDOVER.md) を読むこと。**

## このフォルダの位置づけ

- デジタル庁デザインシステム(DADS)準拠の **A4タテ PowerPointテンプレート** を生成するビルド一式。
- kenesis-loop-kit の既存成果物（`draft-gen/` `mockups/` `catalog/` `docs/wireframes/` 等）とは
  **独立**しており、それらを参照・変更しない。逆も同じ。
- **チケット `DADS-001`（`tickets/active/DADS-001_*.md`）で管理下にある。**
  このフォルダへの変更は DADS-001 のログ・`related_files` へ反映すること。
  スコープ外の項目（チケット本文「スコープ外」節）に着手する前は必ず人間へ確認する。

## 絶対に守る手順

1. 寸法・書式・配色・ガイドを変えるときは **`build/spec.py` だけを編集する。**
   レイアウト・サンプルページ・プレビュー・ガイドはすべてこの定数から導出される。
   数値を `build_template.py` に直接書かないこと。
2. 生成したら **必ず `build/validate.py` を通す。** 終了コード 0 でなければ配布・コピーしない。
   PowerPoint の「修復」要求はここで防ぐ。
3. 生成 → 検証 → プレビューは `sh build/rebuild.sh` で一括実行できる。

```bash
sh build/rebuild.sh          # 初回は .venv を作成して依存も入れる
```

## 事実確認のルール

- **DADS の Markdown に HEX値・デザイントークンの定義は含まれていない。**
  含まれるのは設計原則とコントラスト比の下限のみ。
  特定の色値を「DADSが定める色」と書いてはならない（配色の出所はツールキットのテーマ）。
- コントラスト比は必ず実測値を書く。推定値を書かない。
- **PowerPoint 実機での表示確認は人間が行う。** プレビュー画像/PDF は自前レンダラーによる近似であり、
  PowerPoint の出力そのものではない。「PowerPointで確認済み」と書かないこと。
