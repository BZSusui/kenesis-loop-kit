## 1. 何を作っているか

デジタル庁「ダッシュボードイメージ作成ツールキット」(16:9 pptx) のレイアウト思想をベースに、
デジタル庁デザインシステム(DADS)の基本デザインへ従って **印刷用の PowerPoint テンプレート** を生成する。

**このフォルダは A4タテ・B5タテの2判型（B5は標準／コンパクトの2種）を扱う。**
フォルダ名 `dads-a4-template` は DADS-001 のコミット履歴とドキュメント参照を壊さないための措置で、
A4専用という意味ではない（DADS-002 の論点4で決定）。

| プロファイル | 成果物 | 本文 | 版面幅 | 1行の字数 |
|---|---|---|---|---|
| `a4` | `dist/DADS_A4_Portrait_Template.pptx` | 12pt | 169.3mm | 40字 |
| `b5` | `dist/DADS_B5_Portrait_Template.pptx` | 12pt | 143.9mm | 34字 |
| `b5-compact` | `dist/DADS_B5_Portrait_Compact_Template.pptx` | 10.5pt | 148.2mm | 40字（A4と一致） |

いずれも 8レイアウト／13ページのサンプル兼ガイドを収録する。
判型ごとの寸法の導出根拠と、コンパクト版が DADS から外れている2点は README §4.4・§4.5 にある。

**pptx は手で編集していない。すべて `build/` 配下のスクリプトが生成している。**
テンプレートを直接いじると次回ビルドで上書きされるため、必ずスクリプト側を直すこと。

## 3. 別環境での再開手順

### 3.1 コピー

`dads-a4-template/` フォルダごと、別PCの kenesis-loop-kit リポジトリ直下へ置く。

```
kenesis-loop-kit/
  └── dads-a4-template/     ← ここへ
```

**`.venv/` はコピーしないこと**（OS/CPU依存のバイナリを含む。`.gitignore` 済み）。
`preview/` は**リポジトリに含める方針**（4.3MB）。移行時も一緒に運ぶ。

> **注意: チケット `DADS-001` は git では運ばれません。**
> このリポジトリはパブリックリポジトリ用の `.gitignore` を使っており、`tickets/` 全体が除外対象です。
> 別環境でループを継続するには、次のいずれかが必要です。
>
> 1. `tickets/active/DADS-001_*.md` を手動で別環境へコピーする（最小の対応）
> 2. `.gitignore.private` を `.gitignore` として採用し、`tickets/` をコミット対象に含める
>    （リポジトリを非公開で運用している場合。作業ログが公開されることの可否は人間が判断する）
>
> デスクトップ等へ書き出した配布版には、運搬用に `_tickets/` フォルダとしてチケットの控えを
> 同梱している場合があります。その場合は中の `.md` を `tickets/active/` へ移し、`_tickets/` は削除してください
> （詳細は `_tickets/README.md`）。

### 3.2 再生成して健全性を確認

```bash
cd kenesis-loop-kit/dads-a4-template
sh build/rebuild.sh
```

初回は `.venv` を作り依存を入れたうえで、生成 → 検証 → プレビューまで通す。
最後に `[OK] 検出された不整合はありません。` が出れば環境移行は成功。

Windows（PowerShell）の場合:

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python build\build_template.py
.venv\Scripts\python build\validate.py
.venv\Scripts\python build\render_preview.py
```

### 3.3 Claude Code への指示（そのまま貼れる文面）

**手順1. 環境の引き継ぎを伝える**（新しいセッションの最初の1通）

```
dads-a4-template/ の作業を別環境から引き継ぎます。
まず dads-a4-template/HANDOVER.md と dads-a4-template/CLAUDE.md を読んでください。

チケットは tickets/active/DADS-001_A4タテPowerPointテンプレートの継続整備.md です。
このサブプロジェクトは docs/SPEC.md の対象外なので、REQ-xxx / SCR-xxx との対応付けは不要です。
仕様は dads-a4-template/README.md、受け入れ基準はチケット本文を正としてください。

最初に `sh dads-a4-template/build/rebuild.sh` を実行し、この環境で検証が通ることを
確認してから、現状のサマリと次にやることを教えてください。
```

これで「すでに完成しているものを作り直す」事故を防げる。`rebuild.sh` が
`[OK] 検出された不整合はありません。` で終われば環境移行は成功。

**手順2. 人間による実機確認**（ループ開始前に済ませるのが早い）

受け入れ基準の先頭2項目（PowerPointで修復ダイアログが出ないこと、ガイド線が版面境界に
一致すること）は **Claude Code では確認できない**。`dist/DADS_A4_Portrait_Template.pptx` を
PowerPoint で開き、［表示］→［ガイド］まで確認して、結果を次のように伝える。

```
PowerPointで開いて確認しました。修復ダイアログは出ません。
ガイド線は版面境界に一致しています（またはズレの内容）。
DADS-001 のログに結果を追記してください。
```

先に済ませておくと、ループがすぐ人間待ちで止まるのを避けられる。

**手順3. ループを開始する**

```
/start-loop DADS-001
```

orchestrator が起動時チェックリスト（Autoモード・14日超blocked・in_progress上限3件）を
実行してから、status に応じて investigator へ委譲する。
**Autoモードが無効だとチェックリストで止まる**ため、先に有効化しておくこと。

### 3.4 想定される引っかかりどころ

| 症状 | 対応 |
|---|---|
| architect / reviewer が `docs/SPEC.md` との対応（REQ-xxx / SCR-xxx）を求める | SPEC.md は別プロジェクト（モック生成キット）の要件定義。本チケットは対象外である旨を伝える。受け入れ基準はチケット本文が正 |
| investigator が既存成果物を作り直そうとする | チケットの「背景・目的」と HANDOVER.md §2 を読ませる。完成済みの範囲は再作成しない |
| `rebuild.sh` がフォントで止まる | プレビュー描画用の日本語フォントが無い。pptx の生成・検証には不要なので、`build_template.py` と `validate.py` だけ実行すれば進められる（§3.2） |
| ループが `blocked` になる | 実機確認が必要な項目で止まっている可能性が高い。手順2を実施して結果を伝える |
| 別環境で `DADS-001` が既にある | 上書きせず frontmatter の `updated` を比較する。略称 `DADS` はこのサブプロジェクト専用のため、通常は衝突しない |

## 4. ファイルの役割と依存関係

```
spec.py  ──→  build_template.py ──→ dist/*.pptx ──→ validate.py（検証）
   │                                      │
   │                                      └────────→ render_preview.py ──→ preview/*.png, preview.pdf
   └──→ （寸法・書式・配色・ガイドの唯一の正）
```

| ファイル | 役割 | 編集してよいか |
|---|---|---|
| `build/spec.py` | 用紙・余白スケール・グリッド・タイポグラフィ・配色・ガイドの定数 | **ここを編集する** |
| `build/oxml_helpers.py` | OOXML（pptx内部XML）の生成ヘルパー | 構造を変えるときのみ |
| `build/build_template.py` | マスター／レイアウト／サンプルページの組み立て | 内容・構成を変えるとき |
| `build/validate.py` | 構造検証。PowerPointが修復を要求する不整合を検出 | 検査項目を増やすとき |
| `build/render_preview.py` | pptx を読み取って PNG / PDF を描く検証用レンダラー | 描画の再現度を上げるとき |
| `build/rebuild.sh` | 上記の一括実行 | — |
| `dist/*.pptx` | 生成物 | **手で編集しない**（次回ビルドで消える） |
| `preview/*` | 生成物 | 同上 |
| `README.md` | 設計仕様・寸法表・使い方・出典 | 仕様を変えたら更新 |
| `CLAUDE.md` | このフォルダの運用ルール | — |

### spec.py を編集したときの波及

| 変える定数 | 影響 |
|---|---|
| `COLS` `COL_W` `GUTTER` | 版面幅・マージン・全レイアウトの座標・2カラム幅・ガイド位置 |
| `U`（余白基準単位） | ヘッダー／フッターの高さ、本文領域、全ページの余白 |
| `T[...]`（テキストスタイル） | 該当箇所の文字サイズ・行間・字間、プレースホルダーの高さ |
| `PRIMARY` ほか配色 | テーマ・罫線・表・カード・表紙/裏表紙。**README のコントラスト比実測表も更新すること** |
| `GUIDES` | PowerPoint の表示ガイド |

## 5. 設計上の決定と、その理由

変更する前に理由を確認すること。理由ごと変えるなら構わないが、なんとなく変えない。

| 決定 | 理由 |
|---|---|
| 16:9 の寸法を比例縮小せず、DADS規定から再導出した | ツールキットの左右マージン7.3mmはA4印刷には狭すぎるため。DADSの「ガター＝本文文字サイズの2倍」「カラム幅＝本文文字サイズの整数倍」を先に固定し、マージンを残差（20.333mm）として決めた |
| 12カラムではなく6カラム | A4タテの幅では12カラムだとカラムが細くなりすぎる。DADSはカラム数を規定していない |
| 行間を「倍数」ではなく**固定値(pt)** で指定 | 「倍数」は書体の内部メトリクス依存でCSSの`line-height`と一致しない。固定値なら書体が置き換わっても行位置が保たれる |
| 本文 12pt（DADS 16 CSS px × 0.75） | DADSの本文基準は16 CSS px以上。14 CSS px（10.5pt）未満は使わない |
| ターシャリー `#4F7AE9` を文字に使わない | 白背景とのコントラスト比 3.97:1 で、テキスト要件 4.5:1 を満たさない（非テキストの3:1は満たす） |
| デジタル庁のロゴ・表紙画像を使わない | 「デジタル庁が作成したかのような態様での公表・利用」は禁止されているため |
| 配色を「DADSが定める色」と書かない | DADSのMarkdownにHEX値の定義が無い。出所はツールキットのテーマ配色 |

## 6. これまでに踏んだ不具合（再発させないこと）

| 症状 | 原因 | 対策 |
|---|---|---|
| PowerPoint が「コンテンツに問題が見つかりました」と修復を要求 | スライドマスターの `<p:cSld>` に `<p:bg>` が2個。既定テンプレートの背景を除去せずに追加していた（`<p:bg>` はスキーマ上1個まで） | `oxml_helpers.set_bg()` で既存 `<p:bg>` を除去してから挿入。`validate.py` が重複を検出する |
| `<p:sldSz>` の `type` が `screen4x3` のままで実寸(A4)と矛盾 | 既定テンプレートの属性を更新していなかった | `build_template.main()` で `type="custom"` に設定。`validate.py` が警告する |
| 意味のない十字のガイド線が表示される | 既定テンプレート（4:3スライド）の中心線が残っていた（縦127mm・横95.25mm） | `set_guides()` で版面境界へ張り替え。`validate.py` が用紙範囲を検査 |
| プレビューが白紙になる | スライドのプレースホルダーは座標をレイアウトから継承するため、スライド側XMLに `a:xfrm` が無い | `render_preview.py` でレイアウトのプレースホルダーから継承解決 |
| 表が描画されない | `graphicFrame` の座標は `a:xfrm` ではなく `p:xfrm` | 同上、両方を見るよう修正 |

**教訓: 既定テンプレート由来の要素を「追加」する前に、既にあるかを必ず確認する。**
`validate.py` は要素の重複・出現順序・図形IDの一意性・プレースホルダーの解決可否・
パッケージ整合（Content_Types / rels）・ガイド位置を検査する。検査項目は必要に応じて増やしてよい。
