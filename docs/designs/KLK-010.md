# [KLK-010] ローカルブリッジによるワンクリック生成 設計

> このファイルはarchitectが生成・更新するチケット単位の設計書です。

> 1チケット = 1ファイル（`docs/designs/KLK-010.md` が常に現行）。改訂時は本ファイルを上書きし、
> チケットのログに改訂理由を残す。過去の設計はGitヒストリで追える（status等の状態は持たせない）。

## 1. 目的

設定画面（`draft-gen/index.html`）の「この内容で生成」を、**押すだけで最大3案が生成され比較画面が自動で開く**
ワンクリック体験にする（REQ-005 / REQ-010 のワンクリック化）。現状は生成指示書JSONをクリップボードにコピーするのみで、
実際の生成には**ユーザーがClaude Codeへ切り替えて `/draft-generate` に貼り付ける手動の受け渡し**が要る。
ブラウザの静的ページは生成エンジン（Claude Code）を直接起動できないためである。

- 小さな**ローカルブリッジ**（Python標準ライブラリのみ・`127.0.0.1` 限定）を一度起動しておき、ブラウザの「生成」→
  ブリッジへ生成指示書をPOST→ブリッジが `/draft-generate` を**ヘッドレス実行**（`claude -p`）→生成物（比較画面 or 1案）を
  自動で開く→結果をブラウザへ返す、という第1段階の個人利用向けオプション構成を追加する。
- **ブリッジ非稼働でも壊れない**（グレースフルフォールバック）。純静的HTML単体では従来どおりクリップボード＋手順案内で動く
  （SPEC §9「外部依存なし」の原則を維持）。

保存 → フォルダ自動オープン**のパイプラインは完成済み。唯一残るのが**設定画面から生成エンジンへの手動受け渡し**である。

## 3. 設計方針

**採用する方針（investigator Unknowns U-1〜U-5 ＋ 追加決定 U-6〜U-9 を確定）:**

- **U-1 権限モード＝最小権限フラグ（設定は恒久変更しない）**。ブリッジは
  `claude -p "/draft-generate {instruction.jsonの絶対パス}" --permission-mode acceptEdits --output-format json` で起動する。
  `acceptEdits` が skill の `Write(mockups/**)`（唯一のファイル変更）を自動承認する。**`--dangerously-skip-permissions`・
  `--permission-mode bypassPermissions` は不採用**（必要範囲を大きく超える全許可で、悪意ある `instruction.json` が任意ツールを
  誘発しうる。NFR-004/005 の最小権限に反する）。**`.claude/settings.json` へ `Write(mockups/**)`/`Bash(open *)` を恒久追加する案も
  不採用**（リポジトリの**全**Claude Codeセッション＝開発ループ本体まで権限が緩む。フラグはブリッジが起動する子プロセスにのみ
  スコープされ、CLIフラグは settings より優先されるため設定を触らずに実現できる）。**ブラウザ表示物のオープンはブリッジ自身が行う
  ため（U-5）、ヘッドレス側に `Bash(open *)` は与えない**（skill 内のフォルダ自動オープンは print モードで未許可→報告のパス表示へ
  グレースフルに退避する。二重オープンも避けられる）。※万一 CLI 版差で「未許可 open がスキルの実行を中断する」場合の保険として、
  実装は `--allowedTools "Bash(open *)"`（open のみ追加＝依然最小権限）を**設定可能なフォールバック**として持つ（M群で確認・§6 R-1）。
- **U-2 JSON受け渡し＝一時ファイル経由＋SKILLの後方互換な軽微拡張**。ブリッジは**検証済み**JSONを
  `mockups/.pending/{jobId}.json`（`mockups/` 配下＝Git除外・§11）へ書き、`claude -p` のプロンプトには**そのパスのみ**を埋める
  （argv埋め込みJSON・シェル注入を回避。プロンプトに入る可変値はブリッジ生成の jobId パスだけで、ユーザー文字列は入らない）。
  SKILL.md「起動と入力」に「入力が既存 `.json` ファイルのパスのときはそのファイルを読み込んでから受付チェックする」を**追記**
  （additive）。**従来の `$ARGUMENTS`／貼付JSONも引き続き受理**（後方互換・KLK-009 の S13/S14 依存文字列は削除しない・§6 R-2）。
- **U-3 待ち時間＝ジョブID発行＋ポーリング（非同期）**。NFR-001（3案で最大10分・目安）に対し、同期POSTを最大10分ブロックすると
  fetch/プロキシのタイムアウトや進捗ゼロでUXが破綻する。よって `POST /generate` は検証→pending書出し→**ワーカースレッドで
  `claude -p` を subprocess 実行**→即 `202 {jobId}` を返す。ブラウザは `GET /status/{jobId}` を約2秒間隔でポーリングし、
  `running`/`done`/`error` と経過秒・保存先・開いた対象を受け取る。ブリッジは subprocess に**ハードタイムアウト（既定900秒＝
  NFR-001 目安10分に余裕）**を課し、超過時は kill して `error`。`--output-format json` で最終結果を構造化取得する（`stream-json` の
  逐次進捗解析は本チケットでは採らず、進捗はスピナー＋経過秒に留めて実装を簡潔化）。
- **U-4 ポートとブラウザ疎通＝127.0.0.1固定ポート＋`GET /health` プローブ**。ブリッジは `127.0.0.1` に**固定ポート既定 8765**
  （環境変数 `KLK_BRIDGE_PORT` で上書き可・ブラウザ既定は 8765 を探索）で bind する。起動時に `http://127.0.0.1:8765/` を開く。
  `draft-gen/index.html` の `generate()` は**まず `GET /health`（AbortController で約800msタイムアウト）**を試行し、成功なら
  ブリッジモード（POST起動＋ローディング）、失敗ならクリップボードへフォールバックする（U-7）。**配信方式**: ブリッジ稼働時は
  ブリッジが `GET /` で `draft-gen/index.html` を配信する同一オリジン構成を**主線**とする（CORSレス）。加えて file:// で直開き
  した場合の疎通のため、ブリッジは全レスポンスに寛容なCORSヘッダ（`Access-Control-Allow-Origin: *`）を付け `OPTIONS` プリフライトも
  返す（file:// の fetch がブラウザ側で許可される環境では疎通、遮断される環境では health 失敗→フォールバックで**壊れない**）。
- **U-5 自動オープンの役割分担＝ブリッジが表示物（compare/index）の唯一のオープン主体**。ジョブ完了後、ブリッジが保存先フォルダと
  `output.variants` から**決定論的**に開く対象を選ぶ（variants≥2 → `{folder}/compare.html`、variants==1 → `{folder}/index.html`）。
  ブリッジ自身のプロセスが `open`(mac)/`start`,`explorer`(win)/`xdg-open`(linux) を実行する（ブリッジはユーザー起動の通常プロセスで
  Claude Code の権限系の外＝自由に実行できる）。**skill 側のフォルダ自動オープン（Finder）は U-1 によりヘッドレスでは退避**し、
  ブリッジ主導に一本化する（現行スキルは「フォルダ（Finder）」を開くのに対し、ユーザーが見たいのは「比較/1案の画面」なので
  ブリッジが画面ファイルを開くのが自然）。
- **U-6 ブリッジの配置と構成＝`draft-gen/bridge.py`（Python標準のみ・importable）**。設定画面と密結合のため co-locate する。
  起動は `python3 draft-gen/bridge.py`。標準ライブラリ（`http.server`/`socketserver`/`threading`/`subprocess`/`json`/`urllib`/
  `uuid`/`os`/`sys`/`datetime`）のみ・外部依存ゼロ。**決定論的コア関数（スキーマ検証・案件名安全化・保存先構築・オープン対象選択・
  コマンド構築・OSオープンコマンド構築）はモジュール先頭に純関数として置き、サーバ起動は `if __name__ == "__main__":` ガード下に
  隔離**して import 時に副作用（bind）が起きないようにする（テスト可能性・§4.6）。
- **U-7 フォールバック＝health 失敗時は現行 clipboard 挙動を完全維持**。`generate()` は「①instruction 構築→②`#resultJson` 表示＋
  クリップボードコピー（従来どおり・常時実行）→③`/health` プローブ→成功: POST＋ローディング＋ポーリング、失敗/例外: 現行の手順
  案内のまま」に再構成する。純静的HTML単体（file:// 直開き・ブリッジ無し）でも②で完結して壊れない（NFR-005・SPEC §9）。
- **U-8 セキュリティ＝127.0.0.1限定・二重検証・機密ローカル完結・注入対策**。bind は `127.0.0.1` のみ（`0.0.0.0` 禁止）。ブリッジは
  ブラウザを信用せず**起動前に自前でスキーマ検証**（`schema=="design-draft-instruction"`・`version==1`・必須 `industry.resolved`/
  `layout.columns`/`colors.main`・columns は正規化後6値・KLK-006 §4.4）。`meta.project`（社外秘・§4.5）を含む生成指示書は外部送信せず
  localhost 内で完結（`mockups/` はGit除外）。subprocess は `shell=False`・list引数で起動し、プロンプトに埋めるのは
  `^[0-9a-f]{32}$` の jobId から作る bridge 制御パスのみ（ユーザー文字列を argv/プロンプトに直挿ししない）。`/status/{jobId}` は
  jobId を厳格照合してパストラバーサルを防ぐ。
- **U-9 テスト＝決定論コアはS群（import単体）＋ HTML静的検証、実生成はM群**。ブリッジの純関数（スキーマ検証・保存先構築＋案件名
  安全化・variants別オープン対象選択・コマンド/フラグ構築・OSオープンコマンド構築・localhost限定bind定数）と `draft-gen/index.html`
  の POST/health/フォールバック分岐は `tests/site/check_klk010.py`（Python3標準・exit0/1）で機械検証。`tests/test_palette_klk010.py`
  で S群＋回帰（`unittest discover`）＋ D群（`git check-ignore mockups/.pending/…`）を束ねる。`claude -p` の実生成・実オープンは
  非決定・時間大のため tester 手動の M群。既存 check_klk006-009・smoke_klk006 は回帰させない。

**代替案と却下理由:**
| 案 | 却下理由 |
|---|---|
| U-1 `--dangerously-skip-permissions` / `bypassPermissions` | 全ツール無条件許可。悪意ある/壊れた `instruction.json` が任意 Bash 等を誘発しうる。必要なのは mockups への edit のみ＝`acceptEdits` で足りる（最小権限・NFR-004/005） |
| U-1 `.claude/settings.json` に `Write(mockups/**)`/`Bash(open *)` を恒久追加 | リポジトリの**全**セッション（開発ループ本体）まで権限が緩む。CLIフラグは子プロセス限定＋settingsより優先で、設定を触らず実現できる |
| U-2 JSONを argv/プロンプト本文へ直接埋め込み | argv長制限＋シェル/プロンプト注入リスク。案件名等ユーザー文字列がコマンドに載る。一時ファイル＋パス参照が安全 |
| U-3 同期POST（最大10分ブロック）＋ローディングのみ | fetch/プロキシのタイムアウトで途中切断・進捗ゼロ。10分級の待ちにポーリング＋経過表示が堅牢。ジョブ管理は stdlib(threading) で軽く組める |
| U-4 ポート可変（毎回別ポート） | ブラウザが接続先を知れず疎通検知が複雑化。固定既定8765＋env上書きで単純化 |
| U-4 file:// 直開き＋localhostへ fetch を主線 | file:// オリジンからの fetch はブラウザにより全面遮断され不安定。ブリッジ配信の同一オリジンを主線にしCORSは file:// 用の保険に留める |
| U-5 skill にフォルダ＋画面の両方を開かせる | 二重オープン＋ヘッドレスに Bash(open) 許可が要る。ユーザーが見たいのは画面ファイルなので、ブリッジ（権限系外の通常プロセス）が唯一の主体にする方が単純で権限も狭い |
| U-6 新規 `bridge/` トップ階層 | 設定画面と密結合な補助のため `draft-gen/` co-locate が自然。トップ新設は Write 許可・構成の分散を招く |
| ブリッジ常駐サービス（デーモン/自動起動） | 第1段階の個人利用スコープ超過。ユーザーが必要時に `python3` で起動する明示運用が安全・単純（OQ-001 第2段階は別） |

### 4.1 ブリッジ決定論コア関数（U-6/U-9・純関数・import単体テスト対象＝S群）

`draft-gen/bridge.py` の先頭に、副作用の無い純関数として実装する（サーバ起動と分離）:

```python

COLUMN_ALIAS = {"2col-sub-left":"2col-body-left", "2col-sub-right":"2col-body-right"}
BRIDGE_HOST = "127.0.0.1"          # ★ 0.0.0.0 禁止(U-8)
DEFAULT_PORT = 8765

def normalize_columns(v: str) -> str | None:
    """旧値エイリアスを正規化し、canonical 6値でなければ None。"""

def validate_instruction(obj: dict) -> tuple[bool, list[str]]:
    """schema=='design-draft-instruction' / version==1 / 必須(industry.resolved,
```

### 4.2 HTTPサーバとエンドポイント（U-3/U-4）

`http.server.ThreadingHTTPServer`（stdlib）を `BRIDGE_HOST`（127.0.0.1）:port で bind。ハンドラのルーティング:

| メソッド/パス | 動作 | レスポンス |
|---|---|---|
| `GET /` | `draft-gen/index.html` を配信（同一オリジン運用・U-4） | 200 text/html |
| `GET /health` | 稼働応答 | 200 `{"ok":true,"name":"klk-draft-bridge","version":1}`（+CORS） |
| `POST /generate` | body=生成指示書JSON。`validate_instruction` → 不正 400 `{"error":…}`／正当なら jobId(uuid4hex) 発行・`mockups/.pending/{jobId}.json` へ書出し・ワーカースレッド起動 | 202 `{"jobId":…}`（+CORS） |
| `GET /status/{jobId}` | jobId を `^[0-9a-f]{32}$` で照合（不一致 400）。ジョブ状態を返す | 200 `{"state":"running|done|error","elapsedSec":N,"folder":…,"openTarget":…,"message":…}`（+CORS） |
| `OPTIONS *` | CORS プリフライト | 204 + CORS ヘッダ |

- CORS ヘッダ（file:// 疎通の保険・U-4）: `Access-Control-Allow-Origin: *`・`Access-Control-Allow-Methods: GET,POST,OPTIONS`・
  `Access-Control-Allow-Headers: Content-Type`。localhost 限定 bind のため外部からは到達できない（NFR-004）。
- 起動時に `http://127.0.0.1:{port}/` をブラウザで開く（`build_open_command` 流用）。ポートは `KLK_BRIDGE_PORT` env > `DEFAULT_PORT`。

### 4.3 ジョブ実行とタイムアウト（U-3）

- ジョブ登録: `jobs: dict[str, dict]` を `threading.Lock` で保護。`{state, started_at, folder, openTarget, message}`。
- ワーカースレッド: `subprocess.run(build_claude_command(pending_path), cwd=repo_root, capture_output=True, text=True,
  timeout=BRIDGE_TIMEOUT_SEC)`（既定 900・`shell=False`）。
  - 正常終了(returncode 0): `--output-format json` の結果と保存規約から `folder`（`build_folder(today, project)`）を確定し、
    `select_open_target(folder, variants)` を `build_open_command` で**ブリッジが open**（U-5）。`state="done"`。
  - 非0終了: `state="error"`・`message` に要約。`TimeoutExpired`: プロセス kill・`state="error"`（タイムアウト）。
- `elapsedSec` = now - started_at（ポーリング応答に載せ、ブラウザで経過表示）。
- pending ファイルはジョブ確定後に削除（`mockups/.pending/` 配下・Git除外）。
