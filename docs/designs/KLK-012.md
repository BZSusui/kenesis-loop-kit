## 1. 目的

生成済みデザインラフの**特定セクションだけ**を、番地ラベル（例 `HERO-01`）を指定して作り直せるようにする（REQ-103 / SCR-002）。
他の5セクション・**配色5変数**・カラム骨格（`data-columns`）・全番地ラベル・`<head>` の CSS/アニメ`<script>` は**保持**し、
指定した1つの `.sec` ブロックのみを DRAFT_RULES 準拠で差し替える。「案BのHEROだけ別案にしたい」を実現する。

- SPEC §7 準拠: **存在しない/重複する番地を指定した場合はエラーを返し、ラフを壊さない**（生成を開始せず通知）。
- KLK-009（複数案・`compare.html`）・KLK-010（ローカルブリッジ）・KLK-011（Origin検証・サイズ上限）の完成資産を**additive に
  再利用**し、既存パイプライン（KLK-006〜011）を回帰させない。

## 3. 設計方針

**採用する方針（investigator の判断点 U-1〜U-7 を確定）:**

- **U-1 実装形式＝新スキル `/draft-regenerate`（推奨・回帰リスク最小）**。既存 `/draft-generate` の入力契約は「生成指示書JSON1本
  で全体を1〜3案生成」であり、部分再生成の入力（{対象ラフ, 番地ラベル}）は質が異なる。`/draft-generate` にモード分岐を足すと
  受付/保存分岐が複雑化し、既存 S群（`check_klk007` S12・`check_klk009` S13/S14）の依存文字列に波及する。よって
  **新スキル** `.claude/skills/draft-regenerate/SKILL.md` を追加する（KLK-010 が SKILL を additive 拡張したのと同様、既存資産を
  壊さない）。生成規約は共通の `DRAFT_RULES.md`（§2 番地・§3 アタリ・§5 配色・§6 印刷・§7 アニメ・§12 バリエーション・
  新設 §14 部分再生成）を**参照**する（規約の重複を作らない）。
  - **入力（2経路・後方互換）**: ①ローカルブリッジが渡す**ジョブ仕様 `.json` ファイルのパス**（`mockups/.pending/{jobId}.regen.json`＝
    `{schema:"design-regenerate-job", version:1, target, addr}`）。②手動 `$ARGUMENTS`＝`{folder} {letter} {addr}`（複数案）または
    `{対象HTMLパス} {addr}`（単一案）。いずれも同じ受付チェックへ合流する。
  - **手順**: 受付チェック（番地パターン検証）→ 対象ラフ読込 → 対象 `.sec` 特定（pin一致・一意性検証）→ 併置 `instruction.json`
    から業種/テイスト/カラムの**文脈**を読む＋対象HTMLから**配色5変数**を読む → 当該セクションのみ DRAFT_RULES 準拠で作り直し
    （`.sec`/`.addr`/`.pin {addr}` の枠と番地ラベルは保持）→ 対象HTMLの当該 `.sec` ブロックのみを差し替えて**書き戻し** → 報告。
- **U-2 保持すべき不変＝指定 `.sec` 以外はすべて保存**。差し替えるのは pin 一致の**1つの `.sec` ブロックのみ**。以下は変更しない:
  - **配色5変数**（`--m-main/--m-nav/--m-accent/--m-bg/--m-text`）＝**対象 `index-{letter}.html` のルート `.mock` 定義から実値を読み**、
    新セクションでも `var(--m-*)` で参照する（**instruction.json からは読まない**＝案B/C の派生配色を正しく維持する・実装メモ2）。
  - **カラム骨格**（ルート要素の `data-columns`）・**全番地ラベル**（他5セクションの `.pin` と対象セクションの `.pin {addr}`）・
    `<head>` の CSS（`.reveal`/`@media print`/`.atari` 等）・`</body>` 直前のアニメ `<script>`（§7）・他5セクションの `.sec` ブロック
    （**バイト等価で保存**）。
  - アニメ状態は対象ファイルの現状に合わせる（`.reveal`/observer がある案なら新セクションにも `.reveal` を付け、OFF 案なら付けない）。
- **U-3 番地バリデーション＝安全な文字集合パターン ＋ 対象ファイルでの一意存在検証**。番地ラベルは①`^[A-Z][A-Z0-9]*-\d{2}$`
  （安全な文字集合＝シェル/プロンプト注入不能。基本6種 `NAV/HERO/ABOUT/MENU/GALLERY/FOOTER-01` に加え DRAFT_RULES §2 の
  `SECTION-NN` 連番拡張も許容）に一致し、②**対象HTML内に `<span class="pin">{addr}</span>` がちょうど1回存在**すること
  （0回＝未知 → エラー、2回以上＝重複 → エラー）を確定条件とする。**未知/重複は生成を開始せずエラーを返し、ファイルを一切変更
  しない**（SPEC §7・ラフを壊さない）。①は注入対策（ブリッジ側の門）、②が本質的な特定・一意性ゲート（純関数 `find_target_section`）。
- **U-4 保存方針＝上書き（`index-{letter}.html` 直接更新・単純/決定論）**。`compare.html` の iframe `src="index-{letter}.html"`・
  原寸リンク `href="index-{letter}.html"` が**不変のまま**なので、再表示は iframe/ファイルのリロードだけで済む。リビジョン
  （`index-{letter}-r{n}.html`）は却下（`compare.html` のリンク書き換え・命名/整合テストが増える）。`mockups/` は Git除外なので
  上書きで元案は失うが、部分再生成は「作り直したい」意図そのものであり許容する（§6 R-3）。
- **U-5 ブリッジ連携＝新エンドポイント `POST /regenerate`（body=`{folder, letter, addr}`）**。`/generate` は生成指示書JSON全体を
  受け全案生成する契約で payload が異なるため、`do_POST` に別ルートを足す（KLK-010/011 の防御を**そのまま再利用**）:
  `is_allowed_origin` による Origin 検証（403）・`MAX_BODY_BYTES` サイズ上限（413/400）・jobId+`/status` ポーリング・
  `build_regenerate_command` の最小権限パターン（`acceptEdits`・**危険フラグ非含有**）・`BRIDGE_TIMEOUT_SEC`。
  **注入対策（KLK-010 U-8 踏襲）**: ブリッジは folder/letter/addr を検証し、対象ファイルで番地一意存在を確認してから、
  ジョブ仕様を `mockups/.pending/{jobId}.regen.json` へ書き、**プロンプトには bridge 生成の jobId パスのみ**を埋める
  （`/draft-regenerate {pending_path}`）。ユーザー文字列（folder/addr）を argv/プロンプトへ直挿ししない。
  bind は 127.0.0.1 固定・`shell=False`・list 引数。
- **U-6 トリガーUI（🔄導線）＝MVP は CLI/API 経路を確実に動かし、UI導線は Phase 4 に切り出す**。過剰実装を避ける。
  - **MVP（Phase 1〜3）**: 新スキル `/draft-regenerate` ＋ ブリッジ純関数 ＋ `POST /regenerate` を確実に動かす。
    ブリッジ経由（API）でも手動 `/draft-regenerate`（CLI）でも、対象セクションのみ差し替わり他は保持される経路を成立させる。
  - **UI導線（Phase 4・受け入れ条件 #3 を満たす）＝option (a) `compare.html` に番地選択＋再生成トリガーを新設**（option (b)
    「各 `.addr` に🔄注入」は不採用）。理由: (b) は standalone `index-{letter}.html`（＝印刷/直開きの成果物）に fetch JS を
    増やし、DRAFT_RULES §2（🔄省略）を変え、注入面が6セクション×案数に広がる。(a) は既に「比較・確認」の場である
    `compare.html` に**additive な1つの控えめなコントロール**（番地 `<select>` ＋「🔄 このセクションを再生成」ボタン）を置き、
    選択中の案（checked ラジオの letter）と番地をローカルブリッジへ `fetch('/regenerate')` する。**ブリッジ非稼働時は
    graceful**（`/health` 失敗で導線を無効化し「ローカルブリッジ起動 or 手動 `/draft-regenerate` で再生成できます」を案内・
    KLK-010 U-7 同型）。localhost fetch は外部CDN依存ではない（DRAFT_RULES §1 が禁じるのは外部CDN/フォント/画像）。
    `compare.html` の生成は `/draft-generate`（DRAFT_RULES §13 ＋ SKILL）を**additive に拡張**して🔄コントロールを焼き込む。
- **U-7 再表示＝上書き後、ブリッジが対象を再オープン**（KLK-010 U-5 同型）。`compare.html` が併置されていれば `compare.html` を、
  無ければ対象 `index-{letter}.html`（単一案は `index.html`）を `build_open_command` で開く。上書き（U-4）なので iframe/リンクは
  不変＝リロードで更新が反映される。

**代替案と却下理由:**
| 案 | 却下理由 |

### 4.1 ブリッジ決定論コア関数（U-3/U-4/U-5・純関数・import 単体テスト対象＝S群）

`draft-gen/bridge.py` の純関数群（`is_allowed_origin` の後・`repo_root` の前あたり）へ**副作用なし**で additive 追加する:

```python
KNOWN_ADDR = {"NAV-01","HERO-01","ABOUT-01","MENU-01","GALLERY-01","FOOTER-01"}  # 基本6種(DRAFT_RULES §2)
ADDR_RE = re.compile(r"^[A-Z][A-Z0-9]*-\d{2}$")   # 安全文字集合(SECTION-NN 連番拡張も許容・注入不能)
LETTER_RE = re.compile(r"^[a-c]$")                 # 複数案の letter(a-c)。単一案は letter 無し

def is_valid_addr(addr):
    """番地ラベルが安全な文字集合パターンに一致するか(注入対策の門・U-3)。
    ちょうど1回存在するかの本質判定は find_target_section で行う。"""
    return isinstance(addr, str) and bool(ADDR_RE.match(addr))

def is_valid_letter(letter):
    """letter が a-c か。None/'' は単一案(index.html)を意味し許可(U-4)。"""
    return letter in (None, "") or (isinstance(letter, str) and bool(LETTER_RE.match(letter)))

def is_safe_mockups_folder(folder):
    """folder が mockups/ 配下の相対パスで、パストラバーサルを含まないか(U-5・注入対策)。
    'mockups/' 始まり・絶対パス/バックスラッシュ/'..' セグメント/先頭'/'を拒否。"""
    if not isinstance(folder, str) or not folder.startswith("mockups/"):
        return False
    if "\\" in folder or folder.startswith("/"):
        return False
    return all(part not in ("..", "") for part in folder.split("/")[1:])

def resolve_target_html(folder, letter):
    """再生成対象HTMLの相対パスを決定論的に返す(U-4/U-5)。
    letter が a-c → '{folder}/index-{letter}.html' / None・'' → '{folder}/index.html'。"""
    leaf = "index-{0}.html".format(letter) if letter else "index.html"
    return "{0}/{1}".format(folder, leaf)

def find_target_section(html, addr):
    """対象 .sec ブロックの範囲を特定し一意性を検証する(U-3・SPEC §7)。副作用なし。
    返却: (start, end)  … <span class="pin">{addr}</span> を含む唯一の .sec の [start,end) 文字範囲。
          (None, "unknown")   … 該当 pin が 0 回(未知の番地)。
          (None, "duplicate") … 該当 pin が 2 回以上(重複)。
    アルゴリズム: pin span の出現回数を数え、1 回のときのみ、その pin より前の最も近い
    <div class="sec ...> を開始点とし、<div>/</div> の入れ子を数えて対応する </div> を終端にする。"""

def read_root_palette(html):
    """対象HTMLのルート(.mock)定義から配色5変数の実値を読む(U-2)。
    返却: {'--m-main':..., '--m-nav':..., '--m-accent':..., '--m-bg':..., '--m-text':...}(見つかった分)。
    インライン style="--m-main:..." 形式・<style> 内 '.mock { --m-*:...; }' 形式の双方に対応する。
    ★ instruction.json ではなく対象HTMLから読む(案B/C の派生配色を正しく維持する)。"""

def build_regenerate_command(pending_path, allow_open=False):
    """/draft-regenerate のヘッドレス実行コマンド(list・shell=False)を構築する(U-5/最小権限)。

     '--permission-mode','acceptEdits','--output-format','json'] (+ allow_open で '--allowedTools','Bash(open *)')。
    ★ 全権限スキップ/全許可モードのフラグは決して含めない(build_claude_command と同一方針)。"""
```

- これらは既存 `build_claude_command`/`is_allowed_origin`/`select_open_target` と**同じ設計思想**（純関数・import 安全・S群対象）。
  `MAX_BODY_BYTES`・`BRIDGE_HOST`・`BRIDGE_TIMEOUT_SEC`・`JOB_ID_RE` は既存を流用する（新規定数は上記のみ）。

### 4.2 新スキル `.claude/skills/draft-regenerate/SKILL.md`（U-1/U-2/U-3）

  - ①**ジョブ仕様 `.json` パス**（ブリッジ経由）＝`mockups/.pending/{jobId}.regen.json`（`{schema:"design-regenerate-job",

  2. **文脈と不変の把握**: 併置 `instruction.json`（`{folder}/instruction.json`）から業種（`industry.resolved`）・テイスト（`taste`）・
     カラム（`layout.columns`）の**文脈**を読む。対象HTMLから**配色5変数の実値**（ルート `.mock` の `--m-*`）・`data-columns`・

  3. **当該セクションのみ再生成**: pin 一致の1つの `.sec` ブロックを DRAFT_RULES（§2 番地・§3 アタリ a方式・§5 配色=`var(--m-*)` 参照・
     §7 アニメは対象ファイルの現状に合わせる・§14 部分再生成）に準拠して作り直す。`.sec`/`.addr`/`.pin {addr}` の枠と**番地ラベルは保持**。
     配色は対象HTMLから読んだ5変数を使い、**新しい色値を導入しない**（`var(--m-*)` 経由）。
  4. **書き戻し（上書き・U-4）**: 対象HTMLの当該 `.sec` ブロックのみを Edit で差し替える。**他5セクション・配色5変数・`data-columns`・

### 4.3 ジョブ仕様 `.regen.json`（ブリッジ↔スキルの受け渡し・U-5）

### 4.4 ブリッジ `POST /regenerate`（U-5/U-7・`do_POST` に別ルート追加）

`do_POST`（`bridge.py:320`）に `if path == "/regenerate": self._regenerate(); return` を追加。`_regenerate` の処理フロー:
```
_regenerate():
  ① Origin 検証: is_allowed_origin(Origin, BRIDGE_HOST, port) 不許可 → 403(既存 _generate と同一・body 読取前)
  ② サイズ上限: Content-Length 不正/負 → 400 / > MAX_BODY_BYTES → 413 / 正常のみ read(既存と同一)
  ③ JSON パース失敗 → 400
  ④ 検証: is_safe_mockups_folder(folder) 偽 → 400 / is_valid_letter(letter) 偽 → 400 / is_valid_addr(addr) 偽 → 400
  ⑤ target = resolve_target_html(folder, letter); 実ファイル(root/target)不在 → 404
  ⑥ find_target_section(対象HTML, addr): (None,"unknown") → 404 / (None,"duplicate") → 400
       ← ここで claude を起動しない・ファイルを一切変更しない(SPEC §7)
  ⑦ jobId 発行 → mockups/.pending/{jobId}.regen.json 書出し(schema=design-regenerate-job)
       → started_at 記録 → jobs[jobId]={state:"running", ...} → 再生成 worker 起動 → 202 {jobId}
再生成 worker(_run_regen_job):
  build_regenerate_command(pending_path) を subprocess.run(cwd=root, shell=False, timeout=BRIDGE_TIMEOUT_SEC)
  returncode 0 → open_target = ({folder}/compare.html があれば compare.html / 無ければ target) を build_open_command で再オープン(U-7)
  非0/Timeout → state="error"・message 要約。pending を cleanup。
```
- 既存 `_generate`/`_run_job` と**同じ構造**（jobs/jobs_lock・`/status/{jobId}` ポーリング・pending cleanup・`_now`）を再利用する。
  実装は `_run_job` を一般化しても、`_run_regen_job` を追加してもよい（既存 `/generate` 経路の回帰を出さないこと）。
- `/status/{jobId}` は既存のまま流用（`state/elapsedSec/folder/openTarget/message`）。

## 8. ロールバック戦略

`git revert` ベース（CLAUDE.md「通常のロールバック」準拠）。変更は新規ファイル（新スキル・テスト・ゴールデン）追加と、
`bridge.py`/DRAFT_RULES/`draft-generate` SKILL への additive 変更に閉じる。後方互換（既存 KLK-006〜011 のフロー不変）のため

git log --oneline
git revert {コミットハッシュ}
# 例: [KLK-012][REVERT] 部分再生成(番地ラベル指定のセクション単位再生成)の取り消し

- `mockups/` 配下（生成物・`.regen.json`）は Git 非管理のため revert 対象外（ローカル手動）。上書きされたラフは SCR-001 から再作成。
