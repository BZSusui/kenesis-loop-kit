## 3. 設計方針

**採用する方針:**
- **単一ファイル・依存ゼロ・vanilla JS を厳守**する（NFR-005 / SPEC §9 ★）。新規JS/CSSファイル・CDN・Webフォントは
  一切導入しない。palette と同じ「`<style>` 全CSS + 末尾 `<script>` 全JS」構成。
- **配置は `draft-gen/index.html`（リポジトリ直下の新規ディレクトリ）**とする（U1・§4.1）。`palette/` `flyers/` と
  同階層。palette への起動リンクは `draft-gen/` から見て `../palette/index.html`（相対・外部URLではない）。
- **状態の単一源は DOM**とし、palette 同様の一方向フローにする。`render()` が入力サマリとバリデーション表示を更新し、
  「この内容で生成」押下で `collectInput()`（DOM→プレーンオブジェクト）→`validateRequired()`→`buildInstruction()`
  →クリップボードコピー＋画面テキストエリア表示、の順に流す（§4.3）。
- **純粋ロジックを `render()` より前にまとめて定義**し、DOM 依存コードは後段に置く（palette と同じ配置）。これにより
  動的スモークが `<script>` の純粋ロジック部をスライスして検証できる（F3 / §4.6 / NFR-006）。純粋関数は
  `normalizeHex` / `parsePalette` / `validateRequired` / `buildInstruction` の4本。
- **配色の貼り付けパーサは CSS変数形式・HEX一覧形式の両対応**とする（U2・§4.2）。palette 既定は cssvars だがユーザーは
  hexlist に切替可能（F2）で、どちらを貼られても読めるほうが堅い。大小非依存。解析不能時は §7 に沿って理由を表示する。
- **配色の必須充足条件は「メインが有効HEX」**とする（U5・§4.2.3）。ワイヤー方法②「メインだけ決めて残り自動生成」に
  従い、sub/accent/bg は任意。未指定の役割は生成指示書の `colors.autofill` に列挙し、後続エンジンが自動生成する契約。
- **生成指示書の出力方式はクリップボードコピー＋画面テキストエリア表示のみ**とし、**ブラウザからのファイル保存
  （ダウンロード）は採らない**（U3・§4.5）。理由：(1) palette 踏襲（clipboard のみ・F1）、(2) 案件名を含む JSON は
  社外秘（REQ-011 / NFR-004）であり、ブラウザの `download` は OS の Downloads 等**制御外の場所**へ落ちて REQ-011 の
  Git除外前提を担保できない、(3) `mockups/{日付}_{案件名}/` への保存は REQ-010＝生成エンジン（Claude Code）側の責務で
  ブラウザ単独では不可。→ **本チケットではファイルを一切生成しないため `.gitignore` 整備は不要**（mockups/ の Git除外は
  REQ-010本体を実装する別チケットで対応）。
- **実績サムネイル（REQ-004）はダミー/インラインのプレースホルダ**（CSSグラデーション）に留め、`<img src>` の実画像は
  置かない（R3 / REQ-011）。本チケットは業種連動の選択UI（2〜3枚・拡大モーダル）まで。カタログ連携（SCR-004）は別チケット。
- **業種・カラム構成・配色は「未選択」状態を取り得るUI**にする（§4.3.2）。§7 の生成前バリデーションを実効あるものに
  するため、業種selectは先頭に空の既定option、カラム構成は初期未選択、配色メインは初期空（プレースホルダ）とする。
  ワイヤーの事前充填値は**レイアウト例示**であり値そのものは正ではない（R2）ので、この差異は仕様逸脱ではない。
- **生成指示書JSONに `schema` 名と `version` を持たせる**（U4・§4.4）。後続 REQ-005 の入力契約であり、将来のスキーマ
  変更に耐えるため版フィールドを最初から持つ（palette の URL `v=1` と同じ思想）。
- **テストは既存ラッパー方式に一致させる**（F3 / §4.6）。`tests/site/check_klk006.py`（S群）・
  `tests/site/smoke_klk006.node.js`（D群）・`tests/test_palette_klk006.py`（ラッパー）を新規追加する（tester所有）。
  機械検証の主眼は Python 静的チェッカ側に置く（node 不在時 D群skip・R5）。

**代替案と却下理由:**
| 案 | 却下理由 |
|---|---|
| 配置を `site/` 直下や `palette/` 内に同居させる | `site/` はLP用・`palette/` は配色GEN専用で役割が異なる。相対リンク・テストHTML_PATHが不明瞭になる。独立ツールは独立Dirが慣習（F4/A1） |
| 生成指示書を `Blob`+`<a download>` でJSONダウンロード | 案件名（社外秘・REQ-011/NFR-004）が OS Downloads 等の制御外へ落ち Git除外を担保できない。mockups/保存は REQ-010＝生成エンジンの責務。ファイル生成なしなら機密リスク・.gitignore整備とも不要（U3/R4） |
| 貼り付けパーサを CSS変数形式のみ対応 | palette はユーザーが hexlist 形式に切替可能（F2）。片方のみだと「配色GENで作った出力が読めない」事故が起きる。両対応が要件（REQ-003）に忠実で実装コストも小 |
| 配色必須を4色すべて有効HEXとする | ワイヤー方法②「メインだけ決めて残り自動生成」（`SCR-001-settings.html:423-429`）と矛盾。残り3色は後続エンジンが自動生成する設計なので過剰要求（U5） |
| 実績サムネイルに実画像を置く | REQ-011（実績画像はGit除外フォルダのみ）違反。カタログ（SCR-004）未実装。ダミーのCSSグラデで選択UIのみ検証（R3） |
| ワイヤーのHTML/CSSをそのまま流用 | ワイヤー冒頭に「本番へコピー禁止」明記（R2）。paste-box が `<div>` で貼り付け不可等、実装向けに作り直しが必要 |
| 業種/カラム/配色に既定値を充填（ワイヤーどおり） | §7 の必須バリデーションが常時充足扱いになり無効化する。未選択状態を取り得るUIにして初めてゲートが機能する |

### 4.2 配色入力の3方式と貼り付けパーサ（REQ-003 / U2 / U5）

⑤配色セクションは3つの入力経路を持ち、いずれも**4色の状態（main/sub/accent/bg）に反映**される。状態は各役割の
hexテキスト入力＋カラーピッカーが持つ（DOM が単一源）。

#### 4.2.1 方法①：4色を直接入力
- 各役割に `<input type="color">`（swatch）＋ `<input type="text" class="hexin">`（HEX直接入力）を対で置く。
  片方を変更すると相手へ同期（palette の basePick↔baseHex と同じ双方向同期パターン）。
- 初期状態は**メインのみ空（プレースホルダ `#未指定`）**、他は空可。無効HEX入力時は §4.2.3 の正規化で弾く。

#### 4.2.2 方法②：メインだけ決める（残り自動生成）
- ワイヤー②のカラーピッカーでメインを設定 → メインの hex 状態へ反映。sub/accent/bg は空のまま。
- 「残りを自動で調和」は後続エンジンの責務（本画面は指示書に `colors.mode:"main-only"` と `autofill` を載せるだけ）。

#### 4.2.3 方法③：配色ジェネレーターの出力を貼り付け（両形式・大小非依存）
- ワイヤーの paste-box（`<div>`）は**貼り付け可能な `<textarea>`** に置換（R2）。「取り込み」ボタンで `parsePalette()` を呼ぶ。
- `parsePalette(text)`（純粋関数）は **CSS変数形式**と **HEX一覧形式**の両方を受理する:
  - CSS変数形式: `/--color-(main|sub|accent|bg)\s*:\s*(#[0-9a-fA-F]{3}|#[0-9a-fA-F]{6})/gi` で role→hex を抽出。
  - HEX一覧形式: 行ごとに `/(メイン|サブ|アクセント|背景)\s*[:：]?\s*(#[0-9a-fA-F]{3}|#[0-9a-fA-F]{6})/` で
    ラベル→hex を抽出（ROLE_NAMES ↔ ROLE_KEYS 対応）。
  - 抽出できた role のみ返す（部分一致可）。全 role が空なら解析失敗。HEX は `normalizeHex` で小文字 `#rrggbb` に統一。
- 返却契約:
  ```js
  parsePalette(text) => {
    colors: { main:'#..'|null, sub:'#..'|null, accent:'#..'|null, bg:'#..'|null },
    matched: ['main', ...],   // 抽出できた role
    error: null | '配色を読み取れませんでした。…'   // 1つも抽出できないときのみ理由文字列
  }
  ```
- 成功時は matched の役割を4色フィールドへ適用し、未抽出役割は据え置き。失敗時（`error≠null`）は §7 に沿って
  「配色を読み取れませんでした。配色ジェネレーターの出力（`--color-main:#…;` 等）を貼り付けるか、手動で色を指定して
  ください」を表示し、フィールドは変更しない。

#### 4.2.4 配色の必須充足条件（U5）
- `normalizeHex(s)` : `#rgb`/`#rrggbb`（大小可）→ `#rrggbb`（小文字）、それ以外は `null`。
- **配色が満たされた = `normalizeHex(main) !== null`**（メインが有効HEX）。sub/accent/bg は任意。
  この判定は `validateRequired()` の3ゲートの1つ（§4.3.2）。

### 4.3 一方向フローとバリデーション（§7 / REQ-001,002,003）

#### 4.3.1 収集（DOM→プレーンオブジェクト）
`collectInput()`（DOM依存・render() 後段）は画面の全入力を1つのプレーンオブジェクトへ集める:
```
{
  projectName, industryPreset, industryCustom,
  column,                       // '1col'|'2col-sub-right'|'2col-sub-left'|'3col'|null
  taste,                        // ラベル文字列 | null
  colors: { main, sub, accent, bg, mode },  // mode: 'explicit'|'main-only'|'pasted'
  refThumbs: [{id,label,tags}], // 選択済み（最大3）
  sampleUrls: [ '...' ],        // 任意・最大2・空要素は除外
  atari,                        // 'standard'|'free-photo'
  variants,                     // 1|3
  mobile: { enabled, widthPx }
}
```

#### 4.3.2 必須バリデーション（純粋関数）
```js
function validateRequired(input) {
  const missing = [];
  const industryOk = !!(input.industryCustom?.trim() || input.industryPreset);   // 一覧 or 自由入力
  const columnOk   = !!input.column;                                             // ラジオ選択済み
  const colorOk    = normalizeHex(input.colors && input.colors.main) !== null;   // メインが有効HEX（U5）
  if (!industryOk) missing.push('業種');
  if (!columnOk)   missing.push('カラム構成');
  if (!colorOk)    missing.push('配色');
  return { ok: missing.length === 0, missing };
}
```
- `render()` は入力のたびに `validateRequired(collectInput())` を評価し、`missing` を `.valid-note` へ列挙表示、
  「この内容で生成」ボタンの活性/非活性を切り替える（不足時は生成不可・§7）。
- 未選択初期状態: 業種select 先頭に空 option（例「選択してください」・value=""）、カラム構成は初期未選択、
  メインhexは空。これにより3ゲートが実効を持つ。

#### 4.3.3 生成（＝指示書の組み立てと出力）
「この内容で生成」押下 → `validateRequired` が ok のときのみ `buildInstruction(collectInput())` を実行し、
生成指示書JSONを **(a)クリップボードへコピー**し **(b)画面のテキストエリア（readonly）へ表示**する（§4.5）。
本チケットのゴールはここまで（デザインラフ本体生成 REQ-005 は別チケット）。

### 4.4 生成指示書JSONのスキーマ（U4・後続 REQ-005 の入力契約）

`buildInstruction(input)`（純粋関数）は入力を検証済み前提で次の構造へ整形する。**キー名・階層は後続の生成エンジンの
入力契約**であり、みだりに変えない。将来変更に備え `schema` 名と `version` を持つ。

```json
{
  "schema": "design-draft-instruction",
  "version": 1,
  "meta": {
    "project": "サンプル美容室サイト",
    "createdAt": "2026-07-07T09:00:00.000Z",
    "source": "SCR-001"
  },
  "industry": {
    "preset": "美容・サロン(美容室 / ネイル / エステ)",
    "custom": "",
    "resolved": "美容・サロン(美容室 / ネイル / エステ)"
  },
  "layout": { "columns": "1col" },
  "taste": "シンプル・ミニマル",
  "colors": {
    "mode": "explicit",
    "main": "#2e7d6b",
    "sub": "#8fb9ae",
    "accent": "#e8a33d",
    "bg": "#f7f5f0",
    "autofill": []
  },
  "references": {
    "thumbnails": [
      { "id": "m1", "label": "サロン内観", "tags": "美容 / ナチュラル" },
      { "id": "m2", "label": "ヘアサロンLP", "tags": "美容 / 上質" }
    ],
    "sampleUrls": []
  },
  "atari": "standard",
  "output": {
    "variants": 3,
    "mobile": { "enabled": false, "widthPx": 375 },
    "animation": true
  }
}
```

**フィールド定義:**
| パス | 型・値域 | 対応REQ | 備考 |
|---|---|---|---|
| `schema` | 固定 `"design-draft-instruction"` | - | 契約識別子 |

### 4.5 出力方式（U3：クリップボード＋画面表示・ファイル保存なし）
- コピー: `navigator.clipboard?.writeText(JSON.stringify(instruction, null, 2))`（palette と同じ optional chaining。
  非対応環境でも例外を出さない）。押下フィードバックは palette 同様「✓ コピーしました」→数百ms後に復帰。
- 画面表示: readonly `<textarea>`（または `<pre>`）へ整形JSONを表示し、目視・手動コピーも可能にする（§7「入力・生成
  指示書を失わない」）。
- **ファイル保存（`Blob`/`URL.createObjectURL`/`<a download>`）は実装しない**（U3・§3・機密理由）。→ 本チケットでは
  ファイルを生成せず `.gitignore` 変更も発生しない。

### 4.6 純粋ロジックの配置（テスト用スライス・NFR-006 / F3）
- 純粋関数 `normalizeHex` / `parsePalette` / `validateRequired` / `buildInstruction` は DOM に触れず、`function render()`
  より**前**に定義する。DOM収集（`collectInput`）・イベント登録・`render()`・出力ハンドラは後段。
- 動的スモークがスライスできるよう、純粋ロジック部の**先頭に定数**を1つ置き（例 `const COLUMN_KEYS = [...]`）、
  smoke は `src.indexOf('const COLUMN_KEYS')` 〜 `'\nfunction render() {'` を切り出してフェイクDOM上で実行する
  （palette smoke の `const KEYWORDS`〜`function render()` と同型）。実装者はこのマーカー規約を守ること。
