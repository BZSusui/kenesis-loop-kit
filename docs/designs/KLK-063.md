# [KLK-063] カタログ画像のアップロードUI 設計

## 1. 目的

SCR-004 の「見た目だけのドロップゾーン」を実働させ、**ブラウザから直接カタログへ画像を追加**できるようにする。
`catalog/` は社外秘で配布されない（REQ-011）ため、**配布先の各メンバーは空のカタログから自分で作る**。
その入口が「隠しフォルダへの手動コピー」では実用に耐えない＝**パッケージ化の必須要件**。

## 2. 現状

```
[現在]
  ユーザー → Finder で catalog/.pending/ へ手動コピー
                 ↓
  SCR-004「取り込みを実行」→ POST /catalog-import → AI自動タグ付け
                 → Claude Code のチャットで確認・修正 → catalog.json へ登録   ← ここは実働
       ↑
  ドロップゾーンは <div> の飾りで、D&D もファイル選択も受け付けない   ← ★ここだけが欠けている
```

**流用元**: `POST /upload`（MV写真・KLK-020）が同型の生バイナリ直POST受信で、6段の防御順を確立している。

## 3. 設計方針

**採用する方針: `/upload` の6段防御をそのまま踏襲した `POST /catalog-upload` を新設し、
ドロップゾーンを本物の D&D ＋ ファイル選択にする。**

### 3.1 防御順（`/upload` と同一・多層防御）

```
① Origin 検証            is_allowed_origin → 403     （body 読取前）
② サイズ上限             CATALOG_UPLOAD_MAX_BODY_BYTES 超過 → 413 / 不正 Content-Length → 400
③ 本体読取（生バイナリ）  空 → 400
④ マジックバイト判定      sniff_catalog_image_ext → None なら 400（Content-Type・拡張子は信用しない）
⑤ 保存                    サーバ生成名 pnd-<uuid>.<ext> を catalog/.pending/ へ
⑥ 応答                    200 JSON {savedName, pendingCount}
```

### 3.2 WebP 対応は**別関数**で行う（既存を壊さない）

- `sniff_image_ext()` は **JPEG / PNG のみ**を返す。`check_klk020.py` S9/S11 がこの挙動を固定しているため
  **変更しない**。
- **`sniff_catalog_image_ext()` を新設**し、JPEG / PNG に加えて **WebP（`RIFF` + 4バイト長 + `WEBP`）** を判定する。
  カタログ側は `CATALOG_IMPORT_EXTS` が WebP を含み、catalog-import が `sips` で png へ変換する（KLK-033）。

### 3.3 保存名はサーバ生成

`pnd-<uuid4hex>.<ext>`。**クライアントのファイル名・Content-Type を保存パスに一切使わない**
（パストラバーサル面ゼロ）。catalog-import は画像を**視覚認識**してタグ付けするため、
元のファイル名に意味は無い。

### 3.4 取り込み待ち件数の可視化: `GET /catalog-pending`

ページを開いた時点で「いま何件が取り込み待ちか」を出す。手動コピー派とUIアップロード派の両方に効く。

- 返すのは `{count, names}`。`names` は `catalog/.pending/` 直下の**取り込み対象拡張子のファイル名のみ**。
  アップロード分はサーバ生成名、手動コピー分は利用者自身が置いた名前であり、
  **どちらも同一オリジンの本人にしか返らない**（localhost 限定・Origin 検証済みの GET）。
- ジョブ仕様 `*.import.json` などの非画像は列挙しない。

### 3.5 複数ファイルは「1ファイル1POSTを順次」

エンドポイントを単純に保ち、失敗したファイルだけを特定できるようにする。
UI は「3件中2件成功、1件は形式が対象外」のように**件数で結果を返す**。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| `multipart/form-data` で複数ファイルを一括受信 | `/upload` が確立した生バイナリ直POSTの作法から外れる。パーサを増やすと攻撃面も増える |
| `sniff_image_ext()` に WebP を足して共用する | `check_klk020` S9/S11 が JPEG/PNG の挙動を固定している。MV写真（REQ-104）は仕様上 JPEG/PNG 限定であり、共用すると仕様が混ざる |
| クライアントのファイル名を保存名に使う（sanitize して） | sanitize を1つ間違えるとパストラバーサル。サーバ生成名なら**面そのものが無い**。視覚認識でタグ付けするため元名は不要 |
| ドロップゾーンを消して「手動コピー」だけに統一する | 配布先が空カタログから始める以上、入口の使いやすさが導入の成否を左右する |
| ブリッジ未起動でもローカルに溜めておく | ブラウザからローカルフォルダには書けない。既存の health-gate に合流するのが一貫している |

## 4. 実装詳細

### 4.1 `draft-gen/bridge.py`

```python
CATALOG_UPLOAD_MAX_BODY_BYTES = 8 << 20   # 8 MiB（/upload と同値。フルページのスクショを見込む）

def sniff_catalog_image_ext(head):
    """カタログ取り込み用のマジックバイト判定（JPEG/PNG/WebP）。sniff_image_ext とは別関数。"""
    # JPEG: FF D8 FF / PNG: 89 50 4E 47 0D 0A 1A 0A / WebP: 'RIFF' ....(4) 'WEBP'
```

- ルーティング: `do_POST` に `/catalog-upload`、`do_GET` に `/catalog-pending` を追加。
- `_catalog_upload()` は §3.1 の順で実装（`_upload` を写経）。
- `_catalog_pending()` は `catalog_pending_dir` を列挙し、`catalog_import_ext_ok(name)` で絞る。

### 4.2 `draft-gen/catalog.html`

- ドロップゾーンを `<label for="pendingFiles">` にして**クリックでファイル選択**（`<input type="file" multiple accept=".jpg,.jpeg,.png,.webp">`）。
- `dragover` / `dragleave` / `drop` を配線し、`.dropzone.over` で視覚フィードバック。
- 1ファイルずつ `POST /catalog-upload` を **順次** 実行し、成功/失敗を数える。
- 完了後に `GET /catalog-pending` で件数を更新し、「取り込みを実行」ボタンの説明に反映。
- **ブリッジ未起動時**は入力を無効化し、起動方法を案内（既存の `setBridgeState(alive)` に合流）。
- ドロップゾーンの案内文を「ここに画像をドラッグ&ドロップ、またはクリックして選択」＋
  「（`catalog/.pending/` へ直接コピーしても取り込めます）」の**両立**表現へ。

### 4.3 ドキュメント

- `CATALOG_RULES.md` §2 の対象画像の説明に「SCR-004 のアップロードUI経由でも `catalog/.pending/` に入る」旨。
- `catalog-import/SKILL.md` の入力欄に同旨（手動コピーと同じ扱い）。
- `docs/SPEC.md` REQ-106 の備考に UI 経由の追加ができる旨。変更履歴 v1.6。

## 6. リスク

| リスク | 深刻度 | 軽減策 |
|---|---|---|
| パストラバーサル（クライアント名を保存パスに使う） | **high** | サーバ生成名 `pnd-<uuid>.<ext>` のみ。U5 で検証 |
| 非画像ファイルの混入 | **high** | マジックバイト判定（Content-Type・拡張子を信用しない）。U1 で実関数を実行して検証 |
| `sniff_image_ext` を壊して MV写真アップロードが退行 | **high** | **触らない**。U2 で WebP を受け付けないままであることを検証。`check_klk020` の非回帰も確認 |
| `catalog/` の外へ画像が漏れる | **high** | 保存先は `catalog_pending_dir` 固定。U6 で検証。`catalog/` は3つの .gitignore で除外済み |
| 大きなファイルでメモリを圧迫 | medium | `Content-Length` を body 読取**前**に検証（8 MiB 上限）。`/upload` と同じ順序 |
| ブリッジ未起動時に無言で失敗する | medium | health-gate に合流し、無効化＋起動方法を案内（U11） |
| 手動コピー運用を壊す | low | `.pending/` に置く点は同じ。案内文で両方の手段を示す（U12） |
