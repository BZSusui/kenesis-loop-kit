# [KLK-078] 生成後の型入れ替え 設計

> このファイルは KLK-078 / KLK-079 / KLK-080 の3チケットに共通する設計です。
> 第1期（型入れ替え）の全体像をここに置き、各チケットは実装範囲だけを持ちます。

## 1. 目的

生成済みのラフを見て「この GALLERY はスライダーではなくベントーにしたい」と思ったとき、
**画面から型を選んで、そのセクションだけを作り直せる**ようにする。

現状の 🔄 セクション再生成は**同じ型が決定的に再現される**（§14 の表引き）。
文言やアタリの中身は変わるが、**レイアウトの型は変えられない**。ここを開ける。

## 2. 現状

### 2.1 既にあるもの（作り直さない）

| 部品 | 場所 | 役割 |
|---|---|---|
| 🔄 コントロール | `compare.html`（§13） | 番地 `<select>` ＋ボタン。health-gated |
| `POST /regenerate` | `bridge.py:2023` | 7段防御 → `.regen.json` 書出し → worker |
| `build_regenerate_command` | `bridge.py:490` | `claude -p /draft-regenerate {path}`（最小権限） |
| `/draft-regenerate` スキル | `.claude/skills/draft-regenerate/` | 当該 `.sec` のみ差し替え |
| 型プール | DRAFT_RULES §12.1.2 / §12.1.3 | 14セクション × 各6型 |

**型入れ替えは、この経路に「型を指定できる」を足すだけで済む。**ゼロから作らない。

### 2.2 調査で見つかった既存の不具合（★型入れ替えの前提）

`compare.html` の番地 `<select>` は **6番地の固定リスト**（`NAV-01`/`MV-01`/`ABOUT-01`/`MENU-01`/
`GALLERY-01`/`FOOTER-01`）を焼き込んでいる（§13 の「列挙した固定 `<option>`」）。
しかし KLK-022 以降、生成ページの本文セクションは**指示書ごとに変わる**（14語彙から選択）。
結果、**選択肢と実ページが食い違っている**。同梱の見本3点すべてで発生していた。

| 見本 | select が出す番地 | 実ページの番地 | 食い違い |
|---|---|---|---|
| 01 カフェ | NAV/MV/ABOUT/MENU/GALLERY/FOOTER | ＋ACCESS-01・CONTACT-01 | **2つ選べない** |
| 02 士業 | 同上 | NAV/MV/NEWS/ABOUT/VOICE/FAQ/CONTACT/FOOTER | **MENU・GALLERY は404 / 4つ選べない** |
| 03 クリニック | 同上 | ＋FLOW-01・STAFF-01・ACCESS-01・CONTACT-01 | **GALLERY は404 / 4つ選べない** |

実機で再現済み（2026-09-04・ポート8831）:

```
POST /regenerate {addr:"MENU-01"}   → 404 {"error":"番地 MENU-01 が見つかりません"}   ← select に出ている
POST /regenerate {addr:"VOICE-01"}  → 202 {"jobId":...}                              ← select に出ていない
```

**型入れ替えは「番地を選ぶ」の上に乗る機能なので、土台が歪んだままでは載せられない。**
KLK-078 でここを直す。

### 2.3 型が変えられない理由

§14 のプールマーカー再付与は、**対象HTMLだけで型を自己決定する**（決定的・`instruction.json` 不要）:

```
data-columns × data-nav-position → offset（§12.1.2 のオフセット表）
offset × letter                  → pool index（mod 6 の割り当て表）
pool[index]                      → マーカー
```

同じファイルを何度再生成しても**必ず同じ index** に着地する。これは「再生成で型が勝手に変わらない」
という正しい設計（KLK-029 の意図）であり、**壊さずに上書き経路だけを足す**。

## 3. 設計方針

### 3.1 型の在り処と語彙

型は容器のマーカー1個（`.m-{sec}` のクラス、HERO のみ `data-hero` 属性）。
語彙は §12.1.2 / §12.1.3 の**14セクション × 各6型**。番地からプールが一意に決まる。

| 番地 | 容器 | プール（index 0〜5） |
|---|---|---|
| `MV-01` | `.m-hero` の `data-hero` | full / split / band / overlap / center-scroll / panel-band |
| `ABOUT-01` | `.m-about` | img-left / img-right / img-top / img-overlap / img-circle / img-zigzag |
| `MENU-01` | `.m-menu` | pat-cards / pat-list / pat-zigzag / price-table / tab-switch / feature-large |
| `GALLERY-01` | `.m-gallery` | pat-grid / pat-wide / pat-mosaic / pat-slider / pat-masonry / pat-tab-grid |
| `VOICE-01` | `.m-voice` | voice-cards / voice-quote-stack / voice-feature / voice-two-col / voice-slider / voice-zigzag |
| `FLOW-01` | `.m-flow` | flow-row / flow-timeline / flow-number-card / flow-arrow-band / flow-vertical-split / flow-zigzag |
| `STAFF-01` | `.m-staff` | staff-grid / staff-hscroll / staff-feature / staff-list / staff-two-col / staff-zigzag |
| `NEWS-01` | `.m-news` | news-list / news-cards / news-media / news-timeline / news-table / news-accordion |
| `PRICE-01` | `.m-price` | price-table / price-cards / price-featured / price-list / price-toggle / price-matrix |
| `FAQ-01` | `.m-faq` | faq-list / faq-accordion / faq-two-col / faq-cards / faq-category-tabs / faq-search |
| `ACCESS-01` | `.m-access` | map-side / map-top / map-overlay / map-hours / map-cards / map-steps |
| `CONTACT-01` | `.m-contact` | contact-cta / contact-form / contact-split / contact-methods / contact-banner / contact-steps |
| `SNS-01` | `.m-sns` | sns-grid / sns-slider / sns-cards / sns-masonry / sns-reels / sns-feed |
| `SEARCH-01` | `.m-search` | search-bar / search-keywords / search-filters / search-sidebar / search-header / search-hero |
| `NAV-01` `FOOTER-01` `CTA-01` | — | **プール無し**（CTA はボタン数と文字数で自動整列＝§4.4。型選択の対象外） |

### 3.2 番地も現在の型も「実ファイルから読む」（焼き込まない）

`compare.html` に番地や型を焼き込むと、**再生成のたびに古くなる**（型を変えた直後から嘘になる）。
`GET /sections` を新設し、UI は毎回そこから読む。

```
GET /sections?folder=mockups/…&letter=a
→ 200 {"letter":"a","sections":[
     {"addr":"MV-01","current":"overlap","pool":["full","split",…]},
     {"addr":"NAV-01","current":null,"pool":[]},
     …実ページの DOM 順…
   ]}
```

**この1本で 2.2 の不具合も同時に解ける。**番地リストが実ページから来るので、
404 になる選択肢も、選べない実在セクションも無くなる。

### 3.3 型の指定は「ジョブ仕様に1キー足すだけ」（additive・後方互換）

```jsonc
{ "schema":"design-regenerate-job", "version":1,
  "target":"mockups/…/index-a.html", "addr":"GALLERY-01",
  "desiredType":"pat-masonry" }        // ← 新規・省略可
```

- **省略時＝現行の挙動**（表引き / 参考準拠の現行マーカー優先）。既存の呼び出しは無変更で動く。
- あるときは**表引きより優先**する（§14 の優先順位に1段追加）。

優先順位（強い順）: **`desiredType`** → `data-ref-id` がある案の現行マーカー（§12.2） → 表引き（§14）

### 3.4 検証は許可リスト（正規表現にしない）

`desiredType` は**番地ごとのプールに載っている文字列と完全一致**することだけを許す。
パターン照合ではなく集合の所属判定にする＝注入面をそもそも作らない。
語彙外は 400 で止め、`claude` を起動しない（既存の7段防御に⑧として合流）。

### 3.5 ★「効いたか」をブリッジが確かめる（本設計の要）

このリポジトリは同じ失敗を4回している。

- KLK-064: 非対話経路に人間確認ゲート → **成功したように見えて何もしていなかった**
- KLK-072〜076: 規約を足しても生成側が守らない → **4回とも人手の再生成＋目視で発見**

型入れ替えは**まさに同じ形**（ブリッジが指示 → LLM が生成 → 守ったかは誰も見ていない）なので、
**ブリッジが後段で実ファイルを読み、型が変わったかを機械的に確かめる**。

```
worker 完了
  → 対象HTMLを読み直す
  → read_section_marker(html, addr) == desiredType ?
      YES → done  "GALLERY-01 を pat-masonry にしました"
      NO  → done  "★型は pat-masonry になりませんでした（pat-slider のままです）"  + typeApplied:false
```

**黙って成功と言わない。**`typeApplied` を `/status` に載せ、UI は false を目立つ色で出す。

> 失敗時にファイルを巻き戻すかは**巻き戻さない**を選ぶ。型以外（文言・アタリ）は正しく作り直されている
> 可能性が高く、それを捨てる方が損失が大きい。「何が起きたか」を正確に伝えることを優先する。

## 4. 実装詳細

### 4.1 bridge.py に足す純関数（副作用なし・import 単体テスト対象）

```python
SECTION_TYPE_POOLS = { "MV": (...), "ABOUT": (...), ... }   # 3.1 の表そのもの

def pool_for_addr(addr)          -> tuple   # 番地→プール（NAV/FOOTER/CTA と未知は ()）
def is_valid_desired_type(addr, t) -> bool  # 許可リスト所属判定（3.4）
def list_page_addrs(html)        -> list    # <span class="pin"> の DOM 順・重複は1回だけ
def read_section_marker(html, addr) -> str|None  # 当該 .sec 内の現行マーカー
```

`read_section_marker` は `find_target_section` で範囲を絞ってからプール語を**単語境界つき**で探す
（`(?<![a-z0-9-])marker(?![a-z0-9-])`）。これで `band` が `panel-band` に誤ヒットしない。
複数該当時は**最長一致**を採る。

### 4.2 エンドポイント

| メソッド | パス | 追加 | 役割 |
|---|---|---|---|
| GET | `/sections?folder=&letter=` | KLK-078 | 実ページの番地・現在型・プールを返す |
| POST | `/regenerate` | KLK-079 | body に `desiredType` を受け付ける（省略可） |
| GET | `/status/{jobId}` | KLK-079 | `typeApplied` を追加 |

`/sections` の防御: `is_safe_mockups_folder` / `is_valid_letter` / 実ファイル存在（既存関数を再利用）。

### 4.3 compare.html（§13 の骨格8に追記）

- 番地 `<select>` は**空で出力**し、health OK 後に `/sections` の結果で埋める（`textContent` で構築＝注入対策）
- 型 `<select id="regen-type">` を隣に追加。番地選択で中身を差し替え、現在型に `（現在）` を付ける
- プール無しの番地（NAV/FOOTER/CTA）では型セレクタを無効化し「この番地に型はありません」と出す
- ブリッジ未起動時は**従来どおり**無効化＋手動コマンド案内（graceful は不変）

### 4.4 スキル（`/draft-regenerate`）

手順3のプールマーカー再付与に**優先順位の1段目**を足す。
「`desiredType` があるときは表引きも現行マーカーも見ず、その型で作る。CSS が `<head>` に無ければ足す。」

## 7. マイグレーション戦略

すべて additive。`desiredType` 無しの既存呼び出し・既存 `.regen.json`・既存 compare.html は無変更で動く。
過去に生成した compare.html は固定6番地のままだが、**ブリッジ側が実ページを見て 404 を返す**挙動は従来と同じ。
新しく生成した compare.html から新 UI になる。
