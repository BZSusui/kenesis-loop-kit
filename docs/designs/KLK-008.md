## 1. 目的

KLK-006（設定画面 SCR-001）・KLK-007（生成エンジン `/draft-generate`）で通った縦串パイプラインに、KLK-007 実機
レビューで挙がった2つの生成オプションを追加する（REQ-002 拡張）。両者とも「設定画面 → 生成指示書JSON → 生成エンジン
（DRAFT_RULES）→ 生成物」の縦串に**一貫して**反映する。

- **追加①（カラム構成の拡充）**: 現行4種（`1col`/`2col-sub-right`/`2col-sub-left`/`3col`）を**6系統**へ拡張する。
  2カラムを「**全体2カラム**（サイドバーがページ全高・メインビジュアルの横にも回る）」と「**本文のみ2カラム**
  （メインビジュアルは全幅・その下の本文だけ2カラム＝既存 `2col-sub-*` の実体）」の2系統に分け、それぞれ左右を選べる。
- **追加②（生成時アニメーションON/OFF）**: 読込フェードイン・スクロール出現アニメを付ける/付けないを選択できる。
  既定ON（KLK-007 で好評）。OFF選択時は生成HTMLからアニメを外し即時全表示にする。

本設計のスコープは**縦串3箇所（UI・スキーマ・生成規約）＋SPEC/ワイヤー/SKILL/テスト/ゴールデンの同期**に閉じる。
複数案（REQ-008）・SCR-002比較UI・部分再生成（REQ-103）・b方式（REQ-104）・見本URL反映（REQ-102）は**別チケット**。

## 3. 設計方針

**採用する方針:**

- **U-1 新enum＝6値**（`1col` / `2col-full-left` / `2col-full-right` / `2col-body-left` / `2col-body-right` / `3col`）。
  `full`＝全体2カラム（サイドバーがページ全高・HERO の横にも回る）、`body`＝本文のみ2カラム（FV全幅＋本文だけ2カラム）、
  `-left`/`-right`＝サブカラムの左右。命名は KLK-006/007 の kebab-case 語彙に一貫させ、`full`/`body` で系統を、`-left`/
  `-right` で位置を表す（§4.1）。旧 `2col-sub-*`（＝本文のみ相当）は canonical から外し、下記 U-2 のエイリアスで受ける。
- **U-2 旧値はエイリアス受理（version 据え置き）**。UI・スキーマの**canonical は新6値のみ**を出力する。ただし
  **生成側（`/draft-generate` 受付＋DRAFT_RULES §8）で旧値を正規化**する: `2col-sub-left → 2col-body-left`・
  `2col-sub-right → 2col-body-right`。これで version:1 で作られた既存 `instruction.json`（`mockups/*`・`fixtures/klk007`）が
  そのまま再現でき、後方互換を保つ（§4.2・§4.4）。旧 `mockups/*/instruction.json` は Git 除外で再テスト対象外のため
  書き換えない。UI の smoke テスト入力（旧値）は canonical へ追随更新する（R-A・§4.6）。
- **U-3 アニメフィールド＝`output.animation: boolean`（既定 true）**。`output.mobile` と同階層に additive 追加。UI に
  ON/OFF トグルを追加し、既定 ON。`buildInstruction` は `animation: input.animation !== false`（未指定/true→true、明示 false→false）
  で出力。生成側 DRAFT_RULES §7 に「`output.animation===false` のとき `.reveal`/`IntersectionObserver` を出さず**即時全表示**
  （`opacity:0` を付けない）」の分岐を規定（§4.3）。
- **U-4 版番号＝version:1 据え置き**。本変更は完全に additive かつ後方互換（enum は受理集合の拡張・旧値はエイリアス吸収・
  `output.animation` は未指定時 true＝従来挙動）。既存 version:1 の消費者は一切壊れない。逆に version:2 へ bump すると
  `/draft-generate` 受付チェック（`version==1` 前提）が**既存 JSON と SCR-001 出力を一斉に拒否**し、UI/受付を同時更新するまで
  パイプラインが割れる（益なきコスト）。KLK-006 §7「スキーマ変更時のみインクリメント」の趣旨（＝破壊的変更時）に照らし、
  後方互換な追加は据え置きが正。受付チェックは `version==1` のまま維持し、正規化・既定補完のみ足す（§4.4・R-B）。
- **U-5 ゴールデンサンプルを新規追加**（`tests/fixtures/klk008/`）。「全体2カラム」は実例が無い（R-C）ため機械検証の
  拠り所が無い。KLK-007 の 1col ゴールデン（`tests/fixtures/klk007/sample-draft.html`）は**据え置き**（KLK-007 S8 回帰を守る）、
  KLK-008 で2つ追加する: (a) `sample-full-2col.html`＝全体2カラム（`2col-full-right`・アニメON・新骨格の実例）、
  (b) `sample-anim-off.html`＝アニメOFF（`2col-body-left`・`.reveal`/observer 不在）。新規 `check_klk008.py`＋
  `test_palette_klk008.py` で構造検証する（§4.6・§9）。KLK-007 の S7（アニメ無条件要求）はゴールデン `klk007`（アニメON）
  にのみ適用され続けるため改変不要。新 anim-off ゴールデンは KLK-008 の S群が**アニメ不在を**検証する（R-D 回避）。

**代替案と却下理由:**
| 案 | 却下理由 |
|---|---|
| 旧 `2col-sub-*` を canonical に残し「本文のみ」に意味固定、全体用に別値だけ追加 | UI ラベルが「2カラム・サブ右」のまま「本文のみ」を指すのか「全体」を指すのか曖昧。6系統を `full`/`body` で明示分類したほうが UI・スキーマ・規約・生成物で一貫（U-1）。旧値はエイリアスで後方互換を確保でき、canonical を綺麗に保てる |
| 全リネームしてエイリアスを一切張らない | 既存 version:1 `instruction.json`（`mockups/*`・`fixtures/klk007`）の再現性が壊れる（R-B）。生成側の正規化1段で後方互換を保つのが低コスト・安全（U-2） |
| version:2 へ bump する | additive・後方互換のため破壊的変更ではない。bump すると受付 `version==1` が既存 JSON/SCR-001 出力を一斉拒否し UI/受付の同時更新が必須になる（益なきコスト）。KLK-006 §7 の趣旨に反する（U-4） |
| アニメを CSS だけで OFF（`.reveal` は残し `opacity:1` を上書き） | DOM に不要な `.reveal`/observer が残り「アニメを外す」意図が生成物に表れない。OFF 時はマークアップ・スクリプトごと出さないのが明快で検証も容易（U-3・§4.3） |
| 「全体2カラム」のゴールデンを追加せず M群手動のみ | 新規レイアウトで実例が無く（R-C）、骨格（`.m-layout` が NAV/HERO を内包）を機械検証する拠り所が消える。コミット可能なゴールデンで S群固定するのが KLK-007 の precedent（U-5） |
| KLK-007 ゴールデンを全体2カラム/アニメOFFへ差し替える | KLK-007 S8（1col）・S7（アニメON無条件）の回帰を壊す。KLK-007 資産は据え置き、KLK-008 は**追加**で表現（U-5） |

### 4.2 生成規約 §8：6系統のレイアウト規約と旧値エイリアス（U-1/U-2・R-C・縦串③）

`DRAFT_RULES.md §8` を「本文レイアウトを合わせる」程度の粗い記述から、**6系統の具体的グリッド骨格**へ拡充する。
生成ルート要素 `.mock` に `data-columns="{canonical値}"` を付け、下記の骨格で本文を構成する。

**旧値エイリアス（正規化・受付とも共通）:**
```
2col-sub-left  → 2col-body-left
2col-sub-right → 2col-body-right
```
生成側は data-columns へ**canonical 値**を書く（旧値入力でも正規化後の新値を出力）。既存 mockups は据え置き（Git除外）。

**系統別 HTML 骨格（§10 参照構造を拡張）:**

- **`1col`**: `.m-layout` を使わず、NAV/HERO/本文各セクション/FOOTER を `.sec` で縦積み（全幅）。既存 `klk007` ゴールデン準拠。
- **`2col-body-left` / `2col-body-right`（本文のみ2カラム）**: NAV `.sec`（全幅）→ HERO `.sec`（全幅）→ `.m-layout`
  （`grid-template-columns` を本文＋サイドバーで組む・本文セクション群を `.m-main-col`、サイドバーを `.m-aside`）→ FOOTER `.sec`（全幅）。
  **HERO は grid の外**（＝税理士事務所ラフの構造そのまま）。`-left` はサイドバーを左列（`grid-template-columns:300px 1fr` かつ
  `.m-aside` を DOM 先頭 or `order` で左）、`-right` は右列（既存 `1fr 300px`）。
- **`2col-full-left` / `2col-full-right`（全体2カラム・新規・R-C）**: **`.m-layout` をページ全体に掛け**、`.m-main-col` に
  NAV/HERO/本文/FOOTER を**すべて内包**し、`.m-aside`（サイドバー）を隣列に置いて**天地いっぱい（全高）に立てる**
  （`align-items: stretch`／`.m-aside` は `position: sticky; top:0` 等で全高に見せてよい）。`-left` はサイドバーを左列、
  `-right` は右列。「サイドバーが HERO の横にも回る」＝ HERO も grid の内側にある点が本文のみ2カラムとの決定的な差。
- **`3col`**: 本文領域を `grid-template-columns:200px 1fr 200px`（左サブ・中メイン・右サブ）で3分割。NAV/HERO/FOOTER は
  本文のみ2カラムと同様に全幅 `.sec`（`3col` は本文3分割系統として扱う）。

**レスポンシブ（NFR-002・全系統共通）**: `@media (max-width:640px)` で `.m-layout` を `grid-template-columns:1fr`（縦積み）。
全体2カラムのサイドバーも縦積み時は本文の後ろ（または前）に回す。既存 §8 のハンバーガー・ギャラリー列減は維持。

### 4.3 生成規約 §7：アニメON/OFF分岐（U-3・縦串③）

`DRAFT_RULES.md §7` に「`output.animation` による分岐」を明記する（既定 true・未指定時 true）。

- **`output.animation !== false`（ON・既定）**: 従来どおり。対象セクションに `.reveal` を付け、`<style>` の
  `.reveal{opacity:0;…}` ＋末尾 `<script>` の `IntersectionObserver`（非対応時全表示・reduced-motion/印刷で無効）を出力。
- **`output.animation === false`（OFF）**: `.reveal` クラス・`.reveal` の `opacity:0`/`transition` CSS・
  `IntersectionObserver` の `<script>` を**いずれも出力しない**。全セクションは初期状態で完全表示（`opacity:1`）。
  `@media print` のアニメ全表示行（`.reveal{opacity:1…}`）は `.reveal` 自体が無いので不要（省略可）。他の印刷CSS
  （`.addr`/`.atari-tag`/`.anim-note` の `display:none`）は**アニメと無関係に常に出力**する。

生成側 SKILL は生成前にこの分岐を判定する。ゴールデン `sample-anim-off.html`（§4.6）が OFF 時の姿の実例＝検証対象。

## 7. マイグレーション戦略

**データ移行なし（後方互換・version:1 据え置き）。** 生成指示書スキーマは additive 拡張のみ:
- `layout.columns` は受理集合を拡張（旧値は生成側でエイリアス正規化 `2col-sub-* → 2col-body-*`）。
- `output.animation` は任意フィールドで未指定時 true（従来挙動）。
- `version` は `1` のまま。`/draft-generate` 受付チェック（`version==1` 前提）は不変で、正規化・既定補完のみ足す。

→ 既存 version:1 の `instruction.json`（`mockups/*`・`fixtures/klk007`）は書き換え不要で、旧カラム値のまま再生成しても
`2col-body-*` として正しく解釈される。SCR-001 の新規出力は canonical 新6値＋`output.animation` を持つ。

## 8. ロールバック戦略

`git revert` ベース（CLAUDE.md「通常のロールバック」準拠）。変更は既存ファイルへの追記/差し替えと新規テスト・ゴールデンの
追加に閉じ、後方互換のため revert しても既存 version:1 パイプラインは動作する。Phase 単位でコミットを分ける（§4）ため
問題 Phase のみの部分 revert も可能。

```bash
git log --oneline
git revert {コミットハッシュ}
# 例: [KLK-008][REVERT] 生成オプション拡張(カラム6系統・アニメON/OFF)の取り消し
```
- revert 時は縦串3箇所（UI・スキーマ・規約）とテスト集合が**同一版に揃う**ことを確認（片側だけ戻すと集合完全一致テストが割れる）。
- ロールバック時はチケットを done/→active/ へ戻し status を `implementation_done` にしてログへ理由を追記。
