# [KLK-023] レイアウトを案ごとに本当に変える 設計

> architect生成のチケット単位設計書。KLK-023 に対応。implementer/tester/reviewer が参照する。

## 1. 目的

KLK-021 の `data-archetype` は案ごとに「HERO重心・見出し整列・配色」しか変えず、**本文の組み立ては3案でほぼ同一**だった。
KLK-022 で本文セクションを選べる土台ができたので、その上で**選ばれたセクション集合を案ごとに実際に違うレイアウトで組む**。
「同じ紙面の色違い」を解消する。カラム数（`data-columns`）とセクション集合（`sections`）は全案固定（＝公平比較・KLK-021/022
の原則継承）、振るのは**並び順と各セクション内部の構造**。

## 2. 現状

- KLK-021 §12.1: 3 archetype（stack-centered / split-editorial / banded-showcase）。機械検証（check_klk021）は
  「data-columns 同一 / archetype 相違 / --m-main 相違 / HERO整列シグネチャ相違」＝**整列と色まで**。本文構造は不変。
- KLK-022 §2.1: 本文は `sections`（選択）・番地は選択各自 `{KEY}-01`。
- 不足: セクション**並び順**・**各セクション内部の型**（MENU/GALLERY/ABOUTの組み方・HERO型）が案間で変わらない。

## 3. 設計方針

**`data-archetype` を「整列トークン」から「本文構造の束」へ深化する。** 各 archetype に、離散的で機械検証可能な構造値を
束ねる。カラム数・セクション集合は不変のまま、並び順と内部構造だけを振る。

**archetype → 本文構造の束（案別）:**

| archetype | letter | 並び順（本文） | HERO型 `data-hero` | MENU `.m-menu` | GALLERY `.m-gallery` | ABOUT `.m-about` | 区切り |
|---|---|---|---|---|---|---|---|
| stack-centered | a | canonical（選択順のまま） | `full`（全面中央） | `pat-cards` | `pat-grid` | `img-left` | プレーン |
| split-editorial | b | ABOUT→GALLERY→MENU 型（入替） | `split`（左右分割） | `pat-list`（横並びリスト） | `pat-wide`（横帯ワイド） | `img-right` | 罫線 |
| banded-showcase | c | GALLERY先行 | `band`（下寄せ帯） | `pat-zigzag`（ジグザグ） | `pat-mosaic`（大小モザイク） | `img-top`（横長画像＋下キャプション） | 全幅帯（交互色） |

- **並び順**: 本文セクション（NAV/MV/FOOTER以外）の DOM 順。ルート要素に `data-section-order="ABOUT,MENU,GALLERY,CTA"`
  のように焼き込む。**セクション集合は全案同一**（並べ替えるだけ・抜き差ししない）。CTA/CONTACT 等の誘導系は末尾寄りを保つ。
- **各セクション内部の型**: クラス修飾子（`.pat-*` / `.img-*`）で表す。CSS で実際に組み方が変わる（属性だけの飾りにしない）。
- **ABOUT画像配置（理恵さん要望の第一歩）**: `img-left`（左画像右キャプション）/ `img-right`（右画像左キャプション）/
  `img-top`（横長画像の下にキャプション）。案別に振る。パターン増・他セクション拡充は後続（section-variation-backlog）。
- **継承する不変条件（KLK-021/022）**: 全案で `data-columns` 同一・`sections` 集合同一・`--m-main` 相違・`data-archetype`
  相違・HERO整列シグネチャ相違。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| セクション集合を案ごとに変える | 公平比較が崩れる（KLK-022の「中身は揃える」に反する）。振るのは並び順と内部構造に限る |
| カラム数を案ごとに変える | KLK-021「カラム数固定」に反する。列数はマクロ骨格として据置 |
| CSSだけ変え離散マーカーを持たない | 案間差を機械検証できない。`.pat-*`/`.img-*`/`data-section-order` で検証フックを立てる |
| archetype を増やす（4型以上） | まず既存3型を深める。型数の拡張は将来 |

## 4. 実装詳細

**ファイル構成（変更・追加）:**
```
.claude/skills/draft-generate/templates/DRAFT_RULES.md   （§12.1 拡張: archetype に本文構造の束）
.claude/skills/draft-generate/SKILL.md                    （手順3: 本文構造を案別に振る）
tests/fixtures/klk023/index-a.html   （stack-centered・full/cards/grid/img-left・canonical順）
tests/fixtures/klk023/index-b.html   （split-editorial・split/list/wide/img-right・ABOUT→GALLERY→MENU）
tests/fixtures/klk023/index-c.html   （banded-showcase・band/zigzag/mosaic/img-top・GALLERY先行）
tests/fixtures/klk023/compare.html   （3案比較ハブ・§13）
tests/fixtures/klk023/instruction.json（variants:3・sections=[ABOUT,MENU,GALLERY,CTA]・1col）
tests/site/check_klk023.py           （多軸の構造相違を検証）
tests/test_palette_klk023.py         （回帰＋Git除外）
```

**離散マーカー契約（機械検証フック）:**
```
ルート .mock : data-columns（全案同一） data-archetype（相違） data-section-order（相違） data-nav-position
.m-hero      : data-hero="full|split|band"（相違）
.m-menu      : class 修飾 pat-cards|pat-list|pat-zigzag（相違）
.m-gallery   : class 修飾 pat-grid|pat-mosaic|pat-wide（相違）
.m-about     : class 修飾 img-left|img-right|img-top（相違）
```

**ゴールデンの共通条件:**
- `data-columns="1col"`（3案同一・本文構造差を最も見やすく示す）。
- `sections=[ABOUT,MENU,GALLERY,CTA]`（3案同一集合）。番地は NAV-01/MV-01/ABOUT-01/MENU-01/GALLERY-01/CTA-01/FOOTER-01。
- 配色は案別（`--m-main` 相違・KLK-021）。案A 忠実／案B 濃色高級（serif）／案C 明色ポップ（sans）。

**処理フロー（生成・SKILL 手順3 拡張後）:**
```
1. variants ループ。各案 letter に配色テーマ（§5）＋archetype（§12.1）を割当
2. archetype の束から: 並び順・HERO型・MENU型・GALLERY型・ABOUT画像配置・区切り を決める
3. data-columns / sections（集合）は全案同一。data-section-order は案別の並びを焼き込む
4. 各セクションを型どおりのCSS/構造で組む（.pat-*/.img-*/data-hero）
5. compare.html は §13 のまま（構造差は各 index に現れる）
```

## 5. 影響範囲

| 対象 | 影響 | 対応 |
|---|---|---|
| DRAFT_RULES §12.1 | 変更 | archetype に本文構造の束＋離散マーカーを追記 |
| SKILL 手順3 | 変更 | 本文構造を案別に振る手順 |

| KLK-021/022 のゴールデン・テスト | 影響なし | additive（klk021/022 は据置・自テストは不変で緑） |

## 6. リスク

| リスク | 深刻度 | 軽減策 |
|---|---|---|
| 構造差が属性だけで実CSSに出ない | medium | 各 `.pat-*`/`.img-*` が実際に異なる grid/flex を持つことをゴールデンで実装＋検証は複数軸distinctで担保 |
| セクション集合や列数がブレる | medium | 3案の data-columns 同一・sections 集合同一 を機械検証（公平比較を強制） |
| KLK-021/022 の回帰 | low | additive。klk021/022 のテスト・ゴールデンは変更しない |
| 並び順変更で番地の一意性が崩れる | low | 番地は各セクション1回のまま（並べ替えるだけ）。§2/§14 の一意性は保持 |

## 7. マイグレーション戦略

なし（生成側の出力に離散マーカーを増やすのみ・入力スキーマ不変）。既存 instruction はそのまま再生成でき、archetype の
本文構造は生成側が案別に付与する。

## 8. ロールバック戦略

```bash
git log --oneline
git revert {KLK-023 のコミットハッシュ}   # [KLK-023][REVERT] 本文構造の差別化を取り消し
```
additive のため revert しても KLK-021（整列＋色）＋KLK-022（セクション選択）に無害に戻る。
