# [KLK-059] 業種・テイスト語彙の一本化 設計

## 1. 目的

SCR-001（`draft-gen/index.html`）の業種・テイスト語彙が、カタログ側の canonical 語彙と一致しておらず、
参考サムネの絞り込み（REQ-004）が業種13種中8種・テイスト11種中5種で無効化されている。
本設計はこの**サイレントな機能不全を解消**し、あわせて SPEC §12 の **OQ-002（テイスト語彙）/
OQ-003（業種一覧）を確定**させる。

## 3. 設計方針

**採用する方針: 「表示ラベル」と「canonical 値」を分離する（2層構造）。**

`taste` の二面性（生成ヒント／絞り込みキー）を、1つの値で両立させようとしたことが不具合の根本原因。
**役割ごとに値を分ける**ことで両立させる。

```
SCR-001 のチップ
  <input type="radio" name="taste"
         data-label="先進的・シャープ"    ← 生成へ渡す（表現豊か・instruction.taste）
         data-taste="かっこいい">          ← カタログ照合用（canonical・完全一致）
```

- **表示ラベル（`data-label`）** … 利用者が選ぶ言葉。生成 AI へのヒント。**自由に増やせる**
- **canonical（`data-taste`）** … カタログ絞り込みの軸。**少数に保つ**

業種は canonical が既に十分に説明的なため、2層にせず **value = 表示文字列 = canonical** の単層とする。

**語彙の正は `CATALOG_RULES.md` §3 に一元化する。** 各HTMLはその「写し」であり、
一致は checker（`check_klk059.py`）が機械的に強制する。
※NFR-005（外部依存ゼロ・単一HTML）のため共有 JS ファイルへ切り出すことはできない。
既存の「定数の正＝`check_klk034.py`」と同じドリフト検出パターンを踏襲する。

### 3.1 業種 canonical（17区分・既存の正をそのまま採用・新規決定なし）

```
飲食店・カフェ・食関連 / 美容室・エステ・化粧品 / ファッション / スクール・教室 / 不動産・建築 /
ホテル・旅館・レジャー / 士業事務所（法律/会計/コンサルティング他） / コーポレート／BtoB / EC・物販 /
フィットネス・ジム・スポーツ / イベント・キャンペーンLP / ジュエリー・時計・貴金属 /
クリニック・病院・介護リハビリ / 農業・ファーム / 求人・採用 / アート・ポートフォリオ / その他・団体/NPO
```
表記注意（CATALOG_RULES §3 より）: 「コーポレート／BtoB」は**全角／**、
「士業事務所（法律/会計/…）」内部と「その他・団体/NPO」は**半角/**。**1文字違わず**コピーすること。

### 3.2 テイスト canonical（10種・本チケットで新設）

muuuuu.org（SPEC OQ-002 が参照元として指定）の分類を根拠に、理恵さんの判断で確定した。

| # | canonical | 配色の方向性 | レイアウト・表現の方向性 | muuuuu.org 対応 |
|---|---|---|---|---|
| 1 | シンプル | 白基調・低彩度 | 余白多め・グリッド・装飾を削ぐ | ミニマル・シンプル |
| 2 | ナチュラル | ベージュ／グリーン・やさしく柔らかい配色 | 手書き感・植物モチーフ・曲線 | ナチュラル |
| 3 | 高級感 | 高級感がある配色・ゴールド・中間色 | 大きな余白・細身セリフ・縦組み | エレガント／モダンクラシック |
| 4 | ポップ | 鮮やか・はっきりした派手な配色・カラフル | にぎやか・ジャンプ率高・角丸・図形 | ポップ |
| 5 | 和風 | 和レトロな配色・中間色 | 縦書き・縦組み・テクスチャー | 和風 |
| 6 | かっこいい | スタイリッシュ・知的な配色・寒色／モノトーン | 幾何学モチーフ・洗練されたタイポ・先進的表現 | スタイリッシュ |
| 7 | レトロ | 和レトロ／暖色・くすみ | 雑誌風・ベタ塗・テクスチャー | レトロ・アメリカン |
| 8 | **かわいい** ★新規 | パステル・ペールトーン配色・ピンク系 | 角丸・イラスト・手書き感 | かわいい系 |
| 9 | **アート** ★新規 | 配色の組み合わせが印象的・グラデーション | 歪み・非対称・独創的なギミック・グラフィカル表現 | ユニーク／デザイン・アート |
| 10 | **ダーク** ★新規 | 黒／濃紺／チャコール基調・低明度・高コントラスト（アクセント1色） | 重量感のあるタイポ・全画面インパクトビジュアル・硬質 | グランジ・ハード＋ダーク・重厚感のある配色 |

**`高級感` と `ダーク` の判別基準**（catalog-import が一貫してタグ付けするために必須）:
- `高級感` = **余白と繊細さ**（細身セリフ・ゴールド・上品・明度は問わない）
- `ダーク` = **重量感と硬質さ**（太いタイポ・高コントラスト・低明度が支配的）
- 迷う場合は主配色に `モノトーン` を併記し、テイストは支配的な印象で1つに決める。

### 3.3 SCR-001 チップ 11種 → canonical 10種のマッピング

| 表示ラベル（`data-label`・生成へ） | canonical（`data-taste`・照合へ） |
|---|---|
| シンプル・ミニマル | シンプル |
| 高級感・上質 | 高級感 |
| ポップ・カジュアル | ポップ |
| 和風・和モダン | 和風 |
| ナチュラル・やさしい | ナチュラル |
| かっこいい・スタイリッシュ | かっこいい |
| レトロ・ヴィンテージ | レトロ |
| かわいい・ガーリー | かわいい |
| アート・個性的 | アート |
| ダーク・重厚(黒基調) | ダーク |
| **先進的・シャープ** | **かっこいい** ← 唯一の多対一（muuuuu.org もスタイリッシュに含める） |

**チップは11種のまま維持**するため、`check_klk006.py` S12（`taste_radios >= 11`）は**無傷**。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| SCR-001 のテイストを canonical 10種へ縮める（1層のまま） | 生成ヒントの表現力が落ちる（F3）。`先進的・シャープ` のような利用者に分かりやすい選択肢が消える |
| SCR-001 の語彙に合わせて catalog 側を変更する | catalog.json 53件・SCR-004・CATALOG_RULES・catalog-import の4箇所を書き換えることになり、影響が最大。かつ KLK-032 で確定済みの正を壊す |
| 語彙を共有 JS ファイル（例 `draft-gen/vocab.js`）へ切り出す | NFR-005（外部依存ゼロ・単一HTMLで動く）に反する。`file://` で開いたときに読めない |
| `ダーク` を主配色「モノトーン」で代替しテイストに置かない | 理恵さんの判断で却下（形容詞として意味が強く、テイストとして選択肢に挙げたい）。muuuuu.org にもテイスト側に「グランジ・ハード」があり先例がある |

```js
// draft-gen/index.html: 照合ロジック（industryKey は廃止・完全一致へ）

// 業種: canonical 完全一致。自由入力時のみ従来の前方一致でフォールバックする。
function matchesIndustry(entry, key, isCustom) {
  if (!key) return true;
  var a = entry.industry || '';
  if (!isCustom) return a === key;               // 一覧選択 = canonical 完全一致
  return a.indexOf(key) === 0 || key.indexOf(a) === 0;  // 自由入力 = 従来どおり前方一致
}

// テイスト: data-taste（canonical）で完全一致。
function currentTasteCanonical() {
  var el = document.querySelector('input[name=taste]:checked');
  return el ? el.dataset.taste : null;
}
```

**instruction への影響（重要・後方互換）:**
`collectInput()` の `taste` は **`dataset.label` のまま変更しない**（生成へ渡る値は従来と同じ性質＝表現豊かなラベル）。
`data-taste` は**画面内の絞り込み専用**であり、生成指示書 JSON のスキーマは**一切変わらない**。

**処理フロー（修正後）:**
```
1. 利用者が業種を一覧から選択（value = canonical）／または自由入力
2. テイストチップを選択（data-label と data-taste の両方を保持）
3. applyThumbFilter()
   - 「近い業種のみ」  : matchesIndustry(entry, canonical, isCustom) で完全一致
   - 「同じテイストのみ」: entry.taste === currentTasteCanonical() で完全一致
   - ヒット0件のときのみ従来どおり全件表示＋理由の note を出す
4. buildInstruction() … taste には data-label を載せる（従来と同じ・スキーマ不変）
```
