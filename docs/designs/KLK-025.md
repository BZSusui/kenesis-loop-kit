# [KLK-025] 配色「②メインカラーだけ」初回反映バグ修正 設計

> architect生成のチケット単位設計書。KLK-025 に対応。implementer/tester/reviewer が参照する。

## 1. 目的

SCR-001 の「② メインカラーだけ先に決める」で最初の1回の色選択が `#hex-main` に反映されないバグ（macOS Safari）を
修正する。メイン未定のままでは必須3項目が揃わず生成できないため、優先度 high。

## 2. 現状

- `#mainOnlyPick`（`input[type=color]`）のリスナーは **`input` イベントのみ**。
- macOS Safari では color input の `input` イベントが**初回選択で発火しないことがある**（`change` のみ発火）。
  Chrome 系は `input` がライブ発火するため顕在化しない。→「1回目無反応・2回目反映」と一致。
- 方法①の4色スウォッチ（`pick-main/sub/accent/bg`）も `input` のみバインドで同型の潜在バグ。
- hex テキスト欄（`hex-*`）は text input（`input` 確実発火）のため対象外。

## 3. 設計方針

**`input` / `change` の両イベントに同一ハンドラを束ねる（防御的・ブラウザ非依存）。**

- ハンドラ（`setColorRole` → `colorMode` 設定 → `render()`）は**冪等**: Chrome 等で input→change が二重発火しても
  同じ値を同じ欄に書くだけで無害。
- 対象: `#mainOnlyPick`（本修正）＋ `pick-main/sub/accent/bg`（同型の予防修正）。
- hex 欄・貼り付け取り込み（方法③）は変更しない。純ロジック（buildInstruction 等）も不変。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| `change` のみに置き換える | Chrome 系で「ピッカー操作中のライブ反映」が失われ UX 後退。両バインドが上位互換 |
| Safari 判定で分岐 | UA 判定は脆い。両バインドで全ブラウザ同一コードにできる |

## 4. 実装詳細

```js
// 方法②: メインのみ（KLK-025: Safari は input[type=color] の input が初回発火しないことがあるため
// input / change の両イベントで拾う。ハンドラは冪等＝二重発火は無害）
const applyMainOnly = function (e) {
  setColorRole('main', e.target.value);
  colorMode = 'main-only';
  render();
};
['input', 'change'].forEach(function (ev) {
  document.getElementById('mainOnlyPick').addEventListener(ev, applyMainOnly);
});

// 方法①: スウォッチも同様（applyPick を両イベントへ・KLK-025）
```
