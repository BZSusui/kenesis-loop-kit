## 1. 目的

生成されるデザインラフの番地ラベル **`HERO-01`** を **`MV-01`**（人間向け名称「メインビジュアル」）へリネームする。
利用者（臼井さん）はこのセクションを「MV / メインビジュアル」と呼んでおり、「HERO-01」が実務語彙に馴染まない
（KLK-014 完了後の M群実機確認・2026-07-09 で挙がった要望）。再生成（SCR-002）の「セクション再作成」選択肢では
**「MV-01（メインビジュアル）」** と分かる表示にする。

- 対象は**番地ラベルとしての `HERO-01`**（pin表示・compare の option・テスト固定値・番地表）に限定する。
- **CSSクラス `.m-hero`/`.hero-cta`（構造クラス・②）と一般語「HERO」（レイアウト概念語・③）は変更しない**。
- 他の番地（NAV/ABOUT/MENU/GALLERY/FOOTER-01）は変更しない（本チケットは HERO→MV のみ）。

### 3.2 ゴールデン↔テストのロックステップ更新方針（U3・回帰回避の中核）

**R1（確実に落ちる）**: ゴールデンの pin/option を MV-01 化すると、それを固定検査する `check_klk007/008/009/012` と `test_palette_klk012` が**同時に**落ちる。→ **ゴールデン（9件）とテスト（5件）を同一チケット内で同時（ロックステップ）に MV-01 化**すれば緑化する。
- ゴールデンは **implementer 所有**、テストは **tester 所有**。役割を §9 受け入れ基準で分ける（同一チケット内で両者が並行完了する前提）。
- **KLK-012 の不変条件は MV-01 でも保たれる**:
  - `index-a-after.html` は「差替後も pin 保持」が不変条件（`check_klk012.py` S8-(f)）。before/after の pin を**両方** MV-01 にすれば「差替後も pin 保持」の検査意図はそのまま維持される。
  - 「1ファイル内で番地は一意」も、HERO-01 を MV-01 に 1:1 置換するだけなので一意性は不変。
  - `check_klk012.py:165` の `m-hero`（②）は触らないため、ゴールデンが `.m-hero` を保持する限り緑のまま。

### 3.3 SPEC/ワイヤーの整合（U3 派生・該当すれば）

乖離防止（site/wireframe/design の整合）のため、**番地ラベルの 1:1 リネームに限り**本チケットで整合更新する（レイアウト変更を伴わないため）:
- `docs/SPEC.md` の例示 2 行（L52 用語「例: HERO-01」・L92 REQ-103「例: HERO-01」）→ `MV-01`。
- `docs/wireframes/SCR-002-compare.html` の pin 3 箇所（L313/382/418）→ `MV-01`。ワイヤーは本来 `/wireframe-gen` 管轄だが、番地ラベルの 1:1 置換のみ（見た目の骨格は不変）なので本チケット内で整合させ、乖離を残さない。

## 8. ロールバック戦略

`git revert` ベース（CLAUDE.md「通常のロールバック」準拠）。変更は文字列リネームと新規テスト2件の追加に閉じ、後方互換（`ADDR_RE` 不変で旧ラベルも受理）のため revert しても既存パイプラインは動作する。

```bash
git log --oneline
git revert {コミットハッシュ}
# 例: [KLK-015][REVERT] 番地ラベル HERO-01→MV-01 リネームの取り消し
```
- revert 時は**生成規約（DRAFT_RULES/SKILL）・ゴールデン・テストを同一版に揃える**（片側だけ戻すとゴールデンと検査が割れて Quality Gate が赤になる）。
- ロールバック時はチケットを done/→active/ へ戻し status を `implementation_done` にしてログへ理由を追記。
- `mockups/` 配下（生成物）は Git 非管理のため revert 対象外。
