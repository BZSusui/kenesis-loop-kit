# [KLK-143] 個人名の検査の素通りを見えるようにする 設計

> このファイルはarchitectが生成・更新するチケット単位の設計書です。
> チケット KLK-143 に対応します。implementer・tester・reviewerが参照します。
> 1チケット = 1ファイル（`docs/designs/KLK-143.md` が常に現行）。改訂時は本ファイルを上書きし、
> チケットのログに改訂理由を残す。過去の設計はGitヒストリで追える（status等の状態は持たない）。

> **表記の約束（KLK-141 と同じ）**: 個人名そのものは書かない。「照合語」＝検査が探す個人名の各表記。
> 照合語の実体は Git 管理外の照合語ファイル `.private/personal-terms.txt` にだけある。

## 1. 目的

KLK-141 のレビュー申し送り3点を片付ける。

1. 照合語ファイルが無い環境で、個人名の検査（check_klk141・check_klk077 R7）が「素通り」しても、全体テストでは OK に数えられて見えない。素通りを **skipped** として見えるようにする
2. 照合語ファイルの扱いを CLAUDE.md のセキュリティの節に一文足す（依頼者了承済み 2026-11-27）
3. KLK-141 で「自社所有の実績画像」とした言い換えを、元の意味に忠実な語に直す

**UI の変更は無い**（検査コード・テスト・規約文書・設計書/スキル規約の文言のみ）。デザインシステムの参照は対象外。

## 3. 設計方針

**採用する方針:**

1. **checker は「素通りした」ことを、機械が読める専用の出力行で知らせる。** 終了コードは従来どおり
   （0 = 失敗なし / 1 = 失敗あり）で変えない。印の文字列は `_private_terms.py` に定数として1か所だけ置き、
   checker とラッパーの両方がそれを参照する
2. **ラッパーは、素通りの印が出たときだけ「素通り専用のテストメソッド」を skipTest にする。**
   checker 全体の合否を見るテスト（終了コード・`0 failed`）は従来どおり実行し、skip にしない。
   check_klk077 の R7 以外16件、check_klk141 の K1・K4 の結果を skip で隠さないため
3. ラッパーは checker の出力（印の有無）と、自分で読んだ `load_terms()` の結果を突き合わせる。
   食い違ったら失敗にする（「ファイルがあるのに素通りした」「ファイルが無いのに印が出ない＝素通りが見えない」の両方を捕まえる）
4. checker の実行はクラスごとに1回（`setUpClass`）。テストメソッドを足しても実行時間（パッケージの組み立て）を増やさない
5. CLAUDE.md はセキュリティの節に1項目だけ足す。「ポリシー管理の原則」の表には**追記しない**（理由 §4.4）
6. 「自社所有の実績画像」は SPEC の表記に合わせて「実績画像」にする。KLK-141 の設計書は記録なので直さない

**代替案と却下理由:**
| 案 | 却下理由 |
|---|---|
| 素通り時に専用の終了コード（例 77）を返す | 0/1 の意味は checker の docstring に書かれた約束で、手作業で `python3 check_… && …` とつなぐ使い方も壊れる。check_klk077 は16件が本当に動いて R7 だけ未検査という「一部未検査」で、終了コード1つでは表せない |
| ラッパーが自分で `.private/personal-terms.txt` の有無を見て skip を決める（checker は変えない） | checker が実際に素通りしたかどうかと判定の根拠がずれうる（読み込み失敗・照合語0件も素通りになる）。checker の出力を正とし、ラッパー側の確認は突き合わせにだけ使う |
| 素通り時に checker のテスト全体（test_checker_passes・test_static_checks_pass）を skip | 照合語と無関係に動いた検査（077 の16件・141 の K1/K4）の結果まで skipped に隠れ、別の不具合を見逃す |
| 印を日本語の詳細行（「照合不能・素通り」）のまま判定する | 文言の言い換えで判定が黙って外れる。印は ASCII の固定文字列にして定数で共有する |
| 照合語ファイルが無いときは FAIL にする | CI・clone 直後・配布先で常に赤になる。fail-open は KLK-141 で合意済みの方針（設計 §3-2） |

### 4.2 素通りの印（skipTest の判定方法）

**`tests/site/_private_terms.py` に追加**
```python
# 照合語ファイルが無く、照合を行わずに PASS 扱いにした（素通り）ことを示す印。
# checker が集計行の後に1行で出し、unittest ラッパーがこれを見て skipTest にする。
# ASCII 固定。文言を変えるときは checker・ラッパーの両方がこの定数を参照しているので1か所で済む。
UNVERIFIED_MARKER = "UNVERIFIED personal-terms-missing:"


def unverified_line(ids):
    """素通りした検査 ID の一覧から印の行を作る。例: 'UNVERIFIED personal-terms-missing: K0,K2'"""
    return "%s %s" % (UNVERIFIED_MARKER, ",".join(ids))
```
- 印は照合語を含まない（K0 が自己検査する）。docstring の「★出力の約束」に「素通りした場合は印の行を出す」を1行足す

**`tests/site/check_klk141.py`**
- `skipped_ids = []` を用意し、照合語ファイルが無いために素通り（`SKIP` を詳細にして PASS）とした検査の ID を追加する。
  対象は K0・K2・K3（組み立て成功時のみ。失敗時は FAIL なので入れない）・K5・K6・K7（`terms is None` の分岐のみ。
  「mockups/ が無い」の分岐は照合語と無関係なので入れない）
- 集計行 `"%d checks, %d failed"` の**後**、`sys.exit` の前に、`skipped_ids` が空でなければ
  `print(pt.unverified_line(skipped_ids))` を出す。終了コードは変えない
- docstring の `Exit code` の説明に「照合語ファイルが無いときは 0 のまま、最終行に UNVERIFIED 行を出す」を追記

照合語なしのときの出力末尾（期待）:
```
8 checks, 0 failed
UNVERIFIED personal-terms-missing: K0,K2,K3,K5,K6,K7
```

**`tests/site/check_klk077.py`**
- R7 の素通り分岐（`_terms is None`）で `_r7_unverified = True` を立てる（既存の詳細文言・ラベルは変えない）
- 集計行の後に `if _r7_unverified: print(_private_terms.unverified_line(["R7"]))`
- docstring の `Exit code` の説明に同じ追記

**`tests/test_palette_klk141.py`**
```python
class TestKLK141Checker(unittest.TestCase):
    @classmethod
    def setUpClass(cls):
        cls.proc = subprocess.run(["python3", str(CHECKER)], capture_output=True, text=True, timeout=900)
        cls.unverified = [l for l in cls.proc.stdout.splitlines() if l.startswith(pt.UNVERIFIED_MARKER)]

    def test_checker_passes(self):        # 従来どおり（skip しない）: 終了コード0・", 0 failed"・K2/K3/K5 のラベル

    def test_personal_terms_scanned(self):
        """★照合語での走査が実際に行われたこと。照合語ファイルが無ければ skipped として見せる。"""
        has_terms = pt.load_terms() is not None
        if self.unverified:
            self.assertFalse(has_terms, "照合語ファイルがあるのに素通りした: %s" % self.unverified)
            self.skipTest("照合語ファイル .private/personal-terms.txt が無いため個人名の照合をskip（%s）"
                          % self.unverified[0][len(pt.UNVERIFIED_MARKER):].strip())
        self.assertTrue(has_terms, "照合語ファイルが無いのに素通りの印が出ていない（素通りが見えない）")
        self.assertNotIn("照合不能・素通り", self.proc.stdout)
        self.assertIn("照合 ", self.proc.stdout)   # K2 の詳細「照合 N 語 / 検出=…」
```
- 単体テストを1件追加（`TestUnverifiedLine` など）: `pt.unverified_line(["K0", "K2"])` が
  `pt.UNVERIFIED_MARKER` で始まり `K0,K2` で終わること、`UNVERIFIED_MARKER` が ASCII のみであること
- 冒頭コメント「★このテストが守っているもの」に「素通りは skipped として数える」を1行足す

**`tests/test_palette_klk077.py`**
- `TestKLK077Static` を `setUpClass` で1回実行する形にし、`test_static_checks_pass` は従来どおり（終了コード0）
- `test_r7_personal_name_checked` を追加。判定は上と同じ（印の有無と `load_terms()` の突き合わせ → 印ありなら
  skipTest「照合語ファイル … が無いため R7（個人名の照合）をskip」）。印が無いときは
  `[PASS] R7 ` の行があり、R7 の直後の詳細行が「個人名=なし」であることを確かめる
- `_private_terms` の import のため `sys.path.insert(0, str(ROOT / "tests" / "site"))` を足す

**照合語ファイルがある環境**: checker は従来どおり全件を照合し、印の行は出ない。ラッパーの新テストは実行されて PASS する。
全体の件数は +3 件（141: 素通り専用1・単体1、077: R7 専用1）、skipped は増えない。

**照合語ファイルが無い環境（CI を含む）**: checker は従来どおり終了コード0・`0 failed`、最終行に印。
ラッパーは `test_checker_passes`・`test_static_checks_pass` が OK、新テスト2件が skipped。
全体テストの表示は `OK (skipped=基線+2)` になる。

### 4.3 CLAUDE.md の文案

追記位置: 「## セキュリティ・機密情報の取り扱い」→「**エージェントへの指示:**」の箇条の**末尾**（「コミット前に`git diff`で…」の次）に1項目。

```markdown
- 個人名の混入を見張る検査（check_klk141・check_klk077 R7）は、照合語を Git 管理外の `.private/personal-terms.txt`（`.gitignore` 済み・配布物にも入らない）から読む。このファイルは検査を働かせたい環境ごとに個別に置き、その内容（照合語）はチケット・設計書・コミットメッセージ・報告に書き写さない。ファイルが無い環境では検査が素通りし、全体テストでは skipped として表示される
```

- 照合語そのもの・その一部は書かない（check_klk141 K2・K3 が CLAUDE.md も照合する）
- デザインシステム関連の語（check_klk115 が監視する3語）を入れない
- 書式の詳細は書かない（正は `tests/site/_private_terms.py` の docstring。二重管理を避ける）
- 「誰から受け取るか」は資料に定めが無いため書かない（§10 参照）

### 4.4 「ポリシー管理の原則」の表には追記しない

理由:
1. この表は「CLAUDE.md のポリシーを、実行責任者（エージェント/コマンド）の定義ファイルへ転記したか」を追う対応表。
   今回の一文には転記が要るエージェント/コマンドが無い。ファイルを置くのは人間、照合は検査が自動で行い、
   「照合語を書き写さない」は既存の「個人情報をチケットのいずれのセクションにも記載しない」に含まれる
2. 親に当たるセキュリティの節自体が表に行を持たない。その一部だけを行にすると表の粒度がそろわない
3. 依頼者が了承した範囲は「セキュリティの節に一文」。表の追記はその範囲を超える
- セキュリティ規約全体を表に載せ、エージェント定義へ転記するかどうかは別の論点（本チケットの範囲外）

### Changed（KLK-143・個人名の検査が働いていないことを見えるようにする）

- 照合する語のファイルが無い環境では、個人名の検査を「通過」ではなく「skipped（未検査）」として数えるようにした
