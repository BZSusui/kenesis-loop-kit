# [KLK-014] 生成導線の改善 — ワンクリック起動ランチャー + フォールバック文言の正確化(SCR-001) 設計

> このファイルはarchitectが生成・更新するチケット単位の設計書です。
> チケット KLK-014 に対応します。implementer・tester・reviewerが参照します。
> 1チケット = 1ファイル（`docs/designs/KLK-014.md` が常に現行）。改訂時は本ファイルを上書きし、
> チケットのログに改訂理由を残す。過去の設計はGitヒストリで追える（status等の状態は持たない）。

## 1. 目的

SCR-001 設定画面(`draft-gen/index.html`)で「ラフを生成」押下後、ローカルブリッジ未起動時に出る案内文言が「Claude Code で **/draft-generate** に貼り付けると生成できます」となっており、非エンジニア(里見さん・臼井さん)が「/draft-generate」を**開くべきファイル/フォルダ**と誤解して行き止まる。本設計はこの導線を **2段構え**で改善する。

1. **主経路** — ダブルクリックでローカルブリッジ(`draft-gen/bridge.py`)を起動する**起動ランチャー**を新設し、以降の生成を貼り付けゼロの完全ワンクリック(KLK-010/011 の POST /generate → 比較画面自動オープン)にする。
2. **予備経路** — ブリッジ未起動/失敗時のフォールバック文言を「Claude Code の**チャット欄にそのまま貼り付けて Enter**(コマンドは自動判定)」へ正確化し、その場に**ブリッジ起動手順**を提示して迷子を根絶する。

追加は **index.html の文言 + 新規ランチャー + テスト**のみ。`bridge.py` 本体ロジックは無変更(additive)。

## 3. 設計方針

### 3.1 起動ランチャー(主経路)

| 論点 | 確定 |
|---|---|
| ファイルパス/名称(U2) | **`draft-gen/起動.command`**(日本語名)。非エンジニアが Finder で一目で見つけられることを最優先。Git は UTF-8 ファイル名を保持し文字化けしない。ASCII 別名は作らない(2ファイルは迷いを増やす)。 |
| 中身(U3) | shebang `#!/bin/bash` → `cd "$(dirname "$0")/.."`(repoルート) → `command -v python3`/`command -v claude` の存在チェック(不在時は日本語で原因と対処を出力し `exit 1`) → `exec python3 draft-gen/bridge.py`。**ブラウザ open はブリッジ任せ(§2)=二重 open しない**。 |
| 実行権限(U4) | 実装時に `chmod +x` して **mode 755 でコミット**(Git は実行ビットを保持)。zip 展開/一部 clone で実行ビットが落ちた場合の復旧は**ランチャー冒頭コメントに `chmod +x draft-gen/起動.command` を明記**して案内(README 追記は任意・additive)。 |
| 外部依存(NFR-005) | `bash`・`command -v`・`python3`・`claude` のみ。**ネットワーク取得(curl/wget)・パッケージ導入・外部URL を一切持ち込まない**。 |
| 安全性 | 危険フラグ(`--dangerously-skip-permissions`/`bypassPermissions`)・`rm -rf`・`shell=True` 相当の破壊的記述を含めない。ブリッジの最小権限(acceptEdits)方針を崩さない。 |
| Windows(U5) | **本チケット対象外**(下記 3.3)。 |

**ランチャー確定内容(implementer はこの通り作成する。外部URLを1つも入れないこと):**
```bash
#!/bin/bash
# draft-gen/起動.command — ローカルブリッジ ワンクリック起動 (KLK-014 / macOS)
# ダブルクリックで開けない場合は、ターミナルで一度だけ次を実行してください:
#   chmod +x draft-gen/起動.command

# このスクリプトの場所を基準にリポジトリのルートへ移動する（起動.command は draft-gen/ 配下）
cd "$(dirname "$0")/.." || { echo "リポジトリのフォルダへ移動できませんでした。" >&2; exit 1; }

# 必須ツールの存在チェック（黙って失敗しない＝受入条件2）
if ! command -v python3 >/dev/null 2>&1; then
  echo "【エラー】python3 が見つかりません。" >&2
  echo "対処: macOS に Python 3 を入れてください（ターミナルで xcode-select --install など）。" >&2
  echo "確認: ターミナルで python3 --version が表示されればOKです。" >&2
  exit 1
fi
if ! command -v claude >/dev/null 2>&1; then
  echo "【エラー】claude（Claude Code）が見つかりません。" >&2
  echo "ブリッジは生成時に claude を呼び出すため、これが無いと生成が失敗します。" >&2
  echo "対処: Claude Code をインストールし、ターミナルで claude --version が出ることを確認してください。" >&2
  exit 1
fi

echo "ローカルブリッジを起動します。設定画面が自動でブラウザに開きます。"
echo "停止するには、このウィンドウで Ctrl+C を押してください。"
# ブリッジ本体を起動（設定画面をブラウザで開くのはブリッジ側の役割＝ここで open はしない）
exec python3 draft-gen/bridge.py
```

### 3.2 フォールバック文言の正確化(予備経路)

- **既存の関数名・要素ID・分岐構造を維持**(`showManualGuidance`/`showBridgeError`/`setBridgeStatus`/`bridgeStatus`)。**文言だけ差し替える** ⇒ check_klk010 S7(関数名/要素名を固定)を落とさない。
- **注入対策は維持**: `setBridgeStatus` は `createTextNode`/`textContent` のまま(`innerHTML` を導入しない)。`msg` 等の動的値も引き続き textContent 経由。
- **複数行表示手段**: `setBridgeStatus` は単一テキストノードを注入するため、文言中の `\n` を改行として見せるには CSS が要る。**`.bridge-status`(L274) に `white-space: pre-line;` を追加**し、併せて `align-items: center` → `align-items: flex-start`(複数行を上揃え)にする(additive・単一行の既存 done/loading 表示は無 `\n` のため見た目不変)。`setBridgeStatus` のロジックは変更しない。
- **「/draft-generate に貼り付け」という語を撤去**し、「チャット欄にそのまま貼り付けて Enter(コマンドは自動判定)」に置換。スキル `draft-generate` は指示書JSONを受け取ると発火するため、コマンド名の明示は不要。

**確定新文言(implementer はこの文字列で置換する):**

### 3.3 Windows 対応の要否(U5)

**本チケット対象外(macOS 前提)。** 根拠:
- `.command` は macOS 専用。利用者(里見さん・臼井さん)は Mac 運用(プロジェクトメモ)。SPEC §9 の第1段階は macOS 中心の個人利用向け構成。
- **予備経路に行き止まりは残らない**: フォールバック文言中の `python3 draft-gen/bridge.py` は Windows のターミナルでもそのまま有効(手動起動できる)。Windows でダブルクリック起動が要るなら `.bat` ランチャーを**別チケット**で追加する(過剰実装回避)。設計書にこの方針を明記して implementer/tester の判断を固定する。

### 3.4 U1(claude が PATH にあるか)への対応

`claude` の実在は**環境依存で設計はブロックしない**。ランチャーの `command -v claude` 存在チェック(§3.1)で**事前検知して日本語案内**し、「起動はできたが生成だけ失敗」で黙って詰まる事態を防ぐ(受入条件2)。実機で実際に PATH に在るかは **M群(人間確認)** で担保(ブロッカー既載)。

### 3.5 代替案と却下理由
| 案 | 却下理由 |
|---|---|
| ASCII 名 `start.command` | 非エンジニアには日本語名の方が発見容易。可搬性上の実害は無い(Git は UTF-8 保持)。 |
| ランチャーでも別途 `open http://127.0.0.1:8765/` する | ブリッジが起動時に自前で設定画面を開く(§2)。二重 open は無駄・タイミング競合の元。 |
| `.app`/AppleScript でGUIアプリ化 | 外部依存・複雑度増(NFR-005 に反する)。ダブルクリック `.command` で要件充足。 |
| `setBridgeStatus` を `innerHTML`/`<br>` 対応に改修 | 注入対策(textContent)を崩す。CSS `white-space: pre-line` + `\n` で安全に多行化できる。 |
| 利用者当初案「別ブラウザ画面を開いて貼り付け」 | ブラウザ画面ではAI生成が動かない。実現不能。起動ボタン＋明確な貼付手順で狙いを達成。 |
