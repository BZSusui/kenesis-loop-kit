# [KLK-133] claudeを実体で見つける（PATH頼みをやめる）設計

## 1. 目的

`claude` が入っているのに「見つかりません」で止まる状態をなくす。
起動スクリプト（Windows / macOS）と、生成時に `claude` を呼ぶブリッジの3系統すべてで、
**PATH だけに頼らず実体を探す**。

## 2. 現状

| 場所 | 探し方 | 問題 |
|---|---|---|
| `起動.bat` | `where claude` のみ | インストーラは `%USERPROFILE%\.local\bin` へ置く。そこが PATH に無い環境で止まる（実機で発生） |
| `起動.command` | `command -v claude` のみ | 同じ作り。mac は Terminal 経由でシェル設定が読まれるため表面化しにくいだけ |
| `bridge.py` | `subprocess.run(["claude", ...])` | ★**Windows の CreateProcess は PATHEXT を見ない**。補うのは `.exe` のみ。npm 版（`claude.cmd`）は `where claude` が通るのに**生成の瞬間だけ失敗する** |

```
（レビューで実際に起きたこと）
エクスプローラーから 起動.bat をダブルクリック
  → where claude が失敗（.local\bin が PATH に無い）
  → 「【エラー】claude が見つかりません」で停止
  → 回避のため、利用者のユーザー環境変数 PATH を手作業で書き換えた
```

## 3. 設計方針

**「探す場所を増やす」＋「見つけた場所はその場限りで使う」＋「解決は起動の直前に1箇所で行う」。**

| 対象 | 方針 |
|---|---|
| `起動.bat` | `where claude` が外れたら、よくある3か所を `if exist` で確かめ、**そのウィンドウの `PATH` にだけ**足す（`setlocal` の中なので利用者の環境変数は変えない。`setx` は使わない） |
| `起動.command` | 同じ考え方で mac のよくある3か所を探し、**そのプロセスの `PATH` にだけ**足す |
| `bridge.py` | 起動の直前に `resolve_claude_argv()` で実体へ解決する。`.cmd` / `.bat` は Windows でのみ `cmd /c` を挟む |

**★実機が使えない期間があるので、判定はすべて純関数にする。**
`resolve_claude_argv(cmd, platform, env, which, isfile)` はプラットフォーム・環境変数・
PATH 探索・実在判定を**すべて引数で受ける**。Mac 上で Windows の4条件を再現して検証できる。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| 利用者の環境変数 PATH を書き換える（レビュー時の回避策） | 配布先の全員には頼めない。他のツールにも影響する副作用を、モック生成の起動が持つべきでない |
| `build_*_command` の段階で実体パスを埋める | 既存の受入検査4本が `cmd[:2] == ["claude", "-p"]` を見ている。組み立ては「論理的なコマンド」のままにし、解決は起動直前に分ける方が筋も通る |
| `shell` 経由で起動して PATHEXT に任せる | 最小権限（NFR-004）に反する。`cmd /c` を**必要な場合だけ**挟む方が範囲が狭い |
| ブリッジ起動時に1度だけ解決して保持する | 起動後に claude を入れた場合に追随しない。呼ぶ直前に解決する方が素直（呼び出しは数十秒に1回程度で、コストは無視できる） |

**探す場所（決め打ちの根拠）**

| OS | 場所 | 根拠 |
|---|---|---|
| Windows | `%USERPROFILE%\.local\bin\claude.exe` | 公式インストーラの既定。**レビューで実在が確認された場所** |
| Windows | `%APPDATA%\npm\claude.cmd` | npm 版。レビュアーの PATH にも `%APPDATA%\npm` が入っていた |
| Windows | `%LOCALAPPDATA%\Programs\claude\claude.exe` | Programs 配下へ入る形 |
| macOS | `~/.local/bin/claude` ・ `/opt/homebrew/bin/claude` ・ `/usr/local/bin/claude` | 一般的な置き場所 |

## 4. 実装詳細

**`draft-gen/bridge.py`**
```python
CLAUDE_CANDIDATES = {"win32": (...), "posix": (...)}   # (環境変数名, 続きのパス)

def claude_candidates(platform=None, env=None):
    """探す場所を絶対パスで並べる（純関数）。環境変数が無い項目は飛ばす。
       区切り文字は os.path.join に任せず、platform で決める
       （他OSから Windows の条件を再現して検証できるようにするため）。"""

def resolve_claude_argv(cmd, platform=None, env=None, which=None, isfile=None):
    """起動の直前に実体へ解決する（純関数）。
       ①cmd[0] が 'claude' でなければ何もしない
       ②which('claude') → 外れたら候補を順に isfile で確かめる
       ③見つからなければ cmd をそのまま返す（従来どおり失敗し、案内が出る）
       ④Windows かつ .cmd/.bat のときだけ ['cmd','/c',実体] を前に置く"""
```
起動3箇所は `cmd = resolve_claude_argv(build_xxx_command(...))` に変えるだけ。

> `cmd /c` へ渡すのは当方が組み立てた引数だけ（パスは uuid・日付由来）で、利用者の入力は入らない。
> `list` 渡しのまま（シェル経由の実行はしない）。

**`起動.bat`**（CP932+CRLF のまま編集すること・KLK-132）
```bat
where claude >nul 2>&1
if not errorlevel 1 goto claude_ok
if exist "%USERPROFILE%\.local\bin\claude.exe" set "PATH=%PATH%;%USERPROFILE%\.local\bin"
if exist "%APPDATA%\npm\claude.cmd" set "PATH=%PATH%;%APPDATA%\npm"
if exist "%LOCALAPPDATA%\Programs\claude\claude.exe" set "PATH=%PATH%;%LOCALAPPDATA%\Programs\claude"
where claude >nul 2>&1
if not errorlevel 1 goto claude_ok
echo 【エラー】… 探した場所: …
pause
exit /b 1
:claude_ok
```
> ★**入れ子の括弧を使わない。** `if ( ... set ... if defined ... )` は cmd の変数展開の都合で
> 期待どおりに動かない（遅延展開が要る）。`goto` で平らに書けばその落とし穴を避けられる。

**`起動.command`**: `$HOME/.local/bin` `/opt/homebrew/bin` `/usr/local/bin` を順に `-x` で確かめ、
見つかった1つだけを `PATH` へ足す。
