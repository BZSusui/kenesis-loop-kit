# [KLK-069] README とローカル配布パッケージ 設計

## 1. 目的

`README.md` が空で、受け取った人が何もできない状態を解消する。
あわせて、理恵さんが決めた配布方式（**Git ではなくフォルダを手渡し**）を、
手順書とスクリプトの両方で実現する。

## 2. 現状

- `README.md` は **1バイト**（空）。
- 配布物を組み立てる手段が無く、「どのフォルダを渡すか」が人の記憶頼り。
- カタログ（345MB・社外秘32件＋第三者著作物24件）の同梱可否は**確認待ち**。
- 実測: システム本体は**約2MB**。カタログが全体の99%。

## 3. 設計方針

**採用する方針: 「読む README」と「組み立てるスクリプト」を分け、カタログ同梱は明示フラグにする。**

### 3.1 なぜスクリプトを作るのか

配布のたびに「どのフォルダを含めるか」を人が判断すると、必ずどこかで間違える。
特に**含めてはいけないもの**（`mockups/`＝案件名を含む生成物、`tickets/active`＝作業ログ、
`catalog/`＝社外秘）を、うっかり `cp -r` で丸ごと持っていく事故は起きやすい。

**スクリプトの既定は「カタログを含めない」**とし、含めるには明示フラグを要求する。
可否の確認が済んでいない現時点で、既定が安全側に倒れている必要がある。

### 3.2 README の構成（読む順に）

1. **これは何か**（3行）— デザインラフを自動生成するツール＋開発ループのキット
2. **できること / できないこと** — 期待値を最初に合わせる
3. **動かすのに必要なもの** — python3 / claude / VSCode / macOS
4. **はじめかた** — フォルダを置く → `起動.command` → 画面が開く → 最初の生成
5. **画面の使い分け** — SCR-001 生成設定 / SCR-002 比較 / SCR-004 カタログ / palette
6. **実績カタログについて** — 同梱の有無で読み分けられる書き方
7. **困ったときは** — つまずきやすい5点と対処
8. **開発ループを回す人へ** — チケット・エージェント・テスト
9. **取り扱いの注意** — 社外秘・第三者著作物・`.trash/`

**「できないこと」を上に置く。** 動かしてから気づくより、読む前に分かるほうが親切。

### 3.3 配布スクリプト `tools/make-package.sh`

```bash
tools/make-package.sh [出力先] [--with-catalog] [--with-tests]
```

| 含めるもの（既定） | 理由 |
|---|---|
| `draft-gen/` `palette/` `.claude/` `agents/` `docs/` | 動作に必須 |
| ルート直下の `*.md`（README / CLAUDE / CHANGELOG / LICENSE） | 規約と説明 |
| `tickets/Templates/` | ループを回すのに必要な雛形 |
| 空の `tickets/active` `tickets/done` `mockups` `catalog/.pending` | 実行時に使うフォルダ |

| 含めないもの（既定） | 理由 |
|---|---|
| `catalog/img` `catalog/catalog.json` | **社外秘・第三者著作物**（`--with-catalog` で明示的に含める） |
| `mockups/` の中身 | 生成物・案件名を含む |
| `tickets/active` `tickets/done` の中身 | 作業ログ・内部情報 |
| `tests/` | 使うだけなら不要（`--with-tests` で含める） |
| `.git/` | 配布物に履歴は要らない（社外秘の過去が入る余地も断つ） |

- 実行後に**含めた／含めなかったものを一覧表示**し、カタログを含めた場合は
  **社外秘を含む旨の警告**を出す。
- `--with-catalog` を付けたときだけ 345MB になる。既定は約2MB。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| README に「このフォルダをコピーしてください」と書くだけ | `mockups/`（案件名を含む生成物）や `tickets/`（作業ログ）を一緒に持っていく事故が起きる |
| カタログを既定で含める | 可否が未確認。**既定は安全側**に倒すべき。フラグを付ける手間が確認の機会になる |
| zip まで作る | 受け取り側の解凍環境に依存する。フォルダのままのほうが「置くだけ」に近い |
| `git archive` を使う | `.gitignore` されている `catalog/` を扱えず、逆に `tickets/Templates/` の解禁も要る。素直に `cp` のほうが読みやすい |
| tests を既定で含める | 2.8MB 増える割に、使うだけの人には不要。開発する人はフラグを付ける |

### 3.4 `tickets/Templates/` の配布

現在 `.gitignore` が `tickets/` を丸ごと除外している（パブリック版）。
**`.gitignore` は変更しない**（リポジトリの可視性の話であり、配布とは別問題）。
配布スクリプトが `tickets/Templates/` を**直接コピー**することで解決する。
