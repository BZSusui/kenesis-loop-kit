## 1. 目的

実績カタログ（SCR-004・REQ-105/106）の取り込みで **webp を受理**できるようにする。ネット拾いのサムネはデスクトップに webp で落ちるため。方針は理恵さん確定済み（2026-07-23）:

1. webp は取込時に **`sips` で png へ自動変換**して `catalog/img/cat-00NN.png` として保存（native保持ではなく変換方式）。表示・配信・AI視覚認識はすべて png に統一しリスクを排除。
2. webp由来は **source:ref（収集見本・第三者著作物・橙バッジ）を既定候補**として提示（人間ゲートで own 上書き可）。
3. カタログ画面に **種別フィルタ（自社実績=own / 収集見本=ref）** を追加し、外部資料を一覧で分けられるようにする。

いずれも既存の own/ref 枠・7カテゴリ・validate_catalog を壊さない additive 変更。後方互換（既存 jpg/png 取り込みは不変）を最優先とする。

## 3. 設計方針

**採用する方針（4本の additive 変更＋テスト）:**

**方針A: webp→png 変換は catalog-import スキル側の `sips` で行う（bridge.py に変換コードを入れない）。**
- 変換は catalog-import スキルの **手順1受付の直後（手順2 視覚認識の前）** に Bash で実行する。`sips -s format png <in>.webp --out catalog/img/<newid>.png`（`/usr/bin/sips`・macOS標準・NFR-005 の外部依存禁止と整合）。
- 以後の手順（手順2 Read 視覚認識・手順4 移動）は変換後 png（`cat-00NN.png`）を正とする。webp を直接 Read しない。
- 変換失敗（sips 非0終了・出力未生成）は、既存の「安全でない/取り込めないものは取り込まず理由提示して停止」規律（SKILL.md:47・してはならないこと節）にそのまま合流。当該ファイルを skip し理由提示。

**方針B: bridge.py の「取込許可拡張子」を配信MIMEと切り分けて新設し、全件列挙フィルタに webp を含める。**
- **配信MIME（`CATALOG_MIME` :76・GET `/catalog/img/`）は不変。** png変換方式のため webp を保存せず、配信は png/jpg のまま。webp MIME は追加しない。
- **取込許可拡張子を別集合として新設**する（目的が「取込列挙」で配信とは異なるため分離）。純関数 `catalog_import_ext_ok(name)` を追加し、全件列挙フィルタ（:1043-1049）の絞り込み条件に使う。→ 純関数化によりテスト可能（S群で直接検証）。
- 404文言（:1062）を webp を含む表現へ更新。

**方針C: webp由来は source:ref を既定候補として提示（人間ゲートで own 上書き可）。**
- SKILL 手順2/手順3・CATALOG_RULES §3.7 に「webp から変換したエントリは ref を既定候補として提示し、人間確認ゲートで own に上書き可」を明文化。
- **JSONスキーマ・validate_catalog（source∈{own,ref}）は不変。** ref/own はもとから許容集合であり、既定“候補”を変えるのは人間可読ドキュメントの運用規律のみ。自動確定禁止（従来どおり）。

**方針D: catalog.html に種別フィルタ（source facet）を additive 追加。**
- KLK-032（業種facet追加）と同型。sel に `source:[]` を足し、filterEntries に完全一致判定を追加、frow HTML を1本足す。クリック配線 wireFilters は data-facet/data-val 汎用読みのため無改修で拾う。
- 種別チップは **label≠val**（表示=自社実績/収集見本・data-val=own/ref）。この点が業種/テイスト（label==val）と異なるため、テスト・実装で明示。

**代替案と却下理由:**
| 案 | 却下理由 |
|---|---|
| webp を native 保持（変換せず配信）| 配信MIMEに webp 追加が必要・AI視覚認識で webp を Read できるか不確実・第三者環境で表示互換に不安。理恵さん確定方針で不採用 |
| bridge.py に画像変換コードを実装 | worker(claude -p) がスキル内 Bash で `sips` を叩けば足りる。bridge はジョブ仕様を書くだけの責務境界を保つ。Python依存も増やさない |
| `CATALOG_MIME` に webp を足して列挙も兼ねる | 配信（png保存ゆえ webp不要）と取込列挙（webp必要）は目的が異なる。同一集合に混ぜると「webp を配信する」誤読・実データ非焼込検査(:369)との整合に迷いが出る。**別集合で切り分ける**のが安全 |
| source facet を業種/テイストと同じ label==val で持つ | UI表示は「自社実績/収集見本」が親切だがフィルタ値は own/ref（validate と JSON の正）。label==val にすると own/ref がそのまま画面に出て非エンジニアに不親切。**label≠val** を採用 |
| 種別フィルタ用に新規テストファイルを作る | KLK-013 の S群（check_klk013.py）がカタログ全体の静的検査の正。同ファイルへ S2更新＋S21-S23追加が最小差分で退行検知も一元化できる |

## 4. 実装詳細

### 4-1. bridge.py（取込許可拡張子の切り分け・全件列挙フィルタ改修）

**(1) 定数追加（:76 CATALOG_MIME の直後を推奨）:**
```python
# 配信MIME（GET /catalog/img/ 用）。png変換方式ゆえ webp は保存しない＝ここは不変。
CATALOG_MIME = {".jpg": "image/jpeg", ".jpeg": "image/jpeg", ".png": "image/png"}

# 取込許可拡張子（POST /catalog-import 全件列挙 用・配信MIMEとは目的が別）。
# webp は取込時に sips で png へ変換して保存するため、列挙の許可集合にのみ含める。
CATALOG_IMPORT_EXTS = {".jpg", ".jpeg", ".png", ".webp"}
```

**(2) 純関数追加（`catalog_content_type` :436 の直後を推奨・S群で直接テスト）:**
```python
def catalog_import_ext_ok(name):
    """POST /catalog-import 全件列挙の取込許可拡張子か（配信MIMEではなく取込許可集合で判定）。副作用なし。"""
    if not isinstance(name, str):
        return False
    _, ext = os.path.splitext(name.lower())
    return ext in CATALOG_IMPORT_EXTS
```

**(3) 全件列挙フィルタ改修（:1043-1049）:** `catalog_content_type(n) in ("image/jpeg","image/png")` を `catalog_import_ext_ok(n)` に差し替える。
```python
if obj.get("all") is True:
    try:
        names = sorted(
            n for n in os.listdir(catalog_pending_dir)
            if is_safe_catalog_name(n)
            and catalog_import_ext_ok(n)          # ← webp を含む取込許可集合で判定
        )
    except OSError:
        names = []
```

**(4) 404文言改修（:1062）:** 「… catalog/.pending/ に JPG/PNG を置いてください」→「… catalog/.pending/ に **JPG / PNG / WebP** を置いてください」。

- 明示ファイル列挙経路（`files:[...]`・:1052-1060）は `is_safe_catalog_name` が `.webp` を既に許容するため無改修で通るが、全件ボタンとの非対称を作らないため (3) を必ず入れる。
- **配信 `catalog_content_type`（:431-436）は改修しない**（png保存ゆえ webp を配信しない）。
