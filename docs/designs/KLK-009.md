## 1. 目的

KLK-007（1案生成 `/draft-generate`）・KLK-008（カラム6系統・アニメON/OFF）で通ったパイプラインを、**複数案（最大3案）
の一括生成**と、**案を切り替えて見比べる比較・閲覧画面（SCR-002）**へ拡張する（SPEC v1.2 の REQ-008 / REQ-009 / REQ-010残り）。

- **REQ-008**: 複数案（最大3案）を一括生成し、サムネイル一覧・ボタン切替・クリックで原寸を別タブ表示して比較できる。
  一部の案が失敗しても成功分を表示し失敗を通知する。
- **REQ-009**: 生成モックはブラウザ印刷でPDF化できる（補助表示は印刷時非表示）。※生成HTML側は KLK-007 で対応済み。
  本チケットは**比較画面側の印刷導線**を担う。
- **REQ-010（残り）**: 生成物を `mockups/{日付}_{案件名}/` に整理し、完了後に**保存先フォルダを自動で開く**
  （開けない場合は保存先パスを表示）。
- あわせて DRAFT_RULES §8 レスポンシブに**モバイルファースト原則**を明文化する（全体2カラムのサイドバーはモバイルで
  メインカラム優先・二次情報として本文の後ろに畳む）。

見た目の正は `docs/wireframes/SCR-002-compare.html`（案切替セグメント・サムネイル・原寸別タブ・partial-note・@media print）。
ただし「本番へコピー禁止」なので技術制約に沿って作り直す。

## 3. 設計方針

**採用する方針:**

- **U-A 保存構造＝「同フォルダ・案別ファイル」＋比較ハブ**。`mockups/{日付}_{案件名}/` の中に、成功案ごとの独立HTML
  `index-a.html`/`index-b.html`/`index-c.html`（最大3・letter は a→b→c）と、比較ハブ `compare.html`、入力の写し
  `instruction.json` を置く。各案が**独立URLの単一ファイル**で開けるため REQ-008「クリックで原寸を別タブ表示」を素直に
  満たす（`<a href="index-a.html" target="_blank">`）。設計docの既定線（`DRAFT_RULES.md:233`）に最も近い（§4.1）。
- **U-F variants:1 は従来どおり `index.html` 単独**（後方互換）。`output.variants:1` のときは案別ファイルにも比較ハブにも
  せず、KLK-007/008 と同一の `mockups/{…}/index.html` ＋ `instruction.json` を出す。これで既存 M群・ゴールデン
  （`klk007`/`klk008`）と、`check_klk007.py` S12 が要求する `index.html`/`instruction.json` 文字列が壊れない（回帰最小・§4.1）。
  `output.variants≥2` のときのみ 案別ファイル＋`compare.html` に切り替える。
- **U-B 比較画面＝CSS-only 案切替 ＋ 相対 iframe プレビュー ＋ 原寸別タブ直リンク**。案切替は隠しラジオ＋兄弟結合子
  （`#ra:checked ~ .canvas #paneA{display:block}`）で **JS ゼロ**（ワイヤー準拠・graceful）。各 `.pane` の中身は
  相対 `src="index-{letter}.html"` の **iframe**（`compare.html` 前例流用）。サムネイルの「原寸 ↗」は同じ案別ファイルへの
  相対リンク＋`target="_blank"`。**外部URL 0**・相対リンクのみ（案は `mockups/` 内＝Git除外・NFR-005 維持・§4.2）。
- **U-B（印刷導線）REQ-009＝原寸別タブの標準ファイルで印刷**。比較画面の印刷品質は iframe 経由だと不安定なため、
  高品質PDFは**各案の standalone `index-{letter}.html`（KLK-007/008 の `@media print` 準拠）を別タブで開いて印刷**する
  導線とする。`compare.html` 自身にも補助UIを隠す `@media print` を持たせる（ワイヤー準拠・保険）（§4.2）。
- **U-C バリエーション規約＝配色テーマ主軸・カラム骨格は全案共通**。同一生成指示書から、**案A＝指示書の配色に忠実
  （ベース案）**、**案B・案C＝指示書の `colors.main` を起点に方向性を変えた調和配色**（濃色高級／明色ポップ 等）＋
  テイストの副次的な振れ（フォント serif↔sans・見出しサイズ・角丸）で差別化する。`layout.columns`（カラム骨格）・
  番地ラベル6種・セクション構成・業種/テイストの骨子・アタリa方式は**全案で固定**する。`colors.mode:"main-only"`
  （autofill 多）のときは sub/accent/bg を案ごとに大きく振ってよく、`explicit`（4色指定）のときは main を大きく裏切らず
  差し色/フォント/トーンで差をつける。ワイヤーの案A緑（`--m-main:#2E7D6B`）／案B紺金（`#22303A`+`#C6A15B`）／
  案C桃（`#E86FA0`+`#57C4C4`・sans-serif）を参考の振れ幅とする。生成が非決定的でも品質を安定させるため
  DRAFT_RULES に**振れ幅規約**として明文化する（§4.3）。
- **U-D フォルダ自動オープン＝スキル（Claude Code）が OS 別コマンドを実行・フォールバックはパス表示**。保存後、
  Claude Code が `open '{絶対パス}'`（mac）／`explorer '{パス}'`（win）／`xdg-open '{パス}'`（linux）でフォルダを開く。
  実行できない・非対応・失敗時は**保存先パスを報告に表示**する（SPEC §7 / REQ-010「開けない場合は保存先パスを表示」）。
  **ブラウザ単独では不可**を明示（比較画面の「フォルダを開く」ダミーボタンは実装しない）。前例＝`settings.local.json` の
  `open` 許可（§4.4）。
- **U-E 比較画面ゴールデンを新規追加**（`tests/fixtures/klk009/`）。生成は非決定的・`mockups/` は Git 除外で実生成物を
  CI 検証できない（KLK-007 と同じ課題）。そこで**コミット可能な代表出力**を置き S群で構造検証する: `compare.html`
  （3案成功ハブ）・`compare-partial.html`（一部失敗ハブ・`.partial-note` 焼き込み）・`index-a.html`/`index-b.html`/
  `index-c.html`（案別 standalone・配色違い・同一カラム）・`instruction.json`（variants:3）。KLK-007/008 の precedent に一致（§4.5）。
- **U-G 一部失敗はスキルが焼き込む**。生成ループで各案の成否を把握し、**成功案のみ**保存＆`compare.html` に載せ、
  失敗があれば `compare.html` に `.partial-note`（失敗案の明示＋「設定を変えて再生成」導線）を**焼き込む**。生成指示書
  （`instruction.json`）は常に保存する（SPEC §7・入力を失わない）。部分再生成（REQ-103・🔄）は別チケットのため、
  partial-note の文言は SCR-001 再実行（設定変更→再生成）に寄せる（§4.3・§4.4）。
- **U-H ファイル名・相対リンク規約**。比較ハブ＝`compare.html`（`index.html` は variants:1 単独案用に予約し衝突回避）。
  案別＝`index-a.html`/`index-b.html`/`index-c.html`。原寸別タブ・iframe とも**相対パス**（同ディレクトリ）のみ。
  フォルダ自動オープンで開いた後、ユーザーは複数案なら `compare.html`、1案なら `index.html` を開く（報告で案内）（§4.1・§4.2）。
- **モバイルファースト明文化**（DRAFT_RULES §8）。現行 `DRAFT_RULES.md:215`「本文の後ろ（または前）へ回す」の曖昧記述を
  **メインカラム優先・サイドバー（`.m-aside`）は二次情報として本文（`.m-main-col`）の後ろに畳む**へ確定し「または前」を
  排除する。全体2カラム（`2col-full-*`）・本文のみ2カラム（`2col-body-*`）・3col の全系統で「メインが中核・サブは後ろ」を
  原則とする（DOM順または CSS `order` でメイン先頭を保証）。※ギャラリーサイトのスクレイピングは SPEC スコープ外・
  設計原則のみ反映（§4.6）。
- **既存縦串の変更は additive・回帰ゼロを厳守**。SKILL/DRAFT_RULES の「1案のみ・複数案は別チケット」断定を反転しつつ、
  `check_klk007.py` S12（`index.html`/`instruction.json`/`mockups/`/パス安全化）・`check_klk008.py` S7/S8（version==1不変・
  alias・animation）が依存する文字列は**削除せず維持**する（§4.1・§5・§6 R-1）。UI（`draft-gen/index.html`）・スキーマ
  （`KLK-006.md §4.4` の `output.variants` 値域）は**本チケットでは変更しない**（Q7・変更範囲を最小化）。

**代替案と却下理由:**
| 案 | 却下理由 |
|---|---|
| U-A(B) 案別サブフォルダ（`mockups/{…}/a/index.html` …） | ネスト増でリンク・保存が複雑化。同フォルダ案別ファイル（A）で原寸別タブ・比較ハブが相対リンク1階層で完結し、設計docの既定線（`DRAFT_RULES.md:233`）にも近い |
| U-A(C) 単一 `compare.html` に3案を inline 埋込のみ | 各案が独立URLを持たず REQ-008「原寸を別タブ表示」を素直に満たせない。案別 standalone ファイルが無いと印刷品質（KLK-007/008 の @media print）も流用できない |
| U-B 比較プレビューを inline（各案の `.mock` を compare.html に直書き） | 案別 standalone とマークアップが二重化しドリフトの温床。iframe なら**案は index-{letter}.html の単一ソース**でDRY、生成負荷も少ない。ワイヤーの inline は「見た目の正」であり技術構成は作り直してよい（本番コピー禁止） |
| U-F variants:1 も常に案別ファイル（`index-a.html`）へ統一 | 既存 `index.html` 前提（`check_klk007.py` S12・klk007/klk008 ゴールデン・M群）が壊れ回帰コスト大。1案は従来 `index.html` 維持が後方互換で低リスク |
| U-H 比較ハブを `index.html` にする | variants:1 単独案の `index.html` と命名衝突。`compare.html`（ワイヤー・compare.html 前例と同語彙）で役割を明確化 |
| U-D フォルダオープンを比較画面のボタンで行う | ブラウザはサンドボックスで Finder/フォルダを開けない（Q4）。フォルダオープンは Claude Code（スキル）の責務。比較画面のダミーボタンは実装しない |
| variants の値域・UI を本チケットで拡張（2案追加等） | ticket スコープ外（Q7）。UI/スキーマ（`output.variants` 1 or 3）を触ると check_klk006/smoke の集合テストに波及。生成側は 1〜3 に頑健にしつつ、UI/契約は据え置きで変更範囲を最小化 |
| 実生成物そのものを CI で構造検証 | 生成は非決定的・`mockups/` は Git 除外でリポジトリに残らない（KLK-007 F4）。コミット可能なゴールデン（U-E）＋M群手動に切り分ける precedent を踏襲 |

### 4.1 保存構造とファイル命名（U-A/U-F/U-H・DRAFT_RULES §9 / SKILL 手順4）

### 4.2 比較画面 compare.html の構造規約（U-B/U-H・DRAFT_RULES 新節）

`compare.html`＝**単一ファイル・外部依存ゼロ**の比較ハブ。ワイヤー SCR-002 の chrome を技術制約に沿って作り直す。

**骨格（上から）:**
1. `<head><style>`: ツールchrome CSS ＋ 案切替 CSS ＋ `@media print`（chrome 非表示）。**外部CDN/フォント/`<link>`/
   `<script src>` 禁止**（JS は原則不要。使うなら末尾インラインのみ）。
2. **隠しラジオ**（`type="radio" name="variant"` を案数ぶん・既定は先頭案 `checked`）。切替は **CSS のみ**:
   `#ra:checked ~ .canvas #paneA{display:block}`・セグメント/サムネイルのハイライトも `#ra:checked ~ … label[for=ra]` /
   `.vthumb.va`（ワイヤー `SCR-002:104-113` 準拠）。JS 非依存＝graceful。
3. **toolchrome**: `proj-head`（案件名＝`meta.project` プレースホルダ／生成日／「N案」）＋ `settings-chips`
   （業種・カラム・テイスト・配色・アタリ方式）。
4. **partial-note（失敗時のみ・U-G）**: `.partial-note` に「案Xの生成が一部失敗したため成功案のみ表示」＋「設定を変えて
   再生成できます」を**スキルが焼き込む**。成功時は出力しない。
5. **variant-bar**: `.seg`（`label for=ra/rb/rc` の案A/B/C セグメント）＋ `.thumbstrip`（`.vthumb va/vb/vc`＝案別テーマ色の
   ミニCSSサムネイル。実スクショではなく色面。cap に「案X」＋ `<a href="index-{letter}.html" target="_blank" class="full">原寸 ↗</a>`）。
6. **toolbar**: 「🖨 印刷 / PDFで保存」＝**選択中の案の standalone を別タブで開く導線**（CSS で active 案の
   `index-{letter}.html` リンクのみ表示）。ほか「← 設定を変えて再生成」（任意・SCR-001 への相対リンク or 案内文）。
   ※「📁 保存フォルダを開く」ダミーボタンは**置かない**（U-D）。
7. **canvas**: `.pane#paneA … #paneC` の中に相対 `<iframe src="index-{letter}.html" title="案X プレビュー">`。CSS-only で
   選択案のみ `display:block`。

**依存・安全**: iframe src・原寸リンクとも**同ディレクトリの相対 .html のみ**（`compare.html` 前例 `SCR-002:69` の許可規則と
同趣旨）。`http(s)://` 参照 0 件（`www.w3.org`/`example.*` 除外）・秘密パターン 0 件・実在案件名なし（NFR-005/004・REQ-011）。

**印刷（REQ-009）**: 比較画面の印刷は iframe 経由で不安定なため、**高品質PDFは原寸別タブ（standalone `index-{letter}.html`・
KLK-007/008 の `@media print`）で行う導線**を正とする。`compare.html` 自身の `@media print` は chrome（info/toolbar/variant-bar）
を隠す保険とする。

### 4.3 複数案バリエーション規約（U-C/U-G・DRAFT_RULES 新節）

同一生成指示書から最大3案を出す際の**振れ幅**を規約化し、非決定的生成でも品質を安定させる。

**全案で固定（変えない）:**
- `layout.columns`（カラム骨格・6系統のいずれか）・番地ラベル6種・セクション構成（NAV/HERO/ABOUT/MENU/GALLERY/FOOTER）・
  業種（`industry.resolved`）とテイストの骨子・アタリa方式・外部依存ゼロ・印刷/アニメ規約。

**案ごとに振る（配色主軸）:**
| 案 | 配色方針 | 副次の振れ |
|---|---|---|
| 案A（ベース） | **生成指示書の配色に忠実**（`colors.main/sub/accent/bg`＋autofill補完＝KLK-007 §4.3 のまま） | 標準テイスト |
| 案B | `colors.main` を起点に**濃色・高級方向**（例 紺+金）へ調和させた別テーマ | フォント/見出しトーンを上質寄り |
| 案C | `colors.main` を起点に**明色・ポップ方向**（例 桃+シアン）へ調和させた別テーマ | sans-serif・角丸・軽い配色 |

- `colors.mode:"main-only"`（sub/accent/bg が autofill）: 案B/Cは sub/accent/bg を大きく振ってよい。
- `colors.mode:"explicit"`（4色指定）: main を大きく裏切らず、差し色（accent）・フォント・トーンで差別化する。
- 参考の振れ幅＝ワイヤー案A緑（`--m-main:#2E7D6B`）／案B紺金（`#22303A`+`#C6A15B`）／案C桃（`#E86FA0`+`#57C4C4`・sans-serif）。
- **一部失敗（U-G）**: 生成ループで各案の成否を把握。成功案のみ `index-{letter}.html` を保存し `compare.html` に載せる。
  失敗があれば `compare.html` に `.partial-note` を焼き込み（失敗案の明示＋「設定を変えて再生成」）、報告でも通知する。
  失敗案のファイルは作らない・比較画面から参照しない。`instruction.json` は常に保存（SPEC §7）。
