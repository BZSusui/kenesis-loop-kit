## 1. 目的

配色ジェネレーター（`palette/index.html`）v1.0 の使用者フィードバックに応える v1.1 改修。
(1) メインカラーの傾向に「ゴールド」「シルバー」（metallic）を追加し金属らしい配色を生成できるようにする。
(2) ジャンル（業種）を単一選択化して色相の平均による濁りを解消する。
(3) CSS変数書き出しと (4) URL共有で、生成結果を実務へ持ち出し・再現できるようにする。

## 3. 設計方針

**採用する方針:**
- **単一ファイル構成・依存0を維持**する。新規JS/CSSファイルは作らない（v1.0の構成原則を継続）。
- **metallic は「最終段クランプ」で守る**。seed 段で金銀らしいS/Lを与えても後段5層（スライダー変換群 →
  スキーム導出 → toSameHue → ダークlift → applyContrast）が S/L を書き換えるため、
  `makePatterns` の**戻り値直前で main のみを色味バリエーション固有の帯（§4.1.2）へクランプ**する。
  スライダーは帯の中では効き続ける（帯外へ出た分だけ丸められる）。
- **metallic のサブ・アクセントはスキーム導出ではなく「相性パートナー表」から生成**する。
  補色・トライアド等の既存 SCHEMES は金銀の低〜中彩度と相性が悪く（補色計算で緑や紫が出る）、
  実務の定番（ゴールド×ネイビー等）をデータとして持つ方が結果の品質が安定する。
  3案 = パートナー3種を rng でシャッフルして割り当てる（「別案」の再現性は seed で保たれる）。
- **金属風グラデーションは CSS 表示のみの参考表現**。データ（currentPatterns / 出力HEX / コピー値）は
  従来どおり単色HSLのままとし、paintOutput の描画時にのみ `linear-gradient` を上掛けする。
- **ジャンルは buildKeywords のカテゴリ名分岐で radio 化**し、読み取り側（computeBase / updateSummaries）に
  空値ガードを入れる。値の形式（`cat/key`）は既存と同一に保ち、復元・集計ロジックの互換を維持する。
- **URL共有は `URLSearchParams` ＋ `history.replaceState`**。render() のたびに URL を同期し、
  ページ読み込み時に復元する。乱数はシード付き（mulberry32）で入力から一意のため、
  「入力状態＋seed」だけで生成結果を完全再現できる（微調整モーダルの手編集のみ対象外＝v1.0からの既知制約）。

**代替案と却下理由:**
| 案 | 却下理由 |
|---|---|
| metallic を computeBase の seed 制約だけで実現（クランプ無し） | 後段5層が S/L を書き換え帯から外れる（investigator リスク(a)）。ビビッド+100 でゴールドが蛍光イエロー化する等、金属らしさを保証できない |
| metallic でも既存 SCHEMES をそのまま使い、出力を全てクランプ | sub/accent までクランプすると3案がほぼ同一になる。補色由来の紫・緑が金銀と喧嘩し品質が不安定。定番の相性はデータで持つ方が確実 |
| 金属グラデをHEX複数色として書き出す | チケット要件「書き出すカラーコードは従来どおり単色」に反する。CSS変数出力・微調整モーダルとの整合も崩れる |
| ジャンルを別セクション（#keywords 外）へ分離 | value 形式・イベント登録（L1339）・リセット・URL復元のロジックを二重化することになる。カテゴリ名分岐の方が差分最小 |
| URL共有を「共有ボタン押下時のみ」URL生成（replaceState無し） | 生成のたびにアドレスバーのURLが古くなり、ブラウザのURLコピーで誤った状態を共有する事故が起きる（investigator 指摘） |
| URL状態を localStorage にも保存 | スコープ外。共有要件はURLで満たせる。状態の二重管理は復元順序のバグ源になる |

#### 4.1.2 帯クランプ（最終段）

ユーティリティ群（L621付近）に追加し、**makePatterns の戻り値を作る直前**（applyContrast より後）に
main のみへ適用する。sub/accent はパートナー由来（§4.1.3）でありクランプしない:

```js
// 金属帯クランプ: H は variant.h ± hTol の最短差で丸め、S/L は帯へ収める
function clampMetalBand(col, variant, isDarkBg) {
  const b = variant.band;
  const d = ((col[0] - variant.h + 540) % 360) - 180;      // 最短方向の色相差
  const H = wrap(variant.h + clamp(d, -b.hTol, b.hTol));
  const lb = isDarkBg ? b.lDark : b.l;
  return [H, clamp(col[1], b.s[0], b.s[1]), clamp(col[2], lb[0], lb[1])];
}
```

- `isDarkBg` は判定済みの背景明度で決める: `bgc[2] < 0.45`（dispmode=dark 指定・自動ダークの両方を拾う）。
- 適用順（makePatterns 内・1案ごと）:
  `metallicスキーム生成 → toSameHue（sameHue ON時） → アクセント固定 → bg決定 → ダークlift → applyContrast → clampMetalBand(main)`
  これにより後段のどの変換が S/L を動かしても main は必ず帯内で確定する（investigator リスク(a) への回答）。
- スライダー（vivid/light/muted等）は computeBase の S/L に効き続けるため、**帯の内側では**従来どおり
  調整が反映される。帯外に出る入力だけが丸められる。

#### 4.1.3 computeBase / makePatterns の分岐

**computeBase（L829-844 付近）:**
```js
const famKey = document.querySelector('input[name=colorfam]:checked')?.value || '';
const fam = COLORS.find(c => c.key === famKey);
// metallic: 基準カラー(baseHsl)指定時は従来どおり基準カラーが最優先（metallic扱いしない）
const mvKey = fam?.metallic
  ? (document.querySelector(`input[name=mv-${fam.key}]:checked`)?.value || METALLICS[fam.key].variants[0].key)
  : null;
const metallic = (!baseHsl && fam?.metallic)
  ? { famKey: fam.key, variant: METALLICS[fam.key].variants.find(v => v.key === mvKey) || METALLICS[fam.key].variants[0] }
  : null;
```
- `else if (fam)` 分岐（L835-844）: `metallic` のとき `seedHue = variant.h; seedS = variant.s; seedL = variant.l` とし、
  **言葉による seedS/seedL 上書き（L838-841）はスキップ**する（キーワード選択との優先関係の決定）。
  理由: 言葉平均の S/L（例: ポップ s.90）は帯とほぼ必ず衝突し、クランプで丸められて「言葉が効いたように
  見えて効かない」挙動になる。metallic では S/L の正は色味バリエーションとし、言葉は3軸
  （kwWarm/kwGender/kwFormal）とスライダー経由でのみ寄与させる（色相は従来どおり fam アンカーが優先）。
- 戻り値に `metallic` を追加する（`return { H, S, L, hasInput, ..., metallic }`）。
- `hasInput`（L894-898）は fam が truthy になるため**変更不要**（gold/silver 選択だけで生成可能になることを確認する）。

**makePatterns（L938-984）:**
```js

    accent: [wrap(partner.accent[0] + jit(rng, 6)), partner.accent[1], clamp(partner.accent[2] + jit(rng, 0.03), 0.05, 0.95)],
  };
} else {

```
- 以降の共通後処理（sameHue / アクセント固定 / bg / ダークlift / applyContrast）は**両経路で共通のまま**通し、
  metallic のときのみ最後に `c.main = clampMetalBand(c.main, v, bgc[2] < 0.45)` を適用する。
- sameHue ON のときは従来どおり toSameHue が sub/accent をメイン色相へ圧縮する
  （金銀の同系濃淡でまとめる挙動。main は最終クランプで金属帯を維持）。
- アクセント固定（accentOverride）はパートナー accent より優先（既存の fixedAccent フローのまま）。
- 返す pattern オブジェクトに `metal: true` を追加する（paintOutput のグラデ分岐に使う。
  微調整モーダルは `main/sub/accent/bg` キーのみ触るため既存動作に影響しない）。

描画専用ヘルパーを追加する（データは単色のまま。出力HEX・CSS変数・微調整モーダルは無変更）:

```js
// 金属光沢の参考表現: 単色HSLから4ストップの斜めグラデを合成する
function metalGrad(h, s, l) {
  const hi = hslToHex(h, s, clamp(l + .18, 0, .95));  // ハイライト
  const mid = hslToHex(h, s, l);                       // 地の色（=出力HEXと同一）
  const lo = hslToHex(h, s * .9, clamp(l - .14, .05, 1)); // 陰
  return `linear-gradient(135deg, ${hi} 0%, ${mid} 38%, ${lo} 62%, ${hslToHex(h, s, clamp(l + .10, 0, .95))} 100%)`;
}
```

適用箇所（すべて表示のみ）:
| 箇所 | 対象 | 実装 |
|---|---|---|
| カラーチップ見本ドット | gold/silver チップの `i`（buildColors L1106-1109 の分岐に `metallic` を追加）と変種チップの `i` | `style="background:${metalGrad(...)}"` |
| スウォッチ（メイン） | `p.metal` の案のメインチップ `.sw`（L1038-1042） | background をグラデに。HEX表示・`textOn(mainHex)`・クリック微調整は従来どおり |
| モック: ロゴマーク | `.mock-logo-mark`（L1055） | background をグラデに |
| モック: ボタン | `.mock-navbtn`（L1059）・`.mock-btn`（L1065） | **metallic 案では main のグラデ**＋`color:textOn(mainHex)` にする（金属CTAの定番見え）。あわせて可読性バッジの「ボタン文字×ボタン」（L1080）は metallic 案のみ `contrastBadge(textOn(main), main)` に切り替える |

#### 4.4.2 同期（syncURL）

- `syncURL()` を新設し **render() の末尾で毎回呼ぶ**（入力変更・生成・リセットすべてで URL が現状と一致し、
  「生成のたびに共有リンクが古くなる」事故を防ぐ）。
- hasInput が偽（初期状態・リセット直後）のときは `history.replaceState(null, '', location.pathname)` で
  パラメータを消す。それ以外は `location.pathname + '?' + params` へ `history.replaceState`。
- 微調整モーダルの手編集は URL に載せない（seed 生成モデル外。v1.0 からの既知制約——§10 でなく
  チケット実装メモに記載済みのスコープ外事項）。

#### 4.4.3 復元（restoreFromURL）

- `restoreFromURL()` を新設し、初期化列（L1282-1287: buildColors/buildTones/buildKeywords/sync* の後）で呼ぶ:
```
1. location.search を parse。既知キーが1つも無ければ false を返して終了（従来どおり空の初期表示）
2. 各値を検証して DOM へ反映:
   - c/mv/t/k: `querySelector` で該当 input が実在するものだけ checked（未知keyは黙って無視）
   - スライダー: parseInt → [-100,100] に clamp（NaNは無視）
   - base/accent/bg: /^[0-9a-f]{6}$/i 検証 → pick/hex 両方へ `#`付きで設定し use* を checked
   - sh/dm/cvd: 既知値のみ反映
   - seed: parseInt が正整数なら `seed` へ代入（不正なら既定値のまま）
3. syncBaseUI/syncAccentUI/syncBgUI/syncMetallicUI を再実行し、render() を1回呼ぶ
   （render 末尾の syncURL で URL は正規形に整う）
```
- 復元は buildKeywords 実行後のため、ジャンル radio・変種 radio も同じ経路で復元できる。
- 不正値・未知キーは**すべて黙って無視**（fail-safe。生成が止まらないことを最優先）。
