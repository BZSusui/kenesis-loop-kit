## 1. 目的

REQ-104（フリー実写真アタリ b方式・Should）の本実装。SCR-001 の「フリー実写真を使う」を選ぶと
**メインビジュアル（MV-01）のアタリのみ**を実写真にできるようにする。取り込み方法は理恵さんの確定どおり
**①ローカル画像アップロード**（ブリッジ経由）＋**②ストック写真の検索リンク**（無料中心＋AdobeStock 探索）。
URL 直接入力は将来チケット。他のアタリ枠は従来どおり a方式、写真未供給・読込失敗の MV は a方式へフォールバックする
（SPEC §7「失敗要素は除外して継続」）。実写真は**出力フォルダへ同梱＋相対 `<img>`**で自己完結させ、外部 http URL は
埋め込まない（外部URL0件の原則は維持）。

対象要件: **REQ-104**（b方式）／REQ-006（a方式）／NFR-005（外部依存ゼロ・REQ-104使用時を除く）／
NFR-004・REQ-011（機密保持）／NFR-006（テスト品質）。

## 3. 設計方針

理恵さんの決定事項（MV限定／アップロード＋検索リンク／URL入力は将来／無料中心＋AdobeStock）は確定済み。
investigator Unknowns U1〜U5 は以下で architect 確定（人間エスカレーション不要）。

### 3.1 U1 スキーマ拡張 ＝ 案X（`atari` 文字列維持＋別キー `mvPhoto`）・version:1 据え置き

**採用: 案X。** `atari` は文字列 `"standard"|"free-photo"` を維持し、MV写真は**トップレベルの別キー `mvPhoto`** に載せる。

- **キー名・形**: `mvPhoto: { file: "<ステージング保存名>" }`（例 `{ "file": "upl-<32hex>.jpg" }`）。
- **条件付き出力（後方互換の要）**: `mvPhoto` は **`atari==="free-photo"` かつ 保存名あり のときだけ出力**する。
  それ以外（standard／写真未供給）は**キー自体を出さない** → `buildInstruction` の standard 出力は**既存と完全等価**（バイト一致）。
- **version は 1 据え置き（additive）**。既存 `instruction.json`（文字列 atari・mvPhoto 無）はそのまま有効。
- **消費側の分岐（唯一の判定式）**: `atari === "free-photo" && mvPhoto && mvPhoto.file` → **MV-01 のみ b方式**、else **a方式**。

**却下: 案Y（`atari` をオブジェクト `{mode, mvPhoto}` 化）。** DRAFT_RULES/SKILL の文字列比較を `atari.mode` 参照へ全面改訂が必要で、
既存 fixtures（文字列 atari）の後方互換分岐も要り、互換コストが大きい。案X なら既存の atari 文字列比較も S12 radio 集合も無改変で通る。

### 3.2 U5 受信方式 ＝ 生バイナリ直POST（`cgi` 非依存・外部依存ゼロ）＋マジックバイト二重検証

`cgi` 削除（3.13）を避け、multipart を使わない。**`POST /upload` に画像バイトを直接送る**（`Content-Type: image/jpeg|image/png`、
本体＝`self.rfile.read(length)` のバイト列）。**保存名はサーバ生成**（`uuid4().hex`）とし、**拡張子はマジックバイトで判定**する
（クライアントのファイル名・Content-Type を保存パスに信用しない＝パストラバーサル面をゼロにする）。MIME は Content-Type ではなく
**マジックバイト**を正とする（JPEG `FF D8 FF`／PNG `89 50 4E 47 0D 0A 1A 0A`）。既存防御順（Origin→サイズ→検証→保存→JSON）に乗せる。

### 3.3 U4 サイズ上限 ＝ `/upload` 専用の上限を新設（写真向けに引き上げ）

JSON ルートの `MAX_BODY_BYTES`（1 MiB）は写真に小さい。**`UPLOAD_MAX_BODY_BYTES = 8 << 20`（8 MiB）を新設**し `/upload` のみに適用する
（`/generate` 等の JSON ルートは 1 MiB のまま＝無改変）。8 MiB は一般的な実写真1枚を十分カバーしつつ、ローカル完結なので過大でない。

### 3.4 U3 保存先 ＝ ステージング `mockups/.uploads/`（Git除外・自動）

アップロードは**生成前の先行ステージング**。出力フォルダは生成 job 内で初めて作られる（`build_folder`）ため、アップロードは
`mockups/.uploads/upl-<uuid>.<ext>` に置き、instruction の `mvPhoto.file` に**保存名（basename）**を載せる。`mockups/` は3ファイル
Git除外済み（§11）なので `.uploads/` も**自動的にGit除外**＝機密（実案件写真）が追跡対象に入らない。**`.gitignore` の追加変更は不要**。

### 3.5 U3 出力フォルダへの受け渡し ＝ 相対 `<img>` 同梱（base64 非採用）

`/draft-generate` スキルが、生成時に `atari==="free-photo" && mvPhoto.file` なら**ステージング画像を出力フォルダへコピー**
（`mockups/{…}/assets/mv.<ext>`）し、**MV-01 のアタリを相対 `<img src="assets/mv.<ext>">`** にする。base64 data URI は
instruction/HTML が肥大（写真は数百KB〜）するため非採用（チケット L79・investigator §5）。相対同梱ならフォルダ単位で自己完結し、
**生成物は外部 http URL 0 のままオフライン閲覧可**（＝NFR-005 の思想も実質満たす。§3.7）。

### 3.6 U2 複数案での MV写真 ＝ 全案共通で MV-01 に入れる

`variants≥2` のとき、**同じアップロード画像を全案（index-a/b/c）の MV-01 に共通で入れる**（§12 の配色主軸に整合。配色差は
オーバーレイ／枠で表現）。画像コピーは1回で足り、各案は同じ `assets/mv.<ext>` を相対参照する。

### 3.7 検索リンクの外部URL回避（S15 非抵触）

検索リンクは `<a target="_blank" rel="noopener">`（埋め込み fetch なし・KLK-019 palette 起動リンクと同型）。ただし index.html は
`check_klk006 S15`（外部URL 0件）の対象なので、**`https://` スキームを HTML ソースに literal で書かない**。bridge.py の
`format` 部品組立ての前例に倣い、**スキームを実行時に組み立てる**:

- JS 定数 `const HTTPS = 'https' + '://';`（ソースに `https://` の連続 literal を作らない）。
- プロバイダ表（**スキーム無し**のホスト＋パス literal を保持。S15 の `https?://…` 正規表現に非抵触・S群は下記 literal を grep 可）:
  | プロバイダ | base（スキーム無し・ソースに書く literal） | 末尾 | 完成URL |
  |---|---|---|---|
  | Unsplash（無料） | `unsplash.com/s/photos/` | — | `https://unsplash.com/s/photos/{q}` |
  | Pexels（無料） | `www.pexels.com/search/` | `/` | `https://www.pexels.com/search/{q}/` |
  | Pixabay（無料） | `pixabay.com/images/search/` | `/` | `https://pixabay.com/images/search/{q}/` |
  | Adobe Stock（有料・探索） | `stock.adobe.com/search?k=` | — | `https://stock.adobe.com/search?k={q}` |
- `render()` が各 `<a class="mv-search">` の `href` を `HTTPS + base + encodeURIComponent(q) + suffix` で設定する。`q` は
  `industry.resolved`（未選択時は既定語・例 `business`）。href を JS 設定にすることで HTML ソースには外部 http URL literal が残らない。

**(d) アップロード（file 選択時・ブリッジ経由）** — モジュール変数 `let mvPhotoSaved = null;`:
```js
document.getElementById('mvPhotoFile').addEventListener('change', async function (e) {
  const f = e.target.files && e.target.files[0];
  mvPhotoSaved = null;
  if (!f) { setMvStatus(''); render(); return; }
  const ok = await probeHealth();                       // 既存 probeHealth 流用
  if (!ok) { document.getElementById('mvBridgeNeed').style.display = 'block'; setMvStatus('ブリッジ未起動のためアップロードできません'); render(); return; }

  setMvStatus('アップロード中…');
  try {
    const res = await fetch(BRIDGE_ORIGIN + '/upload', {
      method: 'POST',
      headers: { 'Content-Type': f.type || 'application/octet-stream' },
      body: f,
    });
    const data = await res.json().catch(function () { return {}; });
    if (res.ok && data.savedName) { mvPhotoSaved = data.savedName; setMvStatus('アップロード完了（生成時に MV へ反映されます）'); }
    else { setMvStatus('アップロードに失敗しました：' + ((data && data.error) || '画像を確認してください')); }
  } catch (err) { setMvStatus('アップロードに失敗しました（ブリッジ通信エラー）'); }
  render();
});
```

```python
# 定数（§3.3）
UPLOAD_MAX_BODY_BYTES = 8 << 20   # POST /upload ボディ上限(8 MiB・写真向け。JSON ルートの MAX_BODY_BYTES=1MiB は不変)
UPLOAD_MAGIC = {b"\xff\xd8\xff": ".jpg", b"\x89PNG\r\n\x1a\n": ".png"}  # マジックバイト→拡張子(JPEG/PNG)

def sniff_image_ext(head):
    """先頭バイト列から画像拡張子を判定する(マジックバイト・Content-Type は信用しない・§3.2)。
       JPEG(FF D8 FF)→'.jpg' / PNG(89 50 4E 47 0D 0A 1A 0A)→'.png' / それ以外→None。副作用なし。"""
    if not isinstance(head, (bytes, bytearray)):
        return None
    b = bytes(head)
    if b[:3] == b"\xff\xd8\xff":
        return ".jpg"
    if b[:8] == b"\x89PNG\r\n\x1a\n":
        return ".png"
    return None
```

### 4.3 ブリッジ `POST /upload`（additive・生バイナリ直POST・§3.2/3.3/3.4）

`do_POST`（L763-774）に分岐を**追加**（既存分岐は不変）:


`_upload()` ハンドラ（既存 POST と**同一防御順**）:
```
① Origin 検証: is_allowed_origin(Origin, BRIDGE_HOST, port) 偽 → 403「許可されていないオリジンです」
② サイズ上限: Content-Length を int 化。ValueError/負値 → 400 / > UPLOAD_MAX_BODY_BYTES → 413「リクエストが大きすぎます」
③ 本体読取: raw = self.rfile.read(length)（length==0 は 400「画像がありません」）
④ 画像判定(マジックバイト): ext = sniff_image_ext(raw[:16])。None → 400「画像として認識できません(JPEG/PNGのみ)」
⑤ 保存: os.makedirs(uploads_dir, exist_ok=True) → savedName = "upl-" + uuid.uuid4().hex + ext
         → mockups/.uploads/{savedName} へ raw をバイナリ書き出し（クライアントのファイル名・Content-Type は保存パスに未使用）
⑥ 応答: self._json(200, {"savedName": savedName})
```
- 保存先ディレクトリ `uploads_dir = os.path.join(root, "mockups", ".uploads")`（`_run_server` のパス定義群に追加）。
- `savedName` はサーバ生成 `upl-<32hex>.{jpg|png}` で**必ず `is_safe_catalog_name` を満たす**（basename・危険文字なし）。
- **cgi 不使用・shell 不使用・危険フラグ非含有**（新規コードにサブプロセス起動は無い＝画像保存のみ）。
- ルート閉集合をアサートするテストは無いので `/upload` 追加は既存 bridge テストを壊さない（investigator §4/§7）。

**受け渡し全体像:**
```
[index.html] file選択 → POST /upload(バイナリ) → 200 {savedName}
      → mvPhotoSaved=savedName → collectInput → buildInstruction は free-photo時 mvPhoto:{file:savedName}
      → POST /generate(JSON) → bridge が mockups/.pending/{jobId}.json へ写し（validate_instruction が mvPhoto.file を安全名検証）
      → /draft-generate スキルが mockups/.uploads/{savedName} を出力フォルダへコピー＋MV-01 相対img（§4.4）
```
