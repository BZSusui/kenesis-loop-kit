# KLK-124 セクション型を図解アイコンで選べるようにする（設計・検証）

**状態**: 設計と検証のみ。実装は次回以降（理恵さんの指示・2026-09-14）

## 1. 何を作るか

理恵さんの要望:

> 生成後のモックをセクション別に再生成させる際、選択できる6型の現状の英語だけの表記から
> 簡単な図解アイコンなどを用いてもっと直感的にわかりやすく見せられる方法はないか。
> カラム別レイアウトのアイコンのように分かりやすい図解のようなものがあったほうが良い

現状: KLK-117 で日本語ラベルは付いた（`価格表／料金プラン（price-table）`）。
次はそこへ**図解**を足したい。手本は SCR-001 の「カラム構成」の図（入れ子 span ＋ CSS）。

## 2. 調べて分かったこと

### 2.1 型を選ぶ場所は **2箇所**ある

| 画面 | 場所 | 現状の表示 |
|---|---|---|
| SCR-002（比較画面） | 🔄 セクション再生成 の `<select id="regen-type">` | **日本語ラベル付き**（KLK-117） |
| SCR-001（生成設定） | ページ構成 → 行ごとの「設定 ▾」→ レイアウト型 | ★**英語マーカーのみ**（KLK-117 が未適用） |

**KLK-117 は compare.html にしか入っていない。** SCR-001 側は今も `pat-cards` と出る。
図解を入れるなら両方そろえる。ラベルだけ先に SCR-001 へ広げるのは小さく切り出せる。

### 2.2 ★最大の制約: `<option>` には図が入らない

両方とも `<select>` である。`<option>` は HTML を描けないので、
**アイコンを出すにはセレクタ自体を作り替える**（SCR-001 のカラム図と同じ「カード選択」型へ）。
ここが「大きな作業」の正体であり、絵を描く手間ではない。

### 2.3 84型は **21通りの骨格**に収まる（実測）

規約 §12.1.2／§12.1.3 の説明文を機械分類した結果:

| 骨格 | 型数 |
|---|---|
| 縦積み | 16 |
| グリッド | 16 |
| （骨格語なし＝個別対応が要る） | 10 |
| タブ切替＋表 | 5 |
| 横スクロール | 5 |
| 縦積み＋交互 | 5 |
| 縦積み＋タブ切替 | 4 |
| その他14通り | 23 |

→ **84枚を手描きする必要はない。** 部品の組み合わせ（レシピ）で描ける。

## 5.5 第2段の設計（2026-09-15 理恵さんの回答を反映）

### 決まったこと

| # | 回答 |
|---|---|
| 1 ピッカーの見た目 | **モーダル内の横一列リスト**。アイコン＋日本語ラベル＋マーカーを1行に。
  スマホでもアイコンが分かるサイズを保つ。**実際に使って微調整する前提**で、まず動くものを出す |
| 2 描き分け | **セクションを跨いで同じ内容の型は共通アイコンでよい** |
| 3 段取り | **第1段から一つずつ**。少しずつ検証しながら |

### 形（提案し承認を得たもの）

```
┌─ レイアウト型を選ぶ ── MENU-01 ──────────── × ┐
│  [図] カード群＋名称＋価格        pat-cards  ✓現在 │
│  [図] 横並びリスト                pat-list        │
│  [図] ジグザグ交互                pat-zigzag      │
└──────────────────────────────────────────────┘
```

- 1行＝**アイコン（左・固定幅 56〜72px）＋ 日本語ラベル ＋ マーカー（小さく右）**
- 説明文が長くても改行は1回で収まる（2行組みにすると改行だらけになるため横一列にした）
- スマホでは**アイコンだけ少し小さくして1行を維持**（縦積みにすると1画面に1〜2件しか入らない）
- 行全体がクリック領域。現在の型に `✓現在`
- 6行なのでスクロールはほぼ不要

### 描く枚数（実測）

- 異なるマーカーは **83個**（延べ84型のうち `price-table` だけが MENU と PRICE で共有）
- ★**規約自体が「◯◯を流用」「同機構」と記録している群が 9群・28型分ある**。
  共通アイコンにすると **83 → 64 枚**へ減る。群は規約の文面が根拠であり、当てずっぽうではない

| 群 | 型 |
|---|---|
| 3列カード | `pat-cards` = `news-cards` = `price-cards` = `faq-cards` = `contact-methods` = `map-cards` = `search-sidebar` |
| ステップ | `flow-row` = `flow-timeline` = `map-steps` = `contact-steps` |
| 2カラム | `img-left` = `contact-split` = `map-side` |
| 表 | `price-table` = `news-table` = `map-hours` |
| 縦リスト | `news-list` = `pat-list` = `price-list` |

### レシピをどこまで自動で決められるか（実測）

規約の説明文から骨格を機械推定したところ **83個中 76個**が決まった。

| 骨格 | 型数 |
|---|---|
| rows（縦積み） | 27 |
| grid（格子） | 17 |
| scroll（横スクロール） | 13 |
| split（2カラム） | 9 |
| tabs（タブ切替） | 5 |
| mosaic（大小混在） | 3 |
| row（横並び） | 2 |
| ★推定不能（手で決める） | **7** |

推定できなかった7型: `band` / `full` / `img-right` / `img-top` / `pat-wide` / `search-keywords` / `split`
（MV の整列系など、説明が CSS の整列値で書かれていて骨格語が無いもの）

→ **レシピは「自動推定＋7型の手当て」で作れる。** ただし自動推定を**実装に埋め込まない**。
   推定はレシピの**初稿を作る道具**として使い、確定したレシピは画面側に**明示的に持つ**。
   そうしないと規約の言い回しが変わるたびに絵が勝手に変わる。
