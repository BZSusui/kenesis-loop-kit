# [KLK-021] 複数案のレイアウト差別化 設計

> このファイルはarchitectが生成・更新するチケット単位の設計書です。チケット KLK-021 に対応します。
> implementer・tester・reviewerが参照します。1チケット = 1ファイル。

## 1. 目的

SPEC REQ-008（複数案・U-C/U-G）を強化する。現状の複数案は**配色テーマのみ**を案A/B/Cで振り、レイアウト骨格を
全案固定しているため「同じ紙面の色違い」になりがちで、案を見比べて選ぶ価値が薄い。**配色に加えてレイアウトの型も
案ごとに振る**。ただし比較の等条件性のため**カラム数（`data-columns`）は全案固定を維持**し、レイアウト差は新設の
離散属性 **`data-archetype`（レイアウト原型・3値enum）** で表して、案間の相違を `--m-main` と同型に機械検証する。

## 2. 現状

**現在のフロー（複数案生成・DRAFT_RULES §12 / SKILL 手順3）:**
```
生成指示書(output.variants=3)
  → 案A/B/C を生成
     ・全案固定: data-columns（§8の6系統）/ 番地6 / セクション構成 / 業種・テイスト骨子 / アタリa / 依存0 / print / anim
     ・案ごと: 配色テーマ（§5の5変数）＋テイスト副次差 のみ  ← レイアウトは振っていない
  → compare.html（§13・案切替CSS-only・iframe相対・原寸別タブ）
```

**機械検証の型（tests/site/check_klk009.py S9）:**
- `data-columns` を全案**同一**で検証（`dc_same`・enum=NEW_COLS の6値）
- `--m-main` を案間**相違**で検証（`mm_distinct`・3値distinct）

→ レイアウト差別化は「`data-columns` 同一のまま、案間で相違する離散属性を1本足す」ことで、既存の検証パターンに
そのまま乗る。これが `data-archetype`。

**関連する既存ファイル:**
- `.claude/skills/draft-generate/templates/DRAFT_RULES.md`（§12 複数案規約・§8 カラム）
- `.claude/skills/draft-generate/SKILL.md`（手順3 生成）
- `tests/fixtures/klk009/`（複数案ゴールデンの参照構造）
- `tests/site/check_klk009.py` / `tests/test_palette_klk009.py`（検証パターンの参照）

## 3. 設計方針

**採用する方針: 離散属性 `data-archetype` の新設（`data-columns` と直交）**

- 生成ルート `.mock` に既存 `data-columns`（マクロ骨格＝サイドバー有無・列数）に**加えて** `data-archetype`
  （レイアウト原型＝紙面の構成・重心）を付ける。両者は**直交**する軸: `data-columns` は列数を決め、`data-archetype`
  はその内側の**構成の型**（HERO重心・見出し整列・帯/余白リズム・ギャラリー比重）を決める。**archetype はカラム数を
  変えない**（`.m-layout` の列数・サイドバー有無に触れない）。
- **enum（3値・固定語彙）:**

  | archetype | 割当案 | レイアウトの型（data-columns は不変・列数を変えない） |
  |---|---|---|
  | `stack-centered` | 案A（ベース） | 中央寄せの標準構成。HERO 中央寄せ（`text-align:center`・縦積み中央）・セクション見出し中央・対称グリッド。既存 klk007/009 骨格に忠実 |
  | `split-editorial` | 案B | エディトリアル/非対称。HERO 左寄せ（`align-items:flex-start`＋`text-align:left`）・見出し左寄せ＋左罫（`border-left`）・ABOUT を非対称グリッド（テキスト側を広く）。serif で上質方向（配色の濃色・高級と同調） |
  | `banded-showcase` | 案C | ビジュアル先行/帯構成。HERO 下寄せキャプション（`justify-content:flex-end`）・セクションを全幅帯で交互色・GALLERY 比重増・見出しに下線アクセント。sans-serif で軽い方向（配色の明色・ポップと同調） |

- **不変条件（機械検証の正）:**
  1. 全案で `data-columns` が**同一**（従来どおり・列数固定を維持）。
  2. 案間で `data-archetype` が**相違**（3値 distinct・各値は enum のいずれか）。`--m-main` 相違検証と同型に1本追加。
  3. 配色は従来どおり案間で振る（`--m-main` 相違を維持）＝**配色＋レイアウトの両振り**。
  4. archetype は**実 CSS 差**として現れること（属性だけの飾りにしない）。検証フックとして HERO の整列シグネチャ
     （`justify-content` / `align-items` / `text-align` の組）が案間で相違することを確認する。
- **additive**: `data-archetype` は既存生成物に無くても既存検証（klk009 等）は不変（archetype 検証は klk021 ゴールデン
  限定の新規チェック）。§13 compare.html・§14 部分再生成の構造には触れない。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| 案ごとに `data-columns`（カラム数）を変える | ユーザー方針「カラム数は全案固定を維持」に反する。比較の等条件性が崩れ、番地・骨格の安定（§8）も揺らぐ |
| レイアウト差を CSS だけで表現し離散属性を持たない | 案間の相違を機械検証できない（`--m-main` distinct のような静的フックが立たない）。方針「離散属性で機械検証」に反する |
| archetype を自由文字列にする | enum を固定しないと生成のブレを規約化できず、注入面・検証の一意性も損なう（§8 の canonical enum と同じ理由で固定語彙にする） |

## 4. 実装詳細

**ファイル構成（変更・追加）:**
```
.claude/skills/draft-generate/templates/DRAFT_RULES.md   （§12 改訂: data-archetype 規約を追加）
.claude/skills/draft-generate/SKILL.md                    （手順3 改訂: 案別 data-archetype 付与手順）

tests/fixtures/klk021/index-b.html   （新規・split-editorial / --m-main 案B / data-columns 共通）
tests/fixtures/klk021/index-c.html   （新規・banded-showcase / --m-main 案C / data-columns 共通）
tests/fixtures/klk021/compare.html   （新規・3案比較ハブ・§13準拠）
tests/fixtures/klk021/instruction.json（新規・入力の写し・variants:3）
tests/site/check_klk021.py           （新規・静的受け入れ S群）
tests/test_palette_klk021.py         （新規・回帰＋Git除外 D群）
```

**主要な属性契約（生成ルート `.mock`）:**
```
<div class="mock" data-columns="{§8 canonical・全案同一}" data-archetype="{stack-centered|split-editorial|banded-showcase・案別}">
```
- 案A: `data-archetype="stack-centered"`、案B: `split-editorial`、案C: `banded-showcase`（成功順 a→b→c と同順）。
- klk021 ゴールデンの共通カラムは `2col-body-right`（本文のみ2カラム）を採用し、「同じカラムでもレイアウト原型で
  紙面が変わる」ことを1つの骨格上で示す。3案とも `.m-layout` の列数・サイドバー位置は同一。

**archetype ごとの実 CSS 差（列数不変で成立させる箇所）:**
```
stack-centered : .m-hero{align-items:center;text-align:center}      .m-sec h2{text-align:center}
split-editorial: .m-hero{align-items:flex-start;text-align:left}     .m-sec h2{text-align:left;border-left:...}
                 .m-about{grid-template-columns:1.4fr .9fr}（列数=2は不変。比率のみ非対称）
banded-showcase: .m-hero{justify-content:flex-end;text-align:left}   .m-sec h2{text-align:left; 下線アクセント}
                 セクションを全幅帯で交互色・GALLERY を強調
```
`.m-layout`（サイドバー骨格）の `grid-template-columns` の**列の本数**は3案とも同一（カラム数固定）。archetype が
変えるのは HERO/見出し/ABOUT・GALLERY 内部の**構成**のみ。

**処理フロー（生成・SKILL 手順3 改訂後）:**
```
1. output.variants ぶんループ
2. 各案 letter に配色テーマ（§5・案別5変数）を割り当てる（従来）
3. 各案 letter に data-archetype を割り当てる（新規・a=stack-centered / b=split-editorial / c=banded-showcase）
4. data-columns は全案同一（従来・§8 canonical）
5. archetype に応じた HERO/見出し/ABOUT/GALLERY の構成差を CSS に反映（列数は変えない）
6. 保存・compare.html は §9/§13 のまま（archetype 非依存）
```

## 6. リスク

| リスク | 深刻度 | 軽減策 |
|---|---|---|
| archetype が属性だけで実レイアウト差が無い（飾り化） | medium | S群に HERO 整列シグネチャの案間相違チェックを入れ、実CSS差を強制 |
| archetype がカラム数を変えてしまい方針違反 | medium | 全案 `data-columns` 同一チェック（既存 dc_same）を klk021 でも必須にする |
| 既存複数案（klk009）の回帰 | low | archetype は additive。klk009 検証・ゴールデンは一切変更しない |
| 生成ブレ（enum外の値・案間で重複） | low | enum を固定語彙にし、distinct を機械検証（`--m-main` distinct と同型） |
