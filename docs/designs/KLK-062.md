# [KLK-062] 比較画面の幅切替 設計

## 1. 目的

REQ-201「スマホ表示版の同時生成」を、**比較画面での幅プリセット切替**として実装し直す。
現状のチェックボックスは生成に一切影響しない形骸であり、生成物は既にレスポンシブのため
二重生成は不要（SPEC REQ-201 の改訂を伴う）。

## 2. 現状

```
SCR-001「スマホ表示版も同時に生成する」☑ ＋ 幅 375 px
   ↓ buildInstruction()
instruction.output.mobile = { enabled: true, widthPx: 375 }
   ↓
bridge.py       … mobile への参照 0件
draft-generate  … SKILL.md / DRAFT_RULES.md とも mobile への参照 0件
   ↓
生成物には何の影響もない  ← ★形骸
```

一方、生成物 `index-{letter}.html` は DRAFT_RULES §8 / NFR-002 により
`@media (max-width: 640px)` の定義が**必須**で、**すでにレスポンシブ**である。

比較画面 `compare.html`（生成物・規約は §13）は、隠しラジオ `name="variant"` と
CSS 兄弟結合子だけで案 A/B/C を出し分ける **CSS-only** 構造を持つ。

## 3. 設計方針

**採用する方針: §13 の CSS-only 方式を踏襲し、第2のラジオ群 `name="vw"` で iframe 幅を切り替える。**

```
<input type="radio" name="variant" id="ra" checked> … 案の出し分け（既存）
<input type="radio" name="vw"      id="vwfull" checked> … 幅の出し分け（新規）
      ↓ 兄弟結合子
#vw375:checked ~ .canvas .pane iframe { width: 375px; }
```

2つのラジオ群は `name` が異なるため独立して機能し、`.canvas` に対する兄弟結合子も
互いに干渉しない（案の選択と幅の選択を自由に組み合わせられる）。

**プリセットは3種（全幅 / 768px / 375px）。**
生成物のブレークポイントは `640px` の1つだけなので、
`375px`＝モバイル版レイアウト、`768px`＝PC版が狭まった状態、`全幅`＝通常、で見え方を網羅できる。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| スマホ幅用の HTML を別ファイルで同時生成する（REQ-201 の元の字義） | 生成物は既にレスポンシブ。同じ内容を二重に生成する意味がなく、golden とテストも案数×2 に膨らむ |
| 幅を数値入力にする（REQ-201「数値指定対応」の字義） | compare.html に JS が必要になる。§13 は「JS は原則不要」を掲げており構造と不整合。任意幅はブラウザの開発者ツールで代替できる。**この縮小は SPEC に明記する** |
| SCR-001 に幅設定を残し、生成時に compare.html の既定幅へ焼き込む | 設定を1つ残すために生成指示書のキーを維持することになる。閲覧時に切り替えられれば事前指定は不要 |
| 既存 golden 28件すべてに幅切替を retrofit する | **前例に反する**。KLK-012（🔄 追加）でも retrofit しておらず、`data-folder` を持つのは 23/28。古い golden は当時の生成物のスナップショットとして正しい |

## 4. 実装詳細

### 4.1 DRAFT_RULES §13 への追記（生成規約の正）

§13 の骨格に「**8. 画面幅プレビュー切替（REQ-201・KLK-062）**」を additive に追加する。

- **隠しラジオ**: `<input type="radio" name="vw" id="vwfull" checked>` / `id="vw768"` / `id="vw375"` を
  `name="variant"` の隠しラジオと同じ位置（`.canvas` より前の兄弟）に置く。
- **セグメント**: `.vwseg`（`label for=vwfull/vw768/vw375` ＝「全幅 / 768px / 375px」）を variant-bar 内に置く。
  ハイライトは案切替と同方式（`#vwfull:checked ~ .toolchrome label[for=vwfull]`）。
- **CSS**: `.pane iframe { width: 100%; display: block; margin: 0 auto; }` を既定とし、
  `#vw768:checked ~ .canvas .pane iframe { width: 768px; }` / `#vw375:checked ~ .canvas .pane iframe { width: 375px; }`。
  幅を絞ったときに枠が分かるよう `.pane` 側に中央寄せの余白を持たせる。
- **`@media print`**: `.vwseg` を `display: none`（chrome 非表示の既存方針に合流）。
- **JS 非依存**: 追加 JS は無し。既存の🔄再生成コントロール（JS）とは独立。

### 4.2 SCR-001（draft-gen/index.html）

- 「スマホ表示版も同時に生成する」チェックボックス（`#mobileOn`）と幅入力（`#mobileW`）を**撤去**。
- 代わりに、比較画面で幅を切り替えられる旨の**1行の案内**を置く（利用者が機能を見失わないため）。
- `collectInput()` の `mobile` 収集と `buildInstruction()` の `output.mobile` 出力を**削除**。
- セクション見出し「生成する案の数・オプション」の REQ 表記を `REQ-008・201` から `REQ-008` へ。

### 4.3 生成指示書のスキーマ

`output.mobile` を**出力しなくなる**（キー自体が消える）。

- bridge の `validate_instruction` は `output.mobile` を検証していないため、
  **既存の instruction.json（`output.mobile` あり）もそのまま通る**（余分なキーは無視される）。
- golden の instruction.json 31件は retrofit しない（生成側が読まないため無害）。
