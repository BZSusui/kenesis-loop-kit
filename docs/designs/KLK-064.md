# [KLK-064] カタログ取り込みの画面承認化 設計

## 1. 目的

「取り込みを実行」が構造的に登録へ到達できない不具合を解消する。
**AI は提案するだけ・人間が画面で承認・書き込みは Python が決定的に行う**という3者分業へ作り替える。
あわせて、アップロード完了後の次の一手をモーダルで案内する。

## 2. 現状

```
[現在] ボタン → bridge → claude -p（非対話）
                            └─ SKILL 手順3「承認を得るまで catalog.json へ確定しない」
                               → 答える人間がいない → 登録せず終了
       bridge は catalog.json が読めたことをもって "done" と報告
       → 「取り込みが完了しました。カタログの登録は 53 件です」（実際は0件登録）
```

**設計どうしの衝突**であり、どちらか一方が悪いのではない。
非対話実行に「対話が必須のゲート」を置いたことが問題。

## 3. 設計方針

**採用する方針: 責務を3つに分ける。**

```
① 提案（AI・非対話）      画像を視覚認識してタグ付け案を作り、proposal.json に書き出す
                          ★catalog.json は書かない・画像も移動しない
② 承認（人間・画面）      SCR-004 が proposal を一覧表示。修正・除外・承認を行う
③ 登録（Python・決定的）  承認された内容を検証し、id 採番→画像移動→catalog.json 追記
                          ★AI は関与しない
```

**この分割は現行より安全である。**
現行は AI が `catalog.json` を直接書く前提だったが、新方式では**書き込みが検証つきの Python に集約**され、
AI の出力は必ず人間の目と `validate_catalog` を通ってからでないと永続化されない。

### 3.1 データの流れ

```
catalog/.pending/
├── pnd-<uuid>.jpg              ← アップロード or 手動コピー
├── {jobId}.import.json         ← ジョブ仕様（既存）
└── {jobId}.proposal.json       ← ★新規：AI のタグ付け案

POST /catalog-import   … ①を起動（既存経路・出力先が proposal.json に変わる）
GET  /catalog-proposal … ②のために最新の proposal を返す（★新規）
POST /catalog-commit   … ③承認された分だけを登録（★新規）
```

### 3.2 proposal.json のスキーマ

```json
{
  "schema": "klk-catalog-proposal",
  "version": 1,
  "jobId": "<32hex>",
  "items": [
    {
      "file": "pnd-<uuid>.jpg",
      "title": "カフェのブランドサイト",
      "industry": "飲食店・カフェ・食関連",
      "taste": "ナチュラル",
      "colors": ["ベージュ", "グリーン"],
      "columns": "1col",
      "source": "own",
      "note": "写真主体・余白広め",
      "sectionLayouts": {"HERO": "full"}
    }
  ]
}
```

- `file` は `.pending/` 直下の**安全名**（`is_safe_catalog_name`）。
- 語彙は **KLK-059 の canonical**（業種17 / テイスト10 / 主配色7）に従う。
- `id` は**含めない**（採番は③の責務）。

### 3.3 登録（`POST /catalog-commit`）の責務と防御

```
① Origin 検証 → 403
② サイズ上限 → 413/400
③ JSON パース → 400
④ 入力検証 validate_commit_request → 400
     ・items が配列
     ・各 file が is_safe_catalog_name かつ .pending/ に実在
     ・industry/taste が非空文字列・colors ⊆ CANONICAL_COLORS（1..3・マルチカラー単独）
     ・source ∈ {own, ref}
⑤ id 採番      catalog/img/ と catalog.json の双方から最大連番 +1（衝突回避）
⑥ 事前検証     追記後の catalog 全体を validate_catalog に通す
                 → 不正なら **1件も書かず** 400（all-or-nothing）
⑦ 画像移動     .pending/<file> → catalog/img/<id>.<ext>
⑧ catalog.json 書き込み（一時ファイル→os.replace の原子的置換）
⑨ 200 JSON     {registered, total, ids}
```

- **書き込み先は `catalog/` 配下に限定**（REQ-011 / NFR-004）。
- 承認されなかった画像は `.pending/` に残す（次回また提案できる）。
- 失敗時は `catalog.json` を書き換えない。画像移動は catalog.json 書き込みの**前**に行うが、
  移動済みで書き込みに失敗した場合は移動を巻き戻す（ロールバック）。

### 3.4 スキル（提案モード）

`catalog-import/SKILL.md` の手順を「対話で承認を得る」から
「**ジョブ仕様を受けた場合は proposal.json を書き出して終了する**」へ改める。

- **チャットから直接 `/catalog-import` を呼んだ場合は従来どおり対話で確認・登録**してよい（既存の使い方を壊さない）。
- **ブリッジのジョブ仕様（`{jobId}.import.json`）を受けた場合のみ提案モード**とし、
  `catalog.json` を書かず `{jobId}.proposal.json` を出力して終了する。
- webp は提案フェーズで `sips` により `.pending/` 内で png へ変換し、`file` を変換後の名前にする
  （id 確定は③のため、`catalog/img/` へは書かない）。

### 3.5 画面（SCR-004）

- **`.autotag` パネルを提案の編集フォームにする**。1画像1行。
  - サムネイル（`/catalog/pending-img/<file>` で配信・★新規GET）
  - 業種 `<select>`（canonical 17）／テイスト `<select>`（canonical 10）
  - 主配色 チェックボックス（canonical 7・最大3・マルチカラーは単独）
  - カラム `<select>`（DRAFT_RULES §8 の6値）／own・ref ラジオ／タイトル・メモ テキスト
  - 「登録する / 除外する」トグル
- 「**この内容で登録**」ボタン → `POST /catalog-commit` → 完了後にカタログ一覧と件数を再読込。
- **アップロード完了モーダル**: 既存の拡大モーダルと同じ作法（CSS-only トグルではなく JS 制御・
  背景クリック / × / Esc で閉じる）。「N件を追加しました」「次は『取り込みを実行』」＋その場で実行できるボタン。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| ヘッドレスAIに自動登録させる | CATALOG_RULES「してはならないこと」に真正面から反する。タグの誤りがそのまま永続化する |
| 登録も AI にやらせる（承認だけ画面で取る） | AI が `catalog.json` を書く構造が残る。Python が書けば `validate_catalog` を必ず通せて決定的 |
| ボタンを廃止しチャット `/catalog-import` へ誘導する | 小さく正直だが、配布先の各メンバーが空カタログから登録する体験が「チャットに切り替える」前提になる。理恵さんの判断は画面完結 |
| 提案を画面ではなくチャットに出す | 現状と同じで、ブリッジ経由では誰も見られない |

## 6. リスク

| リスク | 深刻度 | 軽減策 |
|---|---|---|
| 登録処理のバグで `catalog.json` を壊す（53件の社外秘データ） | **high** | ①`validate_catalog` を**書き込み前**に通す ②一時ファイル→`os.replace` の原子的置換 ③all-or-nothing（1件でも不正なら全体を書かない） ④画像移動の巻き戻し |
| AI の提案を人間が読まず素通しする | medium | 既定を「登録する」にせず、**画面で明示的に確認**させる。除外もワンクリックで可能に |
| 語彙が canonical からずれた提案が来る | medium | 画面は `<select>` で canonical のみ選ばせる。commit 側でも colors を `CANONICAL_COLORS` で検証 |
| `.pending/` の画像をブラウザへ配信することによる情報露出 | medium | 同一オリジン・localhost 限定・`is_safe_catalog_name` で `.pending/` 直下に限定。`catalog/` の外は配信しない |
| KLK-061 で書いた「チャットで確認」が嘘になる | **high**（自己矛盾） | 本チケットで `.autotag` の文言と `check_klk061` の H4/H5b を同時に更新する |
| webp 変換の責務移動でバグ | medium | 提案フェーズで `.pending/` 内へ変換し、`file` を変換後名にする。commit は拡張子をそのまま使う |

