## 3. 設計方針

**採用する方針（investigator サマリ 1-7 を確定）:**

### M-SEC-1 Origin 許可リスト検証
- `build_open_command`（L166）直後・`repo_root`（L169）の前に純関数 `is_allowed_origin(origin, host, port) -> bool` を追加（副作用なし・import 単体テスト可＝S群）。許可条件（investigator 7 の4条件で確定）:
  1. `origin is None`（不在）→ **許可**（同一オリジンGET系・一部 file://）
  2. `origin == "null"`（file:// の POST）→ **許可**
  3. `origin ∈ { f"http://{host}:{port}", f"http://localhost:{port}" }`（host=`127.0.0.1`）→ **許可**
  4. それ以外（例 `http://evil.example`）→ **拒否**（False）
- `_generate`（L327）冒頭で `is_allowed_origin(self.headers.get("Origin"), BRIDGE_HOST, port)` を判定し、非許可なら `403 {"error": ...}` を返して claude を起動しない（body 読取前に弾く）。`port` は Handler のクロージャ変数を使用（テスト時は純関数へ任意ポートを明示注入）。
- **Referer フォールバックは不採用（確定）**。理由: ①「Origin 不在なら許可」を基本に据えるのが KLK-010 U-7（file:// フォールバック）維持に最も安全。②file:// の Referer は `file://...` になり得て許可判定が複雑化し、かえって U-7 を壊すリスクがある。③実 POST を止められれば CSRF 対策として十分で、Referer 併用の追加価値が小さい。ブラウザは主要環境で状態変更 fetch に Origin を付与するため、悪意ページ（別オリジン）は条件4で確実に 403 になる。
- **CORS `*` は残す**（GET 疎通維持・KLK-010 U-4 の file:// 保険）。切り分け: 読み取り（GET `/health`・`/status`・`/`）は従来どおり `*` で疎通させ、**状態変更（POST `/generate`）のみ `is_allowed_origin` で同一オリジン+file:// に絞る**。preflight（`do_OPTIONS`）は緩いままでよい（実 POST を `is_allowed_origin` が止める設計で足りる・investigator 7）。

### L-1 リクエストサイズ上限
- 定数ブロック（L30-52）へ `MAX_BODY_BYTES = 1 << 20`（1 MiB）を追加。
- `_generate` の Content-Length 読取直後・body 読取前に上限判定を挿入する:
  - Content-Length が非整数（`int(...)` が `ValueError`）→ `400`（不正ヘッダ）。
  - `length < 0`（負値）→ `400`（`self.rfile.read(負値)` は全読み込みになり危険なため弾く）。
  - `length > MAX_BODY_BYTES` → `413 {"error": ...}`（body を読まずに拒否）。
  - 正常時のみ従来どおり `self.rfile.read(length)`。

### L-2 保存先フォルダ日付整合
- 完了時 L230 の `date_str = _now().strftime("%Y-%m-%d")` を、**ジョブ開始時刻 `started_at` の日付**に置換する。`_run_job` に `started_at`（`_generate` L353 で生成する datetime）を**引数として受け渡す**（`_run_job(job_id, pending_path, project, variants, started_at)`・`_generate` L359-363 の `args` に追加）。これで folder 導出が起動時刻基準になり日跨ぎのずれを解消する。
- **`meta.createdAt` 基準は不採用（確定）**。理由: 客（ブラウザ）入力を信頼せずローカルで完結させる KLK-010 U-8 の方針に沿い、`started_at`（ブリッジが握る内部時刻）基準の方が単純・安全。現状 `meta.createdAt` はコードのどこも読んでいない。

**代替案と却下理由:**
| 案 | 却下理由 |
|---|---|
| Origin 不在時に Referer をフォールバック照合 | file:// の Referer は `file://...` となり許可判定が複雑化。U-7（file:// フォールバック）を壊すリスク。実 POST を止められれば CSRF 対策として十分 |
| CORS を同一オリジンへ厳格化（`*` を廃止） | GET 疎通（`/health` プローブ・file:// 保険 U-4）が壊れ、KLK-010 の回帰（S7 の分岐・M4 フォールバック）を招く。状態変更のみ絞れば足りる |
| preflight（OPTIONS）でも Origin を検証 | 実 POST を `is_allowed_origin` が止めれば十分。preflight を厳格化しても防御は増えず、file:// 疎通を壊しうる |
| サイズ上限を body 読取後に判定 | 巨大 body を先に読み込んでしまい多層防御にならない。Content-Length で body 読取前に弾くのが自然 |
| 保存先日付を `meta.createdAt`（客入力）で導出 | ブラウザ入力を信頼する形になり U-8 に反する。`started_at`（内部時刻）基準が単純・安全 |

```python
# 定数ブロック(L30-52付近)へ
MAX_BODY_BYTES = 1 << 20   # POST /generate ボディ上限(1 MiB・L-1)

# build_open_command(L166)直後・repo_root(L169)の前へ
def is_allowed_origin(origin, host, port):
    """状態変更(POST /generate)の Origin 許可判定(M-SEC-1)。
    None(不在)/"null"(file://) を許可、http://{host}:{port} と http://localhost:{port} を許可、

    if origin is None or origin == "null":
        return True
    allowed = ("http://{0}:{1}".format(host, port), "http://localhost:{0}".format(port))
    return origin in allowed
```

## 6. リスク

| リスク | 深刻度 | 軽減策 |
|---|---|---|
| **R-1** Origin 検証が file:// フォールバック（U-7/M4）を壊す | medium | 条件1（None）・条件2（"null"）で file:// の POST を明示許可。Referer 併用は不採用で複雑化を回避。M群 M3 で実機確認 |
