## 1. 目的

カタログ画面（SCR-004・REQ-105）の業種フィルタが現状**8区分**で粗く、実績が増えるにつれ収まらない業種が出ている。理恵さんが確定した**17区分**（受け皿「その他・団体/NPO」含む）へ拡充し、既存カタログ13件（cat-0001〜0013）の `industry` を新語彙へ完全一致で振り直す。**仕様は決定済み**（17区分の表記・13件マッピング・受け入れ条件・SCR-001非変更）で、本設計は implementer が迷わず実装できる形に落とすことが目的。

## 3. 設計方針

確定仕様のため新規判断は最小。本設計で確定する判断は以下の4点。

### 3.1 業種チップ表記の正規化方針（判断①）

17区分の文字列は**チケット表のとおり1文字も変えない**。`catalog.html` の各チップは **`data-val` とラベル（内側テキスト）を完全に同一の文字列**にする（現行8チップと同じ規約）。フィルタは完全一致（`catalog.html:235`）のため、**`data-val` と `catalog.json` の `entry.industry` が1文字違わず一致**して初めてヒットする。全角/半角記号の混在に特に注意する。

| # | 業種（この表記を厳守） | 記号の注意 |

### 3.2 ワイヤー SCR-004 の整合範囲（判断②）

`docs/wireframes/SCR-004-catalog.html:135-142` の業種チップは **`data-facet`/`data-val` を持たない純モック**で、クリックしても機能しない（見た目確認専用）。したがって:

- **ラベルテキストのみ**を17区分へ更新する（`data-val` は付けない。器 catalog.html と役割が違う）。現状の9チップ（8＋「その他…」）を17ラベルへ置換。「その他…」は17区分の #17「その他・団体/NPO」に吸収されるため、単独の「その他…」チップは残さない。
- `:167` の result-meta ダミー文言「『美容・サロン × ナチュラル』で 12件」や `:174-` のダミータグは**モック文言で pin されない**ため**任意**（更新推奨だが必須ではない）。混乱を避けたい場合のみ実在17区分の一語に差し替える。
- 目的は「器（catalog.html）とワイヤー（見た目の正）の業種一覧の乖離を作らない」こと。**data-val 一致の責務は catalog.html だけが負う**。

### 3.3 ドリフト防止テストの採否（判断③）→ **採用する（S20 を追加）**

investigator の指摘どおり、現在チップ数/名称/data-val を pin する自動テストは無い（`check_klk013.py:128` S2 は `data-facet="industry"` の**存在のみ**確認）。将来の抜け漏れ・表記ゆれ（特に §3.1 の全角/半角ズレ）を機械検出できないため、**軽量な静的検査を1つ `check_klk013.py` に追加する**。

**採用理由:** 完全一致フィルタの性質上、チップの表記ズレは「無反応フィルタ」という気づきにくい不具合になる。静的検査なら依存ゼロ・ネットワーク不要で、既存 S群と同型（catalog.html のソース文字列検査）で安全に追加できる。実データ（catalog.json）は次項のとおりCI対象外だが、**器の17語彙の同一性**を pin するだけでも表記ゆれの大半を防げる。

- **(a) 追加する S20（catalog.html 側）**: 業種チップが**ちょうど17個**で、その `data-val` 集合が17区分の正準集合と一致し、かつ各チップの **data-val とラベル（内側テキスト）が同一文字列**であることを静的検証する。→ §4.4 に実装を具体化。
- **(b) catalog.json 側は CI テストにしない**: `catalog/` は Git除外（社外秘）でCIに載らないため、実データの `industry ⊆ 17区分` を自動テスト化できない。これは **§手動M群（tester がブリッジ起動＋ブラウザで13件が該当チップにヒットするか確認）** と **取り込み時の人間確認ゲート**（CATALOG_RULES / SKILL）で担保する。設計上、S群（機械）は「器の語彙」、M群（人間）は「実データの語彙適合」と役割分担する（色を S群、色の妥当性を M群にしている既存方針と対称）。

> テスト本数への影響: S20 は `check_klk013.py` スクリプト内部の1チェック追加であり、`unittest` の**テスト本数（現状150）は増えない**（`test_palette_klk013.py` が subprocess で exit code を束ねる構造）。新規 `test_*.py` は作らない。既存 S1-S19 の assertion は一切変更しない。

### 3.4 industry のハード enum 化はしない（判断④）

`validate_catalog` は `industry` を**自由文字列のまま**（検証追加なし・後方互換）。17区分は「**カタログの推奨業種語彙**」と位置づける（taste と同じ緩い扱い）。**SCR-001 の生成用業種プリセットは変更しない**（investigator §⑤の根拠）：カタログ連動は双方向前方一致＋0件フォールバックでズレを吸収するため、17区分ラベルがプリセットと前方一致しないケース（例 entry='クリニック・病院・介護リハビリ' vs preset='医療・クリニック・福祉'）でもフィルタは0件フォールバックで壊れず動作する。生成本体（`index.html:935/956`）は `industryCustom||preset||既定` の単純写像でカタログ語彙に依存しない。

**代替案と却下理由:**
| 案 | 却下理由 |
|---|---|
| `industry` を17区分の enum として validate_catalog で強制 | 後方互換を壊す（自由文字列の taste と非対称）。取り込み時は人間確認ゲートで担保済み。過剰統制で将来の語彙追加が硬直化。理恵さん決定（推奨語彙に留める）に反する |
| SCR-001 プリセットも17区分へ統一 | スコープ外（理恵さん決定）。前方一致ブリッジで吸収済みで壊れる箇所が無い。生成タクソノミの見直しは別チケット |
| catalog.json の industry⊆17 をCIテスト化 | catalog/ はGit除外でCIに載らない。実データ適合はM群＋人間ゲートで担保する方が構造的に正しい |
| ワイヤーにも data-val を付ける | ワイヤーは見た目の正で機能を持たない純モック。data-val の責務は器（catalog.html）に一元化する |

### 4.4 S20（ドリフト防止検査・check_klk013.py 追加分）

S19（`check_klk013.py:527` 付近）の直後、`# Report` セクションの前に以下を挿入する。**S1-S19 は変更しない**。`INDUSTRY17` はこの設計書の正順（§3.1）で定義する。

```python
# ===========================================================================
# S20 業種タクソノミ17区分（catalog.html 業種チップの語彙 pin・KLK-032）
# ===========================================================================
# 器（catalog.html）の業種チップがちょうど17個・正準17区分と集合一致・
# 各チップの data-val とラベルが同一文字列であることを静的検証する。
# 実データ（catalog.json）の industry⊆17 は Git除外でCI外 → M群/人間ゲートで担保。
INDUSTRY17 = (
    "飲食店・カフェ・食関連", "美容室・エステ・化粧品", "ファッション",
    "スクール・教室", "不動産・建築", "ホテル・旅館・レジャー",
    "士業事務所（法律/会計/コンサルティング他）", "コーポレート／BtoB", "EC・物販",
    "フィットネス・ジム・スポーツ", "イベント・キャンペーンLP", "ジュエリー・時計・貴金属",
    "クリニック・病院・介護リハビリ", "農業・ファーム", "求人・採用",
    "アート・ポートフォリオ", "その他・団体/NPO",
)
# 業種 frow（data-facet="industry"）だけを切り出す（taste/colors のチップを拾わない）。
_ind0 = CATALOG_HTML.find('data-facet="industry"')
_ind1 = CATALOG_HTML.find('data-facet="taste"', _ind0)
_ind_seg = CATALOG_HTML[_ind0:_ind1] if 0 <= _ind0 < _ind1 else ""
# class="fchip"（color チップは class="fchip color" なので除外される）の data-val とラベル。
_ind_pairs = re.findall(r'class="fchip"\s+data-val="([^"]+)"\s*>([^<]+)</span>', _ind_seg)
_ind_vals = [v for v, _ in _ind_pairs]
s20_count = len(_ind_vals) == 17
s20_set = set(_ind_vals) == set(INDUSTRY17)
s20_val_eq_label = all(v == lbl for v, lbl in _ind_pairs)

    "S20 業種17区分 (catalog.html 業種チップがちょうど17個・正準17区分と集合一致・各 data-val==ラベル)",
    s20,
    f"17個={s20_count}({len(_ind_vals)}), 集合一致={s20_set}"
    f"{'' if s20_set else ' 差分=' + str(set(_ind_vals) ^ set(INDUSTRY17))}, "
    f"data-val==ラベル={s20_val_eq_label}",
)
```
