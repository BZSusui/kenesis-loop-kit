## 1. 目的

ムードカラー ジェネレーター（palette）で、「メインカラーの傾向（カラー）」と同じ形でアクセントの色系統を1つ選べるようにする。
選んだときは、3案すべてのアクセントをその色系統にする（言葉の差し色・金属の定番ペアより優先）。
選ばないときの出力は v1.3 と完全に同じにする（物差しの得点も同じ）。蛍光色は出さない。

**T1 の判断（1a／1b／1c から 1b を採用）:**
- COLORS の s・l はメインの代表値で、アクセントにそのまま使うと蛍光・低コントラストになる（調査の試算 A: 物差しの蛍光 18,917 件）
- COLORS の各行に値を足す（1c）と、主配色16種の正（check_klk067・check_klk119・bridge）の行に触れる。COLORS は変えない取り決め
- 専用の表にしても、名前と並び順は COLORS から引くので2つの一覧はずれない。KLK-139 で COLORS が広がっても、ACCENT_FAMS に無い色はアクセント側に出ない（勝手に連動しない）

**T2 の判断（明度）:**
- スキームの L（メインの明度に連動）を使うと、背景との差が案ごとにばらつく（現行のアクセント対背景 3:1 未満は 34.5%。§4.9）
- coolAccent と同じく「明るい背景用・暗い背景用」の固定値にし、どちらを使うかは**背景とのコントラスト比**で決める（`bgc[2] < 0.40` の閾値より、背景カラー指定の中間色でも破綻しにくい）
- KLK-140 の lightBgs（暗い言葉の3案に混ぜた明るい案）でも、案ごとの背景で決まるので明・暗のどちらの案でも適切な方になる（§4.9 (4)）

**代替案と却下理由:**
| 案 | 却下理由 |
|---|---|
| 色相だけ傾向にし、S/L はスキームのまま（調査の案 A） | 物差しの蛍光が出る（18,917 件） |
| S を 0.72 で頭打ちするだけ（案 B） | 外部照合の定義で 5,666 件残る。背景とのコントラストもばらつく |
| 金属を METALLICS の変種ごとに選ばせる | 依頼者の回答（定番1色）。UI・URL・テストが倍になる。check_klk004 S1 の数え方に触れる |
| ヒント関数（coolAccent 等）を傾向選択時は呼ばない | rng2 の消費が変わり、エレガント＋かっこいいの型B のメイン・濃い一点が傾向の有無で変わる。呼んでから上書きすれば変わらない |
| 生成後に蛍光を判定して S を下げる（後段のガード） | palette に物差しの判定を持ち込むことになる（palette は物差しの文字列を持たない取り決め・check_klk138 C5） |
| 固定と傾向を排他にする（片方を選ぶともう片方を外す） | 依頼者の回答は優先順位（固定が勝つ）。連動処理・URL の扱いが増える。要約の「（固定が優先）」で足りる |

### 4.3 データと関数（palette/index.html・WORD_HINTS 系の関数の後、「3パターン生成」の前）

置き場所は `luxShineOf` の後・`/* ===== 3パターン生成 ====` の前。METALLICS ブロックの中（check_klk004 S1）や SCHEMES の範囲（check_klk004/005 S10）に入れない。
コメントに禁止語（§4.10）を書かない。`accent: [` の書き方は使わない。

```js
/* ===== アクセントカラーの傾向（KLK-142） ==================================
   選ぶと3案すべてのアクセントをこの色系統にする。key と名前・並び順は COLORS と共通
   （モノトーン・カラフルは持たない）。light = 明るい背景用 / dark = 暗い背景用の [H, S, L]。
   背景とのコントラスト比が大きい方を使う。S は 0.72 以下（どの明度でも蛍光にならない）。
   金・銀は変種を持たず定番の1色（明るい背景は高級の輝きと同じ値）。 */
const ACCENT_FAMS = {
  red:    { hJit: 6, light: [  5, .65, .48], dark: [  5, .65, .58] },
  pink:   { hJit: 6, light: [340, .62, .52], dark: [340, .62, .66] },
  orange: { hJit: 5, light: [ 26, .72, .44], dark: [ 28, .72, .56] },
  yellow: { hJit: 4, light: [ 46, .70, .45], dark: [ 48, .62, .56] },
  ygreen: { hJit: 5, light: [ 80, .55, .36], dark: [ 80, .50, .52] },
  green:  { hJit: 6, light: [135, .50, .38], dark: [135, .45, .50] },
  teal:   { hJit: 6, light: [185, .55, .37], dark: [185, .50, .52] },
  blue:   { hJit: 6, light: [210, .65, .46], dark: [210, .65, .62] },
  navy:   { hJit: 5, light: [225, .55, .30], dark: [225, .55, .58] },
  purple: { hJit: 6, light: [275, .50, .46], dark: [275, .50, .64] },
  brown:  { hJit: 5, light: [ 25, .45, .36], dark: [ 25, .45, .50] },
  beige:  { hJit: 4, light: [ 38, .35, .62], dark: [ 38, .35, .74] },
  gold:   { hJit: 3, light: [ 43, .62, .42], dark: [ 46, .55, .55] },
  silver: { hJit: 0, light: [213, .07, .72], dark: [210, .06, .74] },
};
function accentFamOf(t, rng3, bgHex) {
  const pick = (col) => [wrap(col[0] + jit(rng3, t.hJit)), col[1], col[2]];
  const lc = pick(t.light), dc = pick(t.dark);
  return contrastRatio(hslToHex(...lc), bgHex) >= contrastRatio(hslToHex(...dc), bgHex) ? lc : dc;
}
```

- 値の根拠: 明るい背景用は「その色に見える範囲で、明るい背景とのコントラスト 3:1 以上」、暗い背景用は「暗い背景と 3:1 以上」を目標に選んだ。
  黄・ベージュ・金・銀は明るい背景で 3:1 にすると別の色（からし色・茶・灰）になるので、色らしさを優先した（§4.9 (3) の例外）
- 金の明るい背景用・銀の明るい背景用は `WORD_HINTS.luxShine` と同じ値、暗い背景用は `WORD_HINTS.elegantBeige.shines` と同じ値（依頼者が確認済みの金・銀）
- `hJit` は1案ごとの色相の揺れ（±）。`jit(rng3, 0)` も rng3 を1回消費するが、rng3 は傾向専用なので影響しない
- 明・暗の両方で `jit` を呼ぶ（rng3 を1案につき2回消費）。どちらを使っても消費回数が同じなので、背景が変わっても後の案の揺れがずれない

### 4.4 computeBase

`hasInput` の直前に足し、`hasInput` と戻り値に `accentFam` を加える。

```js
  const accKey = document.querySelector('input[name=accentfam]:checked')?.value || '';
  const accentFam = Object.prototype.hasOwnProperty.call(ACCENT_FAMS, accKey)

  const hasInput = checked.length > 0 || baseHsl || fam || bgOverride || accentOverride || accentFam || …（以下は従来どおり）

  return { …（従来どおり）, lightBgs, accentFam };
```

H・S・L・metallic・hints・metalAutoDark・lightBgs の計算は変えない（傾向はメイン側に一切効かない）。

### 4.5 makePatterns

1. `const hints = b.hints || {};` の次に:
   ```js
   const rng3 = b.accentFam ? mulberry32((seed ^ 0x2c1b3c6d) >>> 0) : null; // KLK-142: 傾向専用の乱数列（未指定は作らない）
   ```
2. 同系色の注記（傾向が効くときだけ文言を変える。固定があれば従来の文言）:
   ```js
   note = b.accentFam && !b.accentOverride ? '同系色モード: メイン・サブの色相を揃え、アクセントは選んだ傾向の色'
                                          : '同系色モード: 色相を揃えて彩度・明度で差別化';
   ```
3. 言葉のヒントの `if (!b.metallic && !fixedAccent && !sameHue) { … }` の**直後**（ダークの持ち上げの前）に:
   ```js
   // KLK-142: アクセントカラーの傾向。固定が無ければ、上のどの経路のアクセントもこの色に置き換える
   if (b.accentFam && !fixedAccent) {
     c.accent = accentFamOf(b.accentFam, rng3, hslToHex(...bgc));
     if (name === 'ベージュ＋濃い一点') note = 'エレガント: ベージュに濃い一点（黒・濃茶）と、選んだアクセントの色を添えた型';
     if (b.metallic) {
       name = `${COLORS.find(x => x.key === b.metallic.famKey).name}×${b.accentFam.name}`;
       note = '金属色の定番ペアのサブに、選んだアクセントの傾向を合わせた配色';
     }
   }
   ```
   - `bgc` はヒント（型B のアイボリー）を反映した後の背景なので、型B でも正しい方の明度になる
   - ヒントの分岐は従来どおり実行する（rng2 の消費を変えない）。型B のメイン・サブ（濃い一点）・背景は傾向の有無で変わらない
4. 金属の `return` を `name: sc.name` から `name` に変える（未指定のときは `name === sc.name` なので出力は同じ）。
5. ダークの持ち上げ・コントラストのスライダーは**従来の式のまま**（`fixedAccent ? c.accent : lift(c.accent)` 等）。傾向のアクセントは自動のアクセントと同じく持ち上げ・コントラストが掛かる。S は変わらないので蛍光の保証は崩れない。
6. `applyContrast` の最後の呼び出しは `clampMetalBand` より前のまま（check_klk004 S3）。

適用の条件のまとめ:

| 条件 | アクセント | 案名・注記 |
|---|---|---|
| 傾向なし | 従来どおり | 従来どおり |
| 傾向あり・固定あり | 固定の色（傾向は無視） | 従来どおり（固定と同じ） |
| 傾向あり・同系色 | 傾向の色（メイン・サブは同系色の結果のまま） | 注記「メイン・サブの色相を揃え、アクセントは選んだ傾向の色」 |
| 傾向あり・かっこいい／スタイリッシュ・高級の明るい案 | 傾向の色（coolAccent・luxShine を置き換え） | 従来どおり |
| 傾向あり・エレガントの3案目（型B） | 傾向の色（型B のメイン・濃い一点・アイボリーは残す） | 名前「ベージュ＋濃い一点」のまま・注記を変える |
| 傾向あり・メインが金・銀 | 傾向の色（サブは定番ペアのまま） | 案名「ゴールド×（傾向の色名）」（3案とも同じ名前）・注記を変える |
| 傾向あり・背景カラー指定 | 傾向の色（指定背景とのコントラストが大きい方の明度） | 従来どおり |

### 4.6 要約・URL・UI の組み立て・リセット・イベント（palette/index.html）

```js
  const accKey = document.querySelector('input[name=accentfam]:checked')?.value || '';
  const accName = ACCENT_FAMS[accKey] ? COLORS.find(c => c.key === accKey).name : '';
  set('sumAccentFam', accName && document.getElementById('useAccent').checked ? `${accName}（固定が優先）` : accName);
```

**restoreFromURL**:
- `KNOWN` に `'ac'` を足す（`'mv'` の後。既存の12キーと `...URL_SLIDERS` はそのまま。check_klk005 S11）
- mv の復元の後に:
