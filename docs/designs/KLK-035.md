# [KLK-035] セクション型プール拡充 第1弾 設計

> architect 生成。KLK-035 に対応。implementer・tester・reviewer が参照する。

## 1. 目的

KLK-034（参考準拠 §12.2）で案Aを見本に寄せられるようになったが、型が少ない（VOICE/FLOW/STAFF 各5・
HERO/MENU/GALLERY/ABOUT 各3）ため「寄り」が粗い。STEP B（型プール拡充）第1弾として、**既にプール方式の
VOICE/FLOW/STAFF を各5→6型に増やす**（`§12.1.2(6)` の「データ追加だけ」の土台を実証）。同時に KLK-029 の
reviewer 残タスク R1（2col golden 未固定）・R2（表とchecker定数のドリフト穴）を解消する。

## 2. 現状

investigator 調査（チケット実装メモ 2026-07-27）より:

- §12.1.2（DRAFT_RULES.md:523-612）: (1)型プール表（各5型 index0-4・:538-542）(2)オフセット表（12セル・値域0-4・:564-571）
  (3)割り当て表（offset→(idxA,idxB,idxC)・巡回 `(o,o+1,o+2) mod 5`・:575-581）。
- **制約A（型数を揃える）**: 割り当て表は VOICE/FLOW/STAFF が同一 index を共有（check_klk029.py:181-183）。
  ∴型数は3セクションとも等しく N。**FLOW も同数に増やす必要**がある。現状 DRAFT_RULES に未明文化。
- **制約B（N拡張で既存golden一部更新）**: 巡回窓のため N=5→6 で offset3 の割り当てが (3,4,0)→(3,4,5) に変わる。
  klk029b（1col×below-hero=offset3）の案C が index0→index5(新型) に変化＝index-c.html 更新が必要。
  klk029（offset0=(0,1,2)）は不変。
- checker の POOL/OFFSET/ASSIGN が check_klk029.py（:34-51）と check_klk034.py（:48-62）に二重ミラー（R2）。
  本文の表の**値そのもの**を照合する検査は無い（N11/N12 はマーカー文字列の存在照合のみ）。
- fixtures は klk029（offset0）/klk029b（offset3）のみ。2col系 offset(1/2/4) の golden は無い（R1）。
- §12.2（KLK-034）・§14/draft-regenerate は型数非依存（index等値比較・表の名指し参照のみ）。ただし
  check_klk034 も OFFSET/ASSIGN を共有ミラーするため R2 の定数更新は klk034 側でも必須。

## 3. 設計方針

**採用: N=6（各セクション+1）へ拡張。新型3つ（縦ジグザグ系）を index5 に追加。巡回窓を維持し、到達可能性は
オフセット表の 3col×top を offset5 に振ることで確保。klk029b/index-c のみ更新（案C→index5）、klk029 は不変。
R1 は 2col×top(offset4) の新 golden(klk035) で固定。R2 は「本文の表 vs checker定数」の機械照合を新設。**

### 3.1 なぜ N=6（各+1）か
- 理恵さんの「少しずつ確実に」方針。実需は VOICE 縦ジグザグ・STAFF 2カラム交互の2つ（メモリ section-variation-backlog）。
  制約Aにより FLOW も1つ揃える（計3新型）。各+1が最小の確実な前進。
- N=7（各+2）は FLOW に実需薄い型を2つ作る必要があり過剰。第2弾以降で段階的に増やせる（土台は不変）。

### 3.2 巡回窓維持と到達可能性
- 割り当て表は `(o,o+1,o+2) mod 6`（6行）を維持＝distinct 保証・決定性の原理を崩さない。
- N=6 では offset5 に届くセルが必要（現状12セルは0-4のみ）。**3col×top を 0→5 に変更**（3col の golden は無く影響最小）。
  1col 行（klk029/klk029b が使う）は不変。
- 到達可能性の実証: klk029(offset0)={0,1,2} ∪ klk029b(offset3・更新後)={3,4,5} = 全6型を union で網羅。

**採用しなかった代替案:**
| 案 | 却下理由 |
|---|---|
| VOICE/STAFF だけ +1（FLOW据置） | 制約A（3プール共通index）に反し FLOW で index範囲外。構造上不可能 |
| N=5 のまま新型と既存を差し替え | 「型を増やす」目的に反する。既存型が消えると過去生成の再現性が壊れる |
| 巡回窓をやめ offset3 を (3,4,0) に固定して klk029b 温存 | (3,4,0) は N=6 の巡回窓に存在せず、distinct/到達可能性の設計原理が崩れる。klk029b更新は本質的帰結として受容 |
| checker 定数を単一 _pool_tables.py へ集約 | 既存 check_klk029/034 の改変＝回帰リスク。第1弾では非採用。代わりに「3checkerの定数一致＋本文照合」で R2 を検出（後日集約は別チケット可） |

### 3.3 新型（index5・実CSS差は N7/R4 の飾り禁止を通す）
既存の 2カラム系（voice-two-col=grid並列・staff-two-col=order反転なし）と**別物の実CSS宣言**にする。

- **VOICE `voice-zigzag`**: 全幅1カラム縦積み（`flex-direction:column`）＋各カードが内部 `grid-template-columns:1fr 1fr`、
  `nth-child(even)` で画像の `order` を反転（画像/文章 左右交互）。voice-two-col（グリッド並列2カラム）と構造が別。モバイルは各カード縦積み・order解除。
- **FLOW `flow-zigzag`**: 全幅縦積み（`flex-direction:column`）＋各ステップ内 `grid-template-columns:1fr 1fr`、
  `nth-child(even)` で本文/番号の `order` 反転。flow-vertical-split（grid 88px 1fr の固定左番号）と別。
- **STAFF `staff-zigzag`**: 全幅縦積み（`flex-direction:column`）＋各カード `grid-template-columns:200px 1fr`、
  `nth-child(even)` で画像 `order` 反転（画像左右交互）。staff-two-col（repeat(2,1fr)・order反転なし）・staff-list（96px列・反転なし）と別。

### 3.4 R2（ドリフト検出）
- **型プールの正は DRAFT_RULES §12.1.2 本文**。新 checker `check_klk035.py` に検査を追加:
  1. DRAFT_RULES 本文の (1)型プール表・(2)オフセット表・(3)割り当て表を正規表現でパースし、構造化する。
  2. `check_klk029.POOL/OFFSET/ASSIGN` と `check_klk034.POOL/OFFSET/ASSIGN` を import し、**本文由来の表＝029定数＝034定数**の
     三者一致を照合（不一致なら FAIL）。→ 本文を変えたら両 checker 定数も追随しないとテストが落ちる＝ドリフト防止。
- これは既存 checker を壊さない additive な検査（新ファイルのみ）。
