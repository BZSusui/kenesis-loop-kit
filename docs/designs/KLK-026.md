# [KLK-026] カタログ非表示時の開き方ガイダンスと自動復帰 設計

> architect生成のチケット単位設計書。KLK-026 に対応。implementer/tester/reviewer が参照する。

## 1. 目的

実績カタログのサムネイルが「file:// で開くとブリッジ稼働中でも非表示」になる開き方の罠を、**セキュリティ設計
（同一オリジンのみ・REQ-011）を変えずに**UXで解決する。ユーザーがどう開いても「次に何をすればカタログが
見えるか」がその場で分かり、可能なケースでは自動復帰する。

## 2. 現状

- `setupThumbPicker()`: `catalogAlive = (location.protocol !== 'file:') && await probeHealth()`。false なら
  固定文言「ブリッジを起動すると実績カタログから参考を選べます」を表示して終了（再試行なし）。
- `probeHealth()` は絶対URL（`BRIDGE_ORIGIN + '/health'`）のため **file:// からも稼働検知は可能**（KLK-010 実績）。
- カタログ本体（`/catalog.json`・`/catalog/img/`）は**相対＝同一オリジン fetch のみ**（file:// からは読めない・設計）。
- check_klk017 が上記固定文言のソース内存在をピン留めしている。

## 3. 設計方針

**同一オリジン設計は不変。案内と再探知だけを足す（additive）。**

| 状況 | 表示・挙動 |
|---|---|
| file:// ＋ ブリッジ**稼働中** | 「ブリッジは起動中です。実績カタログを使うにはブリッジ経由で開き直してください（入力中の内容は引き継がれません）」＋ **`http://127.0.0.1:8765/` へのリンク**（開き直し導線）。以後の再探知は不要 |
| file:// ＋ ブリッジ**未稼働** | 「実績カタログを表示するには draft-gen/**起動.command** をダブルクリック（またはターミナルで `python3 draft-gen/bridge.py`）→ 表示される `http://127.0.0.1:8765/` からこの画面を開いてください」＋ **3秒間隔で再探知**し、起動を検知したら上の「開き直しリンク」表示へ自動更新 |
| http（ブリッジ経由）＋ /health 一時失敗 | 3秒間隔で再探知し、復帰したら **catalogAlive を立ててカタログを自動読込**（`loadCatalog()`→`applyThumbFilter()`・リロード不要） |

- 再探知は **3秒 × 最大40回（約2分）** で打ち切り（無限ポーリングしない・タブ放置時の無駄な通信を防ぐ）。
- 動的な文言・リンクは **createElement / textContent** で組み立て（innerHTML への変数埋め込みなし＝注入対策）。
  リンク href は既存定数 `BRIDGE_ORIGIN`（localhost）から組み立てる（外部URL 0 を保つ・S15 非抵触）。
- 既存ピン文言はソースに残す（renderThumbs 内はそのまま。ガイダンスは直後に上書き描画する別関数）。
- **やらないこと**: file:// からの実画像読込（cross-origin 化）・ページからのブリッジ自動起動（ブラウザ上不可能）・
  自動リダイレクト（入力中フォームを黙って破棄しない。リンク提示までにとどめる）。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| file:// でも絶対URLで catalog.json/画像を読む | 社外秘画像の供給面を広げる（REQ-011）。同一オリジン限定の現行設計を維持する |
| 稼働検知したら自動で location 遷移 | 入力途中の内容が黙って消える。リンク提示（ユーザーの意思で遷移）が安全 |
| ページからブリッジを自動起動 | ブラウザのサンドボックスで不可能。起動導線は 起動.command（KLK-014）が正 |

## 4. 実装詳細

```js
// KLK-026: カタログ非表示時の能動ガイダンスと自動復帰（同一オリジン設計は不変・additive）
function showCatalogGuidance(alive) { /* file://: 稼働→開き直しリンク / 未稼働→起動.command 手順。
  http: 「接続を再確認しています…」。全て createElement/textContent・リンクは BRIDGE_ORIGIN から組立 */ }

function startCatalogRecovery() { /* 3秒×最大40回:
  - file://: probeHealth() → showCatalogGuidance(alive)。alive になったら打ち切り（リンク提示が最終形）
  - http:   probeHealth() → 復帰したら catalogAlive=true → loadCatalog() → applyThumbFilter() で自動復帰 */ }

async function setupThumbPicker() {
  catalogAlive = (location.protocol !== 'file:') && await probeHealth();
  if (!catalogAlive) { renderThumbs([]); startCatalogRecovery(); return; }   // ← 変更点はこの1行の追加
  ...
}
```

## 5. 影響範囲

| 対象 | 影響 | 対応 |
|---|---|---|
| draft-gen/index.html（カタログ節） | 変更 | ガイダンス2関数追加＋setupThumbPicker に1行（additive） |
| bridge.py / catalog.html / スキーマ | 影響なし | 供給側・同一オリジン設計に触れない |
| check_klk017 のピン（固定文言・同一オリジン） | 影響なし | 文言は残置・/catalog.json 相対 fetch 不変 |

## 6. リスク

| リスク | 深刻度 | 軽減策 |
|---|---|---|
| ポーリングの無駄な通信 | low | 3秒×40回で打ち切り・file://で稼働検知後は停止 |
| 動的文言の注入 | low | createElement/textContent のみ・リンクは BRIDGE_ORIGIN 定数から組立 |
| 開き直しで入力内容が消える混乱 | medium | リンク文言に「入力中の内容は引き継がれません」を明記（自動遷移しない） |
