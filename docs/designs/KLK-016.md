## 1. 目的

実績カタログ(SCR-004・REQ-105/106)の主配色タグを、多色サイトへ対応できるよう拡張する。KLK-013 の
6カテゴリ(`CANONICAL_COLORS`)では「何色とも決められない」ラフを1色へ押し込めざるを得なかった
(実運用で cat-0003 を暫定複数指定＋note補足で登録)。本設計で **(1) 主配色の複数選択
(第1必須/第2・3任意・最大3件)** と **(2) 7番目カテゴリ「マルチカラー」の追加** を正式化する。
NFR-005(外部依存禁止・PIL不可)は不変で、厳密HEX抽出は行わず視覚推定の離散カテゴリを維持する。

## 2. 現状

主配色カテゴリの**決定論の正**は `draft-gen/bridge.py:62` の `CANONICAL_COLORS`(Python set・6値)。
同一値の独立コピーが `draft-gen/catalog.html:214`(JS配列)にあり、`SCR-004ワイヤー` / `CATALOG_RULES`
/ `SKILL` / `S群テスト` が同じ6値を人間可読・検証可能な形で写している(**同期6系統**)。

**現在のフロー(主配色まわり):**
```
[取り込み] catalog-import(視覚推定) → colors[](6カテゴリのいずれか・通常1件)
                                        ↓
```

**確定事実(investigator 調査サマリ 2026-07-10):**

- 既存データ後方互換は良好(cat-0002 fixture・cat-0003 実データが既に複数値)。破壊的マイグレーション不要。

## 3. 設計方針

**採用する方針(4点):**

1. **集合拡大** — `CANONICAL_COLORS` に `マルチカラー` を加えて7値化する。決定論の正 `bridge.py:62` を先に変え、他5系統(catalog.html / ワイヤー / CATALOG_RULES / SKILL / テスト)を機械的に同期させる(CLAUDE.md「ポリシー管理の原則」)。
2. **件数の機械強制(OQ-B=機械強制)** — `validate_catalog` に `colors` の要素数 `1 <= len <= 3` 検証を追加する(第1必須＝空配列reject、最大3件＝4件以上reject)。既存全エントリ(1〜2件)は不変。
3. **マルチカラー排他の機械強制(OQ-C=単独排他)** — `colors` に `マルチカラー` を含む場合は `len(colors)==1` でなければ reject(具体色との併用不可)。「色でなく色集合」という意味軸を検証層で守る。
4. **UI/運用ガイド/テストの同期** — チップを7個化(マルチカラーは多色を表すグラデーションスウォッチ)、CATALOG_RULES/SKILL に「第1必須/第2・3任意・最大3件」「マルチカラーは単独指定」を明記、S群テストを7対応＋件数/排他ケース追加。フィルタ意味論(OQ-E)は現行の素直なOR一致のまま変更しない。

**代替案と却下理由:**
| 案 | 却下理由 |
|---|---|
| 件数・排他を運用ガイド止まり(機械強制しない) | validate_catalog が唯一の決定論ゲート。ガイド任せでは空配列/4件以上/マルチカラー併用が素通りし、意味軸が崩れる。強制コストは数行で低く、後方互換も保たれる(既存は1〜2件) |
| マルチカラーを具体色と併用可(`["マルチカラー","ピンク"]`) | 「単一色を決められない受け皿」という定義と矛盾し、フィルタの意味が二重化する。人間承認済み方針=単独排他 |
| 新テスト `check_klk016.py` を新設しS3/S7を上書き | 主配色カテゴリの契約が6→7へ**変わった**ため、KLK-013 の S3/S7 は「ちょうど6」を主張し続けると恒久的に赤い正になる。契約の正である既存Sを直接更新するのが整合(OQ-A=既存更新) |
| 厳密HEX抽出で多色判定 | NFR-005(PIL不可・外部依存禁止)に反する。離散カテゴリ視覚推定を維持 |

### 4.1 bridge.py（決定論の正）

**(a) 定数(:62):** 集合へ `マルチカラー` を追加して7値化する。
```python
CANONICAL_COLORS = {"グリーン", "ブルー", "レッド", "ゴールド", "ピンク", "モノトーン", "マルチカラー"}
# ワイヤー主配色チップ7値(§3.3・KLK-016で「マルチカラー」を追加)
```

**(b) `validate_catalog`(:374-380 の colors ブロック):** 既存の集合メンバーシップ検証の直後へ、件数と排他の検証を追加する(colors が list のときのみ)。
```python
colors = entry.get("colors")
if not isinstance(colors, list):
    errors.append("{0}.colors が配列ではありません".format(where))
else:
    for c in colors:
        if c not in CANONICAL_COLORS:
            errors.append("{0}.colors に未対応の主配色 '{1}' があります".format(where, c))
    # KLK-016: 件数(第1主配色が必須・最大3件)
    if len(colors) < 1:
        errors.append("{0}.colors は第1主配色が必須です(空配列不可)".format(where))
    elif len(colors) > 3:
        errors.append("{0}.colors は最大3件までです".format(where))
    # KLK-016: マルチカラーは単独指定のみ(具体色と併用不可)
    if "マルチカラー" in colors and len(colors) != 1:
        errors.append("{0}.colors のマルチカラーは単独指定のみ可です(他色と併用不可)".format(where))
```
※ `colors` を持たない/list でないエントリは従来どおり reject(挙動不変)。fixture(cat-0002 は2件)・実データ(1〜2件)は全て `1<=len<=3` を満たすため無変更で有効。

### 4.2 catalog.html

**(a) JS 定数(:214):** `マルチカラー` を末尾へ追加(未知色サイレント破棄で消えないように)。
```javascript
var CANONICAL_COLORS = ["グリーン", "ブルー", "レッド", "ゴールド", "ピンク", "モノトーン", "マルチカラー"];
```

**(b) フィルタチップDOM(:160-165):** モノトーンの後に7個目チップを追加する。マルチカラーは「多色」を表すため、単色スウォッチではなく6色相を並べた **conic-gradient**(外部依存なし・CSS-only)のスウォッチにする。`class="fchip color"` と `data-val="マルチカラー"` は必須(S3の正規表現が拾う)。
```html
<span class="fchip color" data-val="マルチカラー"><span class="sw" style="background:conic-gradient(from 0deg,#2E7D6B,#2E5FA3,#B23A48,#C6A15B,#E86FA0,#333,#2E7D6B)"></span>マルチカラー</span>
```

**(c) `filterEntries`(:229-247)・`loadCatalog`(:383-387):** ロジック変更なし(OQ-E=素直なOR一致)。マルチカラーチップは他色チップと同列で、`colors` に `マルチカラー` を含むエントリをOR一致で拾う。`loadCatalog` の未知色破棄は (a) で `マルチカラー` が既知になることで通過する。
