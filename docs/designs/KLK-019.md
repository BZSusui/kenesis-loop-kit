# [KLK-019] ブリッジ経由で配色ジェネレーター(palette/index.html)がnot foundになる 設計

> このファイルはarchitectが生成・更新するチケット単位の設計書です。
> チケット KLK-019 に対応します。implementer・tester・reviewerが参照します。
> 1チケット = 1ファイル（`docs/designs/KLK-019.md` が常に現行）。改訂時は本ファイルを上書きし、
> チケットのログに改訂理由を残す。過去の設計はGitヒストリで追える（status等の状態は持たない）。

## 1. 目的

REQ-003（配色ジェネレーター連携）の導線を**ブリッジ配信経路でも成立**させる。設定画面（SCR-001・`draft-gen/index.html`）を
ローカルブリッジ経由（`http://127.0.0.1:8765/`）で開いているとき、「🎨 配色ジェネレーターを起動」リンクが解決する
`http://127.0.0.1:8765/palette/index.html` を**ブリッジが配信していない**ため `{"error":"not found"}` になる不具合を、
ブリッジに `palette/index.html` の単一ファイル配信ルートを追加して解消する（file:// 直開き時の従来動作は不変）。

## 2. 現状

`draft-gen/bridge.py` の `do_GET`（L734〜）は `/`・`/index.html`・`/health`・`/status/{id}`・`/catalog`・`/catalog.json`・
`/catalog/img/{name}` のみ配信し、それ以外は L755 で `self._json(404, {"error": "not found"})` を返す。
**`/palette/…` のルートが無い**のが直接原因（investigator §1・orchestrator一次調査で確定）。

**現在のフロー（バグ再現）:**
```
[SCR-001 draft-gen/index.html L491] <a href="../palette/index.html" target="_blank">配色ジェネレーターを起動</a>
   │  bridge配信(基準URL "/"): ../palette/index.html → /palette/index.html に解決
   ▼
draft-gen/bridge.py do_GET(L734): /・/index.html・/health・/status/・/catalog・/catalog.json・/catalog/img/ のみ配信
   │  /palette/index.html はどの分岐にもヒットせず
   ▼
L755 self._json(404, {"error":"not found"})  ← ブラウザに {"error":"not found"} が表示される
```
一方 file:// 直開き時は `../palette/index.html` が兄弟ディレクトリ `.../palette/index.html` に解決し従来どおり開ける
（ブリッジ配信時のみ発生）。

**investigator が確定した事実（実装材料はほぼ確定済み）:**

  ③成功時 `send_response(200)` → `Content-Type: text/html; charset=utf-8` → `Content-Length` → `self._cors()` →
  `end_headers()` → `wfile.write(body)`。**引数（ユーザー入力）を一切取らない固定1ファイル配信**。`_serve_catalog_html`
  （L786-799）も完全同型（KLK-013 が「新しい固定HTMLルートを足す」前例そのもの）。
- **F** `palette/index.html` は 83,062 バイトの**外部依存ゼロの単一HTML**。`http(s)://`／`fetch(`／`<link>`／`<script src>`／
  `<img src>`／CSS `url(...)`／`@import`／`@font-face`／外部 `href` すべて0件。追加アセット配信（`/palette/img/…` 等）は**不要**。
- **F** `git ls-files` 追跡済み・`git check-ignore` exit=1（＝Git除外対象外）。catalog/ と違い任意クローンで確実にディスクから読める。
- **F** ボタン経由で来るパスは常に `/palette/index.html` の1種のみ（`/palette`・`/palette/` はボタンからは発生しない）。
- **F（リンク側は変更不可）** `tests/site/check_klk006.py` S2（L79-89）が `href="../palette/index.html"`＋`target="_blank"`・
  `../../palette`不在・絶対URL不在を**アサート**。リンクを変えると check_klk006 が落ちる。両モードで同一相対リンクのまま成立。

## 3. 設計方針

**採用する方針（KLK-013 の `/catalog` 配信ルート追加＝本件と同型を踏襲）:** `bridge.py` に `palette/index.html` を
配信する**固定1ファイルの GET ルート**を additive に追加する。ユーザー入力を取らない決め打ち配信で、パストラバーサル面を作らない。

### 3.1 新ルートと配信メソッド（確定）

- **パス定数（L471-480 の既存パス定数群へ追加）:**
  ```python
  palette_index_path = os.path.join(root, "palette", "index.html")
  ```
- **`do_GET` の分岐（L755 の 404 フォールバックの手前に追加。既存分岐は不変）:**
  ```python
  # 配色ジェネレーター(KLK-019・REQ-003)。ブリッジ配信時 ../palette/index.html は /palette/index.html に解決
  if path in ("/palette", "/palette/", "/palette/index.html"):
      self._serve_palette()
      return
  ```
- **ハンドラ `_serve_palette`（`_serve_index` の複製・`_serve_catalog_html` と同型で新規追加）:**
  ```python
  def _serve_palette(self):
      """GET /palette[/][index.html] — 配色ジェネレーター palette/index.html を配信
         (KLK-019・REQ-003・_serve_index と同型・固定1ファイル決め打ち)。"""
      try:
          with open(palette_index_path, "rb") as fh:
              body = fh.read()
      except OSError:
          self._json(500, {"error": "palette/index.html を読み込めません"})
          return
      self.send_response(200)
      self.send_header("Content-Type", "text/html; charset=utf-8")
      self.send_header("Content-Length", str(len(body)))
      self._cors()
      self.end_headers()
      self.wfile.write(body)
  ```

確定事項（implementer はこの名称・位置で実装する）:

| 項目 | 確定値 |
|---|---|
| 受けるパス | `"/palette"`・`"/palette/"`・`"/palette/index.html"`（3パスを同一分岐で受理） |
| 追加メソッド名 | `_serve_palette`（引数なし・固定パス決め打ち） |
| 追加パス定数名 | `palette_index_path = os.path.join(root, "palette", "index.html")` |
| 分岐位置 | `do_GET` の `self._json(404, {"error": "not found"})`（現L755）**手前** |
| MIME | `text/html; charset=utf-8`（`_serve_index` と同一） |
| ヘッダ | `Content-Length` ＋ `self._cors()`（`_serve_index` と同型） |
| 読取失敗時 | `self._json(500, {"error": "palette/index.html を読み込めません"})`（`_serve_index` と同型） |

### 3.2 `/palette`・`/palette/` の正規化（U・確定＝3パス受理）

**確定: `/palette`・`/palette/`・`/palette/index.html` の3パスを同一分岐で `_serve_palette` へ回す（同一ファイルを返す）。**

- **理由:** 再現条件の解消には `/palette/index.html` の1パスで足りるが、既存の `if path in ("/", "/index.html")` と**完全に同じ形**
  （タプルメンバーシップ）で末尾スラッシュ無し／ディレクトリ形の直接URL入力を吸収できる。追加コストはタプルに2要素足すだけで、
  新たな入力面・分岐・状態を一切作らない。過剰な抽象化（正規表現・prefix一致・ディレクトリリスティング）は導入しない。
- **投資対効果:** 「`/` と `/index.html` を同じ固定ファイルへ束ねる」既存作法の水平展開に留まり、堅牢化の便益（直打ちURLでも開ける）に
  対しコストが軽微。prefix一致（`path.startswith("/palette/")`）は**採用しない**——`/palette/foo.html` のような未知サブパスまで
  拾ってしまい「未知パスは404維持」（§3.4）に反するため。あくまで**列挙した3パスの完全一致のみ**受理する。

### 3.3 リンクは変更しない（確定）

`draft-gen/index.html` L491 `<a href="../palette/index.html" target="_blank" rel="noopener" class="launch-link">` は
**変更しない**。理由:
- file:// では兄弟ディレクトリ `.../palette/index.html` に、ブリッジ配信（基準URL `/`）では `/palette/index.html` に解決し、
  **両モードで同一相対リンクのまま成立**する（investigator §3 で実証）。
- `tests/site/check_klk006.py` S2 が `href="../palette/index.html"`＋`target="_blank"`・`../../palette`不在・絶対URL不在を
  固定アサートするため、変更すると KLK-006 の S群が回帰する。**index.html は非変更が必須かつ十分**。

### 3.4 セキュリティ

- **固定1ファイル決め打ち（ユーザー入力を取らない）＝パストラバーサル面を作らない。** `_serve_palette` は URL からファイル名を
  受け取らず `palette_index_path` を決め打ちで読むため、`_serve_catalog_img` が要する `is_safe_catalog_name`／`os.path.realpath`
  封じ込めは**不要**（`_serve_index`・`_serve_catalog_html` と同じ安全クラス）。
- **未知パスは従来どおり404を維持。** 新分岐は列挙3パスの**完全一致**のみ（prefix一致にしない・§3.2）で、必ず404フォールバックの
  手前に置く。`/palette/foo`・`/palette/../x` 等は3パスに一致せず 404 に落ちる。
- localhost限定bind（`BRIDGE_HOST == "127.0.0.1"`）・外部依存ゼロ・危険フラグ非含有・`shell=True` 非使用 は本変更
  （GET配信追加のみ）で影響を受けない。`do_POST`・既存配信・`build_*_command` は**不変**。

### 3.5 代替案と却下理由

| 案 | 却下理由 |
|---|---|
| `/palette/index.html` の1パスのみ受理 | 再現解消には十分だが、末尾スラッシュ無し/ディレクトリ形の直打ちURLで404になる。3パス受理は既存 `("/", "/index.html")` と同型で軽微・便益あり（§3.2） |
| `path.startswith("/palette/")` の prefix 一致で配下を配信 | `/palette/foo.html` 等の未知サブパスまで拾い「未知パスは404維持」に反する。加えて任意ファイル配信＝パストラバーサル面を作る。固定1ファイルの完全一致3パスに限定（§3.2/§3.4） |
| `draft-gen/index.html` の起動リンクを絶対URL/別パスへ変更 | check_klk006 S2 が固定文字列をアサートし回帰。両モードで同一相対リンクのまま成立するため変更は不要かつ不可（§3.3） |
| 汎用静的ファイルサーバ（任意パス→ディスク）を導入 | localhost限定・最小権限・固定配信という既存方針から逸脱し攻撃面を拡大。本件は単一HTML1ファイルで足りる（investigator §2） |
