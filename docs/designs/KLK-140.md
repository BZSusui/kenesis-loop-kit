## 1. 目的

KLK-138 の物差し（`tests/fixtures/klk138/ruler.json`）に合格範囲があるのに、ジェネレーター
（`palette/index.html`）の辞書 `KEYWORDS` に無いため採点できなかった4語（エレガント・かっこいい・
スタイリッシュ・ダーク）を辞書に加え、物差しで採点できるようにする。

- 辞書の値だけでは出ない「意図」を、生成側の小さな処理で出す（判定者の回答 Q1・Q2）
  - かっこいい・スタイリッシュ: モノトーン基調に、寒色寄りのはっきりした差し色を1つ効かせる
  - エレガント: 3案のうち1案を型B（ベージュ系＋濃い一点〔黒・濃茶〕＋輝きの差し色〔金・銀〕）にする
- 物差しにも「差し色があること」の確認を足す（Q1）
- palette を v1.3 に上げ、新しいベースライン `baseline-v1.3.json` を記録する。v1.2 のベースラインは残す（Q4）
- KLK-138 レビュー申し送り M1（C4 が v1.2 の sha を求め続ける／`--write-baseline` の出力先が v1.2 固定）を直す（Q5）
- （改善ループ1）メインの色系統を金属（ゴールド・シルバー）にしたとき、言葉が暗い配色を求めていても背景が白系になる
  不具合を直す。表示モード「自動」の明暗判定を、金属でも言葉に従わせる（§4.12）
- （改善ループ2）ダーク以外の暗い雰囲気の11語は、黒系の背景でなくても成り立つ。世間での使われ方（チケットの調査レポート
  「改善ループ2」）で11語を判別し、表示モード「自動」の3案の背景を 黒系2・明系1／黒系1・明系2 に割り振る。
  高級は物差しで背景＝暗いと決めているため、物差しに「3案のうち1案に限り明るい背景を認める」例外を足す（§4.13）

SPEC との関係: `docs/SPEC.md` は palette を参考資料として挙げるだけで、「言葉→色」の要件は無い（KLK-138 調査 F9）。
この設計の正はチケット KLK-140（ログ 2026-11-26 12:56・13:07 の回答と決定）と KLK-138 の物差し。

## 3. 設計方針

**採用する方針:**

1. **4語は各カテゴリの末尾に足す。既存語は1文字も変えない。** 印象＝エレガント・かっこいい、
   スタイル＝スタイリッシュ・ダーク。既存の上品・高級・クール・モダンは残す。言葉の名前は「ダーク」のまま（Q3）。
   末尾に足すのは、`smoke_klk004` が「ジャンル以外の最初のカテゴリの最初の語」を使い、URL 共有の
   `k=カテゴリ/語` が既存語で変わらないようにするため。
2. **語ごとの処理は、辞書の値に「ヒント」を1つ持たせて表す。** `KEYWORDS` の語に任意のキー `hint` を足す
   （`'coolAccent'`・`'elegantBeige'`）。`computeBase` は選んだ語のヒントを集めて返し、`makePatterns` が
   案を作った後に適用する。語の名前で分岐しない（辞書の値だけで振る舞いが決まる）。
3. **ヒントの処理は専用の乱数列を使い、既存の乱数列を1つも消費しない。** `rng2 = mulberry32((seed ^ 0x5bd1e995) >>> 0)`。
   これで、ヒントを持たない語（既存の39語・ダーク）の出力は v1.2 とビット単位で同じになる。
   ヒントを持つ語でも、差し替える役割以外（メイン・サブ・背景、スキームの並び）は変わらない。
4. **差し色は「蛍光にならない」ことを値の範囲で保証する。** HSL の彩度 s が 0.72 以下なら、明度をどう変えても
   物差しの蛍光の線引き（HSV S>=0.60 かつ V>=0.90）に掛からない（§4.3 の証明）。差し色の s は 0.68 に固定する。
   色相も物差しの蛍光の色相帯（50〜200°・280〜345°）の外（200〜230°）に置く（二重の保証）。
5. **利用者が明示した指定はヒントより優先する。** アクセント固定・背景固定・同系色モード・金属（ゴールド/シルバー）・
   表示モード「ダーク」では、ヒントを適用しない（§4.4 の表）。
6. **物差しの「差し色の確認」は、人間の判定を1件も覆さない値にする。** かっこいい・スタイリッシュの○に
   「アクセントがモノトーンでない（OKLCH C >= 0.06）」を足す。第2回の○案はすべて満たし、V-C は変わらない。
   「寒色寄り」は物差しでは測らない（○案に寒色でない差し色の案がある。§4.6）。暖色アクセントは従来どおり弱い減点。
7. **M1 は「過去版のベースラインは履歴として形だけ検査し、現行版（生成側の指紋が一致する1件）だけを照合する」
   で直す**（investigator 調査 §3 の (1)-a と (2)）。v1.2 のファイルは1バイトも変えない。

**代替案と却下理由:**
| 案 | 却下理由 |
|---|---|
| 辞書の値だけで4語を足す（生成側の処理を足さない） | 物差しは満点になるが、差し色が立たず、型B も出ない（investigator 調査 §5）。判定者が Q1・Q2 で処理を足すと回答 |
| `makePatterns` で語の名前（'かっこいい' 等）を見て分岐する | 語の追加・改名のたびにロジックを触る。辞書の値（hint）で表すほうが「辞書を育てる」設計（KEYWORDS のコメント）に合う |
| ヒントの処理に既存の `rng` を使う | 消費の順序が変わり、同じ語・同じシードで別のスキームの揺れまで変わる。比較（v1.2 と v1.3）が濁る |
| 差し色の色相を寒色全域（160〜260°）にする | 160〜200° は蛍光の色相帯に入る。シアン寄りは s を落とさないと蛍光に近づく。200〜230° に絞る |
| 型B をシードで3案のどこかに置く | 位置が毎回変わると比較しにくい。先頭2案は語の色（型A）を見せ、3案目を型B にする |
| 3案すべてを型A・型B 混在の新スキームで作り直す | 既存スキームの仕組みを壊す。1案の差し替えで足りる |
| 物差しで「差し色が寒色寄り」も○の条件にする | 第2回で○の案に、寒色でない差し色の案がある（かっこいい E1・E2）。V-C が下がる。寒色は生成側の好みとして持つ |
| M1 (1)-b: dictLabel を除いた ruler の sha を照合 | v1.2 の記録済みの値と計算方法が変わり、v1.2 のファイルを書き換える必要がある |
| M1 (1)-c: dictLabel を ruler.json の外に出す | KLK-138 §4.2・§7 の約束（dictLabel は ruler に置く）と C2・T3 を作り直す。変更が大きい |
| 現行版のベースラインが無いとき C4 を FAIL にする | 後続チケット（KLK-139 など）が辞書を触った瞬間に全体テストが赤になる（KLK-138 R-E の方針に反する）。`--check` と同じく SKIP にする |
| 「既存16語が v1.2 を下回らない」をテストで assert する | 「得点率がいくつでもテストは赤にならない」（KLK-138 方針3）に反する。ベースラインに比較の数値を記録し、受け入れ条件で確認する |

### 4.3 ヒントの定義と処理（palette/index.html）

`makePatterns` の直前（`/* ===== 3パターン生成 ====` の前）に置く。**`applyContrast`・`clampMetalBand` を呼ばない**
（`check_klk004` S3 は `makePatterns` 内の `applyContrast` の最後の出現が `clampMetalBand` より前であることを見る）。

```js
/* ===== 言葉ごとの味付け（KLK-140） =======================================
   KEYWORDS の hint で選ぶ。乱数は makePatterns の rng とは別の列（rng2）を使い、
   ヒントを持たない語の出力は変えない。
   coolAccent: モノトーン基調に、寒色寄りのはっきりした差し色を1つ効かせる（かっこいい・スタイリッシュ）
   elegantBeige: 3案目をベージュ系＋濃い一点（黒・濃茶）＋輝き（金・銀）にする（エレガントの型B） */
const WORD_HINTS = {
  coolAccent: { h: 215, hJit: 15, s: .68, lLight: .48, lDark: .58 },
  elegantBeige: {
    bg:   [40, .40, .97],                       // アイボリー
    main: [38, .32, .80], mainHJit: 6,          // ベージュ
    darkPoints: [ [25, .35, .20], [30, .08, .13] ],   // 濃茶 / 黒（濃い一点）
    shines:     [ [46, .55, .55], [210, .06, .74] ],  // 金 / 銀（輝きの差し色）
  },
};
function coolAccentOf(rng2, darkBg) {
  const t = WORD_HINTS.coolAccent;
  return [wrap(t.h + jit(rng2, t.hJit)), t.s, darkBg ? t.lDark : t.lLight];
}
function elegantBeigeOf(rng2) {
  const t = WORD_HINTS.elegantBeige;
  const dp = t.darkPoints[Math.floor(rng2() * t.darkPoints.length)];
  const sh = t.shines[Math.floor(rng2() * t.shines.length)];
  return { bg: t.bg.slice(), main: [wrap(t.main[0] + jit(rng2, t.mainHJit)), t.main[1], t.main[2]],
           sub: dp.slice(), accent: sh.slice() };
}
```

```js
    // KLK-140: 言葉ごとの味付け。利用者の明示指定（アクセント固定・同系色・金属）があれば適用しない
    if (!b.metallic && !fixedAccent && !sameHue) {
      if (hints.elegantBeige && i === 2 && !b.bgOverride && b.disp !== 'dark' && bgc[2] >= 0.40) {
        const t = elegantBeigeOf(rng2);
        c = { main: t.main, sub: t.sub, accent: t.accent };
        bgc = t.bg;
        name = 'ベージュ＋濃い一点';
        note = 'エレガント: ベージュに濃い一点（黒・濃茶）と輝き（金・銀）を添えた型';
      } else if (hints.coolAccent) {
        c.accent = coolAccentOf(rng2, bgc[2] < 0.40);
      }
    }
    // 以降（ダークモードの持ち上げ・コントラスト・金属クランプ）は既存のまま
    …
    return { name, note, main: c.main, sub: c.sub, accent: c.accent, bg: bgc };   // name: sc.name → name
  });
```

- 金属のときは `picks` がパートナー表で、上の分岐に入らない（`!b.metallic`）。金属の `return`（`metal: true`）も `sc.name` のままでよい。
- 両方のヒントがある（エレガント＋かっこいい）ときは、3案目が型B、1・2案目に寒色の差し色が付く。
- 型B は3案目だけ。3案目の背景が暗い（自動で種の L < 0.40）とき・表示モード「ダーク」・背景固定のときは型B にせず、
  3案とも従来どおり（型A）。
- 型B の案にもコントラストのスライダーは効く（利用者の操作として尊重する。§6 R-3）。

**蛍光にならないことの根拠（coolAccent・elegantBeige の金）:** HSL(h, s, l) を HSV にすると、l <= 0.5 では
V = l(1+s) <= 0.5 × 1.72 = 0.86 < 0.90。l > 0.5 では x = 1−l として V = 1 − (1−s)x、S_hsv = 2sx / V。
V >= 0.90 には x <= 0.10/(1−s) が要り、そのとき S_hsv <= 0.2s / (0.9(1−s))。これが 0.60 以上になるのは
s >= 0.7297 のときだけ。よって **s <= 0.72 の色は、どの明度でも物差しの蛍光に掛からない**
（設計時に 0〜360° × 明度 0.005 刻みで総当たりし、s=0.72 で 0件、s=0.73 で 107件を確認）。
差し色は s 0.68、金は s 0.55、銀は s 0.06。ダークモードの持ち上げ・コントラストのスライダーは明度だけを
動かすので、この保証は崩れない。差し色の色相 200〜230° は蛍光の色相帯の外でもある。
外部照合の蛍光の定義（OKLCH C>=0.20 かつ L>=0.65）にも、スライダー0では掛からない（§4.9）。

### 4.8 M1 の直し方とベースライン（klk138_score.node.js・check_klk138.py）

#### 4.8.1 ベースラインのファイル名と「現行版」

- ファイル名は `tests/fixtures/klk138/baseline-{label}.json`。`label` は `^v\d+(\.\d+)+$`（例 `v1.3`）。

#### 4.8.2 `klk138_score.node.js`

```

node tests/site/klk138_score.node.js --json                            # JSON を標準出力へ
node tests/site/klk138_score.node.js --write-baseline --label v1.3 [--compare-with v1.2]

```

- `--write-baseline`
  - `--label` が無い・形式が違う → 終了コード 2（使い方を表示）
  - 書き出し先 `baseline-{label}.json` が既にあり、その `generator.fingerprint` が今の指紋と**違う** → 書かずに終了コード 1
    （「記録済みの過去版 {label} は上書きしない」）。**v1.2 はこの規則で守られる**
  - 別の名前のベースラインが今の指紋と一致する → 書かずに終了コード 1（「同じ生成側が {label2} として記録済み」）
  - 指紋が同じファイルの書き直し（物差しだけを変えたとき）は許す（KLK-138 §7 の運用）
  - `--compare-with {label}` があれば、そのファイルを読んで比較の小計（下記 `comparison`）を書く。ファイルが無ければ終了コード 2
- `--check`
  - `baseline-*.json` をすべて読み、今の指紋と一致するものを探す
  - 0件 → `[SKIP] 生成側が記録済みのどの版（v1.2, v1.3 …）とも違う。--write-baseline --label で新しい版を記録すること` で終了コード 0
  - 2件以上 → 終了コード 1
  - 1件 → 採点し直し、`schema・version・generator・ruler・primary・ageVariant・reference・comparison` の完全一致を確かめる
    （`comparison` はそのファイルの `comparison.with` を使って計算し直す。無ければ比べない）。不一致は終了コード 1
- `--json`・表示: ラベルは現行版のものを使う。現行版が無ければ `"未記録"`。
- 表の文言の「16語」を件数の変数に直す（`全体の合格率（${wordsScored}語・…）`、参考 B1 の `× ${scored.length}語`）。
  `comparison` があれば「既存{n}語（{with} と同じ語）: B0 {prevRate}→{rate}・合格 {prev}→{now}／B1 {prevRate}→{rate}」を1行出す。

### 4.12 改善ループ1: 金属（ゴールド・シルバー）でも暗い言葉なら暗い背景にする

#### 4.12.1 不具合と原因

画面確認（チケットのログ 2026-11-26 14:16 ③）: 言葉「ダーク」だけなら背景は暗いが、メインの色系統をゴールドまたは
シルバーにすると背景が白系になる。

原因（スクラッチ領域の写しで確認）:

1. 表示モード「自動」の明暗は `makePatterns` の `bg()` で決まる。`b.disp !== 'light' && L < 0.40` なら暗い背景。
2. `L` は `computeBase` の種の明度 `seedL` から求める。カラー系統（金属以外）を選んだときは、言葉があれば
   `seedL` = 選んだ語の `l` の平均なので、ダーク（l 0.20）は L 約0.17 になり暗い背景になる。
3. **金属のときだけ** `seedL` = 色味バリエーションの `l`（KLK-004 §4.1.3「言葉による S/L 上書きはスキップ」）。
   ゴールド 黄み 0.54・赤み 0.62・緑み 0.48、シルバー 青み 0.72・暖かみ 0.70 なので、言葉が何であっても L>=0.40 になり、
   「自動」は必ず明るい背景を選ぶ。ガンメタ（0.30）だけは従来から暗い背景になる。
4. KLK-004 の S/L スキップは「メインの色を金属の帯に保つ」ための決定で、背景の明暗の判定まで言葉から切り離す意図は
   書かれていない（KLK-004 §4.1.3・リスク表は「言葉は3軸とスライダー経由でのみ寄与」）。背景の判定が言葉に効かないのは
   その副作用。

同じ原因で、**ダーク以外の暗い語でも起きる**（1語だけ・スライダー0・ゴールド黄みで確認）:
クール・かっこいい・力強い・知的・高級・神秘的・和風・スタイリッシュ・ダーク・コーポレート・ファッション・ラグジュアリー
の12語。どれも金属以外のカラー系統では「自動」が暗い背景を選ぶ語。物差しで背景＝暗いと決めている語は
ダークと高級感の2語で、現状はゴールド（3種）・シルバー（青み・暖かみ）で全案 ×（背景 ×）になる。

#### 4.12.2 範囲の判断（architect 決定）

**ダーク以外の暗い語も範囲に含める**（言葉ごとの例外を作らず、原因そのものを直す）。理由:
- 不具合の原因は「金属のときだけ、自動の明暗判定に言葉の明度が効かない」こと。ダークだけを特別扱いすると、
  高級（物差しで背景＝暗い・金銀のメインは ○）がゴールドで × のまま残る
- 直した後の振る舞いは「金属以外のカラー系統と同じ判定」なので、新しい規則を作らない
- 出力が変わる範囲は §4.12.4 の条件に限られ、機械的に確かめられる（AC12）

採らなかった案: ダークに専用のヒント（`darkBg`）を持たせ、ダークのときだけ暗い背景にする。変化はダークを含む組み合わせだけに
収まるが、高級＋ゴールドの × が残り、「金属のときだけ言葉が背景に効かない」理由を語ごとに説明することになる。
人間が範囲を狭めたい場合は、§4.12.3 の判定式の `checked` を「ヒント `darkBg` を持つ語」に置き換えるだけで切り替えられる
（その場合 AC12 の変化範囲はダークを含む組み合わせだけになる）。

#### 4.12.3 直し方（palette/index.html）

**(1) `computeBase`: 言葉から求めた明度で、金属の「自動で暗い」を判定する**

- いまの明度の計算（`let L = seedL + …` から季節の行までのうち、**L に関わる式だけ**）を、関数内の小さな関数
  `lightOf(l0)` にまとめ、`L = lightOf(seedL)` とする。式と適用の順序は変えない（S の式はその場に残す。
  年齢・季節のブロックで S と L は互いの値を使わないので、分けても結果は同じ）。
- 次のフラグを足して戻り値に含める:
  ```js
  // KLK-140 改善ループ1: 金属は seedL を帯の値にするため、自動の明暗判定が言葉に効かない。
  // 言葉から求めた明度（金属以外のカラー系統と同じ式）が暗ければ、自動でも暗い背景にする。
  const metalAutoDark = !!(metallic && checked.length && disp === 'auto' && !bgOverride &&
    L >= 0.40 && lightOf(checked.reduce((a, k) => a + k.l, 0) / checked.length) < 0.40);
  return { H, S, L, hasInput, bgOverride, accentOverride, contrast, disp, metallic, hints, metalAutoDark };
  ```
  - `L >= 0.40`: 従来から暗い背景になる場合（ガンメタ等）は従来の経路のまま（出力不変）
  - `disp === 'auto'`: 表示モード「ライト」「ダーク」を利用者が明示したら従来どおり
  - `!bgOverride`: 背景固定は利用者の指定を優先（従来どおり）
  - 基準カラー指定時は `metallic` が null なので対象外（従来どおり）
  - 言葉が無いときは対象外（金属だけを選んだ出力は不変）

**(2) `makePatterns` の `bg()`: 既存の「自動」の行の直後に1行足す**

```js
if (b.metalAutoDark) return [H, clamp(S * 0.45, 0, 0.10), 0.13]; // 金属×暗い言葉: チャコール寄りの暗い背景
```
- 明度 0.13 は既存の暗い背景と同じ（ダーク単独の「沈み具合ちょうどよい」に揃える）。
- 彩度の上限を 0.10 にしてチャコール寄りにする（既存の式のままだとゴールドでは彩度 0.25 前後の茶色がかった暗色になる）。
  試算: 背景の OKLCH L 0.247〜0.258・C 0.011 以下。物差しの純黒（L<0.20 かつ C<0.02）に当たらない
  （verification #17「純黒よりチャコール寄り」）。
- 表示モード「ダーク」を明示した金属の背景（既存の式・彩度上限 0.5）は変えない（出力不変の範囲外にしない）。

**(3) `makePatterns` の持ち上げ: 表示モード「ダーク」と同じ持ち上げをかける**

```js
if ((b.disp === 'dark' || b.metalAutoDark) && !b.bgOverride) {   // 既存の if の条件だけ広げる
```
- パートナー表のアクセントは濃い色（明度 0.10〜0.30）が多く、そのままだとチャコールの背景に沈んで差し色が見えない
  （試算: アクセントと背景のコントラスト比が最小 1.00）。表示モード「ダーク」の金属と同じ持ち上げで、最小 2.26 になる。
- メインは最後の `clampMetalBand` が背景の明暗（`bgc[2] < 0.45`）で `lDark` の帯を選ぶ（既存の仕組みそのまま）。
  金・銀は暗い背景の上で明るく起きたメインになり、背景とのコントラスト比は最小 6.44（ガンメタは従来どおり 4.67）。
- verification #20（明るく鮮やかなメインはダーク感を消す）との関係: メインは金属の帯の中に留まり、蛍光（物差しの `isNeon`）は
  0件。物差しはダークのメインとしてゴールド・シルバーを △ と判定しているので（判定者の判定）、メインは △ で頭打ちになる
  （§4.12.5）。

**変えないもの**: ヒント（coolAccent・elegantBeige）は金属では従来どおり適用しない。URL のパラメータは増やさない
（判定は入力から一意に決まる）。要約表示（表示モードの欄）は変えない。`METALLICS`・`clampMetalBand` は変えない。

#### 4.12.4 出力が変わる範囲

次をすべて満たす入力の3案だけが変わる（背景が明るい → チャコールの暗い背景、sub・accent・main が持ち上げ・帯の切り替えで変わる）:

- カラー系統がゴールドまたはシルバー（基準カラーなし）
- 言葉を1つ以上選んでいる
- 表示モードが「自動」、背景固定なし
- 従来の判定で背景が明るい（`L >= 0.40`）
- 言葉から求めた明度（金属以外のカラー系統と同じ式・スライダー込み）が 0.40 未満

それ以外（金属以外・言葉なし・表示モードの明示・背景固定・従来から暗い背景）の出力は a4d051c と完全一致。
