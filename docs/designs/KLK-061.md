# [KLK-061] UI文言を実態へ揃え、SPEC を現状に追従させる 設計

## 1. 目的

配布前に「画面が約束していることと、実装が実際にできることの差」をゼロにする。
機能追加はせず、**文言と仕様書の記述だけ**を現実に合わせる。

## 2. 現状

| 箇所 | 画面の主張 | 実装の現実 |
|---|---|---|
| SCR-001 見本サイトURL | placeholder「配色・構成の傾向を参考にします」／注記「読み取れないURLは…続行します（REQ-102）」 | `references.sampleUrls` は生成指示書に載るが bridge・スキルとも参照0件。**完全に無反映** |
| SCR-004 自動タグ付けパネル | 「自動タグ付けの結果(登録前に確認・修正できます)」 | `#autotagBody` は静的テキスト。**画面に結果は出ない**。確認・修正は Claude Code のチャット |
| SPEC 画面一覧 SCR-003 | 他画面と同列に記載 | `draft-gen/` に実装なし・履歴保存もなし。実質の履歴は `mockups/{日付}_{案件名}/` |

## 3. 設計方針

**採用する方針: 「できないこと」を画面と SPEC に明示する。入力欄・キーは壊さず残す。**

1. **A-1 見本サイトURL** — 入力欄と `references.sampleUrls` キーは**維持**する。
   後続チケットで本実装する際、instruction のスキーマを変えずに済むため（後方互換）。
   placeholder から「参考にします」という**約束の表現を外し**、注記で未対応と対応予定を述べる。
2. **A-4 自動タグ付けパネル** — 見出しと本文を「チャットで確認・修正する」実態に書き換える。
   **「承認前に確定しない」という保証は残す**（これは CATALOG_RULES で実際に守られている真実）。
3. **B-1 SCR-003** — SPEC の画面一覧・要件表・画面遷移図の3箇所で未実装と分かるようにする。
   あわせて「実質の履歴は `mockups/`」を書き、利用者が困らないようにする。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| 見本サイトURL の入力欄を削除する | 後続チケットで本実装が確定しており、消して戻すのは二度手間。`sampleUrls` キーを消すと instruction のスキーマ変更になり後方互換を損なう |
| 自動タグ付け結果を画面に表示する実装を入れる | 本チケットは文言のみの範囲。UI 化は実装を伴うため別チケット（実運用で不便が出てから判断） |
| SCR-003 のワイヤーフレームを削除する | ワイヤーフレームは将来実装するときの設計資産。SPEC に未実装と書けば誤解は生じない |
| SPEC REQ-201（スマホ）もここで改訂する | 実装（幅切替）が伴わないため「SPEC が未実装の仕様を語る」状態になる。実装チケットと同時に行う |

## 4. 実装詳細

**draft-gen/index.html（SCR-001・見本サイトURL）**
- placeholder: `（配色・構成の傾向を参考にします）` → 約束を外した表現へ
- 注記: 未対応である事実＋対応予定＋現時点の代替手段（実績カタログのサムネ選択）を述べる

**draft-gen/catalog.html（SCR-004・自動タグ付けパネル）**
- `.at-head`: 「(登録前に確認・修正できます)」→ 「(Claude Code のチャットで確認・修正します)」
- `.at-body`: 結果が画面に出ると誤解させる記述を、チャット側で提示される旨に修正

**docs/SPEC.md**
- REQ-102 の備考に実装状況（UI のみ・生成未反映・対応予定）を追記
- REQ-202 の備考に未実装と `mockups/` が実質の履歴である旨を追記
- 画面一覧 SCR-003 の行に「**未実装**（ワイヤーフレームのみ）」を明記
- 画面遷移図の SCR-003 ノードに未実装が分かる注記
- 変更履歴 v1.4

**tests/site/check_klk061.py（新規）** — 文言の退行を機械検出する。

| ID | 検証内容 |
|---|---|
| H1 | SCR-001 の見本URL欄に未対応の明示がある（「生成には反映されません」相当の文言） |
| H2 | SCR-001 の placeholder から「参考にします」という約束表現が消えている |
| H3 | `references.sampleUrls` を生成指示書に載せる実装が**維持**されている（後続実装のための後方互換） |
| H4 | SCR-004 の `.at-head` が「チャット」で確認する旨になっている |
| H5 | SCR-004 に「登録前に確認・修正できます」の旧文言が残っていない |
| H6 | SCR-004 の「承認前に確定しません」保証は**維持**されている |
| H7 | SPEC の REQ-102 備考に未反映である旨が書かれている |
| H8 | SPEC の REQ-202 備考に未実装と `mockups/` が書かれている |
| H9 | SPEC の画面一覧 SCR-003 行に未実装の明記がある |
