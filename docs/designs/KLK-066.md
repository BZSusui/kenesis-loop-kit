# [KLK-066] 取り込み待ちの残留物と表示ずれ 設計

## 1. 目的

登録が成功しても `.pending/` に画像と提案JSONが残り、「取り込み待ち」の表示が実態とずれる不具合を解消する。
残骸が積み上がることで**同一画像の二重登録**（cat-0054 / cat-0056＝バイト一致）まで誘発していた。

## 2. 現状

```
webp をアップロード
   ↓ 取り込み実行（AI が sips で変換）
.pending/  pnd-X.webp（元） ＋ pnd-X.png（変換後）    ← 2件と数えられる
   ↓ 提案は pnd-X.png を指す
   ↓ 登録
catalog/img/cat-00NN.png へ移動
.pending/  pnd-X.webp が残る ＋ proposal.json も残る  ← ★残留
   ↓ 次に取り込み実行すると webp を**再変換** → pnd-X.png がまた生える
   ↓ 提案に出るので、また登録できてしまう              ← ★二重登録
```

## 3. 設計方針

**採用する方針: 「1画像＝1論理エントリ」を basename で束ね、登録時に束ごと片付ける。**

スキルの webp 変換は `.pending/` 内で**同じ basename** の `.png` を作る（CATALOG_RULES・KLK-033）。
したがって `pnd-X.webp` と `pnd-X.png` は**同じ画像の2つの表現**である。これを前提に3点を直す。

### 3.1 取り込み待ちの数え方（`_pending_names_count`）

basename でグループ化し、**1グループ＝1件**として数える。表示名は登録に使われる側（`.png` 優先）。
→ 画像1枚が「2件」と表示される混乱が消える。

### 3.2 登録時の片付け（`_catalog_commit`）

登録した画像について、**同じ basename の兄弟ファイルもすべて `.pending/` から取り除く**。

- 変換元の特定は **①提案JSONの `sourceFile`（あれば）→ ②同一 basename の兄弟**の順。
  既存の提案JSONには `sourceFile` が無いため、②のフォールバックが要る。
- 兄弟の削除は **`catalog.json` の書き込みが成功した後**に行う（登録が確定してから消す）。
  ここで失敗しても登録は有効なので、**削除失敗は握りつぶしてログに出すだけ**にする
  （残骸が1つ残るのは、登録が巻き戻るより遥かに軽い）。
- 登録に成功したら、**`.pending/` 内の `*.proposal.json` をすべて削除**する。
  提案は「その時点の `.pending/` の写像」であり、登録後は必ず陳腐化している。
  除外した画像は `.pending/` に残るので、取り込みを再実行すれば新しい提案が作られる。

### 3.3 再変換の抑止（スキル）

`<basename>.png` が既にあるなら `sips` を実行しない。あわせて提案JSONに **`sourceFile`** を書かせる。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| 変換元 webp を「変換した時点で」消す | 変換だけして登録しなかった場合に原本を失う。**登録が確定してから**消すのが安全 |
| 兄弟の削除失敗で登録全体をロールバックする | 過剰。登録は正しく完了しており、残骸1つのために巻き戻す方が害が大きい |
| 提案JSONを1件だけ選んで消す | 複数の提案が溜まっている現状では取りこぼす。登録後は全提案が陳腐化しているので全削除が正しい |
| 数え方は変えず UI 側で重複排除する | 件数の正はブリッジ側にあるべき。UI ごとに重複排除を書くと必ずずれる |

## 6. リスク

| リスク | 深刻度 | 軽減策 |
|---|---|---|
| 兄弟削除で無関係のファイルを消す | **high** | 削除は `catalog_pending_dir` 直下・**同一 basename** に限定。`os.path.dirname` で配下確認。C7 で検証 |
| 登録済み画像を消す | **high** | 削除は `.pending/` のみ。`catalog/img/` には一切触れない |
| 削除失敗で登録が巻き戻る | medium | 削除は `os.replace` 成功**後**・例外は握りつぶす。登録の成否に影響させない |
| 除外した画像の提案まで消える | low | 意図どおり。`.pending/` に画像は残るので取り込み再実行で新しい提案が出る |
