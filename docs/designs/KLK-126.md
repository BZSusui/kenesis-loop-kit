# [KLK-126] 型ピッカーを図解アイコンのモーダルにする 設計

> KLK-124（設計・検証）の第2段＝実装。KLK-124 の §5.5 で理恵さんと合意した仕様をここで実装設計へ落とす。

## 1. 目的

SCR-002（比較画面）のセクション再生成で、6つの型を**絵で見て**選べるようにする。
いまは `select` の文字列だけなので、型を選ぶ前にどんなレイアウトになるか分からない。

## 2. 現状

| 箇所 | いまの姿 |
|---|---|
| SCR-002 `draft-gen/compare_template.html` | `<select id="regen-type">`。KLK-117 で「日本語ラベル（マーカー）」まで来ている |
| SCR-001 `draft-gen/index.html` | KLK-125 で同じ体裁になった。第3段でここにも載せる |
| 型の総数 | 14セクション × 6型 = 84（`price-table` が MENU/PRICE で共通なので**相異なるマーカーは83**） |

`<option>` の中には図を描けない。だから**セレクタ自体を作り替える**しかない（KLK-124 の結論）。

## 3. 設計方針

### 3.1 絵は「レシピ＋レンダラ」で描く

84枚の手描きはしない。**レシピ表（マーカー → 骨格の指定）** と **レンダラ（指定 → 入れ子 div）** に分ける。

- ★レシピは規約 §12.1.2/§12.1.3 の説明文を読んで**明示的に**書く。
  規約テキストからの自動推定は**初稿を作る道具としてのみ**使う。
  実測すると 83 中 7 件が誤分類だった（例: `tab-switch` は説明文に
  「モバイルは横スクロール」とあるため *横スクロール* に分類されてしまう）。
  自動のままにすると、規約の言い回しを直しただけで絵が勝手に変わる。
- ★セクションを跨いで同じ内容の型は**同じレシピ**を指す（理恵さんの方針）。
  どれとどれが同じかは**規約が「◯◯を流用」「同機構」と書いている**のを根拠にする。
  結果、83型 → **相異なる絵は62枚**（32型が共有）。
- 外部依存ゼロ（NFR-005）。`div` と CSS だけ。SCR-001 のカラム図と同じ流儀。

### 3.2 見せ方はモーダルの縦一覧・1行＝アイコン＋説明

理恵さんの指定どおり。

```
┌─ レイアウト型を選ぶ ── MENU-01 ─────────────── × ┐
│  [図]  カード群＋名称＋価格            pat-cards  現在 │
│  [図]  横並びリスト                    pat-list       │
│  ...                                                  │
└───────────────────────────────────────────────────────┘
```

- 1行＝アイコン（左・固定幅）＋ 日本語ラベル ＋ マーカー（小さく右）
- 行全体がクリック領域。現在の型に「現在」
- 幅はアイコン 72px（≥600px）／56px（<600px）。**スマホでも1行を保つ**

### 3.3 ★`<select>` は値の受け皿として残す（不変条件を機械的に守る）

再生成の送信処理は `typeSel.value` を見ている。ここを作り替えると、
KLK-078/079/081 で積み上げた不変条件（下記）を**全部書き直すことになる**。

- 送る値はマーカーのまま
- 現在と違う型のときだけ `desiredType` を送る
- 型を持たない番地は「この番地に型はありません」

そこで **`<select>` は残して隠し**、モーダルは `select.value` を書いて `change` を発火するだけにする。
送信側のコードは1行も変えない。既存テスト（smoke_klk079 / e2e_klk117）もそのまま効く。

## 4. 実装詳細

`draft-gen/compare_template.html` に追加する（KLK-103: 生成側は書かない。テンプレートを直す）。

| 追加 | 内容 |
|---|---|
| CSS `.ico` 一式 | アイコンの部品。`--ic/--is/--il` の3色 |
| CSS `.tm` 一式 | モーダル（覆い／枠／行） |
| JS `ICONS` | レシピ表（83件） |
| JS `renderIcon(marker)` | レシピ → DOM。16種の骨格 |
| JS `openTypeModal()` / `buildTypeList()` | モーダルの開閉と一覧の組み立て |
| HTML | `<button id="regen-type-btn">`（顔）と `<div id="type-modal">`（中身） |

キーボード: `Esc` で閉じる／閉じたら開いたボタンへフォーカスを戻す／
行は `<button>` なので Tab と Enter で選べる。覆いのクリックでも閉じる。

## 5. 影響範囲

- `draft-gen/compare_template.html`（唯一の実体）
- `samples/*/compare.html`・`mockups/*/compare.html` … `make_compare.py` で書き直す
- `tests/site/smoke_klk079.node.js` … DOM シムに `className/style/classList/hidden` と
  新しい id を足す（**足すだけ**。既存の検証項目は変えない）

## 6. リスク

| リスク | 対策 |
|---|---|
| 隠した `select` が「無い」と見なされ既存テストが落ちる | `hidden` で残す。DOM 上は今までどおり存在する |
| モーダルが開けず型を選べなくなる（退化） | e2e で**実際に開いて選び**、`select.value` が変わることを見る |
| アイコンが潰れて判別できない | 375px で実描画し、アイコンの実寸を測る |
| 83件のレシピに欠けがある | プール全件と突き合わせる静的チェックを置く |
