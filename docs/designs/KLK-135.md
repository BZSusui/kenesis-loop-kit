# [KLK-135] 配布パッケージに別案件の設計書が混入する 設計

## 1. 目的

配布物に入る設計書を、このシステム（モック生成）のものだけにする。
KLK-115 で立てた「配布物に別案件のものを混ぜない」という保証の、漏れていた一箇所をふさぐ。

## 2. 現状

```
make-package.sh
  → cp -R docs "$DEST/"          ← docs/ をディレクトリごと写す
  → rm -rf "$DEST/docs/design-system"   ← KLK-115 で名指しで外した箇所
  ※ docs/designs/ の中身は素通り → DADS-002 / 003 / 005.md が同梱される
```

- `check_klk115 P4/P5` は「**リポジトリ直下**に何が増えても配布物に出ない」ことを保証している。
  しかし**既に同梱しているディレクトリの中身**には、その網がかかっていない
- チケット番号と `docs/designs/` は別案件と共有している（`SESSION-HANDOFF-モック生成.md` §3）。
  向こうが設計書を足すたびに再発する構造

## 3. 設計方針

**組み立て時に `docs/designs/` を allowlist（残すものを列挙）で絞る。**

| 案 | 採否 | 理由 |
|---|---|---|
| allowlist（`KLK-*.md` / `README.md` / `_TEMPLATE.md` だけ残す） | **採用** | 次に別の案件が来ても漏れない。リポジトリ直下の同梱方針と同じ考え方 |
| `DADS-*.md` を名指しで除く | 却下 | 今の1件しか塞げない。次の案件でまた漏れる |
| DADS 側へ `docs/designs/` の外へ移してもらう | 却下 | 相手の作業を止める。こちらで完結しない（理恵さんの判断・2026-09-17） |
| `docs/designs/` ごと配布物から外す | 却下 | このシステムの設計書は受け取った人が読む前提の同梱物 |

リポジトリ本体からは**消さない**。外すのは配布物だけ。

## 4. 実装詳細

`tools/make-package.sh` のデザインシステム除去ブロックの直後に置く。

```bash
if [ -d "$DEST/docs/designs" ]; then
  _dropped=0
  for f in "$DEST"/docs/designs/*; do
    [ -e "$f" ] || continue
    case "$(basename "$f")" in
      KLK-*.md|README.md|_TEMPLATE.md) ;;
      *) rm -rf "$f"; _dropped=$((_dropped + 1)) ;;
    esac
  done
  echo "  絞った: docs/designs/（KLK-* のみ / 別案件の設計書 ${_dropped} 件を外した）"
fi
```

**検査 `tests/site/check_klk135.py`（7項目）**

| ID | 内容 |
|---|---|
| B1 | 組み立てが allowlist で絞っている（形） |
| B2 | 既定ビルドが成功する |
| B3 | ★実ビルドの `docs/designs` に `KLK-*` 以外が無い |
| B4 | ★妨害注入: `docs/designs/ZZZ-999.md`（別案件の設計書に見立てた実ファイル）を**実際に置いてから**組んでも配布物に出ない |
| B5 | リポジトリ本体の設計書は消していない |
| B6 | 空振りでない（`KLK-*` の設計書と README は入っている） |
| B7 | 妨害注入の後始末ができている（リポジトリに残っていない） |

> B4 は「allowlist にこう書いてある」ではなく「置いても出てこない」を見る（`check_klk115 P5` と同じ思想）。
> 注入したファイルが**置けたこと**を先に assert してから判定する。
