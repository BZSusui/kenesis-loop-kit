## 1. 目的

REQ-004（実績カタログのサムネイルから参考画像を2〜3枚選択できる）を「選べるだけ」から「生成に反映される」へ進める。
SCR-001 でカタログサムネイルを選択したとき、**3案のうち案Aを、その参考エントリのレイアウト型・配色カテゴリに寄せた
「カタログ準拠案」**として生成する（B/Cは従来どおり）。方式は**タグ駆動**＝生成時は決定的な表引きのみ
（画像は見ない・KLK-029 の決定性を維持・golden で固定可能）。
※REQ-102（見本サイトURLの反映）は本チケットの対象外（別チケット）。

## 3. 設計方針

**採用する方針: 「指示書に焼く」タグ搭載 ＋ 生成側は表引きのみ ＋ 席替え（swap）規則で案間 distinct を維持**

1. **データ経路 = 指示書に焼く**: SCR-001 の `selectedThumbs()` を拡張し、`references.thumbnails[]` の各要素へ
   `colors`（7カテゴリ配列）・`sectionLayouts`（KLK-030 の1対1 map）・`source`（own|ref）を**追加**する
   （既存 `{id,label,tags}` は不変＝additive）。生成は instruction.json だけを入力とし catalog.json を読まない。
   → 指示書が自己完結し、(a) 同一指示書＝同一出力の決定性、(b) 社外秘の catalog.json に依存しない golden 固定、
   (c) file://・部分再生成（§14）との整合、がすべて成立する。
2. **参考準拠は案Aのみ・対象は thumbnails[0]（先頭の1件）**: ロードマップ合意（案A=カタログ準拠+B/C従来）。
3. **レイアウト反映 = 「席替え（swap）」規則**（§12.1.1/§12.1.2 の型の割り当てだけを差し替える。算術なし・表と等値比較のみ）:
   - 案Aは参考の型をそのまま採る。
   - **既定でその型を持っていた案（BまたはC）があれば、その案は「案Aの既定型」を代わりに使う**（席替え）。
   - これにより「3案で型が重複しない」不変条件（§12.1.1⑥⑦⑧⑨・§12.1.2 の3値distinct）が**常に**保たれる。
4. **配色反映 = 7カテゴリ→hex の明示表（新設 §5.1）＋トグル**: `references.colorSource`（`"reference"`|`"specified"`）を
   新設。`"reference"`（既定）なら案Aの `--m-main` を表引き hex に、colors[1] があれば `--m-accent` も表引き。
   B/C は従来どおり指示書 `colors.main` 起点の濃色/明色（変更なし）。
5. **そっくり再現の構造的禁止**: 生成は画像を一切見ない（タグしか受け取らない）ため、模写は構造的に不可能。
   その旨と「参考は着想のみ」を DRAFT_RULES 新設 §12.2 と生成物（compare.html バッジ）に明記する。

**代替案と却下理由:**
| 案 | 却下理由 |
|---|---|
| 生成時にスキルが catalog.json を id で引く | 生成入力が指示書＋外部ファイルの2系統になり決定性が崩れる。catalog.json は社外秘・Git除外のため golden/テストが組めない。file:// や部分再生成で経路が壊れる |
| 生成時にAIが参考画像を直接見る | 非決定的（同一入力で出力が揺れる）。ロードマップで不採用が確定済み |
| 案Aの型衝突時に distinct 要件を緩める | 既存 checker（klk021/023/029 の distinct 検証）の思想と衝突。「3案が実際に違う紙面」という価値も損なう |
| 衝突時にB/C全体を表からずらす（offset+1等） | 算術に近づき §12.1.2 の「表を読むだけ」原則から外れる。席替えなら等値比較2回で済む |
| SCR-001 で7カテゴリ→hexを解決して指示書に hex を焼く | 生成規約（DRAFT_RULES）と検証（checker）から変換表が見えなくなり、表の正が UI 側に移ってしまう。§12.1.2 と同じく規約側に表を置き checker がミラー検証する既存パターンに合わせる |

### 4.2 DRAFT_RULES 新設 §5.1 — 参考配色の7カテゴリ→hex 変換表（決定的）

`references.colorSource:"reference"` かつ thumbnails[0].colors があるとき、**案Aに限り** §5 の入力を次の表で差し替える:

| 7カテゴリ | hex（案A `--m-main` / colors[1]なら `--m-accent`） | トーンの意図 |
|---|---|---|
| グリーン | `#2E7D6B` | 深緑（ワイヤーSCR-002 案Aの基準緑） |
| ブルー | `#2C5F8A` | 落ち着いた紺青 |
| レッド | `#B3402F` | 朱寄りの赤（彩度を上げすぎない） |
| ゴールド | `#C6A15B` | ワイヤー案Bの金 |
| ピンク | `#E86FA0` | ワイヤー案Cの桃 |
| モノトーン | `#444850` | 墨色（KLK-028 の受理例と同系） |
| マルチカラー | （表引きしない・下のフォールバック） | — |

- `colors[0]` → 案A `--m-main`。`colors[1]`（あれば）→ 案A `--m-accent`。`colors[2]` は反映しない（note扱い）。
- `sub`/`bg` は §5 の autofill 規則（main 起点の color-mix）をそのまま適用。`--m-text` も §5 のまま。
- **マルチカラー（単独指定のみ）のフォールバック**: 表引きせず**指示書の指定色（従来の案A忠実）**へ退避し、
  実効 `colorSource` を `"specified"` として扱う（生成物マーカー・compare 注記にその旨を出す）。
- `colorSource:"specified"` のときは配色は従来どおり（レイアウトだけ参考準拠）。
- 案B/C の配色は**常に従来どおり**（指示書 `colors.main` 起点の濃色/明色・§12）。案間 `--m-main` 相違の不変条件は
  「案Aが表引き hex・B/C が別方向の派生」で引き続き成立させる（万一一致する場合は B/C 側の派生で必ずずらす＝§12 既存要件）。

### 4.3 DRAFT_RULES 新設 §12.2 — 参考準拠レイアウト（席替え規則・§12.1.1/§12.1.2 と直交・additive）

**発動条件**: `references.thumbnails` が1件以上（対象は **thumbnails[0]** のみ）かつ `sectionLayouts` が present。
無ければ本節は不発（従来どおり）。`variants:1` は案A相当なので同様に適用する。

**規則（各セクションKEYごとに独立に適用・等値比較のみ）:**

1. KEY が指示書 `sections` に無い → 何もしない（セクション自体が出ない・§12.1.2(5) と同じ）。
2. 参考の値 v が無い（キー省略）or `"other"` or 語彙外 → 何もしない（そのセクションは従来規則のまま）。
3. **案A := v**。
4. **席替え**: §12.1.1 系（HERO/MENU/GALLERY/ABOUT）は「案B/Cの既定型（§12.1.1 表）」と比較し、
   v と同じ型を持つ案があれば**その案 := 案Aの既定型**。§12.1.2 系（VOICE/FLOW/STAFF）は表引き結果
   (idxA,idxB,idxC) と比較し、v の pool index が idxB（または idxC）と同じなら**その案 := pool[idxA]**。
   どの案とも重複しなければ B/C は従来のまま。
   → いずれの場合も3案の型は **常に3値 distinct**（§12.1.1⑥⑦⑧⑨・§12.1.2 の不変条件を維持）。

**§12.1.1 の既定型（席替えの参照表・§12.1.1 表の転記）:**

| KEY | 案A既定 | 案B既定 | 案C既定 |
|---|---|---|---|
| HERO | `full` | `split` | `band` |
| MENU | `pat-cards` | `pat-list` | `pat-zigzag` |
| GALLERY | `pat-grid` | `pat-wide` | `pat-mosaic` |
| ABOUT | `img-left` | `img-right` | `img-top` |

**スコープ外（本節が触らないもの）:** `data-columns`・`sections` 集合・並び順（`data-section-order`）・
`data-archetype`（3案 distinct のまま）・番地一意性（§2/§14）・§4 文言・アニメ/印刷。
HERO の整列シグネチャは `data-hero` の型に付随して振る（full=中央/split=左/band=下寄せ帯）＝型が distinct なら
シグネチャ相違（§12.1 不変条件4）も維持される。

**生成物マーカー（機械検証フック・案Aルート `.mock` のみに付与）:**
- `data-ref-id="{thumbnails[0].id}"`（例 `cat-0031`）
- `data-ref-colors="reference|specified"`（**実効**の配色ソース。マルチカラーfallback は `specified`）
- 案B/C のルートにはどちらの属性も**付けない**（distinct フック）。
- compare.html: 案Aカードに「参考準拠: {label}（{id}）／参考は着想のみ・そっくり再現はしません」のバッジ
  `.ref-badge` を出す（ref/own を問わず同文言・§13 に additive）。

**規律（そっくり再現禁止の明記）:** 生成は参考の**タグ（型マーカー・配色カテゴリ）だけ**を受け取り、画像・実文言には
一切アクセスしない（構造的に模写不可能）。収集見本（`source:"ref"`）は第三者著作物であり、参考準拠は**着想の反映**に
限る。1:1 の複製・実在サイトの文言流用をしてはならない。

### 4.4 SCR-001（index.html）の変更

1. `cardHtml()`: `data-sl`（sectionLayouts の JSON・HTMLエスケープ）と `data-source` を追加（既存 data-* に並べる）。
2. `loadCatalog()`: sectionLayouts の軽検証（object・値が非空文字列。不正は捨てて undefined 扱い）を colors 7カテゴリ
   filter と同様に行う。

4. **配色トグルUI**: 参考サムネイル欄のフッタに、**1件以上選択時のみ表示**するラジオ2択
   「配色: ◉ 参考の配色を使う ／ ○ 指定色を使う」＋注記「参考準拠に使うのは最初に選択した1件（案Aに反映）」。
   未選択時は非表示・指示書に `colorSource` を出さない（後方互換）。
5. `buildInstruction()`: thumbnails ≥1 のとき `references.colorSource` を付与（既定 `"reference"`）。

### 4.5 bridge.py `validate_instruction` の additive 検証

すべて**キーが present のときだけ**検証（無ければ従来どおり通す）:
