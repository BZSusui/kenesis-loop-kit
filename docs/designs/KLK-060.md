# [KLK-060] リポジトリ整理 設計

## 1. 目的

パッケージ化（チーム配布）に向け、デザインラフ・ジェネレーター本体と無関係な成果物を
リポジトリから除去し、受け取った人が構成を一目で理解できる状態にする。

## 2. 現状

```
kenesis-loop-kit/
├── draft-gen/     ← 本体（SCR-001/SCR-004・ブリッジ）
├── palette/       ← 本体（配色ジェネレーター・REQ-003 の取り込み元）
├── catalog/       ← 本体データ（Git除外・社外秘）
├── mockups/       ← 生成物（Git除外）
├── .claude/ agents/ docs/ tests/ tickets/   ← ループキット本体
├── site/          ← ★KLK-002 の手書きLP（生成ツールの出力ではない）
├── flyers/        ← ★別件のチラシHTML 2点
└── src/           ← ★.gitkeep のみの空ディレクトリ（テンプレート由来・未使用）
```

investigator の調査により、`site/` `flyers/` `src/` への**テストからの依存は0件**、
参照はすべて過去の記録（設計書・CHANGELOG）であることを確認済み。

## 3. 設計方針

**採用する方針: `git rm` による作業ツリーからの除去（履歴は保持）。**

- 履歴を書き換えない（`filter-branch` / `force push` は行わない）。過去のコミットからいつでも復元できる。
- `.gitignore` への追加は行わない（再生成されるものではないため、除外ルールは不要）。
- **過去の設計書は書き換えない**。`docs/designs/KLK-002.md` 等の記述は「当時 `site/` を作った」という
  事実の記録であり、削除後も正しい。歴史を改変しない。
- **CHANGELOG にのみ除去を追記する**。CHANGELOG は「何が起きたか」の時系列記録なので、
  追加（KLK-002）と除去（KLK-060）の両方が載るのが正しい状態。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| `git rm --cached` でローカルに残しつつ追跡だけ外す | 作業ツリーに残るため「これは何か」という迷いは解消しない。理恵さんの判断も「削除して問題ない」 |
| 別リポジトリへ分離する | `site/` は用事を満たし済みで、独立して保守する予定がない。履歴から復元できれば十分 |
| 履歴からも完全に消す（filter-branch） | 過剰。機密情報ではなく、履歴の書き換えは共有リポジトリで害が大きい（CLAUDE.md「ロールバックをNeverとすべき操作」） |

## 4. 実装詳細

```bash
git rm -r site flyers src        # 追跡ファイルごと作業ツリーから除去（src は .gitkeep のみ）
# CHANGELOG.md に KLK-060 の記録を追記
python3 -m unittest discover -s tests   # 非回帰確認（183 tests OK）
```

## 5. 影響範囲

| 対象 | 影響の種類 | 対応方針 |
|---|---|---|
| `site/`（5ファイル） | 削除 | Git履歴から復元可能 |
| `flyers/`（2ファイル） | 削除 | 同上 |
| `src/`（.gitkeep 1件） | 削除 | 同上 |
| `CHANGELOG.md` | 変更 | 除去の記録を追記 |
| `docs/designs/KLK-002/004/005/006.md` | **変更なし** | 過去の事実の記録として保持 |
| `tests/` | **変更なし** | 依存0件（investigator 確認済み） |
| `tests/site/` | **変更なし** | トップレベル `site/` とは無関係な checker 置き場 |

## 6. リスク

| リスク | 深刻度 | 軽減策 |
|---|---|---|
| `tests/site/` を誤って巻き込む | **high** | `git rm -r site` はリポジトリ直下の `site` のみを対象とする。実行後に `ls tests/site` と full suite で確認する |
| 後から `site/` が必要になる | low | Git履歴に残るため `git checkout {commit} -- site` で復元できる。手順を本書 §8 に記載 |
| 過去の設計書の記述が実体と食い違う | low | 意図した状態。設計書は当時の記録であり、CHANGELOG が現在までの経緯を補う |

## 7. マイグレーション戦略

なし（データ移行を伴わない）。

## 8. ロールバック戦略

```bash
git revert {コミットハッシュ}                  # 除去コミットごと取り消す
git checkout {削除前のコミット} -- site flyers src   # 特定ディレクトリだけ復元する場合
```

## 9. 受け入れ条件

- [ ] リポジトリ直下から `site/` `flyers/` `src/` が消えている
- [ ] `tests/site/` は**残っている**（checker 置き場・巻き込み事故の防止）
- [ ] `python3 -m unittest discover -s tests` が全 pass（183 tests・非回帰）
- [ ] CHANGELOG に KLK-060 の除去記録がある
- [ ] `docs/designs/KLK-002.md` 等の過去の設計書が**変更されていない**
- [ ] 履歴が書き換えられていない（`git log` で削除前のコミットが辿れる）
