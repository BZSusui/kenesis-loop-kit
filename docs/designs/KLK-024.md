# [KLK-024] MVキャッチコピー・リード文の事前指定 設計

> architect生成のチケット単位設計書。KLK-024 に対応。implementer/tester/reviewer が参照する。

## 1. 目的

コピー確定済みの案件（リニューアル等）で、AIの提案文言ではなく**指定した文面をそのまま**MV-01 に出せるようにする。
MVは1行/2行で印象が大きく変わるため、**改行をそのまま保持**する。文言事前指定ロードマップ
（MVキャッチ→各セクションリード→生成後編集）の第1段。

## 2. 現状

- 文言は DRAFT_RULES §4（仮文言）で「業種・テイストに合った実文言をAIが生成。ダミー禁止」。指定手段はない。
- 条件付きキーの後方互換パターンは KLK-020 `mvPhoto` に前例（指定時のみキー・無指定はバイト等価・bridgeは存在時のみ検証）。
- SCR-001 の純ロジック（COLUMN_KEYS〜render()直前）は smoke が slice して実挙動を検証する仕組みがある。

## 3. 設計方針

**「指定があれば最優先・無ければ従来どおりAI提案」の上書き規則を §4.1 として追加する。**

- スキーマ: トップレベル **`copy` オブジェクト**（指定時のみ出現）。
  ```jsonc
  "copy": { "mvCatch": "地域とともに、次の10年へ。\n確かな技術を、暮らしのそばに。", "mvLead": "…" }
  ```
  - `mvCatch`＝MVキャッチコピー（最大60字・**改行可**）。`mvLead`＝MVリード文（最大200字・改行可）。
  - **片方だけの指定も可**（あるキーだけ出す）。**両方空なら `copy` キー自体を出さない**＝無指定の出力は従来と
    バイト等価（KLK-020 mvPhoto と同型の後方互換）。version:1 据置。
- 生成規則（§4.1）:
  1. `copy.mvCatch`/`copy.mvLead` があるときは **その文言をそのまま** `.catch`/`.lead` に使う（AIが変えない）。
  2. **改行（\n）→ `<br>`** に変換して行組を保持（1行/2行の印象差を再現）。
  3. **HTMLエスケープ**して埋め込む（`< > &` 等を実体参照へ・textContent相当＝注入対策）。
  4. **複数案でも全案共通**（中身は揃える・§12。配色・レイアウト型は従来どおり案別）。
  5. 無指定のフィールドは従来どおり業種・テイストからAIが提案（§4）。
- 入力整形（SCR-001・純関数 `sanitizeCopy`）: `\r\n→\n` 正規化 → **改行以外の制御文字を除去** → trim → 上限で切詰め。
- bridge 検証（存在時のみ）: `copy` は dict・キーは `mvCatch`/`mvLead` のみ・文字列・非空・上限以内・改行以外の制御文字なし。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| `sectionOptions.MV` に載せる | MVは§2.1の選択セクションではない（常時必須）。sections外キーのoptionsは検証で弾く設計。独立した `copy` が素直で、KLK-025（セクションリード）拡張時も `copy` に寄せられる |
| 改行を無視して1行にする | 要望の核が「1行/2行で印象が変わる」。改行保持は必須 |
| version を 2 に上げる | 条件付きキー追加は後方互換（mvPhoto前例）。据置 |

## 6. リスク

| リスク | 深刻度 | 軽減策 |
|---|---|---|
| 指定文言経由のHTML注入 | medium | 生成規則でHTMLエスケープ必須を明文化（S検証）＋入力/bridge両方で制御文字除去・上限 |
| 無指定時の出力が変わる（後方互換破れ） | medium | copyキーは指定時のみ（mvPhoto同型）。smokeで「無指定→キーなし」を固定 |
| 長文で紙面崩れ | low | 上限（60/200字）で切詰め・bridge でも検証 |
