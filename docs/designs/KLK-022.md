# [KLK-022] セクション選択機能 設計

> architect生成のチケット単位設計書。KLK-022 に対応。implementer/tester/reviewer が参照する。

## 1. 目的

生成する本文セクションを **人間が SCR-001 で選択**でき、選んだ内容（＋ヘッダー位置）が生成ラフに反映されるようにする。
クライアントの簡易ワイヤーを写して実践的なモックにするため。「中身＝人間が選ぶ／見せ方＝AIが振る（次段KLK-023）」の前半。

## 2. 現状

- 生成本文は6固定（NAV/MV/ABOUT/MENU/GALLERY/FOOTER）。DRAFT_RULES §2 は「番地は増減可・増やす場合 `SECTION-01`
  連番」と既に許容。生成指示書は `buildInstruction()`（draft-gen/index.html:708）で組成、`collectInput()`（:855）が集約。
- bridge.py `validate_instruction`（:82）は schema/version/industry/columns/colors.main を検証。`mvPhoto` は「存在時のみ」検証
  （後方互換パターンの前例）。
- 契約テスト smoke_klk006 D7 は**キー存在・値**を検査（`Object.keys`完全一致でない）→ 新キー追加は非破壊。

## 3. 設計方針

**中身（何を載せるか）を離散データとして生成指示書に持たせ、生成側はそれを忠実に反映する。**

- SCR-001 に「本文コンテンツ構成」カードを新設（カラム構成の直後・以降のステップ番号を+1）。
  - **ヘッダー位置**（ラジオ・常設）: `MV上` / `MV下`
  - **本文セクション**（チェック・任意・複数）: 14種（下 §4）
  - **CTAの誘導先**（CTA選択時のみ有効・プリセット＋自由入力）
- 生成指示書スキーマ拡張（**version:1 据置・すべて追加キー・後方互換**）:
  ```jsonc
  "layout":   { "columns": "...", "navPosition": "top" | "below-hero" },
  "sections": ["ABOUT", "GALLERY", "CTA", "ACCESS"],        // 選択された本文のみ・canonical順
  "sectionOptions": { "CTA": { "purpose": "order", "label": "ご注文はこちら" } }
  ```
- **後方互換**: `navPosition` 無 → `top`／`sections` 無 → `["ABOUT","MENU","GALLERY"]`／`sectionOptions` 無 → `{}`。
  既存 instruction.json はそのまま従来どおり生成できる。
- **MV/FOOTERは常時**（`sections` に含めない＝暗黙必須）。NAVは常設で位置のみ。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| `sections` を文字列とオブジェクトの混在配列に | 型が不揃いで検証・生成が複雑。個別設定は別 `sectionOptions` map に外出しする方が素直 |
| version を 2 に上げる | 追加キーは後方互換で済む。KLK-008 も version:1 据置で追加した前例に合わせる |
| セクションを自由文字列で受ける | enum を固定しないと生成・検証・注入対策が緩む（§8 canonical と同じ理由で固定語彙） |

## 4. 実装詳細

**セクション語彙（14種・canonical順・各 `{KEY}-01` 番地）:**

| 生成順 | KEY | 番地 | 見出し例 | 中身（a方式プレースホルダ） |
|---|---|---|---|---|
| 1 | NEWS | `NEWS-01` | お知らせ | 日付つきリスト（仮文言） |
| 2 | ABOUT | `ABOUT-01` | CONCEPT | アタリ＋紹介文 |
| 3 | MENU | `MENU-01` | MENU/SERVICE | カード群（アタリ＋名称＋価格） |
| 4 | PRICE | `PRICE-01` | PRICE | プラン比較表（仮） |
| 5 | GALLERY | `GALLERY-01` | GALLERY | アタリのグリッド |
| 6 | SEARCH | `SEARCH-01` | SEARCH | 条件検索フォーム面（静的・入力は飾り） |
| 7 | FLOW | `FLOW-01` | FLOW | ステップ①→②→③ |
| 8 | VOICE | `VOICE-01` | VOICE | お客様の声カード（アタリ＋コメント） |
| 9 | STAFF | `STAFF-01` | STAFF | 人物カード（アタリ＋肩書） |
| 10 | FAQ | `FAQ-01` | FAQ | Q&A積み上げ（抜粋→誘導） |
| 11 | SNS | `SNS-01` | SNS | 埋め込み**枠**のアタリ面（実埋込なし・外部依存0） |
| 12 | ACCESS | `ACCESS-01` | ACCESS | 地図アタリ面＋住所・営業時間 |
| 13 | CTA | `CTA-01` | （誘導） | 見出し＋ひとこと＋ボタン（目的で文言可変） |
| 14 | CONTACT | `CONTACT-01` | CONTACT | お問い合わせ誘導（ボタン/リンク） |

- **並び順**: v1 は上の canonical 順のうち **選ばれた分だけ**を出力（ドラッグ並べ替えは将来）。KLK-023 で案ごとに順を振る。
- **番地**: `NAV-01`（navPosition=top なら MV上・below-hero なら MV下に置くが番地文字列は不変）・`MV-01`・
  各選択セクション `{KEY}-01`・`FOOTER-01`。すべて `.addr > .pin`（§2）。
- **SNS/地図の制約**: 外部依存ゼロ（NFR-005）のため実埋め込み・実地図は不可。アタリ色面で「ここに入る」を示す。

**CTA 誘導先（`sectionOptions.CTA.purpose` → 既定ラベル）:**

| purpose | 既定ボタン文言 |
|---|---|
| `contact` | お問い合わせはこちら |
| `order` | ご注文はこちら |
| `reserve` | ご予約はこちら |
| `document` | 資料を請求する |
| `signup` | 友だち追加・会員登録 |
| `custom` | `label` の自由入力テキストをそのまま使用 |

- CTA選択かつ purpose 未指定 → 業種から無難な誘導（既定 `お問い合わせはこちら`）。`label` があれば優先。

**主要インターフェース（draft-gen/index.html・純ロジック定数を追加）:**
```js
const SECTION_KEYS = ['NEWS','ABOUT','MENU','PRICE','GALLERY','SEARCH','FLOW','VOICE','STAFF','FAQ','SNS','ACCESS','CTA','CONTACT'];
const NAV_POSITIONS = ['top','below-hero'];
const CTA_PURPOSES = ['contact','order','reserve','document','signup','custom'];
// buildInstruction 追加出力:
//   layout.navPosition = NAV_POSITIONS.includes(input.navPosition) ? input.navPosition : 'top'
//   sections = canonical順に filter(SECTION_KEYS) した重複なし配列（空/無 → ['ABOUT','MENU','GALLERY']）
//   sectionOptions = CTA選択時 { CTA:{purpose,label} }（未選択/無 → {}）
```

**bridge.py `validate_instruction` 追加（すべて「存在時のみ」厳格検証・後方互換）:**
- `layout.navPosition` があるとき `top`/`below-hero` のみ許可
- `sections` があるとき: 配列・各要素が SECTION_KEYS のいずれか・重複なし
- `sectionOptions` があるとき: dict・キーは sections に含まれる KEY・`CTA.purpose` は CTA_PURPOSES・`label` は文字列で
  制御文字/過長を拒否（サニタイズ）

**処理フロー:**
```
SCR-001（人間が選択）→ collectInput（navPosition/sections/ctaPurpose/ctaLabel 収集）
→ buildInstruction（canonical順に整形・後方互換の既定補完）→ instruction.json
→ 生成（DRAFT_RULES §2拡張・SKILL）: NAV位置反映・選択セクションのみ番地つき生成・CTA文言 purpose反映
→ bridge validate_instruction（存在時のみ厳格検証）
```

## 6. リスク

| リスク | 深刻度 | 軽減策 |
|---|---|---|
| 既存契約テスト（D7・check_klk006/008/020）の回帰 | medium | 追加キーのみ・presence検査に非抵触。全体スイートで確認 |
| ステップ採番のズレ・UI崩れ | low | 採番+1は機械的。スモークの純ロジックスライスは定数〜render()直前で不変域 |
| SNS/地図の外部埋め込み誤生成（外部URL混入） | medium | 語彙定義で「アタリ面のみ・実埋込禁止」明記＋テストで外部URL0検査 |
| CTA自由入力の注入 | low | bridge/生成側で textContent 相当・制御文字/過長拒否 |
