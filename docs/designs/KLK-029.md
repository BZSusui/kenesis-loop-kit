## 3. 設計方針

### 3.1 決定的選択規則 — 「2次元オフセット表引き」（論点1・採用案）

算術（文字コード合計 mod N 等）は Claude が寸分違わず再現できないため**不可**。代わりに**すべて書き下した明示表**で決める。

**構成要素:**

1. **型プール（各セクション5型・順序固定・index 0〜4）** — 各型はマーカー class ＋ 実際に異なる grid/flex 宣言を伴う（§4.3）。
2. **オフセット表（2次元 lookup・6×2＝12セルを全書き下し）** — キーは**指示書中の安定値2つ**
   `data-columns`（§8・canonical 6値・全案同一）× `navPosition`（§2.1・top/below-hero・全案同一）。値は offset 0〜4。
   両キーとも全案で不変（§12・§2.1）なので、**同一指示書＝同一 offset**（決定性）。両キーとも**閉じた小さな enum** なので
   表に全パターンを書ける（Claude は計算せず1セルを読むだけ）。
3. **割り当て表（offset → 案A/B/C の pool index・5行を全書き下し）** — offset 行を読むと (a,b,c) の index が3つ得られる。
   各行は連続3窓（wrap 込み）で必ず **3値 distinct**（プールが3未満に縮まない限り）。

**なぜ2次元（columns × nav）か（1次元 columns だけにしない理由）:**
1col しか使わないユーザーは 1次元だと offset が常に同じ→先頭3型しか出ない。2次元にすると 1col でも nav 切替で 2つの offset に
届き（下表 offset 0 と 3）、**1col のまま5型すべてに到達**できる（到達可能性＝論点1制約③を常用ケースで満たす）。算術ゼロ・
表引きのみを維持したまま到達性を上げられる。

### 3.2 プール全体到達可能性の検証の落とし所（論点2・採用案 = (a)＋(b) ハイブリッド）

- **(a) 2本の golden で2つの offset を実測固定** — 主 golden `klk029`（1col×top→offset 0→index (0,1,2)）＋
  副 golden `klk029b`（1col×below-hero→offset 3→index (3,4,0)）。両者の union で **5 index すべてが実 HTML に出現**することを
  チェッカーが検証（N9）→ プール全体到達を実証。両 golden とも 1col なので HTML が単純（実装リスク最小）。
- **(b) DRAFT_RULES 文言（存在）検証** — オフセット表・割り当て表・各プール5マーカー（計15）・「未選択は no-op」記述の
  存在をチェック（N11）→ 表そのものと型定義が規約に在ることを構造的に担保。STEP B の「データ追加だけ」性を守る。

**採用理由:** 生成は Claude の手書きなので「規則表が正しく存在し（b）」「手書きが表どおり distinct＋実CSS を出せる（golden で実測）」の
2点を押さえれば十分。offset ごとに5本 golden を並べるより、2 offset の実測＋表の存在検証でコスト/確実性のバランスが最良。
副 golden の below-hero は KLK-022 のヘッダー下配置も同時に踏むため一石二鳥。

### 3.3 代替案と却下理由

| 案 | 却下理由 |
|---|---|
| `project名の文字コード合計 mod N` でオフセット | 算術で再現性が弱く Claude が毎回同値を保証できない。ticket・investigator が明確に不可と指摘 |
| 1次元（columns だけ）オフセット表 | 1col 常用ユーザーが offset 固定→先頭3型しか出ず到達性が損なわれる（増やす意味が薄い） |
| §12.1.1 を丸ごとプール方式へ書き替え | HERO/MENU/GALLERY/ABOUT の既存 a/b/c 軸・klk021/023 goldens を回帰させるリスク。additive の新設 §12.1.2 が安全 |
| offset を案(a/b/c)ごとに別々の値にする | 案間で offset を変えると同一 index が別案に来て distinct が崩れうる。offset は**指示書単位で1つ**（案共通）にし、割り当て表で a/b/c に3窓を割る方が単純で決定的 |
| VOICE/FLOW/STAFF を compare.html の再生成 `<select>` に追加 | 既存6番地 UI 制約の変更は本チケット非対象（investigator 指摘）。STEP B へ分離。手動 `/draft-regenerate` は ADDR_RE 既対応 |

## 4. 実装詳細

### 4.1 型プール定義（index 固定・マーカー class）

| section | 容器 class | index0 | index1 | index2 | index3 | index4 |
|---|---|---|---|---|---|---|
| VOICE | `.m-voice` | `voice-cards` | `voice-quote-stack` | `voice-feature` | `voice-two-col` | `voice-slider` |
| FLOW | `.m-flow` | `flow-row` | `flow-timeline` | `flow-number-card` | `flow-arrow-band` | `flow-vertical-split` |
| STAFF | `.m-staff` | `staff-grid` | `staff-hscroll` | `staff-feature` | `staff-list` | `staff-two-col` |

- 出力 DOM は `<div class="m-voice voice-cards">…`（容器＝`m-{sec}` ＋ プールマーカー 1個）。KLK-023 の
  `class="m-menu pat-cards"` と同一パターン（`modifier()` / `css_layout_rule()` がそのまま効く）。
- index0 は「最も定番／従来寄り」を置く（offset 0 で見慣れた姿が出る）。

### 4.2 選択規則の2表（DRAFT_RULES §12.1.2 に全書き下し）

**オフセット表（`data-columns` × `navPosition` → offset・12セル）:**

| data-columns ＼ navPosition | `top` | `below-hero` |
|---|---|---|
| `1col` | 0 | 3 |
| `2col-full-left` | 1 | 4 |
| `2col-full-right` | 2 | 0 |
| `2col-body-left` | 3 | 1 |
| `2col-body-right` | 4 | 2 |
| `3col` | 0 | 3 |

**割り当て表（offset → 案A/B/C の pool index・5行）:**

| offset | 案A（`a`） | 案B（`b`） | 案C（`c`） |
|---|---|---|---|
| 0 | 0 | 1 | 2 |
| 1 | 1 | 2 | 3 |
| 2 | 2 | 3 | 4 |
| 3 | 3 | 4 | 0 |
| 4 | 4 | 0 | 1 |

- 全12セルの offset の集合 = {0,1,2,3,4}、割り当て表の全 index の集合 = {0,1,2,3,4} → **プール全体が到達可能**（システムとして）。
- 各割り当て行は 3値 distinct（連続3窓・wrap 込み）→ **3案で型が重複しない**（制約②）。
- キー2値は全案不変 → **同一指示書＝同一割り当て**（制約①・決定性）。

**Claude の生成手順（§12.1.2・SKILL 手順3 に転記）:**
1. ルートの `data-columns`（正規化後）と `navPosition` を確定（既に §8/§2.1 で確定済み）。
2. オフセット表で1セルを読み offset を得る（**表を読むだけ・計算しない**）。
3. 割り当て表の offset 行から (idxA, idxB, idxC) を読む。
4. VOICE/FLOW/STAFF が sections にあるとき、各案の容器へ **プール[該当 index] のマーカー**を付け、対応 CSS ブロックを `<head>` に含める。
   - 例: 1col×top（offset 0）→ 案A VOICE=`voice-cards`、案B=`voice-quote-stack`、案C=`voice-feature`（FLOW/STAFF も同 index で対応マーカー）。
5. `variants:1`（単案）は archetype 既定 `stack-centered`＝**案A相当** → 各セクションは **idxA のマーカー**を使う（単一・distinct 検証は働かない）。

### 4.4 後方互換・不変（論点3）

- **未選択 no-op**: VOICE/FLOW/STAFF が sections に無ければセクション自体を出さない＝プールマーカー・CSS とも不発（additive）。
- **variants:1 不変**: 単案は idxA のマーカーで1型のみ（§4.2手順5）。既存単案 goldens（klk007/008）は当該セクションを含まず不変。

- **不変条件**: data-columns 同一・sections 集合同一・番地一意性（§2/§14・VOICE-01/FLOW-01/STAFF-01 各1回）を保持。
  セクションの**有無**は案間で同じ、変わるのは**内部マーカーだけ**。
