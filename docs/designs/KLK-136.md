# [KLK-136] 既定以外のポートで起動すると画面がブリッジを見つけられない 設計

## 1. 目的

どのポートでブリッジを起動しても、画面がそのブリッジを見つけて動くようにする。
同梱の案内（`はじめにお読みください.txt`）が `KLK_BRIDGE_PORT=8766` での起動を勧めているのに、
その手順では実績カタログもワンクリック生成も動かない状態を解消する。

## 2. 現状

```js
// draft-gen/index.html
const BRIDGE_HOST   = '127.0.0.1:8765';         // 決め打ち
const BRIDGE_ORIGIN = 'http://' + BRIDGE_HOST;  // /health・/upload・/generate・/status…
```

**同じ画面の中で「相対URL」と「絶対URL(8765)」が混在**していた。

```
起動（KLK_BRIDGE_PORT=8766）
  → ブラウザは http://127.0.0.1:8766/ を開く（画面はブリッジから配信されている）
  → setupThumbPicker() → probeHealth() は http://127.0.0.1:8765/health を叩く ← ここで失敗
  → catalogAlive = false → renderThumbs([]) → カタログを読みに行かない
  ※ /catalog.json は相対URLなので、叩けば正しく返る（実測 220件）。**判定だけが落ちていた**
```

比較画面も同様: `compare_template.html` の `var BASE = 'http://127.0.0.1:8765'`。
ただし compare.html は **file:// で開かれる**ため、画面の場所からは接続先を決められない。

**テストへの影響**: e2e は空きポートでブリッジを立てるため、画面はカタログを読まない。
`e2e_klk127` / `e2e_klk128` がこれまで緑だったのは、**別途 8765 でブリッジが動いていたから**
と考えられる（テストが外の常駐プロセスに依存していた）。

## 3. 設計方針

**配信元を接続先とする。** 画面が http(s) で開かれているなら、その配信元こそがブリッジである。

| 画面 | 接続先の決め方 | 理由 |
|---|---|---|
| index.html（http 配信） | `location.origin` | 配信元＝ブリッジ。ポートを知る必要がそもそも無い |
| index.html（file://） | `http://127.0.0.1:8765`（既定値） | 配信元が無いので既定を案内するしかない（KLK-026 の開き直しリンク） |
| compare.html（file://） | **書き出し時に埋め込む**（`KLK_BRIDGE_PORT` 由来） | file:// では配信元が無い。ポートを知っているのは書き出す側だけ |
| compare.html（http で開いた場合） | `location.origin` | 同上の原則 |

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| 画面に「ポート入力欄」を足す | 非エンジニアに設定を求めることになる。配信元から分かるものを人に聞かない |
| ブリッジが index.html を配信するときにポートを差し込む | 配信のたびに HTML を書き換える必要があり、静的ファイルでなくなる。`location.origin` で足りる |
| 既定ポートを固定し、変更手段を廃止する | 案内済みの回避策（ポート衝突時）を奪う。衝突は実際に起きる |

**環境変数の引き継ぎ**: ブリッジは `KLK_BRIDGE_PORT` を読んで待受ポートを決める。
この環境変数は ブリッジ → `claude` → スキル → `make_compare.py` へそのまま引き継がれるため、
書き出し時に同じ値が読める。ブリッジはポートが埋まっていると起動を止める（自動で別ポートへ
移らない）ので、環境変数の値と実際の待受ポートは食い違わない。

## 4. 実装詳細

**`draft-gen/index.html`**
```js
const BRIDGE_HOST = '127.0.0.1:8765';
const BRIDGE_ORIGIN = (location.protocol === 'http:' || location.protocol === 'https:')
  ? location.origin
  : 'http://' + BRIDGE_HOST;
```
決め打ちが残っていた `fetch('http://' + BRIDGE_HOST + '/read-colors')` も `BRIDGE_ORIGIN` へ統一。

**`draft-gen/compare_template.html`**
```js
var BASE = (location.protocol === 'http:' || location.protocol === 'https:')
  ? location.origin : '{{BRIDGE_ORIGIN}}';
```

**`draft-gen/make_compare.py`**
```python
DEFAULT_BRIDGE_PORT = 8765   # bridge.py の DEFAULT_PORT と同じ値（兄弟モジュールは import しない流儀）

def bridge_origin(env=None):
    """compare.html が叩くブリッジの接続先を決める（副作用なし）。
    数字として読めない値・範囲外は既定へ倒す（壊れた値で壊れた HTML を書かない）。"""
```
`build_context` の辞書へ `"BRIDGE_ORIGIN": bridge_origin()` を追加する
（`render` は埋め残しがあれば例外を投げるので、追加漏れは自動で落ちる）。

## 5. 影響範囲

| 対象 | 影響の種類 | 対応方針 |
|---|---|---|
| `draft-gen/index.html` | 変更 | 定数の決め方と1箇所の呼び出し |
| `draft-gen/compare_template.html` | 変更 | `BASE` の決め方 |
| `draft-gen/make_compare.py` | 変更 | `bridge_origin()` 追加・ctx へ1キー追加 |
| 既存の生成物（過去の compare.html） | 影響なし | 作り直さない限り従来どおり 8765 を見る（既定で動いていた環境はそのまま） |
| `check_klk026`（file:// 案内） | 影響なし | file:// では従来と同じ値になる（実行して確認済み） |
| `check_klk011`（Origin 検証・403） | 影響なし | ブリッジ側は `127.0.0.1:{実ポート}` と `localhost:{実ポート}` を許可しており、配信元はこれに一致 |
| `e2e_klk127` / `e2e_klk128` | **回復** | 外部の常駐ブリッジに依存せず緑になる |

## 6. リスク

| リスク | 深刻度 | 軽減策 |
|---|---|---|
| 画面がブリッジ以外の http サーバから配信された場合、そこへ POST する | low | ブリッジは Origin を検証して非許可なら 403。配信元＝ブリッジ以外の使い方は想定外（NFR-005 外部依存ゼロ） |
| `KLK_BRIDGE_PORT` が claude へ引き継がれない環境があると、compare.html が既定を埋める | medium | その場合も**既定ポートで動いている環境では正しい**。http で開いた場合は `location.origin` が優先される |
| 既定ポートの数字が二重管理 | medium | C6 が `bridge.py` と機械照合する |
