## 1. 目的

「デザインラフ・ジェネレーター」（SPEC v1.2）の中核＝**生成エンジン**を実装する。KLK-006 で確定した
**生成指示書JSON**（`schema:"design-draft-instruction"`/version:1・`docs/designs/KLK-006.md` §4.4）を入力に、
SCR-002 の `.mock` 部を見た目・構造の正とする**デザインラフHTML（1案）**を生成し、`mockups/{日付}_{案件名}/`
へ保存する。SPEC §9 の技術制約に従い生成エンジンは **Claude Code（スラッシュコマンド化）** とし、AI APIの個別契約・
サーバー・DBは使わない。対象要件は REQ-005 / 006 / 007 / 010（保存部分） / 011 と NFR-003 / 004 / 005 / 006。

本設計のスコープは **1案生成 + `mockups/` 保存 + `.gitignore` 整備まで**。複数案（REQ-008）・SCR-002 比較閲覧UI・
印刷PDF化UI・部分再生成（REQ-103）・フリー実写真b方式（REQ-104）・見本URL反映（REQ-102）・保存後フォルダ自動
オープン（REQ-010残り）は**別チケット**（§スコープ外に明記）。

## 3. 設計方針

**採用する方針:**
- **実装形式＝スキル**（U1）。`.claude/skills/draft-generate/SKILL.md`（手順の統括）＋
  `templates/DRAFT_RULES.md`（`WIREFRAME_RULES.md` 相当の生成規約＝SCR-002 `.mock` から抽出）とする。理由：生成規約が
  大きく、「入力契約から単一HTMLを生成」が `wireframe-gen` と同型。コマンド（単一 `.md`・素プロンプト）では規約が
  肥大化して見通しが悪い。**採用形式は CLAUDE.md「スラッシュコマンド一覧」への登録が必要**（実装者がPhase 5で追記・§4.6）。
- **起動語＝ `/draft-generate`**（U2）。実装ディレクトリ `draft-gen/`（SCR-001 の設定画面）と紛らわしい `/draft-gen`
  は避ける。skill の YAML `name: draft-generate`。引数 `$ARGUMENTS`＝生成指示書JSON（クリップボードから貼り付け or
  会話に添付されたもの）。
- **生成は Claude 駆動（非決定的）**（F2）。SKILL.md が「入力＝生成指示書JSON → 生成前に必ず DRAFT_RULES.md を読む →
  Claude が単一HTMLを書く → `mockups/{日付}_{案件名}/` へ Write」の手順を統括する。`wireframe-gen` 構造をほぼ踏襲。
- **1案生成に限定**（U7）。本チケットは1回の生成で**単一のデザインラフHTMLを1つ**出す。生成指示書の `output.variants`
  が `3` でも本スキルは1案のみ生成し、「複数案は別チケット（REQ-008）」と報告する。案切替UI・比較（SCR-002）は作らない。
- **配色マッピングを DRAFT_RULES.md で確定**（U5・§4.3）。指示書 `colors.main/sub/accent/bg(+autofill)` → SCR-002 mock
  テーマ変数（`--m-main/--m-accent/--m-bg/--m-nav/--m-text`）の対応と、`autofill`（null役割）の補完ルールを規約に固定。
- **スクロール出現アニメ＝インラインJS `IntersectionObserver`**（U6・§4.4）。外部依存ゼロを維持し、`IntersectionObserver`
  非対応時は全要素表示（graceful）、`prefers-reduced-motion` と `@media print` では無効化する。
- **保存主体はスキル指示による Claude Code の Write**（U4・§4.5）。日付書式 `YYYY-MM-DD`（例 `2026-07-07`。SCR-002
  「生成日 2026-07-07」準拠）、フォルダ `mockups/{日付}_{案件名}/`、ファイル `index.html`（デザインラフ本体）＋
  `instruction.json`（入力の生成指示書を併置し再実行可能に・SPEC §7）。案件名はパス安全化（空白→`_`、`/ \ : * ? " < > |`
  除去）。
- **テストは「ゴールデンサンプルの構造検証 + `git check-ignore`」に寄せる**（U3・§4.7・§9）。生成物は非決定的で
  mockups/ はGit除外のため、実生成物をCI検証できない。そこで **コミット可能なゴールデンサンプル**（プレースホルダ案件名
  のみ・機密なし・DRAFT_RULES に完全準拠した代表出力）を `tests/fixtures/klk007/` に置き、`check_klk007.py`（S群）で
  構造検証する。NFR-004 は `git check-ignore`（D群）で検証。実生成の品質は **M群（人間の実機確認）** に置く。investigator
  選択肢のうち **(a)ゴールデンサンプル+構造検証 + (b)git check-ignore + (c)規約Doc静的検査** を採用し、**(d)汎用リンタは
  不採用**（本チケットは1案・過剰。将来 REQ-103/複数案で任意HTML検査が要るときに別途）。
- **`mockups/` を三 `.gitignore` へ同期追記**（F5・§4.5）。アクティブ `.gitignore`・`.gitignore.public`・
  `.gitignore.private` すべてに `mockups/` 行を追加し、乖離を増やさない。

**代替案と却下理由:**
| 案 | 却下理由 |
|---|---|
| 実装形式をコマンド（`.claude/commands/draft-generate.md`）にする | 生成規約（配色マッピング・アタリ方式・番地ラベル・印刷CSS・アニメ・保存規約）が大きく、単一.mdのプロンプトでは肥大化。`wireframe-gen` の前例（SKILL.md＋規約Doc分離）が同型で保守しやすい（U1/F1） |
| 決定論的テンプレート展開エンジン（プレースホルダ差し込み）を作る | SPEC §9 は生成エンジン＝Claude Code と明記。`wireframe-gen` にも展開エンジンは無く、業種に合った仮文言（REQ-007）はテンプレ置換では出せない。過剰設計（F2） |
| 起動語を `/draft-gen` にする | 実装ディレクトリ `draft-gen/`（SCR-001）と衝突・混同。`/draft-generate` で明確に分離（U2） |
| 実生成物そのものをCIで構造検証する | 生成は非決定的、保存先 mockups/ はGit除外でリポジトリに残らない。CIで安定検証できない（F4課題）。ゴールデンサンプル＋M群手動に切り分ける（U3） |
| ゴールデンサンプルを mockups/ 配下に置く | mockups/ はGit除外（REQ-011/NFR-004）でコミットできず、CIから消える。`tests/fixtures/klk007/` に置く（U3/F4） |
| スクロールアニメをCSSのみ（load時アニメ）で実装 | CSS単独ではスクロール到達での出現（REQ-005「スクロール出現」）を再現できない。`IntersectionObserver` が必要。外部依存ゼロは維持（U6） |
| `mockups/` をアクティブ `.gitignore` のみに追記 | `.gitignore.public`/`.gitignore.private` と乖離が拡大（F5）。可視性切替時に除外が外れREQ-011違反の恐れ。三者同期が正しい |
| autofill（null役割）を空のまま生成 | 配色は必須充足＝メインのみ（KLK-006 U5）。sub/accent/bg が null でもラフは全色必要。補完ルールを規約で固定し欠色を防ぐ（U5） |
| 複数案（最大3案）を本チケットで生成 | REQ-008 は別チケット（SCR-002 比較UI含む）。スコープ逸脱・過剰設計。本チケットは1案（U7） |

### 4.1 スキルの起動と手順（U1/U2・SKILL.md）

- YAML: `name: draft-generate` / `description:`（「生成指示書JSONからデザインラフHTML（1案）を生成し
  mockups/{日付}_{案件名}/ に保存する。ユーザーが『デザインラフを生成』『このJSONからラフを作って』等と言ったとき使う」）。
- 起動: `/draft-generate`。引数 `$ARGUMENTS` またはユーザーが会話へ貼り付けた**生成指示書JSON**を入力にする。
- 手順（SKILL.md 本文）:
  1. **受付チェック**: 入力JSONが `schema:"design-draft-instruction"` / `version:1` であること・必須（`industry.resolved`・
     `layout.columns`・`colors.main`）が埋まっていることを確認。欠けていれば生成せず「SCR-001（`draft-gen/index.html`）で
     生成指示書を作り直してください」と案内。version が 1 以外なら未対応として停止（前方互換の版分岐は将来）。
  2. **規約読込**: 生成前に必ず `templates/DRAFT_RULES.md` を全読する（`wireframe-gen` と同じ規律）。
  3. **生成**: DRAFT_RULES に完全準拠した単一HTMLを Claude が書く（配色マッピング §4.3・アタリ §4.2・番地ラベル・印刷CSS・
     出現アニメ §4.4）。`output.variants` が 3 でも**1案のみ**生成し、複数案は別チケットである旨を報告（U7）。
  4. **保存**: `mockups/{日付}_{案件名}/index.html` と `mockups/{日付}_{案件名}/instruction.json`（入力の写し）を Write（§4.5）。
  5. **報告**: 保存先パス・番地ラベル一覧・`(要検討: …)` 箇所・除外した外部参照（あれば）を非エンジニア向けに提示。

### 4.2 生成HTMLの技術規約（DRAFT_RULES.md・SCR-002 `.mock` 部が正）

`DRAFT_RULES.md` に以下を必須節として明記する（REQ-005/006/007/009・NFR-003/005）。構造の正は SCR-002-compare.html:116-232, 296-372。

- **単一ファイル・外部依存ゼロ（NFR-005）**: `<style>` にインラインCSS・アニメJSは末尾インライン `<script>`。CDN /
  `<link>` / `<script src>` / Webフォント / 外部画像 URL 禁止。
- **番地ラベル（REQ-005・REQ-103 の基盤）**: 各セクションを `.sec` で囲み `.addr > .pin`＝`NAV-01`/`HERO-01`/`ABOUT-01`/
  `MENU-01`/`GALLERY-01`/`FOOTER-01` を付与（画面のみ表示）。SCR-002 の `.regen` 🔄 は**部分再生成が別チケット（REQ-103）
  のため本チケットでは省略可**（ラベルのみで足りる）。
- **アタリ画像 a方式（REQ-006）**: `.atari`＝色面（`linear-gradient` + `color-mix(in srgb, var(--m-main)…, var(--m-accent)…)`）＋
  `.desc`（内容説明）＋`.kw`（`検索: <b>keyword</b>`）。HERO は `.atari-tag`。**検索キーワードが定まらない箇所は `.desc`
  のみ**とし kw を省く（REQ-006 フォールバック）。`atari` が `free-photo`（b方式）でも本チケットは a方式で生成し「b方式は
  別チケット（REQ-104）」と注記（スコープ外）。
- **仮文言（REQ-007）**: 業種（`industry.resolved`）・テイスト（`taste`）に合った実キャッチ/見出し/本文を書く。
  「サンプルテキスト」「テキストテキスト」「aaa」「lorem ipsum」等のダミー禁止。決めきれない箇所は
  `<span class="todo">(要検討: …)</span>`（SCR-002:168, 330）。
- **@media print（REQ-009/NFR-003）**: `.addr, .atari-tag, .anim-note`（および補助注記）を `display:none !important`。
  デザイン本体（nav/HERO/セクション）は印刷に残す。出現アニメ対象は印刷時に全表示（§4.4）。
- **レスポンシブ（NFR-002）**: `@media (max-width:640px)` で多カラム→縦積み・グローバルナビ→ハンバーガー相当・
  ギャラリーの列減少（SCR-002:213-223 準拠）。
- **ダミー禁止事項**: 実在の個人情報・顧客名・シークレットを使わない（プレースホルダのみ・NFR-004/REQ-011）。

### 4.3 配色マッピングと autofill 補完（U5・DRAFT_RULES.md §配色）

指示書 `colors`（main必須・sub/accent/bg は任意で null 可、`autofill` に null 役割名を列挙）を SCR-002 mock テーマ変数へ
写す。`.mock`（または生成ルート要素）の `style` / `:root` に CSS変数を定義し、全体を `var(--m-*)` で参照する。

| 指示書 colors | mock テーマ変数 | 役割 | autofill（null）時の補完ルール |
|---|---|---|---|
| `main`（必須） | `--m-main` | 主色（見出し・HERO地・アクセント面） | （必須のため補完なし） |
| `sub` | `--m-nav` | ナビ／フッター地（濃色） | null → `color-mix(in srgb, var(--m-main) 62%, #000)`（主色を暗くした濃色。SCR-002 の #2E7D6B→#24463E と同傾向） |
| `accent` | `--m-accent` | CTA・強調・アタリ差し色 | null → 主色から調和する暖色アクセントを Claude が導出（ゴールデンサンプルでは `color-mix(in srgb, var(--m-main) 45%, #E8A33D)`） |
| `bg` | `--m-bg` | 背景 | null → `color-mix(in srgb, var(--m-main) 6%, #fff)`（主色の極淡ティント＝オフホワイト） |
| （指示書に無し） | `--m-text` | 本文文字色 | `--m-bg` の明度で自動決定（明背景→`#333` / 暗背景→`#fff`）。純黒 `#000` は使わない |

- `colors.mode`（`explicit`/`main-only`/`pasted`）に関わらずマッピングは同一。`main-only` は sub/accent/bg が全て
  `autofill` に入るので3補完ルールが全適用される。
- CSS変数化により配色4色が確実に反映され、テストで検証可能（S2）。

### 4.4 スクロール出現アニメ（U6・DRAFT_RULES.md §アニメ）

外部依存ゼロのインライン実装。対象セクションに `.reveal` を付け、`IntersectionObserver` で可視化時に `.in` を付与する。

```html
<style>
  .reveal{opacity:0;transform:translateY(16px);transition:opacity .6s ease,transform .6s ease;}
  .reveal.in{opacity:1;transform:none;}
  @media (prefers-reduced-motion:reduce){.reveal{opacity:1;transform:none;transition:none;}}
  @media print{.reveal{opacity:1 !important;transform:none !important;}}
</style>
<script>
  (function(){
    var els=document.querySelectorAll('.reveal');
    if(!('IntersectionObserver' in window)){els.forEach(function(e){e.classList.add('in');});return;}
    var io=new IntersectionObserver(function(en){en.forEach(function(x){
      if(x.isIntersecting){x.target.classList.add('in');io.unobserve(x.target);}});},{threshold:.12});
    els.forEach(function(e){io.observe(e);});
  })();
</script>
```
- `IntersectionObserver` 非対応 → 全要素即表示（コンテンツが消えない）。`prefers-reduced-motion` / 印刷 → アニメ無効・全表示。
- 外部ライブラリ・CDN不使用（NFR-005）。SCR-002 の `.anim-note` はワイヤーの注記なので生成HTMLでは実アニメに置き換える。

## 8. ロールバック戦略

`git revert` ベース（CLAUDE.md「通常のロールバック」準拠）。変更は新規追加ファイルと `.gitignore`/CLAUDE.md への追記に
閉じ、既存成果物へ影響しないため revert は追加分の除去のみで完結する。Phase 単位でコミットを分ける（§4）ため部分 revert 可。

```bash
git log --oneline
git revert {コミットハッシュ}
# 例: [KLK-007][REVERT] デザインラフ生成エンジンの取り消し
```
- ロールバック時はチケットを done/→active/ へ戻し status を `implementation_done` にしてログへ理由を追記。
- 注意: revert では追跡済みファイルのみ戻る。`mockups/` 配下の生成物は元々 Git 非管理のため revert 対象外（ローカル手動削除）。
