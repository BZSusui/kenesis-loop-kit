# [KLK-065] 提案フェーズが承認待ちで停止する不具合 設計

## 1. 目的

KLK-064 の提案フェーズが `sips` のコマンド承認待ちで停止し、提案が1件も作られない不具合を解消する。
あわせて「非対話実行に対話ゲートを置かない」規律を、スキルと UI の両方に埋め込む。

## 2. 現状

```
claude -p "/catalog-import {spec}" --permission-mode acceptEdits
                                     └─ **ファイル編集のみ**自動承認。Bash は承認を要求する
   ↓ webp→png の sips が承認待ち
   ↓ 非対話なので誰も答えられない
提案JSON が作られないまま終了（subtype:success / num_turns:9 / 56秒）
   ↓
bridge: proposal.json 無し → ジョブ失敗
UI: 提案0件のとき **何も描画せず無言** → 利用者には「何も起きていない」ように見える
```

**KLK-064 と同型の失敗。** 非対話経路に対話ゲート（あちらは人間への質問、こちらはコマンド承認）を
置いたことが原因。どちらも「止まる」より悪く、**成功したように見えて何もしていない**状態を作る。

## 3. 設計方針

**採用する方針: 3層で塞ぐ。**

| 層 | 対策 | 効果 |
|---|---|---|
| ① 権限 | `--allowedTools "Bash(sips *)"` を付ける | 承認待ちが起きない（根本対処） |
| ② スキル | 提案モードでは**質問せず切り詰めて継続**し、**必ず提案JSONを書く** | 別のゲートが現れても停止しない |
| ③ UI | 提案0件のとき**理由と次の手を表示**する | 万一失敗しても利用者に伝わる |

①だけでは「次に別のコマンドが必要になったとき」また同じ事故が起きる。
②で「止まらない」を、③で「気づける」を担保する多層防御とする。

### 3.1 権限（最小権限を維持する）

- 許可するのは **`Bash(sips *)` の1つだけ**。単一バイナリに限定する。
- 既存の `allow_open` と同じ枠組みに載せ、必要なら `Bash(open *)` を足せる形にする。
- **全権限スキップ／全許可モードのフラグは決して使わない**（既存3コマンド構築関数と同一方針）。

### 3.2 スキル（提案モードの規律）

`catalog-import/SKILL.md` の手順3' に明記する:
- **人間に質問してはならない**（質問した時点で止まる）。
- 処理できない画像は**その画像だけ外して残りを出力**する。理由は報告文へ。
- **1件も処理できなくても `items: []` の提案JSONを必ず書き出す**
  （提案JSONが無いとブリッジは「ジョブ失敗」としか言えず、原因が利用者に伝わらない）。

### 3.3 UI（無言を禁じる）

`pollStatus` の done 分岐で、提案0件のときに明示メッセージを出し、件数表示も更新する。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| `--dangerously-skip-permissions` 等の全許可フラグを使う | 既存3つのコマンド構築関数がいずれも「決して含めない」と明記している方針に反する。取り込みのためだけに全許可は不要 |
| webp 対応をやめる（jpg/png のみにする） | KLK-033 で webp 受理を決めており、web 拾いサムネの主要形式。機能後退になる |
| Python 側で先に webp を変換してから claude を呼ぶ | 変換責務が bridge と skill に分散する。`sips` は macOS 専用でもあり、将来 Windows 対応時に Python 側へ持つと分岐が増える（→ パッケージ化チケットで別途検討する） |
| ①だけ実施して②③を省く | 次に別のコマンドが必要になったとき同じ事故が再発し、また無言で失敗する |

## 4. 実装詳細

### 4.1 `draft-gen/bridge.py`

```python
    tools = ["Bash(sips *)"]          # 取り込みに必要な Bash は sips(webp→png)のみ
    if allow_open:
        tools.append("Bash(open *)")
    cmd += ["--allowedTools", ",".join(tools)]
```

### 4.2 `catalog-import/SKILL.md`

手順3' へ「提案モードでは人間に質問してはならない（最重要）」の節を追加（§3.2 のとおり）。

### 4.3 `draft-gen/catalog.html`

`pollStatus` の done 分岐に、提案0件時のメッセージと `refreshPendingCount()` を追加。

### 4.4 テスト `tests/site/check_klk065.py`

| ID | 検証内容 |
|---|---|
| Q1 | `build_catalog_import_command()` が `--allowedTools` に `Bash(sips *)` を含む（**純関数を実行**） |
| Q2 | `allow_open=True` で `Bash(open *)` も含み、両方が1つの `--allowedTools` にまとまる（純関数を実行） |
| Q3 | 危険フラグ（`--dangerously-skip-permissions` 等）を**含まない**（純関数を実行・既存方針の維持） |
| Q4 | 他の2つのコマンド構築関数（生成・再生成）に `sips` を足していない（influence の局所性） |
| Q5 | SKILL.md の提案モードに「質問してはならない」が明記されている |
| Q6 | SKILL.md に「1件も処理できなくても `items: []` を必ず書く」が明記されている |
| Q7 | SKILL.md に「処理できない画像は外して残りを出力する」が明記されている |
| Q8 | SCR-004 が提案0件のときに明示メッセージを出す（無言でない） |

## 6. リスク

| リスク | 深刻度 | 軽減策 |
|---|---|---|
| `Bash(sips *)` により sips で任意パスへ書き込める | medium | 単一バイナリに限定。スキル側は `.pending/` 内での変換しか指示していない。全許可フラグに比べれば桁違いに狭い |
| 別のコマンドが必要になり再発する | medium | ②③の多層防御で「止まらない・気づける」を担保。教訓をチケットとメモリへ記録 |
| `sips` は macOS 専用 | low | 既知（KLK-033 の時点で macOS 前提）。**Windows 配布時の課題として申し送る**（パッケージ化チケット） |
