# [KLK-005] 配色ジェネレーター可読性表示のわかりやすさ改善とコピー形式切替 設計

> チケットのログに改訂理由を残す。過去の設計はGitヒストリで追える（status等の状態は持たない）。

## 1. 目的

配色ジェネレーター（`palette/index.html`）v1.1 の使用者フィードバックに応える表示層の改善。
(1) 可読性バッジをWCAG等級（AAA/AA/大文字のみ/✕）から**日常語＋信号色**（読みやすい◎ / 小さい文字は注意△ /
読みにくい✕）へ翻訳し、生数値・正式等級はツールチップへ集約する。(2) 注意・NG判定に**直し方の一言**を添える。
(3) CSS変数コピーに**デザイナー向けHEX一覧形式**を追加し、エンジニア向けCSS変数形式と切り替えられるようにする。
判定ロジック（`contrastRatio`/`wcagLum`）と生成ロジックは一切変えず、**表示・出力層のみ**を改善する。

## 3. 設計方針

**採用する方針:**
- **単一ファイル構成・依存0を維持**する。新規JS/CSSファイルは作らない（v1.0以来の構成原則を継続）。
- **判定ロジックには一切触れない**。`contrastRatio`/`wcagLum` と閾値 `7 / 4.5 / 3` は現状のまま。
  変えるのは `contrastBadge` の**返却文字列（body/title/CSSクラスの割当）だけ**——investigator が
  「翻訳は 1 関数の返却文字列で完結する」と確認したとおり、表示層に閉じる。
- **信号色は既存クラスの再マッピングで実現し、CSSクラスの追加・改変をしない**。これが cvdBadge 退行を
  構造的に防ぐ最小変更（§4.1.2）。`contrastBadge` の cls を **緑=`aaa` / 黄=`lg` / 赤=`ng`** の3クラスに寄せ、
  `.aa`（青）は contrastBadge からは使わなくなるが CSS ルールは温存（削除しない）。cvdBadge が使う
  `aaa`（緑）/`ng`（赤）の定義は無改変のまま維持される。
- **生コントラスト比と正式WCAG等級は title へ集約**。バッジ本体からは数値と AAA/AA 表記を外し、日常語＋信号
  アイコンのみにする（現状すでに title に比率を出しているので、そこへ等級も足して集約）。
- **直し方の一言はバッジ本体（可視）に出す**。ツールチップはホバー/タップ非対応環境で見えず、本チケットの主眼
  「見て次に何をすればよいか分からない」を解決しないため。◎には不要、△/✕にのみ短い方向指示を本体へ、
  詳しい一文は title にも併記する（§4.1.3）。
- **HEX一覧はcssVarsOfと同じ4色算出を流用した姉妹関数を1本追加**する（`hexListOf`）。新しい色計算は増やさない。
- **形式切替UIは #output の外（グローバル1箇所）に置き、選択状態を JS 変数 `copyFormat` に持たせる**。
  paintOutput が out.innerHTML を全置換するため、カード内トグルは再描画で状態が飛ぶ（investigator 指摘）。
  UI を再描画対象外へ出し、かつ選択値を変数化して**都度参照**することで「UIが消えない」「値が正しく反映される」を
  両立する（§4.2.2）。
- **コピーの呼び分けは純粋関数 `copyTextOf(p)` に集約**する。paintOutput のクリックハンドラは
  `copyTextOf(currentPatterns[+btn.dataset.p])` を呼ぶだけにし、既存の「都度 currentPatterns 参照」構造
  （微調整反映の要）を壊さない。切替判定を純粋関数に切り出すことで動的テスト（D群）でも検証可能にする。
- **copyFormat は URL共有・リセットの対象に含めない**。表示・引き渡しの好みであって生成結果ではないため、
  URLスキーマ `v=1` は据え置き（§4.2.4）。investigator が「含めなくても退行なし」と確認済み。
- **版数は v1.2 へ上げる**。生成能力の追加はないが、可読性翻訳＋コピー形式という**利用者に見える機能単位**の
  リリースであり、KLK-003=v1.0 / KLK-004=v1.1 のチケット単位の版数運用に揃える（§4.3）。

**代替案と却下理由:**
| 案 | 却下理由 |
|---|---|
| 信号色のため `.cbadge` に緑/黄/赤の新クラス（.ok/.warn/.bad 等）を追加 | 表示は既存 aaa/lg/ng で緑/黄/赤を満たせる。新クラスは CSS 増分と命名の二重管理を生むだけで視覚的利得がない（architect優先: 複雑性最小） |
| 既存 `.cbadge.aaa`/`.aa` の色を信号色へ再定義（アルファベット等級名のまま色だけ変更） | cvdBadge が `aaa`(緑)/`ng`(赤) を色として再利用しているため、色定義を触ると色覚バッジが連動退行する（investigator 指摘の最重要リスク） |
| 直し方をツールチップ（title）のみに出す | タップ/ホバー非対応環境で見えず、「次アクションが分からない」という主訴を解決しない。可視の本体に短く出す方が要件に忠実 |
| 形式切替を各カードの pattern-head 内に置く | paintOutput の innerHTML 全置換で再描画のたびに選択がリセットされる（investigator リスク）。生成・微調整のたびに初期化される |
| 形式切替を各カード内に置き、選択状態を data属性で復元 | 復元ロジックをカード数ぶん再実装することになり、グローバル変数1つで足りる話を複雑化する |
| copyFormat を URL/リセット対象に含める | 生成結果ではなく引き渡しの好み。URLスキーマ変更（v=1据え置き崩れ）と復元順序の追加検証を招くだけで、共有の再現性には寄与しない |
| HEX一覧を大文字HEX（#3B5BA5）で出す | 既存 cssVarsOf は hslToHex の小文字。形式間で大小混在すると静的/動的検証が特別扱いになり保守が増える。機能要件に大小は無いので**両形式とも小文字**で統一する |

### 4.1 可読性バッジの日常語＋信号色化

#### 4.1.1 表示仕様（判定閾値は不変）

閾値 `7 / 4.5 / 3` と分岐順は現状のまま。各分岐で **正式等級（title用）** と **日常語＋信号クラス（body用）** の
両方を決める。AAA と AA は日常語では同一（「読みやすい ◎」・緑）に統合する:

| コントラスト比 r | 正式WCAG等級（title） | 信号クラス | 日常語（body） | 直し方（body & title） |
|---|---|---|---|---|
| r ≧ 7 | AAA | `aaa`（緑） | 読みやすい ◎ | なし |
| 4.5 ≦ r < 7 | AA | `aaa`（緑） | 読みやすい ◎ | なし |
| 3 ≦ r < 4.5 | 大文字のみ | `lg`（黄橙） | 小さい文字は注意 △ | 文字を濃く |
| r < 3 | ✕ | `ng`（赤） | 読みにくい ✕ | 文字を濃く/背景を明るく |

#### 4.1.2 CSSクラスの再マッピング（cvd退行防止の要）

- `contrastBadge` が出す cls は **`aaa` / `lg` / `ng` の3種のみ**。`aa`（青）は contrastBadge からは出さない。
- CSS `.cbadge.aaa/.aa/.lg/.ng`（L251-254）は**4ルールとも無改変で残す**（`.aa` は色覚バッジも含め未使用に
  なるが削除しない＝退行防止と将来利用の余地）。
- cvdBadge（L878-893）は**一切変更しない**。`aaa`（緑）/`ng`（赤）の色定義が保たれるため色覚バッジは無退行。

#### 4.1.3 contrastBadge の書き換え（この1関数のみ）

```js
function contrastBadge(label, fg, bg) {
  const r = contrastRatio(fg, bg);          // 判定ロジックは不変
  let grade, cls, daily, hint;
  if (r >= 7)        { grade = 'AAA';        cls = 'aaa'; daily = '読みやすい ◎';       hint = ''; }
  else if (r >= 4.5) { grade = 'AA';         cls = 'aaa'; daily = '読みやすい ◎';       hint = ''; }
  else if (r >= 3)   { grade = '大文字のみ'; cls = 'lg';  daily = '小さい文字は注意 △'; hint = '文字を濃く'; }
  else               { grade = '✕';          cls = 'ng';  daily = '読みにくい ✕';       hint = '文字を濃く/背景を明るく'; }
  const body = hint ? `${label} ${daily} ・ ${hint}` : `${label} ${daily}`;
  const tip = `コントラスト比 ${r.toFixed(2)}:1 ・ WCAG ${grade}（AAA≧7 / AA≧4.5 / 大文字≧3）`
            + (hint ? '。文字色を濃くするか背景を明るくすると読みやすくなります' : '');
  return `<span class="cbadge ${cls}" title="${tip}">${body}</span>`;
}
```

- **body から生数値（`r.toFixed`）と AAA/AA 表記を除去**し、日常語＋信号アイコンのみ（△/✕ は短い直し方を併記）。
- **title に比率（`r.toFixed(2)`）＋WCAG正式等級＋しきい値凡例**を集約。△/✕ には改善の一文も追記。
- `paintOutput` の contrastRow（L1324-1332）は **無改修**。label 文字列（'本文×背景' 等）と 3+cvd の組み立ては
  現状のまま（翻訳語は contrastBadge 側が付与する）。metal 案のボタンバッジ切替（L1329-1330 の三項）も不変。
- `cvdBadge` も無改修。

### 4.2 CSS変数コピーの形式切替

#### 4.2.1 HEX一覧形式の出力仕様

`cssVarsOf` と同じ4色算出（`ROLE_KEYS.map(hslToHex)`）を流用した姉妹関数を1本追加する。
ラベルは `ROLE_NAMES`、**1色1行・`{名前} {HEX}` の改行区切り**、HEXは hslToHex 準拠の**小文字**（両形式で統一）:

```js
// デザイナー向け: 4色を「名前 HEX」の一覧で書き出す（常に単色HEX・改行区切り）
function hexListOf(p) {
  return ROLE_KEYS.map((k, i) => `${ROLE_NAMES[i]} ${hslToHex(p[k][0], p[k][1], p[k][2])}`).join('\n');
}
```
出力例:
```
メイン #3b5ba5
サブ #a9c0e8
アクセント #e8a33b
背景 #f5f7fb
```
- 既存 `cssVarsOf`（`:root { --color-main: … }`）は**無改変**で残す（エンジニア向け形式）。

#### 4.2.2 形式選択の状態保持（グローバル変数＋再描画対象外UI）

- グローバル変数を1つ追加する（`currentPatterns` L1169 近傍）:
  ```js
  let copyFormat = 'cssvars';   // 'cssvars' | 'hexlist'
  ```
- 切替UIは **`#output` の外**（=paintOutput の innerHTML 全置換の対象外）に置く。`#output`（L522）の直前へ
  静的マークアップを追加する:
  ```html
  <div id="outputTools" hidden>
    <span>コピー形式:</span>
    <label class="chip"><input type="radio" name="copyfmt" value="cssvars" checked><span>CSS変数</span></label>
    <label class="chip"><input type="radio" name="copyfmt" value="hexlist"><span>HEX一覧</span></label>
  </div>
  ```
  （既存の `.chip` スタイルを流用。`#outputTools` の並び用に軽いスタイルを1〜数行追加してよい）
- **表示切替**: 出力が空のときトグルを見せる必要はないため、`render()`（L1261-1276）の両分岐で
  `document.getElementById('outputTools').hidden = !b.hasInput;` を設定する（hasInput 偽=空表示のとき隠す）。
  トグル自体は `#output` の外なので `hidden` の付け外しだけで DOM の checked 状態は保持される。
- **切替リスナー（静的登録・1回のみ）**: 初期化列で登録する。UI は再描画されないため paintOutput 内では登録しない:
  ```js
  document.querySelectorAll('input[name=copyfmt]').forEach(el =>
    el.addEventListener('change', () => {
      copyFormat = document.querySelector('input[name=copyfmt]:checked').value;
      if (currentPatterns.length) paintOutput();   // ボタン表記を新形式へ更新（render は呼ばない＝微調整を保持）
    }));
  ```
  paintOutput を直接呼ぶだけなので **currentPatterns（微調整済み）を再生成せず**、ボタン表記のみ更新できる。

#### 4.2.3 コピー本文の呼び分け（都度 currentPatterns 参照を維持）

- 切替判定を純粋関数に集約する（`cssVarsOf` の直後に配置）:
  ```js
  function copyTextOf(p) {
    return copyFormat === 'hexlist' ? hexListOf(p) : cssVarsOf(p);
  }
  ```
- paintOutput（L1277-1355）の変更点は2つのみ:
  1. ボタン表記を現在の形式に合わせる。map の外で `const copyLabel = copyFormat === 'hexlist' ? 'HEXコード一覧をコピー' : 'CSS変数をコピー';` を作り、pattern-head のボタン（L1335）を
     `<button type="button" class="css-copy" data-p="${pi}">${copyLabel}</button>` にする。
  2. クリックハンドラ（L1348-1354）を `copyTextOf` 経由にし、復帰ラベルも `copyLabel` にする:
     ```js
     out.querySelectorAll('.css-copy').forEach(btn => {
       btn.addEventListener('click', () => {
         navigator.clipboard?.writeText(copyTextOf(currentPatterns[+btn.dataset.p]));  // 都度参照＝微調整反映
         btn.textContent = '✓ コピーしました';
         setTimeout(() => { btn.textContent = copyLabel; }, 900);
       });
     });
     ```
- `currentPatterns[+btn.dataset.p]` を**クリック時に都度参照**する構造は不変（微調整モーダル編集後の値が反映される要）。
  `copyTextOf` は copyFormat をクリック時に読むため、トグルを切っても最新形式でコピーされる。

#### 4.2.4 URL共有・リセットとの関係（copyFormat は非対象）

- **URL共有**: `copyFormat` は生成結果ではなく引き渡しの好みのため、**URLスキーマに含めない**。
  `syncURL`/`restoreFromURL`/`KNOWN`（L1217）は無改変で `v=1` を維持する（investigator が退行なしと確認済み）。
- **リセット**（`#reset` ハンドラ L1627付近）: copyFormat は生成入力ではないため**リセット対象に含めない**
  （ユーザーが選んだ引き渡し形式を維持する方が親切。退行なし）。リセット後は hasInput 偽で outputTools が
  隠れ、次の生成時に前回選択のまま再表示される。
- `updateSummaries` は入力サマリ表示のみで copyFormat/可読性に非依存 → 影響なし。
