# [KLK-132] 起動.batがWindowsのバッチとして成立していない 設計

> このファイルはarchitectが生成・更新するチケット単位の設計書です。
> チケット KLK-132 に対応します。implementer・tester・reviewerが参照します。

## 1. 目的

配布物の `起動.bat` を、日本語 Windows の `cmd.exe` が**そのまま実行できる形**にする。
SPEC の NFR「非エンジニアがダブルクリックだけで使える」を Windows でも満たすための最低条件であり、
現状は Windows ユーザー全員がここで止まっている。

## 2. 現状

**現在のファイルの形:**

| 対象 | 文字コード | 改行 | 備考 |
|---|---|---|---|
| `起動.bat` | UTF-8（BOM なし） | **LF のみ**（CRLF 0 / LF 54） | 5行目に `chcp 65001 > nul` |
| `起動.command` | UTF-8 | LF | macOS 用。**正しい形なので触らない** |

**cmd.exe が失敗するまで:**
```
ダブルクリック
  → cmd.exe が .bat を CP932 として読む（既定）
  → ① 改行が LF のみ  → 行の区切りを正しく取れない
  → ② 日本語が UTF-8  → マルチバイト文字の途中で読み取り位置がずれる
  → 行の後半が別コマンドとして実行される（'ode' is not recognized）
  → @echo off も効かず、ウィンドウが閉じる／無反応に見える
  ※ chcp 65001 は5行目。ずれは**それより前の読み取り段階**で起きるので効かない
```

**関連する既存ファイル:**
- `起動.bat` — 変換対象
- `tests/site/check_klk070.py:33` — `BAT = open(..., encoding="utf-8")`。**CP932 化で落ちる**
- `tests/site/check_klk105.py:49` — 同上（`io.open(..., encoding="utf-8")`）。**落ちる**
- `tests/site/check_klk098.py` / `check_klk115.py` — 存在確認のみ。影響なし
- `tools/make-package.sh:89` — `cp` の素コピー。バイトはそのまま
- 文字コード・改行を検査するものは**存在しない**

## 3. 設計方針

**採用する方針: リポジトリに置く `起動.bat` そのものを CP932(Shift_JIS) + CRLF にする。**

配布物と同じ形をリポジトリが持つ。変換工程を挟まないので、「リポジトリでは直っているのに
配布物では直っていない」というズレが原理的に起きない。clone 利用者も同じ恩恵を受ける。
`chcp 65001 > nul` は CP932 化により役目を失うので削除する。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| UTF-8/LF のまま置き、`make-package.sh` がビルド時に CP932+CRLF へ変換する | clone 利用者の Windows は壊れたまま。ソースと配布物で形が違うため、検査が「形」を見る側に寄ってしまう（実効果を見る流儀に反する）。二重管理になる |
| BOM 付き UTF-8 にする | **実機で悪化を実測済み**（レビュアーの方）。BOM が先頭行に食い込み `@echo off` すら効かない |
| 日本語メッセージを捨てて ASCII のみのバッチにする | 非エンジニア向けの案内が英語になる。導入の敷居を上げるので本末転倒 |
| `chcp 65001` を先頭へ移す | 読み取りのずれは `chcp` 実行前に起きているため効かない。`cmd /c` の起動時点の符号化が問題の本体 |

**あわせて直す小さな一点（ダメ文字の除去）:**

CP932 には2バイト目が `0x5C`（`\`）になる文字がある（いわゆるダメ文字）。
現在の文面には **「表」が1箇所だけ**ある（28行目「python --version が表示されればOKです。」）。
日本語 Windows では問題にならないが、英語ロケール等で `\` と解釈される余地を残す理由がない。
**「出ればOKです」へ言い換えて、ダメ文字ゼロにする。** これにより検査で
「ダメ文字を含まない」を機械的に固定できる（この文言を見ている検査は無い＝安全に変更できる）。

## 4. 実装詳細

**ファイル構成（変更・追加）:**
```
起動.bat                      変更（CP932+CRLF 化・chcp 削除・ダメ文字1件の言い換え・先頭 rem に警告）
.gitattributes                新規（Git に改行を触らせない）
tests/site/check_klk132.py    新規（文字コード・改行の検査）
tests/test_palette_klk132.py  新規（unittest ラッパー）
tests/site/check_klk070.py    変更（BAT の読み取りを cp932 へ）
tests/site/check_klk105.py    変更（同上）
```

**変換手順（再現可能な形で記録する）:**
```bash
# 1) chcp 行を落とす → 2) CP932 へ → 3) LF を CRLF へ
python3 - <<'PY'
src = open("起動.bat", encoding="utf-8").read()
src = "".join(l for l in src.splitlines(True) if not l.startswith("chcp "))
src = src.replace("が表示されればOKです", "が出ればOKです")
open("起動.bat", "wb").write(src.replace("\n", "\r\n").encode("cp932"))
PY
```

**`.gitattributes`（新規・リポジトリ直下）:**
```
# 起動.bat は Windows の cmd.exe が読む。CP932(Shift_JIS)+CRLF 固定（KLK-132）。
# Git に改行を触らせない。テキストとして扱うと環境次第で LF へ潰され、Windows で起動しなくなる。
起動.bat -text
```
> `make-package.sh` の同梱対象は allowlist なので、`.gitattributes` が配布物に混ざることはない。
> `check_klk115` の `EXPECTED_TOP` は**配布物の**最上位を見るものなので更新不要。

**`起動.bat` 先頭に置く警告（rem）:**
```
rem ★このファイルは CP932(Shift_JIS) + CRLF で保存すること（KLK-132）。
rem   UTF-8 や LF で保存し直すと、Windows でダブルクリックしても起動しなくなる。
rem   検査: python3 tests/site/check_klk132.py
```

**`tests/site/check_klk132.py` の検査項目:**

判定は**純粋関数**（バイト列 → 真偽）として書き、末尾で**自己検査**する。
検査そのものが効いていることを、壊したバイト列を与えて確かめる（妨害注入は
「壊したことを assert してから」判定する流儀に合わせる）。

| ID | 内容 |
|---|---|
| A1 | `起動.bat` が CP932 として復号できる |
| A2 | UTF-8 としては復号**できない**（＝ UTF-8 で保存し直したら落ちる） |
| A3 | すべての改行が CRLF（単独 LF が 0 件） |
| A4 | BOM が無い（UTF-8 BOM / UTF-16 LE・BE BOM） |
| A5 | `chcp` を含まない |
| A6 | ダメ文字（2バイト目が `0x5C` の CP932 文字）を含まない |
| A7 | 制御構造が壊れていない（`@echo off` / `setlocal` / `endlocal` / `cd /d "%~dp0"` / `draft-gen\bridge.py`） |
| A8 | 日本語メッセージが CP932 復号後に読める（`【エラー】` `ローカルブリッジを起動します` を含む） |
| A9 | `起動.command`（macOS）は UTF-8 で復号でき、CRLF を**含まない**（mac 側を巻き込まないための固定） |
| A10 | `.gitattributes` に `起動.bat -text` がある |
| A11 | ★**実ビルドした配布物の `起動.bat` がリポジトリのものとバイト一致**する（`--fast` で省略可） |
| A12 | 自己検査: UTF-8/LF に戻したバイト列を判定関数へ渡すと A1〜A3 が**落ちる**ことを確認する |

> A11 は `tools/make-package.sh` を実ビルドするため数十秒かかる。
> 既存の `check_klk111` / `check_klk112` と同じく `--fast` で省ける形にする。

**`check_klk070.py` / `check_klk105.py` の修正:**
```python
BAT = io.open(BAT_PATH, encoding="cp932").read()   # KLK-132: 起動.bat は CP932
```
読んだあとの文字列比較（`%~dp0` / `where claude` / `【エラー】claude` / `Add Python to PATH` 等）は
復号後の文字列に対する比較なので**そのまま通る**。

## 5. 影響範囲

| 対象 | 影響の種類 | 対応方針 |
|---|---|---|
| `起動.bat` | 変更 | CP932+CRLF 化。処理の流れは変えない |
| `.gitattributes` | 追加 | 改行の保護のみ |
| `check_klk070` / `check_klk105` | 変更 | 読み取り符号化を cp932 へ |
| `check_klk132` / ラッパー | 追加 | 回帰の番人 |
| `make-package.sh` | 影響なし | 素の `cp` のためバイトが保たれる（A11 で実測） |
| `起動.command` | 変更なし | A9 で「変わっていないこと」を固定する |
| KLK-133（claude の探索） | 後続 | 同じファイルを触るので**直列**。133 の実装者は CP932 のまま編集すること |

## 6. リスク

| リスク | 深刻度 | 軽減策 |
|---|---|---|
| 以後この bat を UTF-8 で保存し直してしまう（人・エディタ・AI のいずれでも起きる） | **high** | A2（UTF-8 で復号できないこと）＋ A3 で機械的に落とす。ファイル先頭に rem で警告を置く |
| Git が改行を変換して LF へ戻す（`core.autocrlf` 設定次第） | high | `.gitattributes` の `-text` で保護し、A10 で存在を固定 |
| 英語ロケール Windows で表示が化ける | low | 制御構造はすべて ASCII なので**動作には影響しない**。ダメ文字も A6 で 0 にする |
| 配布物だけ壊れる（ビルド工程の事故） | medium | A11 で実ビルドとバイト比較する |
| CP932 のためエディタでの差分が読みにくい | low | 変換手順を §4 に残す。編集は UTF-8 で行い、最後に同じ手順で戻せる |

## 7. マイグレーション戦略

なし（単一ファイルの形式変更。データ・API の互換性に関わらない）。
既に配布済みの A/B パッケージは、次回の再作成時に差し替わる。

## 8. ロールバック戦略

```bash
git revert {コミットハッシュ}   # 起動.bat / .gitattributes / 検査がまとめて戻る
```
戻すと Windows では再び起動しなくなるため、**戻すのは別の直し方に差し替えるときだけ**。
