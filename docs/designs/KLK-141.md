# [KLK-141] CHANGELOGの依頼者の呼称を置き換える 設計

> このファイルはarchitectが生成・更新するチケット単位の設計書です。
> チケット KLK-141 に対応します。implementer・tester・reviewerが参照します。
> 1チケット = 1ファイル（`docs/designs/KLK-141.md` が常に現行）。改訂時は本ファイルを上書きし、
> チケットのログに改訂理由を残す。過去の設計はGitヒストリで追える（status等の状態は持たない）。

> **表記の約束（この設計書全体）**: 個人名そのものは書かない。「呼称」＝依頼者の現在の呼称、
> 「姓」＝依頼者の姓、「旧称」＝依頼者の以前の呼称、「照合語」＝これらの各表記
> （漢字・ひらがな・カタカナ・ローマ字）。照合語の実体は Git 管理外の照合語ファイル（§4.2）にだけ置く。

## 1. 目的

CLAUDE.md「セキュリティ・機密情報の取り扱い」は、ドキュメントに個人情報（氏名など）を書くことを禁じている。
しかし CHANGELOG.md をはじめ、配布物に入るファイル・生成物の雛形（compare_template.html）に依頼者の呼称が残っている。
これを一般的な呼び方（「依頼者」「利用者」など）に置き換え、あわせて再発を検査で止める。

**UI の変更は無い。** 置き換え対象はすべてコメント・docstring・ドキュメント本文・検査のラベル文字列・
カタログの備考欄であり、画面に表示される文言・動作は変わらない。したがってデザインシステムの参照は対象外。

## 3. 設計方針

**採用する方針:**

1. 置き換えは「定型句（機械置換）」と「文脈判断（手作業）」の2段で行う（§4.3）。
   機械置換は**列挙した接尾語に続く場合だけ**に限り、残りは全件を人が見て直す
2. 照合語は **リポジトリ内の Git 除外パス `.private/personal-terms.txt`** に置き、検査は実行時に読む。
   ファイルが無ければ素通り（fail-open）。検査ファイル・設計書・チケットには照合語を書かない（KLK-108 の方針）
3. 再発防止の検査 `tests/site/check_klk141.py`（＋ラッパー `tests/test_palette_klk141.py`）を**足す**。
   照合ロジックは共有モジュール `tests/site/_private_terms.py` に1つだけ置き、check_klk077 R7 もこれを使う
   （照合規則を2か所に書かない＝KLK-131 で起きかけた食い違いを避ける）
4. compare_template.html を直し、samples/ の見本3点には**同じ文言の置き換えを手で当てる**（再生成はしない）

**代替案と却下理由:**
| 案 | 却下理由 |
|---|---|
| 検査を足さず、置き換えだけで済ませる | 生成器コメント・設計書・テンプレートは今後も書き足される。KLK-140 のレビューで偶然見つかった経緯からも、人の注意だけでは再発する |
| 照合語を検査ファイルに直書き（check_klk077 R7 方式を広げる） | 検査ファイル自身が個人名の漏洩源になる（KLK-108 の教訓）。tests/ は `--with-tests` で配布される |
| 照合語を環境変数で渡す | 毎回の設定が要り、普段の全体テストで検査が実質働かない。ファイルの方が置きっぱなしで効く |
| 照合語を auto-memory（~/.claude/…）から読む | リポジトリ外・Claude Code 固有の場所に検査が依存する。チームの他の人の環境で意味を持たない |
| 照合語を catalog/ 配下に置く | catalog/ は「実績カタログ」の置き場で目的が違う。`--with-catalog` の同梱対象との境界も曖昧になる |
| 照合語を `.claude/` 配下に置く | `.claude/` は make-package.sh が丸ごと配布物へ入れる |
| samples/ の見本を make_compare.py で再生成 | 置き換え以外の差分（生成日時など）が混ざり、レビュー範囲が広がる。check_klk103 M はテンプレート由来（`--c-main`・`KLK-103` の有無）を見るだけなので、手で同じ置き換えを当てれば足りる |
| `git filter-repo` 等で履歴も消す | 範囲外（チケットの合意） |

### 4.2 照合語ファイル `.private/personal-terms.txt`

- **場所**: リポジトリ直下 `.private/`。`.gitignore` に次を追加する（.gitignore はチームで共有されるため、
  `.git/info/exclude` ではなく `.gitignore` に書く）
  ```gitignore
  # 個人名など、検査の照合語だけを置く場所（KLK-141）。Git 公開対象外・配布物にも入らない
  .private/
  ```
- 配布物に入らない根拠: make-package.sh の直下コピーは allowlist（`draft-gen palette .claude agents docs samples`
  と列挙ファイル）なので `.private/` は入らない。check_klk141 で実ビルドして確かめる（§4.4 K4）
- 追加後に `git check-ignore -v .private/personal-terms.txt` が `.gitignore` の行を返すことを確認する
- **書式**（UTF-8・1行1件）
  - 空行と `#` で始まる行は無視
  - 通常の行 = 照合語（呼称・姓・旧称の各表記）
  - `!` で始まる行 = 誤検知の除外語（照合語を部分に含む一般語。種類: カタカナの外来語、ひらがなの
    動詞・形容詞の活用形。具体語はチケットの調査メモ参照）。照合の前に本文からこの語を取り除く
  - ASCII 英字だけの照合語は、大文字小文字を無視し単語境界つきで照合する
- **作成者**: implementer。investigator が使った Git 管理外の検索語（呼称・姓・旧称の漢字/ひらがな/カタカナ/
  ローマ字）から作る。除外語は §4.3 の置き換え後に検査を走らせ、残った一致が誤検知であることを確かめてから足す。
  **照合語の内容をチケット・コミットメッセージ・報告に書き写さない**

### 4.3 置き換えの規則

**段階1: 定型句（機械置換）**

対象は「呼称・姓・旧称の漢字表記 + `さん`」（以下「名さん」）で、直後が次のいずれかの場合だけ。
置き換え後は「依頼者」（敬語の `のご` は `の` に寄せる）。

| 直後の語（例） | 置き換え後 |
|---|---|
| `のご要望` / `のご指示` | `依頼者の要望` / `依頼者の指示` |
| `の要望` `要望` `の指定` `の指示` `の修正指示` `の指摘` `の方針` `方針` `の意向` `の依頼` `の条件` `の合意` `と合意` `の選択` `の明示的` | `依頼者` + 同じ続き |
| `決定` `の決定` `確定` `が確定` `判断` `の判断` `確認` `の確認` `が確認` `回答` `の回答` `が決めた` `が選んだ` `が挙げた` `に提案` `経由` `から` | `依頼者` + 同じ続き |

- 実施は scratchpad に置く使い捨てスクリプトで行い、**リポジトリにはコミットしない**（照合語を読むため）。
  スクリプトは照合語ファイルから語を読み、上の接尾語リストに一致した箇所だけを置き換え、残りの一致を一覧で出す
- 文字列リテラルを誤って触らないよう、置き換え後に `git diff --stat` と差分を目視し、
  .py/.js/.html は変更行がコメント・docstring・check ラベルだけであることを確かめる

**段階2: 文脈判断（手作業）** — 段階1の残り全件を人が読んで直す。目安の対応表:

| 文脈 | 例（名前部分を伏せた形） | 置き換え後 |
|---|---|---|
| 実際に使った環境 | 「名さんの環境で 404」「（名さんの環境）」 | 「実運用の環境で 404」「（実運用の環境）」 |
| 実機 | 「M群（名さん実機）」「名さんの実機で」 | 「M群（実機）」「実機で」 |
| 目視で発覚 | 「名さんの目視で発覚」 | 「人の目視で発覚」 |
| 報告・実際に使って見つけた | 「名さんの報告」「名さんが…実際に使って見つけた」「名さんの踏んだ状態」「名さんの実使用」「名さんのテスト」「名さんの作業物」「名さんが見る」「名さんがマニュアル…」 | 「利用者の報告」「利用者が…実際に使って見つけた」「利用者の踏んだ状態」「利用者の実使用」…（主語を「利用者」へ） |
| 利用者を列挙 | 「利用者（名さん・名さん）」「名/名さんが」 | 「利用者（非エンジニア）」「利用者が」 |
| 実績画像の所有者 | 「旧称さん所有の実績画像」 | 「自社所有の実績画像」 |
| さん無しの姓 | 「人間（姓）のレビュー待ち」 | 「人間（依頼者）のレビュー待ち」 |
| 上の表に当てはまらない | — | 要望・指定・決定に当たるなら「依頼者」、実際に使った人なら「利用者」、どちらでもなければ主語を落とす |

- CHANGELOG.md の3箇所: 「名さんの要望。」→「依頼者の要望。」（2箇所）、「名さんが KLK-120 の編集機能を実際に使って見つけた不具合。」→「利用者が KLK-120 の編集機能を実際に使って見つけた不具合。」
- check_klk077 R7 は文言の置き換えではなく §4.5 の改修で直す

**誤検知の除外**: 置き換え対象にしない。照合語ファイルの `!` 行で検査から外す（§4.2）。
investigator が確認した誤検知はデザインシステム文書の2件（ひらがな）と、カタカナ・ひらがなの姓表記の部分一致。

**範囲外（触らない）**: 過去のコミット履歴／未追跡の配布物フォルダ「モック生成キット_B_…」／tickets/ 配下
（ログは追記のみのため既存行は直さない）／mockups/*/index-*.html（ラフ本体）。

def find_hits(text, terms, allows):

def scan_tree(root, terms, allows):
