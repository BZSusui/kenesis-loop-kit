## 1. 目的

SPEC REQ-004「実績カタログのサムネイルから参考画像を2〜3枚選択できる」を、SCR-001 設定画面
（`draft-gen/index.html`）で実装する。現状はハードコードのダミー6枚（`m1`〜`m6`）で、実績カタログ
（`catalog/catalog.json`・ブリッジ `/catalog.json`・`/catalog/img/`）を一切読んでいない。これを
実カタログへ接続し、v1.0 成功基準（SPEC §13: Must REQ-001〜011 完了）の唯一の未完点を閉じる。

**本チケットの完成境界（OQ-2 確定・人間承認済み）:**
REQ-004 の完成は「**実カタログから選んだ参考が、生成指示書JSONの `references.thumbnails`（`{id,label,tags}` 契約）
に正しく載る**」ところまでとする。選択した参考を draft-generate 生成本体が配色・構成のヒントとして
**消費する**ことは本チケットのスコープ外（フェーズ2・別チケット）。`draft-generate` SKILL / DRAFT_RULES は
現状 `references.thumbnails` を消費していない（grep 0件）ことを確認済み。設計・受け入れはこの境界で判定する。

## 3. 設計方針

**採用する方針:**

1. **`#thumbs` を実カタログ由来の動的描画に置換**する。`catalog.html` の `probeHealth`/`loadCatalog`/`imgSrc` パターンを踏襲。
   - 「ピッカー稼働」の判定は catalog.html と同一規律: **`location.protocol !== 'file:'` かつ `probeHealth()` が真**。これを満たすときのみ `/catalog.json`（相対・同一オリジン）を読み、`/catalog/img/{file}`（相対）で画像を出す。
   - フィールド写像: **`id = e.id, label = e.title, tags = e.tags`**。フィルタ用に `industry / taste / colors` も各カードへ保持する。既存の `references.thumbnails {id,label,tags}` 契約（KLK-006 S9）を維持する。
2. **フォールバック（OQ-1・NFR-005 確定）**: ブリッジ非稼働・`file://` 単体では `#thumbs` を**空**にし、案内文
   「ブリッジを起動すると実績カタログから参考を選べます」を表示（catalog.html 空状態と同型）。**実データ（案件名・画像）は社外秘のため `file://` にスナップショットを置かない**。現行ダミー6枚は撤去し、実データ導線に一本化する（器に実案件名を書かない）。
3. **`#thumbFilter` を実際に機能させる**（ハンドラ登録＋実データフィルタ）。3択「近い業種のみ / すべての実績 / 同じテイストのみ」を実装する。
4. **業種連動を実データフィルタ化**する。三重タクソノミ不一致（SCR-001 長ラベル ≠ catalog.json industry ≠ catalog.html 短縮チップ）に対し、**先頭トークン＋双方向前方一致**のマッピング規約を定める（§4）。**一致0件時は全実績表示＋注記**にフォールバックし、実データが少ない現状でも破綻させない。
5. **拡大モーダルで実画像を表示**する（ピッカー稼働時のみ `/catalog/img/{file}`）。非稼働・`file://` 時は従来同様プレースホルダ。
6. **テスト温存（R-F・OQ 確定）**: 実画像は `document.createElement('img')` + `setAttribute('src', …)` で描画し、**器のHTMLソースに `<img` リテラルを焼き込まない**。これで `check_klk006.py` S13（`no_img`）を温存する。S13 が同時に要求する `.thumb .ph` グラデCSS・`class="thumb"`・`data-id=`・最大3ロジック・`#thumbCount`「/ 3枚」も**JS描画テンプレート内のリテラルとCSSとして残す**（撤去した静的ダミーの代替として）。S9（`thumbnails:` キー）は契約維持で温存。
7. **選択下限は必須化しない（警告に留める）**。上限3の強制は維持しつつ、「2〜3枚推奨」はUIヒント/カウント表示に留め、**0枚でも生成可能**という既存挙動を保つ。理由は §3 代替案表参照。
8. **機密規律（REQ-011）維持**: 実データは `catalog/`（Git除外）からの**同一オリジン fetch のみ**。器 `index.html` に実案件名・実データを焼き込まない。

**採用しなかった代替案とその理由:**
| 案 | 却下理由 |
|---|---|
| S13 を「実画像接続前提」に改訂し `<img>` を許可 | v1.0 回帰スイート（全 `check_klk*` を通す運用）で S13 赤化を招く。createElement 方式なら S13 を無改訂で温存でき、影響範囲が最小。確定方針。 |
| `file://` に実績のスナップショット（画像＋メタ）を同梱してオフラインでも選べるようにする | 実データ（案件名・画像・タグ）は社外秘（REQ-011）。Git除外の `catalog/` 外に複製すると機密が漏れる。OQ-1 で却下確定。 |
| 選択「2枚以上」を必須バリデーションにして生成をブロック | 既存は0枚でも生成可能で、SPEC でも REQ-004 は「推奨」。過度な強制は生成導線を阻害し既存挙動と非整合。推奨表示に留める（確定）。 |
| 業種を厳密な正規化テーブル（全13ラベル×全industry の写像表）で解決 | 実データ3件・タクソノミが将来増えるため、固定表は保守負債になる。先頭トークン＋双方向前方一致＋0件フォールバックの規約で十分頑健（§4）。 |
| ピッカーの画像取得を `BRIDGE_ORIGIN` 絶対URLにして `file://` でも cross-origin fetch する | OQ-1 の「`file://` は空＋案内」確定に反する。catalog.html と同じく `file:` を非稼働扱いにする方が規律が一貫し、相対パスで NFR-005 の外部URL検査も安全。 |

**4.3 業種マッピング規約（三重不一致の対処）**

SCR-001 の業種ラベル（`:350-362` の長ラベル、または自由入力）→ カタログ `industry` の照合手順:
```
industryKey(label):
  s = (label || '').split('(')[0].trim()   // 先頭トークン: 最初の '(' より前
  return s                                   // 例「美容・サロン(美容室 / ネイル / エステ)」→「美容・サロン」
                                             //   「医療・クリニック・福祉」→「医療・クリニック・福祉」

matchesIndustry(entry, key):
  if (!key) return true                      // 業種未選択は絞らない
  a = entry.industry || ''
  return a.startsWith(key) || key.startsWith(a)   // 双方向前方一致
```
- 双方向前方一致にする理由: SCR-001 ラベルはカタログ `industry` より**広い/長い**ことがある
  （例 ラベル「医療・クリニック・福祉」 vs entry `industry`「医療」→ `key.startsWith(a)` で一致）。
  逆に entry が長い将来ケースは `a.startsWith(key)` で拾う。
- 自由入力（`industryCustom`）が非空ならそれを優先（`render()` の `industry` 決定と同じ規則）、それを `industryKey` に通す。
- **一致0件のフォールバック**: 「近い業種のみ」で0件になったら**全実績を描画**し、`#industryChip` 付近に
  注記「近い業種の実績が見つからないため、すべての実績を表示しています」を出す（実データ3件の現状で多くの業種が0件になるため必須）。

参考（現データでの期待挙動・照合の目安）:
| SCR-001 選択 | industryKey | 一致する entry.industry | 結果 |
|---|---|---|---|
| 医療・クリニック・福祉 | 医療・クリニック・福祉 | 医療 | 大村クリニックのみ |
| 美容・サロン(…) | 美容・サロン | （なし） | 0件→全表示＋注記 |
| （未選択） | ""（空） | — | 全表示 |
| 自由入力「ジュエリー」 | ジュエリー | ジュエリー・アクセサリー | アミュールのみ |

**4.4 絞り込み（#thumbFilter）**
```
applyThumbFilter():
  key = industryKey(現在の業種)      // 4.3
  taste = 現在選択中のテイスト(dataset.label) or null
  mode = #thumbFilter.value          // '近い業種のみ' | 'すべての実績' | '同じテイストのみ'
  list =
    mode==='すべての実績' → catalogEntries
    mode==='同じテイストのみ' → catalogEntries.filter(e => !taste || e.taste===taste)   // 0件/未選択は全件
    それ以外(近い業種のみ・既定) → catalogEntries.filter(e => matchesIndustry(e,key))
  0件フォールバック（近い業種/同じテイスト）: list.length===0 → list=catalogEntries、注記表示
  renderThumbs(list)
  選択状態は id で保持を試みる（再描画で選択が消えないよう、既選択 id を再適用してから updateThumbCount）
```

**4.5 描画（S13 温存が肝）**
```
renderThumbs(list):
  if (!catalogAlive || list.length===0):
     #thumbs に空状態を描画（catalogAlive=false は案内文、alive で0件は「条件に合う実績がありません」）
     updateThumbCount()
     return
  // カード骨格は innerHTML の文字列テンプレートで組み、class="thumb"・data-id="…"・
  // <span class="ph">TITLE</span>（プレースホルダ）・zoom/check/cap を含める（<img は書かない）
  #thumbs.innerHTML = list.map(cardHtml).join('')
  // 画像は稼働時のみ createElement で後付け（<img リテラルを器に残さない＝S13温存）
  list.forEach(e => {
     img = document.createElement('img')
     img.setAttribute('src', '/catalog/img/' + encodeURIComponent(e.file))   // 相対・同一オリジン
     img.setAttribute('alt', e.title)
     img.setAttribute('loading','lazy')
     img.onerror = () => img.remove()      // 失敗時は .ph プレースホルダのまま
     該当 .thumb に prepend（.ph は背景として残す）
  })
  各 .thumb に選択トグル＋zoom のハンドラを（再）登録（4.6）
  updateThumbCount()
```
- `cardHtml(e)` が出力する文字列に **`class="thumb"` と `data-id="` のリテラルを必ず含める**（S13 `has_thumb_ui` の温存）。`.ph` の中身は `esc(e.title)`。`data-tags` 等は 4.1 のとおり付与。
- **重要（回帰）**: カード骨格を `createElement` で全面生成すると `class="thumb"`/`data-id=` リテラルがソースから消え S13 が赤化する。骨格は innerHTML 文字列、画像のみ createElement、という分担を厳守する。

**4.6 選択トグル（既存ロジックを動的カードへ再配線）**

**4.7 selectedThumbs / references 契約（写像維持）**
```js
function selectedThumbs() {
  return Array.prototype.map.call(document.querySelectorAll('.thumb.selected'), function (el) {
    var tags;
    try { tags = JSON.parse(el.dataset.tags || '[]'); } catch (e) { tags = []; }
    return { id: el.dataset.id, label: el.dataset.label, tags: tags };
  });
}
```
- `buildInstruction()` の `references.thumbnails = refThumbs.slice(0,3).map({id,label,tags})`（`:710-712`）は不変。
  写像後も `{id,label,tags}` の3キー契約（KLK-006 S9）を満たす。`tags` は配列（`e.tags`）で載る。
