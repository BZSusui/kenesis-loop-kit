# [KLK-028] カラーコードの「#」省略入力（6桁）受理 設計

> architect生成のチケット単位設計書。KLK-028 に対応。implementer/tester/reviewer が参照する。

## 1. 目的

Photoshop 等のスポイトからコピーした **#なし6桁のカラーコード**（例 `444850`）を SCR-001 の配色欄に
そのまま貼り付けても色が反映されるようにする（実務のコピペ動線の解消）。

## 2. 現状

- `normalizeHex`（純ロジック）が `^#` 必須。全消費箇所（4色 hex 欄・setColorRole・validateRequired・
  buildInstruction・parsePalette）がこの関数を通る。
- 既存契約: smoke_klk006 D4 が `abc`（#なし3桁）→ null を含む入出力をピン留め。**#なし6桁は未固定**。

## 3. 設計方針

**`normalizeHex` を1箇所拡張し「#なし6桁」を受理する（3桁は従来どおり # 必須）。**

- 6桁のみとする理由: ① Photoshop のコピー形式は6桁 ② 既存ピン（`abc→null`）と衝突しない
  ③ 3文字入力は一般語と紛らわしく誤解釈リスクがある。
- 全経路が normalizeHex 経由のため、関数1箇所で「4色すべての欄・必須判定・JSON 正規化」に波及する。
- 出力 JSON は従来どおり **必ず `#rrggbb`（小文字）**＝bridge `_HEX_RE`・下流（生成・palette）は不変。
- UX 補完: hex 欄の **change（blur）時に正規形 `#rrggbb` へ表示を整形**（input 中は書き換えず入力を妨げない）。
- ヒント文言に「#なし6桁（例 444850）でも可」を明記（発見性）。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| 3桁の#なし（`abc`）も受理 | smoke_klk006 D4 の既存ピンと衝突。3文字は誤入力と紛らわしい。6桁で実需要（Photoshop）は満たせる |
| 各入力欄側でだけ `#` を前置補完 | validateRequired / buildInstruction が生値を読む経路で漏れる。関数1箇所の方が漏れなく最小 |
| input 中にリアルタイムで欄を書き換え | 入力途中のカーソル位置が乱れる。blur 時のみ整形する |

## 4. 実装詳細

```js
// #rgb / #rrggbb（大小可）→ #rrggbb（小文字）。
// KLK-028: #省略の6桁（Photoshop等のコピー値）も受理する（3桁は誤入力と紛らわしいため従来どおり # 必須）。
function normalizeHex(s) {
  if (typeof s !== 'string') return null;
  let t = s.trim();
  if (/^[0-9a-fA-F]{6}$/.test(t)) t = '#' + t;   // KLK-028
  ...従来どおり...
}
```

```js
// init（方法①）: blur 時に正規形へ表示整形（KLK-028・input 中は非干渉）
hex.addEventListener('change', function () {
  const norm = normalizeHex(hex.value);
  if (norm) { hex.value = norm; pick.value = norm; render(); }
});
```

- ヒント: 配色カードの `.hint` に「カラーコードは #なし6桁（例 444850）でも入力できます」を追記。
