# [KLK-070] Windows 対応 設計

## 1. 目的

配布先に Windows 環境の方がいる。現状は起動すらできないため、**同じ操作感で使える**ようにする。
あわせて、調査で見つかった `catalog-import/SKILL.md` の**手順2-0 と 手順3' の矛盾**を解消する。

## 2. 現状

| # | 箇所 | Windows での状態 |
|---|---|---|
| 1 | `draft-gen/起動.command` | bash 専用。**動かない** |
| 2 | `.claude/settings.json` の hook 3本 | すべて `python3 "..."`。**`python3` が無いと毎回エラー**＝状態検証が効かない |
| 3 | webp→png（`sips`） | macOS 標準。**無い** |
| 4 | `README.md` | 手順が macOS 前提 |

`bridge.py` は `build_open_command` が `win32` 分岐を持ち、それ以外も OS 非依存。**対応不要**。
`tools/make-package.sh` は配布物を**作る側**（macOS）で動けばよい。**Windows 版は不要**。

## 3. 設計方針

### 3.1 起動: `起動.bat` を追加する（`起動.command` は残す）

同じ考え方で書く。`%~dp0..` でリポジトリルートへ移動し、前提を確認してから `bridge.py` を起動。

- Python の探索は **`py -3` → `python`** の順（Windows の実情に合わせる。`python3` は最後）
- `claude` の有無も確認し、無ければ**日本語で対処を示して**終了する（`起動.command` と同じ親切さ）
- 見つかった Python のコマンド名を使って `bridge.py` を起動する

### 3.2 hook: `python3` 直書きをやめ、**ランチャ経由**にする

hook は3本とも `python3 "<script>"` を直に呼んでいる。これを

```
python3 → 見つかったPython
```

に解決する小さなランチャ `.claude/hooks/run_hook.py`（Python で書くと鶏卵問題になる）ではなく、
**`settings.json` のコマンド自体を OS 非依存の形へ変える**のが素直。

採用: **`python3` が無い環境向けに、コマンドを `python3 ... || python ...` のフォールバック形にする。**

```
python3 "<script>" 2>/dev/null || python "<script>"
```

- macOS/Linux: `python3` が成功して終わり（`python` は呼ばれない）
- Windows: `python3` が見つからず非0 → `python` で実行される

**なぜラッパースクリプトにしないか**: ラッパー自体を起動するのに Python が要るので、
「Python を探す処理を Python で書く」という循環になる。シェルの `||` で足りる。

**hook は fail-open 設計**（CLAUDE.md）なので、両方失敗しても**ループは止まらない**。
状態検証が効かなくなるだけであり、この変更で「効くようになる」のが得。

### 3.3 webp: macOS 以外では skip する

`sips` が無い環境では**変換せず、その画像だけを提案から外して残りを出力**する。
KLK-065 で入れた「提案モードでは質問してはならない／処理できない画像は外して残りを出力する／
1件も無くても `items: []` を書く」の規律がそのまま効く。**追加の仕組みは要らず、明文化だけで足りる。**

- スキルには「**`sips` は macOS 専用。使えない環境では webp を skip し、理由を報告する**」と書く
- README の「できないこと」は既に「WebP は macOS でのみ」と書いてある（変更不要）

### 3.4 手順2-0 の矛盾を解消する

| | 変換先 | id |
|---|---|---|
| 現在の手順2-0（旧・KLK-033） | `catalog/img/<新id>.png` | スキルが確定 |
| 手順3'（新・KLK-064） | `.pending/` 内 | **ブリッジの責務** |

**手順3' に合わせる。** 手順2-0 は「`.pending/` 内で `<同じbasename>.png` へ変換する。
`catalog/img/` へは書かない。id を採番しない」に書き換える。
対話モード（チャットから直接実行）では従来どおりスキルが登録するが、**変換先は `.pending/` で統一**し、
移動は手順4で行う（そのほうが分岐が減る）。

### 3.5 README の両OS化

起動・停止・ポート確認を macOS と Windows の両方で書く。表形式にして並べる。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| PowerShell スクリプト（`.ps1`）にする | 既定で実行ポリシーに阻まれる。`.bat` はダブルクリックで動く |
| hook のコマンドを `py -3` に変える | macOS に `py` は無い。両方で動く形が要る |
| hook を Python ラッパー経由にする | ラッパーの起動に Python が要る（循環）。シェルの `\|\|` で足りる |
| Windows 用に webp 変換を実装する（PowerShell + WIC） | 環境差が大きく壊れやすい。JPG/PNG で運用でき、skip の仕組みは既にある |
| `起動.command` を廃して `.bat` に統一 | macOS ではダブルクリックで動かない。両方置くのが利用者にとって最も簡単 |
