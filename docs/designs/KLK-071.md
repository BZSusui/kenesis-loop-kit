# [KLK-071] 見本となる生成ページの同梱 設計

## 1. 目的

受け取った人が **README を読む前に「何ができるか」を目で見られる**ようにする。
実物を1つ開いてもらうのが、いちばん早い説明になる。

## 2. 現状

- 配布物に見本が無い。README の文章だけでは、生成物の質感が伝わらない。
- `mockups/` に開発中のテスト生成物が16件（3.0MB）残っている。理恵さんの決定で**削除**する。

## 3. 設計方針

**採用する方針: `samples/` を新設し、実際にツールで生成した3点を置く。**

### 3.1 なぜ `mockups/` ではなく `samples/` か

`mockups/` は **Git 除外**であり、`test_palette_klk010` と `klk021` が
`git check-ignore` で**除外されていること自体を検証している**。
見本を `mockups/` に置くと追跡されず、配布物にも入らない。
`samples/`（追跡対象）を分けるのが正しい。

役割も違う。`mockups/` は**利用者の作業場**（生成のたびに増える・案件名を含む・機密）。
`samples/` は**配布物の一部**（固定・ダミー案件名・公開してよい）。

### 3.2 見本は「実際に生成したもの」にする

手で書いた見本は、いずれ本物とずれる。**ツールで生成した実物**を置く。
そのため、生成に使った `instruction.json` も一緒に置く（何を指定するとこうなるかが分かる）。

### 3.3 見本では 🔄 セクション再生成が使えない

`compare.html` の 🔄 は `data-folder` をブリッジへ送るが、
`is_safe_mockups_folder()` が **`mockups/` 始まりでないパスを拒否**する（実測確認済み）。
`samples/` 配下は拒否され、**押してもエラーになるだけで危険はない**。

**見本を書き換えて 🔄 を消すことはしない。** 実際の生成物と違うものを見本にすると、
「見本にはあるのに自分の出力には無い」「その逆」という混乱を生む。
代わりに `samples/README.md` で「見るための見本です。🔄 はご自身の生成物でお使いください」と説明する。

### 3.4 カタログ非依存にする

`references.thumbnails` を空にして生成する。
配布先にカタログが無くても、見本の生成条件をそのまま再現できる。

**代替案と却下理由:**

| 案 | 却下理由 |
|---|---|
| 既存の `mockups/` から数点を選んで同梱 | 案件名が実在に見えるものがある（「内科クリニックサイト」等）。新規生成のほうが安全で、最新の生成規約も反映される |
| 見本を `mockups/` に置く | Git 除外なので配布物に入らない。テストが除外を検証しているため `.gitignore` の変更も不可 |
| 見本から 🔄 を削除して置く | 実際の生成物と違う見本になる。「見本には無いのに自分の出力にはある」混乱を生む |
| 見本を1点だけにする | カラム構成の違いが伝わらない。1col と 2col の両方を見せたい |
| スクリーンショット画像で見せる | 実際に触れない。幅切り替えや案切り替えの体験が伝わらない |

## 4. 実装詳細

### 4.1 `samples/` の構成

```
samples/
├── README.md                       見本の説明・🔄 が使えないこと
├── 01_カフェ_1カラム/
│   ├── index-a.html / index-b.html / index-c.html
│   ├── compare.html
│   └── instruction.json            この条件で生成した、という記録
├── 02_士業_本文2カラム/
└── 03_クリニック_ナビ下配置/
```

生成は `mockups/{日付}_{案件名}/` に出るので、**生成後に `samples/` へ移して番号つきの名前にする**。

### 4.2 `.gitignore`

`samples/` は**追跡対象**にする（除外行を足さない）。`mockups/` の除外は**変更しない**。

### 4.3 `tools/make-package.sh`

必須コピー対象に `samples` を追加する（既定で含める。見本に機密は無い）。

### 4.4 `README.md`

「はじめかた」の直前に、**まず見本を開いてもらう**導線を置く。

### 4.5 テスト `tests/site/check_klk071.py`

| ID | 検証内容 |
|---|---|
| S1 | `samples/` に見本が3点以上あり、各々に `index-a.html` と `instruction.json` がある |
| S2 | 各見本の `compare.html` があり、案切り替え（`name="variant"`）と幅切り替え（`name="vw"`）を持つ |
| S3 | 見本が **Git 追跡対象**である（`git check-ignore` が非0＝除外されていない） |
| S4 | 見本に**実在を思わせない**案件名が使われている（`meta.project` が「サンプル」で始まる） |
| S5 | 見本が**カタログ非依存**である（`references.thumbnails` が空） |
| S6 | 見本に外部URL参照が無い（NFR-005） |
| S7 | 見本が生成規約を満たす（`@media (max-width: 640px)` を持つ＝レスポンシブ） |
| S8 | `samples/README.md` に 🔄 が使えない旨がある |
| S9 | `make-package.sh` が `samples` を含める |
| S10 | README に見本への導線がある |
| S11 | `mockups/` に開発中の生成物が残っていない |
| S12 | `.gitignore` が `samples/` を除外していない（＆ `mockups/` の除外は維持） |

## 6. リスク

| リスク | 深刻度 | 軽減策 |
|---|---|---|
| 見本に実在の案件名が入る | **high** | 新規生成し、`meta.project` を「サンプル〜」で統一。S4 で検証 |
| 見本がカタログに依存し、配布先で意味をなさない | medium | `references.thumbnails` を空で生成。S5 で検証 |
| `mockups/` の削除で何かが壊れる | low | テストは `mockups/` の**除外設定**のみを見ており中身に依存しない（調査で確認）。S11 で確認 |
| 見本が生成規約から古くなる | medium | S2/S7 で「案切り替え・幅切り替え・レスポンシブ」を検証。規約が変われば FAIL して気づく |
| 見本の 🔄 でエラーが出て利用者が戸惑う | low | `samples/README.md` で明記（S8）。ブリッジは安全に拒否する |

## 7. マイグレーション戦略

`mockups/` の16件を削除する。Git 管理外なので履歴からの復元はできないが、
いずれも開発中のテスト生成物であり、理恵さんの決定に基づく。

## 8. ロールバック戦略

```bash
git revert {コミットハッシュ}     # samples/ と設定の巻き戻し
```
削除した `mockups/` は戻らない（Git 管理外）。
