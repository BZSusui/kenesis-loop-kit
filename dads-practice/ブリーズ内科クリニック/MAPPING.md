## 2. ブロックごとの対応づけ

元ラフの8ブロックすべてに対応先がある。欠落なし。

### NAV-01 → ヘッダーコンテナ ＋ 水平メニュー ＋ ボタン（アウトライン）

| 元ラフ | 対応先 | 判断の根拠 |
|---|---|---|
| 紺地のバー・ロゴ・4リンク・橙のCTA | `components/header-container` の ①ロゴ ③水平メニュー ＋ ②アイテム（ボタン） | ヘッダーコンテナの構成要素にそのまま当てはまる |
| 橙の塗りCTA | **アウトラインボタン**へ降格 | 塗りボタンは1画面1つ。最重要のCTAはCONTACTに置いた（→ 判断#1） |
| 紺地の背景 | **白背景＋下罫線**へ変更 | アウトラインボタンの外周はページ背景に3:1必要。紺地の上では 1.53:1 で満たせない（→ 判断#10） |
| リンクがただの`<li>`テキスト | `<a>`＋下線・`min-height:44px` | 押せるものが押せると分かる形になっていなかった |
| `::after`で作ったハンバーガー記号 | 削除 | 装飾の疑似要素で、押せない。`hamburger-menu-button` を使うべきだが今回は狭幅でメニューを折り返す方式にした（→ 判断#12） |

### MV-01 → 見出し（hgroup）＋ ボタン（追加スタイル）

| 元ラフ | 対応先 | 判断の根拠 |
|---|---|---|
| `<h1 class="catch">毎日の安心を…` | `<hgroup><h1>ブリーズ内科クリニック</h1><p class="hero-catch">毎日の安心を…</p></hgroup>` | 見出し: `<title>`に相当するページの主題をh1に。キャッチはサブタイトルなので`<p>`＋`<hgroup>`（→ 判断#5） |
| キャッチが32pxで最も大きい | **そのまま32pxを維持**（h1は20px） | 見出しレベルの大小とフォントサイズの大小は別々に定義してよい、と明記されている |
| 写真＋`rgba(6,20,40,.5〜.58)`の暗幕＋`text-shadow` | 暗幕の濃度を **0.66** に変更・`text-shadow`は削除 | 写真が何色か分からないので、**写真が純白のときを最悪ケース**として計算した。0.58では 4.43:1 で不足、0.66 で 5.78:1（→ 判断#4） |
| 橙の塗りCTA | **反転塗りボタン（白い面・青ラベル）** | 写真の上では枠線が3:1を保証できない。白い面そのもので 5.78:1 を確保する追加スタイル。DADSは「異なる視覚表現を用いたい場合には追加の表現を用意してスタイル化する」を認めている |
| 実写真 `assets/mv.png` | **同梱しない**（写真が入る場所として図示） | 入力素材は社外秘の可能性があるためGit管理外。暗幕の計算は写真によらず成立する |

### NEWS-01 → 箇条書きリスト（`components/list`）

| 元ラフ | 対応先 | 判断の根拠 |
|---|---|---|
| `<div class="news-row">`の羅列 | `<ul><li>`＋`<time datetime>` | リソースリストが該当しそうだが**準備中**で仕様なし。テーブルは「比較のため」、説明リストは「名前–値のペア」でどちらも違う（→ 判断#3） |
| 日付 `2026.09.01` | `<time datetime="2026-09-01">2026年9月1日</time>` | 機械可読な日付を持たせた |
| カテゴリバッジ | `<span class="news-cat">`＋枠線 | チップラベルが**準備中**。色だけの区別にならないよう枠線を付けた（→ 判断#2） |
| 見出しテキストがリンクでない | `<a>`＋下線・44px | 一覧の各行は詳細への導線であるべき。リンクテキストは記事タイトル自体にした（「詳細を読む」型は要素リストで区別がつかないと明記されている） |

### ABOUT-01 → 見出し ＋ 段落 ＋ 箇条書きリスト ＋ 画像

| 元ラフ | 対応先 | 判断の根拠 |
|---|---|---|
| `<div class="sym"><span>発熱・かぜ</span>…` | `<ul class="sym"><li>` | 見出しコンポーネント「項目を列挙するときは箇条書きリストを使用してください」 |
| `<h2>`→`<h3>` | 維持 | レベル飛びなし |
| 英字ラベル `ABOUT`（字間.3em） | **削除し、日本語のリード文に置換** | 字間を広げると1語として読めなくなる、と余白（アクセシビリティ）に明記。読み上げでも意味を成さない（→ 判断#8） |
| `(要検討: …)` の赤いTODO | `<span class="tbd">（未定）…`（帯背景＋枠線・本文色） | 元は #B54 / #FFF0F0 で 4.5:1 未満。色だけでなく「（未定）」の文言でも示す |

### MENU-01 → カード（`components/card`）

| 元ラフ | 対応先 | 判断の根拠 |
|---|---|---|
| `box-shadow` だけで枠線なしのカード | **1px枠線を追加**（白背景に 3.98:1） | 「コンテナは必ず外周をもつ」「外周は外側の背景に3:1以上」。ラフは**DADSが挙げる悪い例そのもの**だった |
| `<h4>一般内科`（h2の直下） | `<h3>` | h2→h4はレベル飛び |
| カードタイトルがリンクでない | `<a>`＋下線 | メインエリアのタイトルをリンクにした。コンテナ自体はクリッカブルにしない（両立できない仕様のため） |
| 橙の`price`バッジ（白文字） | 帯背景＋青文字＋枠線のラベル | 橙 #E8A33D に白文字は 2.16:1（→ 判断#9） |

### ACCESS-01 → 説明リスト ＋ テーブル ＋ 画像

| 元ラフ | 対応先 | 判断の根拠 |
|---|---|---|
| `<dl>` 所在地／電話／アクセス | 維持（`components/description-list`） | 名前–値のペアなので説明リストが正しい。ただし**仕様は準備中**なので構造だけ踏襲 |
| 診療時間の`<table>`（`<tr>`直書き） | `<thead>/<tbody>`・`scope`属性・`<caption>` | 表の構造を明示。DADSは「レイアウト目的で使用しない」とも明記（この表はデータなので適切） |
| `#ddd` の罫線 | `#1a1a1a` の罫線 | 「テーブルヘッダーとデータセルは黒いボーダーで明確に区切り、ヘッダーセルのテキストは太字に」 |
| `text-align:center` | `text-align:left` ＋ `vertical-align:top` | 「縦方向は上寄せ、横方向は値によって左寄せまたは右寄せ」。中央寄せは挙げられていない |
| `●` と `／` のみ | `●`＋読み上げ用「診療」／`—`＋読み上げ用「休診」＋**凡例** | 記号だけでは意味が伝わらない。凡例と代替テキストの両方を足した（→ 判断#6） |
| 横幅超過の考慮なし | `overflow-x:auto` のスクロール領域 | 「モバイルではテーブルの領域内での横スクロールとします」 |

| `📞` 絵文字 | 「電話」の文字 | 絵文字は読み上げ環境で挙動が安定しない |

### FOOTER-01 → ユーティリティリンク

## 3. 配色の決定と実測コントラスト比

**DADSに色の値（HEX）は無い。** あるのは原則と下限だけなので、こちらで決めて測った。
出発点はラフの参考ブルー `#2C5F8A`。DADSの「ブランドカラーと同じ色相で明度を調整する」に従って暗くした。

| 役割 | 値 | 由来 |
|---|---|---|
| プライマリー | `#0f4c81` | 参考ブルーと同色相で明度を下げた |
| プライマリー（hover） | `#0b3a63` | さらに明度を下げた |
| セカンダリー（枠線・区切り線） | `#4d85ad` | 同色相・明度高。非テキスト専用 |
| アクセント（飾り罫） | `#a8630b` | ラフの橙 `#E8A33D` は白背景に 2.16:1 で非テキストの3:1すら満たさない。同色相で暗くした |
| 背景 | `#ffffff` / 帯 `#eef4f8` | |
| 本文 | `#1a1a1a` | |
| フォーカス | 黄 `#fbbf24` ＋ 黒 `#000000` | **変更禁止**。値はプロジェクトの既存実装（`デザインシステムの使い方.html` の `.demo-btn`）に合わせた |

### フォーカスインジケーターの2重構造（重要）

黄単体・黒単体では、背景によっては 3:1 を満たさない。**どちらか一方が効けばよい**構造になっている。

| 背景 | 黄 | 黒 | 有効な方 |
|---|---|---|---|
| 白 | 1.67:1 | 21.00:1 | 黒 21.00:1 |
| 帯 `#eef4f8` | 1.50:1 | 18.93:1 | 黒 18.93:1 |
| 青 `#0f4c81` | 5.31:1 | 2.37:1 | **黄 5.31:1** |
| ヒーロー暗幕（最悪） | 3.46:1 | 3.63:1 | 黒 3.63:1 |
| 黒帯 `#1a1a1a` | 10.43:1 | 1.21:1 | **黄 10.43:1** |

白背景では黄が 1.67:1 しかない。**「黄 vs 背景」だけを機械的に測ると、
DADSが変更を禁じている色そのものを違反と判定してしまう。** 第2段の判定器で必ず踏む地雷。

### 余白

基準単位 8 CSS px の倍率で **4段階**（DADSの目安は3〜5段階）。

| トークン | 値 | 倍率 |
|---|---|---|
| `--sp-1` | 8px | ×1 |
| `--sp-2` | 16px | ×2 |
| `--sp-3` | 32px | ×4 |
| `--sp-4` | 64px | ×8 |

`margin` / `padding` / `gap` の宣言 **75件**を検査し、スケール外は1件のみ
（`.vh` の `margin:-1px`。これは読み上げ専用テキストを隠す定型技法であり余白ではない）。

## 4. 機械には決められなかった判断

**第1段の本命。** ここに挙げたものは、規約を読んでも答えが一つに決まらず、
人が決めるしかなかった。第3段（変換の半自動化）で「人の確認をどこに挟むか」の答えは、この一覧そのもの。

| # | 判断 | なぜ機械に決められないか | 今回の決定 |
|---|---|---|---|
| 1 | **繰り返しCTAのうち、どれを唯一のプライマリーにするか** | DADSは「塗りボタンは1画面に原則1つ」。しかし販促ページは同じCTAを何度も置くのが常道。どれが本命かは事業判断 | CONTACTの予約ボタンをプライマリーに。ヘッダーはアウトライン、ヒーローは反転塗り、フッターはリンクに降格 |
| 2 | **仕様が「準備中」の部品をどう代替するか** | `chip-label` `resource-list` `description-list` は中身がない。DADSに聞いても答えが返ってこない | 枠線付きの`span` / 箇条書きリスト / `<dl>`で代用。**将来DADSが仕様を出したら作り直しが必要** |
| 3 | **お知らせ一覧は何コンポーネントか** | テーブル（比較用）でも説明リスト（名前–値）でもカードでもない。リソースリストが近いが準備中 | 箇条書きリスト |
| 4 | **写真の上に載る文字をどう保証するか** | 写真の色は入稿まで分からない。測定対象が存在しない | 「写真が純白のとき」を最悪ケースとして暗幕の濃度を逆算（0.66）。**この発想自体が人間の発明**で、機械は「測れない」で止まる |
| 5 | **h1 をキャッチコピーにするか、事業者名にするか** | DADSは「`<title>`に相当するページの主題をh1に」としか言わない。何が主題かは人が決める | 事業者名をh1、キャッチを`<hgroup>`内の`<p>`に |
| 6 | **記号（●／）の読ませ方** | 「●」を「診療」と読ませるか「まる」と読ませるかは文脈依存 | 読み上げ用テキスト「診療」「休診」＋凡例を追加 |
| 7 | **タグ群は列挙か装飾か** | 「発熱・かぜ」等は意味のある列挙にも、見た目のアクセントにも見える | 箇条書きリスト（意味のある列挙として扱った） |
| 8 | **どこまでが「捨ててよい装飾」か** | 英字ラベル`NEWS`・字間.3em・出現アニメ・影。DADSは字間と動きに注意を促すが、捨てるかどうかは言わない | 英字ラベルは日本語リード文へ置換、字間は標準へ、アニメと影は削除 |
| 9 | **ブランド色が下限を満たさないときどうするか** | DADSは「同色相で明度調整」「別の色を選ぶ」「ロゴだけに使う」の3案を並べるだけ。どれを選ぶかはブランド判断 | 橙を同色相で暗くして飾り罫に降格（#E8A33D → #a8630b） |
| 10 | **ヘッダーの地色を変えてよいか** | 紺地だとアウトラインボタンの外周が 1.53:1 で満たせない。地色を変えるか、ボタンの形を変えるかの二択 | 白地＋下罫線に変更。**見た目の印象が大きく変わるのでクライアント確認が要る** |
| 11 | **フォーカスの2重構造をどう判定するか** | DADSは「フォーカスインジケーターも3:1必要」と「黄+黒の2重構造は変更禁止」を別々に書いており、両立の解釈は書いていない | 「どちらか一方が3:1を満たせばよい」と解釈。第2段の判定器に埋め込む前に人の合意が要る |
| 12 | **狭い画面のメニューをどうするか** | ラフは疑似要素でハンバーガー記号を描いていただけで機能がない。`hamburger-menu-button`＋`drawer`＋`mobile-menu`の3点セットが要るが、JavaScriptが必要 | 今回は折り返し表示で回避。**JavaScriptなしという制約と、DADSのモバイルメニュー仕様は両立しない** |

## 5. 人間の承認が要る変更（クライアント確認事項）

見た目・内容が変わったもの。技術的には正しいが、勝手に決めてよい範囲を超えている。

1. ヘッダーの地色を紺 → 白に変更（判断#10）
2. ブランドの橙を暗くして役割を降格（判断#9）
3. ヒーロー以外のCTAボタンの見た目を降格。フッターのCTAボタンは削除（判断#1）
4. 英字ラベル（NEWS / ABOUT など）を削除し日本語のリード文に置換（判断#8）
5. 出現アニメーションを削除
6. リンクにすべて下線が付いたことによる見た目の変化
7. 実写真を同梱していない（社外秘の可能性があるため）

## 6. 第2段（判定の機械化）へ渡す申し送り

実際に手を動かして分かった、**判定器を書くときに間違えやすい点**。

1. **フォーカスの黄を単独で測ってはいけない。** 白背景で 1.67:1 になり、変更禁止の色を違反判定する
2. **「大きな文字は3:1」の緩和を入れてはいけない。** DADSはこの規定を明示的に除外している
3. **写真の上の文字は「測れない」で止まる。** 最悪ケースを合成して判定する仕組みが要る
4. **`box-shadow` だけのカードは検出できると価値が高い。** DADSが挙げる悪い例で、ラフは実際にこれを踏んでいた
5. **見出しレベルの飛びは機械で確実に取れる。** ラフは h2→h4 で飛んでいた
6. **押せない「リンク風テキスト」は静的解析で取れる。** ラフのフッターナビが該当
7. **余白は変数定義と使用箇所の両方を見ないと空検査になる。** 値が `var()` 経由だとリテラルpxの走査は何も保証しない（今回、最初に書いた検査が実際にこれで空になった）
8. **49種すべてに仕様があるとは限らない。** 「準備中」のコンポーネントに当たったとき、判定器は「不明」を返せる必要がある
